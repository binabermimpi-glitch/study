# static과 인스턴스 멤버

## 2026-08-23 자바 참조와 자료형 기초

### static과 인스턴스 호출

> `static` 멤버는 클래스 이름으로 직접 호출할 수 있지만, 인스턴스 멤버는 객체를 생성하여 주소를 확보한 뒤 호출해야 합니다.

자바에서 클래스는 실행과 구성의 기본 단위이며, 클래스 안에는 필드, 생성자, 메소드 등의 멤버가 선언됩니다. 메소드를 호출할 때 가장 먼저 확인할 요소는 해당 메소드가 `static`인지 여부입니다.

`static` 멤버는 선언 시점에 클래스 차원에서 관리되므로 클래스 이름을 통해 바로 접근할 수 있습니다. 반면 인스턴스 멤버는 객체마다 별도의 상태와 주소를 가질 수 있으므로 객체 생성 이후에 접근해야 합니다.

```java
class Test {
    static void staticMethod() {
    }

    void instanceMethod() {
    }
}

Test.staticMethod();      // static 메소드는 클래스명으로 호출합니다.
// Test.instanceMethod(); // 인스턴스 메소드는 직접 호출할 수 없습니다.

Test test = new Test();
test.instanceMethod();    // 객체 생성 후 호출합니다.
```

| 구분 | 귀속 대상 | 기본 호출 방식 | 예시 |
|---|---|---|---|
| `static` 멤버 | 클래스에 귀속 | `클래스명.멤버` 형식으로 호출합니다. | `Math.PI` |
| 인스턴스 멤버 | 객체에 귀 | `객체참조.멤버` 형식으로 호출합니다. | `file.exists()` |

인스턴스 메소드를 호출하기 위해 객체를 생성하는 과정은 생성자와 연결됩니다. 이후 학습에서는 `new` 연산자, 생성자, 객체 주소, 인스턴스 필드와 인스턴스 메소드의 관계를 함께 다루게 됩니다.


### 상수와 필드

> `static final` 필드는 클래스에 귀속된 변경 불가능한 값이며, 일반적으로 `클래스명.필드명` 형태로 참조합니다.

필드는 클래스 내부에 선언되는 값 저장 공간입니다. 특히 `static final`이 함께 선언된 필드는 클래스가 공유하는 고정값, 즉 상수로 사용됩니다. 대표적인 예가 `Math.PI`입니다.

```java
public class Score {
    public static final double DEFAULT_SCORE = 50.0;
    public static double currentScore = 50.0;
}
```

상수는 선언과 동시에 초기값이 고정되며 이후 재대입할 수 없습니다. 반면 `static`만 선언된 필드는 클래스 차원에서 공유되지만 값 변경은 가능합니다.

| 선언 형태 | 값 변경 가능 여부 | 호출 방식 | 의미 |
|---|---|---|---|
| `static final` 필드 | 값을 변경할 수 없습니다. | `클래스명.필드명`으로 호출합니다. | 클래스 상수입니다. |
| `static` 필드 | 값을 변경할 수 있습니다. | `클래스명.필드명`으로 호출합니다. | 클래스 변수입니다. |
| 인스턴스 필드 | 객체별로 값을 변경할 수 있습니다. | `객체참조.필드명`으로 호출합니다. | 객체 상태 값입니다. |

상수 이름은 관례적으로 대문자와 밑줄을 사용하여 작성합니다. 이는 API 문서에서 상수와 일반 변수 또는 메소드를 빠르게 구분할 수 있게 해주는 중요한 명명 규칙입니다.


## 2026-08-27 자바 메소드와 객체 생성

### static과 non-static 설계

> `static` 멤버는 클래스 단위의 공용, 공통 데이터를 처리하고, non-static 멤버는 객체별로 달라지는 상태와 동작을 처리합니다.

클래스는 사용자 정의 자료형을 만드는 키워드이며, 일반적으로 필드와 메소드로 구성됩니다. 필드는 객체의 상태나 속성을 표현하고, 메소드는 클래스 또는 객체가 수행하는 기능을 표현합니다.

`static`은 특정 객체에 소속되지 않고 클래스에 소속됩니다. 따라서 객체를 생성하지 않아도 클래스 이름을 통해 접근할 수 있습니다. 공통 상수, 누적 개수, 공용 기능처럼 모든 객체가 함께 사용해야 하는 데이터와 기능에 적합합니다.

- `static` 필드는 모든 객체가 공유하는 하나의 값으로 관리됩니다.
- `static` 메소드는 클래스 이름으로 직접 호출할 수 있는 공용 기능입니다.
- non-static 필드와 메소드는 생성된 객체마다 독립적으로 존재합니다.
- 객체별 점수, 이름, 급여, 상태처럼 유동적인 값은 non-static으로 설계하는 것이 적절합니다.

예를 들어 학생별 국어, 영어, 수학 점수와 개인 총점은 각 레코드마다 달라지므로 non-static 데이터입니다. 반면 전체 학생 수, 전체 합계, 공용 기준값처럼 누적되거나 공유되는 데이터는 `static`으로 관리할 수 있습니다.

사과나무를 여러 작업자가 공유하는 상황에서도 나무의 사과 개수는 공용 상태이므로 `static`으로 볼 수 있습니다. 반면 작업자별 수확량이나 개별 상태는 객체마다 달라지므로 non-static 필드가 됩니다.

```java
class AppleTree {
    static int appleCount = 6;
    String workerName;
}
```

API 문서에서 `static`으로 선언된 멤버는 클래스 멤버로 즉시 접근할 수 있는 공용 기능임을 의미합니다. 반면 객체지향 설계에서는 객체별 상태를 다루기 위해 non-static 메소드가 더 빈번하게 사용됩니다.


### static 필드와 객체별 상태

> 인스턴스 필드는 객체마다 독립적으로 존재하지만, `static` 필드는 클래스당 하나만 생성되어 모든 객체가 공유합니다.

인스턴스 필드는 힙 영역의 각 객체에 포함됩니다. 따라서 같은 클래스에서 여러 객체를 생성하면 객체마다 서로 다른 필드 값을 보유할 수 있습니다. 카운터 객체를 여러 개 만들면 각 객체의 non-static 카운트는 독립적으로 증가합니다.

```java
class Counter {
    private int count;

    public void add() {
        count++;
    }
}
```

반면 `static` 필드는 특정 인스턴스가 아니라 클래스 자체에 소속됩니다. 여러 객체가 생성되어도 저장 공간은 하나이며, 한 객체에서 변경한 값이 다른 객체에서도 동일하게 확인됩니다.

```java
class Counter {
    private static int count;

    public static void add() {
        count++;
    }
}
```

| 구분 | 인스턴스 필드 | static 필드 |
|---|---|---|
| 소속 | 생성된 객체에 소속됩니다. | 클래스에 소속됩니다. |
| 생성 개수 | 객체마다 별도로 생성됩니다. | 클래스당 하나만 생성됩니다. |
| 접근 방식 | `참조변수.필드`로 접근합니다. | `클래스명.필드`로 접근합니다. |
| 적합한 용도 | 객체별 상태를 저장합니다. | 전체 객체가 공유할 상태를 저장합니다. |

참조 변수에 `null`을 대입하면 해당 참조 변수와 객체 사이의 연결이 끊깁니다. 다만 객체가 즉시 삭제되는 것은 아니며, 더 이상 참조되지 않는 객체는 가비지 컬렉터가 판단하는 시점에 회수 대상이 됩니다.
