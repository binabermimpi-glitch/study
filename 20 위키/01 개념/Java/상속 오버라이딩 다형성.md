# 상속 오버라이딩 다형성

## 한 문장 설명

상속은 부모의 공통 구조를 자식이 확장하는 문법이고, 다형성은 하나의 부모 타입으로 여러 자식 객체의 서로 다른 동작을 호출하는 성질이다.

## 상속과 생성 순서

```java
class Person {
    Person(String name) { }
}

class Student extends Person {
    Student(String name) {
        super(name);
    }
}
```

자식 객체를 만들 때 부모 부분이 먼저 초기화된다. 부모에 매개변수 없는 생성자가 없다면 자식 생성자가 알맞은 `super(...)`를 첫 문장으로 호출해야 한다.

## 오버라이딩과 동적 바인딩

```java
class Person {
    String role() { return "사람"; }
}

class Student extends Person {
    @Override
    String role() { return "학생"; }
}

Person person = new Student();
System.out.println(person.role()); // 학생
```

- 컴파일 시 접근 가능한 멤버는 참조 변수의 선언 타입을 기준으로 검사한다.
- 오버라이딩된 인스턴스 메서드는 실행 시 실제 객체 타입을 기준으로 선택한다.
- 필드와 `static` 메서드는 같은 방식으로 다형적으로 오버라이딩되지 않는다.

## private와 protected

부모의 `private` 필드는 자식이 직접 접근할 수 없다. 부모가 제공하는 메서드를 사용한다. `protected`는 같은 패키지 또는 상속 관계에서 접근을 허용하지만, 상태를 무조건 노출하기보다 필요한 동작을 메서드로 제공하는 설계를 우선한다.

## 안전한 형변환

부모 참조를 자식 타입으로 내릴 때 실제 객체 타입이 맞지 않으면 `ClassCastException`이 발생한다.

```java
if (person instanceof Student student) {
    System.out.println(student.role());
}
```

## 실무에서는 어떻게 쓰이나

Spring은 구현 객체를 인터페이스나 상위 타입으로 주입하여 교체 가능한 구조를 만든다. 상속은 `is-a` 관계가 분명할 때 사용하고, 단순 코드 재사용 목적이라면 조합을 함께 검토한다.

## 흔한 실수

- 부모 타입 변수로 자식 전용 멤버에 바로 접근한다.
- 형제 클래스끼리 실제 객체 타입 확인 없이 강제 형변환한다.
- 오버로딩과 오버라이딩을 혼동한다.
- 생성자는 상속된다고 생각한다.
