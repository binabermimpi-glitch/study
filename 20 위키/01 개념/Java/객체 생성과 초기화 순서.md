# 객체 생성과 초기화 순서

## Java 객체 생성자 캡슐화 복습

### Java 객체·생성자·캡슐화 복습 정리

지금까지 이해한 것, 헷갈린 것과 놓치기 쉬운 핵심을 정리했다.


### 1. 현재까지 이해가 잘 잡힌 부분

- `Person`은 객체가 아니라 클래스(설계도)다.
- `Person p1 = new Person();`에서 `new Person()`이 실제 Person 객체를 만들고 `p1`은 객체를 가리키는 참조 변수다.
- `new`는 객체를 생성하는 연산자이며 객체 생성 시 생성자가 호출된다.
- 생성자를 직접 만들지 않으면 조건에 따라 기본 생성자 `Person()`이 자동 제공된다.
- 생성자는 상속되지 않지만 자식 객체를 만들 때 부모 생성자가 먼저 호출된다.
- `static` 요소는 클래스 소속이고 객체 없이 접근할 수 있으며 non-static 요소는 객체 소속이다.
- Mutable 객체는 같은 객체를 계속 참조하면서 내부 필드 값을 바꿀 수 있다.


### 2. 헷갈렸던 부분과 정리

#### 2-1. 클래스와 객체 구분

```java
class Person {
    public int age;
}

Person p1 = new Person();
```

`Person` 클래스는 설계도이고 `new Person()`을 실행할 때 그 설계도를 이용한 새로운 객체가 힙에 생성된다. `p1`은 클래스 자체가 아니라 생성된 Person 타입 객체를 가리킨다.

```text
Person 클래스(설계도)
       ↓ new
p1 ─────→ Person 객체(실제 데이터)
             age = 0
```


#### 2-3. 객체 생성과 초기화 순서

```java
Person p1 = new Person("철수", 20);
```

1. `new`가 객체 공간을 마련한다.
2. 인스턴스 필드가 기본값으로 초기화된다. 예: `String → null`, `int → 0`, `boolean → false`.
3. 필드에 직접 적은 초기값과 인스턴스 초기화가 적용된다.
4. 생성자 본문이 실행되어 원하는 값으로 초기화한다.
5. 생성이 정상 완료되면 참조 변수 `p1`에 참조값이 대입된다.


## 자바 메소드와 객체 생성

### 클래스, 생성자, 인스턴스 필드

> 생성자는 `new` 연산자와 함께 호출되어 객체를 만들고, 객체가 보유할 인스턴스 필드를 초기화합니다.

클래스는 속성을 나타내는 필드와 기능을 나타내는 메소드로 구성됩니다. 클래스 내부에 `static` 없이 선언된 필드는 인스턴스 필드이며, 객체가 생성될 때마다 객체별로 독립적인 저장 공간을 갖습니다.

```java
public class Person {
    private String name;
    private int age;
}
```

생성자는 클래스와 이름이 같고 반환형을 작성하지 않는 특수한 메소드입니다. 생성자는 객체 생성 직후 필드를 초기화하는 역할을 담당합니다. 생성자도 매개변수 구성에 따라 오버로딩할 수 있습니다.

```java
public Person() {
    this.name = "홍길동";
    this.age = 0;
}

public Person(String name, int age) {
    this.name = name;
    this.age = age;
}
```

`this`는 현재 생성 중이거나 현재 메소드를 실행 중인 객체 자신을 의미합니다. 필드명과 파라미터명이 같을 때 `this.필드명`으로 객체 필드를 명확히 구분합니다.

- 생성자를 하나도 작성하지 않으면 기본 생성자가 자동으로 제공됩니다.
- 매개변수가 있는 생성자를 직접 작성하면 기본 생성자는 자동으로 추가되지 않습니다.
- 객체마다 별도의 값을 가져야 하는 필드는 인스턴스 필드로 선언합니다.
- 인스턴스 메소드는 참조 변수와 점 연산자를 사용하여 호출합니다.

```java
Person hong = new Person("홍길동", 30);
System.out.println(hong.getName());
```

필드를 `private`으로 선언하면 클래스 외부에서 직접 접근할 수 없습니다. 이때 `getter`는 필드 값을 반환하고, `setter`는 검증 규칙을 적용하여 필드 값을 변경하는 통로가 됩니다. 이러한 구조는 객체 내부 상태를 보호하는 캡슐화의 기본 형태입니다.
