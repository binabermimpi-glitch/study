# 자바 컬렉션 프레임워크와 자료구조

# PART 1. 자바 컬렉션 프레임워크와 자료구조

## 1. 컬렉션 프레임워크(Collection Framework)

> 컬렉션 프레임워크는 여러 객체를 효율적으로 저장, 조회, 수정, 삭제하기 위한 인터페이스, 구현 클래스, 알고리즘의 집합이다.

### 1-1. 배열과 컬렉션의 차이

배열(Array)은 선언할 때 크기가 결정되며, 인덱스를 통해 요소에 접근한다.

```java
int[] numbers = new int[3];

numbers[0] = 10;
numbers[1] = 20;
numbers[2] = 30;
```

배열은 생성한 뒤 길이를 변경할 수 없다.

반면 컬렉션은 구현체에 따라 요소를 추가하거나 삭제하면서 크기를 동적으로 관리할 수 있다.

```java
List<Integer> numbers = new ArrayList<>();

numbers.add(10);
numbers.add(20);
numbers.add(30);
numbers.add(40);
```

ArrayList는 내부적으로 배열을 사용하지만, 저장 공간이 부족하면 더 큰 배열을 확보하여 데이터를 관리한다.

| 구분 | 배열 | 컬렉션 |
|---|---|---|
| 크기 | 고정 | 구현체에 따라 동적 관리 |
| 기본형 저장 | 가능 | 제네릭 요소 타입으로 직접 사용 불가 |
| 인덱스 접근 | 가능 | List 계열에서 가능 |
| 요소 추가/삭제 | 직접 처리 필요 | 다양한 메서드 제공 |
| 주요 용도 | 고정된 크기의 데이터 | 유연한 데이터 관리 |

### 1-2. 컬렉션의 전체 구조

자바 컬렉션 프레임워크의 대표적인 구조는 다음과 같다.

```text
Iterable
    |
Collection
    |
    +-- List
    |     |
    |     +-- ArrayList
    |     +-- LinkedList
    |
    +-- Set
    |     |
    |     +-- HashSet
    |     +-- LinkedHashSet
    |     +-- SortedSet
    |            |
    |            +-- NavigableSet
    |                   |
    |                   +-- TreeSet
    |
    +-- Queue
          |
          +-- PriorityQueue
          |
          +-- Deque
                 |
                 +-- ArrayDeque
                 +-- LinkedList

Map (Collection을 상속하지 않음)
    |
    +-- HashMap
    +-- LinkedHashMap
    +-- SortedMap
           |
           +-- NavigableMap
                  |
                  +-- TreeMap
```

위 그림은 주요 관계를 단순화한 것이다. List, Set, Queue, Deque 및 Map에는 다른 하위 인터페이스와 구현체도 존재한다.

중요한 점은 Map이 Collection 인터페이스를 상속하지 않는다는 것이다.

하지만 Map도 컬렉션 프레임워크에 포함된다.

### 1-3. List, Set, Map의 차이

| 인터페이스 | 데이터 관리 방식 | 중복 | 순서 |
|---|---|---|---|
| List | 인덱스 | 허용 | 위치 순서 유지 |
| Set | 값의 유일성 | 허용하지 않음 | 구현체에 따라 다름 |
| Map | 키-값 | 키 중복 불가 | 구현체에 따라 다름 |

예제:

```java
List<String> list = new ArrayList<>();
Set<String> set = new HashSet<>();
Map<String, Integer> map = new HashMap<>();
```

각 자료구조의 사용 목적은 다르다.

- List: 게시글 목록, 댓글 목록
- Set: 중복 없는 태그, 사용자 권한 집합
- Map: 사용자 ID와 사용자 정보의 연결

### 1-4. 인터페이스 타입으로 선언하는 이유

```java
List<String> names = new ArrayList<>();
```

왼쪽의 List는 인터페이스이고, 오른쪽의 ArrayList는 구현 클래스이다.

실제 객체는 ArrayList로 생성되지만, 참조 변수는 List 타입으로 선언한다.

이렇게 하면 이후 구현체를 변경하기 편리하다.

```java
List<String> names = new LinkedList<>();
```

List에 정의된 기능을 사용하는 코드는 구현체를 바꾸더라도 대부분 그대로 유지할 수 있다.

단, 구현체에 따라 성능과 지원 기능에는 차이가 있다.

## 2. Collection 인터페이스와 공통 메서드

> Collection은 List, Set, Queue 등에서 공통으로 사용할 수 있는 메서드를 정의한다.

### 2-1. 공통 메서드

| 메서드 | 기능 |
|---|---|
| add(E e) | 요소 추가 |
| remove(Object o) | 지정한 요소 삭제 |
| contains(Object o) | 요소 존재 여부 확인 |
| size() | 요소 개수 조회 |
| isEmpty() | 비어 있는지 확인 |
| clear() | 모든 요소 삭제 |
| iterator() | 반복자 반환 |
| toArray() | 배열로 변환 |
| addAll() | 다른 컬렉션의 요소 추가 |
| removeAll() | 지정 컬렉션에 포함된 요소 삭제 |
| retainAll() | 지정 컬렉션과 공통인 요소만 유지 |

주의할 점:

Collection의 add()는 boolean을 반환하지만, List의 add(int, E)는 void를 반환한다.

remove()도 오버로딩된 형태에 따라 반환값이 달라진다.

### 2-2. CRUD 실습

CRUD는 데이터 처리의 기본 작업을 뜻한다.

```text
C = Create : 생성
R = Read   : 조회
U = Update : 수정
D = Delete : 삭제
```

예제:

```java
List<String> names = new ArrayList<>();

// Create
names.add("홍길동");
names.add("김철수");

// Read
System.out.println(names.get(0));

// Update
names.set(0, "이순신");

// Delete
names.remove("김철수");

System.out.println(names);
```

실행 결과:

```text
홍길동
[이순신]
```

실행 과정:

1. 빈 ArrayList 생성
2. 홍길동 추가 → [홍길동]
3. 김철수 추가 → [홍길동, 김철수]
4. get(0)으로 홍길동 조회
5. set(0, "이순신")으로 첫 번째 요소 변경
6. remove("김철수")로 해당 요소 삭제
7. 최종적으로 [이순신] 출력

## 3. List와 ArrayList

> List는 인덱스로 요소를 관리하며, ArrayList는 내부 배열을 이용하는 대표적인 구현 클래스이다.

### 3-1. List의 특징

- 인덱스는 0부터 시작한다.
- 중복 요소를 허용한다.
- 여러 개의 null을 저장할 수 있는 구현체가 있다.
- 요소의 순서를 관리한다.
- get(), set() 등을 이용할 수 있다.

```java
List<Integer> numbers = new ArrayList<>();

numbers.add(100);
numbers.add(200);
numbers.add(100);
numbers.add(null);

System.out.println(numbers);
```

실행 결과:

```text
[100, 200, 100, null]
```

### 3-2. add()와 set()의 차이

```java
List<String> names = new ArrayList<>();

names.add("A");
names.add("B");
names.add("C");

names.add(1, "X");

System.out.println(names);
```

실행 결과:

```text
[A, X, B, C]
```

add(1, "X")는 인덱스 1에 요소를 삽입한다.

기존 요소들이 뒤로 이동한다.

반면 다음 코드는 다르다.

```java
names.set(1, "Y");

System.out.println(names);
```

실행 결과:

```text
[A, Y, B, C]
```

set()은 해당 인덱스의 기존 요소를 새로운 요소로 교체한다.

### 3-3. remove() 이후 인덱스 변경

```java
List<String> names = new ArrayList<>();

names.add("홍길동");
names.add("김철수");
names.add("이순신");

names.remove(0);

System.out.println(names.get(0));
```

실행 결과:

```text
김철수
```

삭제 전:

```text
인덱스 0 : 홍길동
인덱스 1 : 김철수
인덱스 2 : 이순신
```

삭제 후:

```text
인덱스 0 : 김철수
인덱스 1 : 이순신
```

ArrayList에서는 요소가 삭제되면 뒤쪽 요소들이 앞으로 이동한다.

### 3-4. Integer 리스트에서 remove() 주의

```java
List<Integer> numbers =
    new ArrayList<>(List.of(10, 20, 30));

numbers.remove(1);

System.out.println(numbers);
```

실행 결과:

```text
[10, 30]
```

왜 20이 삭제될까?

List에는 다음 메서드들이 있기 때문이다.

```java
remove(int index)
remove(Object o)
```

remove(1)은 인덱스 1을 삭제한다.

만약 정수 값 10을 삭제하려면 다음처럼 작성할 수 있다.

```java
numbers.remove(Integer.valueOf(10));
```

이 경우에는 값이 10인 요소를 삭제한다.

### 3-5. IndexOutOfBoundsException

```java
List<String> names = List.of("A", "B");

System.out.println(names.get(3));
```

리스트의 유효 인덱스는 0, 1뿐이므로 예외가 발생한다.

인덱스로 조회하거나 변경할 때는 일반적으로 다음 범위를 만족해야 한다.

```text
0 <= index < size()
```

단, add(index, element)는 마지막 위치에 추가할 수 있으므로 index == size()도 허용한다.

## 4. ArrayList와 LinkedList

### 4-1. ArrayList 내부 구조

ArrayList는 내부 배열을 기반으로 요소를 관리한다.

```text
인덱스 :   0    1    2    3
데이터 : [10] [20] [30] [40]
```

장점:

- 특정 인덱스 조회가 빠르다.
- 순차적으로 데이터를 탐색하기 좋다.
- 일반적인 목록 처리에서 효율적이다.

주의할 점:

중간에 요소를 추가하거나 삭제하면 다른 요소를 이동해야 할 수 있다.

### 4-2. LinkedList 내부 구조

LinkedList는 노드 사이의 연결 관계를 이용한다.

자바의 LinkedList는 이중 연결 리스트 구조이다.

```text
null <- [10] <-> [20] <-> [30] -> null
```

각 노드는 개념적으로 다음 정보를 가진다.

```text
이전 노드 참조
현재 요소
다음 노드 참조
```

예를 들어 20과 30 사이에 25를 삽입한다면 다음처럼 연결을 변경한다.

```text
[10] <-> [20] <-> [25] <-> [30]
```

이미 삽입 위치의 노드를 알고 있다면 연결 변경은 효율적이다.

하지만 인덱스만 알고 있다면 해당 위치까지 노드를 탐색하는 비용이 발생한다.

### 4-3. 시간 복잡도 비교

| 작업 | ArrayList | LinkedList |
|---|---|---|
| 인덱스 조회 | O(1) | O(n) |
| 끝에 추가 | 평균적으로 O(1) | O(1) |
| 인덱스로 중간 삽입 | O(n) | O(n) |
| 인덱스로 중간 삭제 | O(n) | O(n) |
| 위치를 알고 노드 연결 변경 | 요소 이동 필요 | O(1) |

LinkedList가 모든 삽입과 삭제에서 빠른 것은 아니다.

특히 get(index)를 반복해서 호출하면 탐색 비용이 크게 증가할 수 있다.

실무에서는 일반적인 목록 처리에 ArrayList를 우선 고려하는 경우가 많다.

### 4-4. Queue와 Deque

LinkedList는 Deque 인터페이스도 구현한다.

```java
Deque<Integer> deque = new LinkedList<>();

deque.addLast(10);
deque.addLast(20);
deque.addFirst(5);

System.out.println(deque);
```

실행 결과:

```text
[5, 10, 20]
```

Queue는 일반적으로 FIFO 구조이다.

```text
FIFO = First In First Out

먼저 들어온 요소가 먼저 나감
```

Stack은 LIFO 구조이다.

```text
LIFO = Last In First Out

나중에 들어온 요소가 먼저 나감
```

실무에서는 큐와 스택 기능이 필요할 때 ArrayDeque도 자주 사용한다.

## 5. List.of(), Arrays.asList(), ArrayList의 차이

> 모두 리스트처럼 사용할 수 있지만 요소 변경과 크기 변경 가능 여부가 다르다.

### 5-1. List.of()

```java
List<Integer> numbers = List.of(1, 2, 3);
```

List.of()는 수정할 수 없는 리스트를 생성한다.

```java
numbers.add(4);  // 예외
numbers.set(0, 5); // 예외
numbers.remove(0); // 예외
```

UnsupportedOperationException이 발생한다.

List.of()는 null 요소도 허용하지 않는다.

### 5-2. Arrays.asList()

```java
List<Integer> numbers =
    Arrays.asList(1, 2, 3);

numbers.set(0, 100);

System.out.println(numbers);
```

실행 결과:

```text
[100, 2, 3]
```

Arrays.asList()로 생성한 리스트는 크기가 고정되어 있다.

따라서 set()으로 요소를 변경할 수 있지만, 일반적으로 add()와 remove()로 크기를 변경할 수 없다.

또한 전달받은 배열을 기반으로 리스트를 만든 경우에는 배열과 리스트가 요소 변경을 공유한다.

### 5-3. 변경 가능한 ArrayList 만들기

```java
List<Integer> numbers =
    new ArrayList<>(List.of(1, 2, 3));

numbers.add(4);
numbers.set(0, 100);

System.out.println(numbers);
```

실행 결과:

```text
[100, 2, 3, 4]
```

List.of()로 만든 요소들을 새로운 ArrayList에 복사했기 때문에 요소를 추가하고 변경할 수 있다.

단, 요소가 참조형 객체라면 객체 자체를 깊은 복사하는 것은 아니다.

## 6. Set과 HashSet

> Set은 중복된 요소를 허용하지 않으며, HashSet은 해시 기반으로 요소를 저장하고 검색한다.

### 6-1. Set의 특징

```java
Set<String> names = new HashSet<>();

names.add("홍길동");
names.add("홍길동");
names.add("김철수");

System.out.println(names.size());
```

실행 결과:

```text
2
```

동일한 문자열인 홍길동을 두 번 추가했지만 하나만 저장된다.

HashSet은 출력 순서를 보장하지 않는다.

### 6-2. Set은 인덱스가 없다

```java
Set<String> names = new HashSet<>();

names.add("A");
names.add("B");
```

다음 코드는 사용할 수 없다.

```java
names.get(0);       // 컴파일 오류
names.set(0, "C");  // 컴파일 오류
```

Set은 인덱스로 데이터를 관리하지 않기 때문이다.

일반적으로 요소를 교체하려면 기존 요소를 삭제한 뒤 새 요소를 추가한다.

```java
names.remove("A");
names.add("C");
```

### 6-3. null 처리

```java
Set<String> names = new HashSet<>();

names.add(null);
names.add(null);

System.out.println(names.size());
```

실행 결과:

```text
1
```

HashSet에는 null을 하나 저장할 수 있다.

하지만 모든 Set 구현체가 null을 허용하는 것은 아니다.

### 6-4. Set 구현체 비교

| 구현체 | 주요 특징 |
|---|---|
| HashSet | 중복 방지, 순서 보장 없음 |
| LinkedHashSet | 중복 방지, 삽입 순서 유지 |
| TreeSet | 비교 기준에 따른 정렬 순서 유지 |

TreeSet은 자연 정렬 기준 또는 Comparator를 사용한다.

사용자 정의 객체를 TreeSet에 저장할 때는 적절한 비교 기준을 제공해야 한다.

TreeSet에서 두 요소의 비교 결과가 0이면 정렬 기준상 중복으로 판단한다.

따라서 equals()가 false여도 compare() 결과가 0이라면 하나만 저장될 수 있다.

## 7. 객체의 동일성과 동등성

> 동일성은 같은 객체를 참조하는지를 의미하고, 동등성은 객체의 값이나 상태가 같은지를 의미한다.

### 7-1. == 연산자

```java
class Address {
    String city;

    Address(String city) {
        this.city = city;
    }
}
```

```java
Address a1 = new Address("서울");
Address a2 = new Address("서울");

System.out.println(a1 == a2);
```

실행 결과:

```text
false
```

new를 두 번 실행했으므로 서로 다른 객체가 생성되었다.

두 객체의 필드 값이 같아도 참조는 다르다.

### 7-2. Object.equals()

모든 자바 클래스는 직접 또는 간접적으로 Object를 상속한다.

Object의 equals() 기본 구현은 동일한 객체를 참조하는지 비교한다.

개념적으로 다음과 같다.

```java
public boolean equals(Object obj) {
    return this == obj;
}
```

따라서 재정의하지 않았다면 다음 결과가 나온다.

```java
System.out.println(a1.equals(a2));
```

실행 결과:

```text
false
```

### 7-3. equals() 재정의

주소의 모든 필드 값이 같으면 동등한 객체라고 판단하도록 만들 수 있다.

```java
import java.util.Objects;

class Address {
    String city;
    String district;
    String detail;

    Address(String city, String district, String detail) {
        this.city = city;
        this.district = district;
        this.detail = detail;
    }

    @Override
    public boolean equals(Object obj) {
        if (!(obj instanceof Address other)) {
            return false;
        }

        return Objects.equals(city, other.city)
            && Objects.equals(district, other.district)
            && Objects.equals(detail, other.detail);
    }

    @Override
    public int hashCode() {
        return Objects.hash(city, district, detail);
    }
}
```

실행 예제:

```java
Address a1 = new Address("서울", "강남", "1번지");
Address a2 = new Address("서울", "강남", "1번지");

System.out.println(a1 == a2);
System.out.println(a1.equals(a2));
```

실행 결과:

```text
false
true
```

### 7-4. a1.equals(a2)의 실행 과정

```java
a1.equals(a2);
```

이 코드를 실행하면 다음과 같은 관계가 만들어진다.

```text
a1 → equals()를 호출한 객체(this)

a2 → equals()의 매개변수(obj)
```

메서드 내부에서 다음 코드가 실행된다.

```java
if (!(obj instanceof Address other)) {
    return false;
}
```

실행 과정:

1. obj가 Address 타입인지 검사
2. Address 타입이므로 true
3. 패턴 변수 other가 a2 객체를 참조
4. 앞에 !가 있으므로 if 조건은 false
5. return false를 실행하지 않고 다음 문장으로 이동

다음으로 필드를 비교한다.

```java
return Objects.equals(city, other.city)
    && Objects.equals(district, other.district)
    && Objects.equals(detail, other.detail);
```

실제 비교는 개념적으로 다음과 같다.

```java
return Objects.equals("서울", "서울")
    && Objects.equals("강남", "강남")
    && Objects.equals("1번지", "1번지");
```

계산 결과:

```text
true && true && true

→ true
```

따라서 equals()가 true를 반환한다.

Objects.equals()는 null도 안전하게 비교할 수 있다.

### 7-5. equals() 구현 시 지켜야 할 규칙

equals()는 다음 성질을 만족하도록 작성해야 한다.

- 반사성: x.equals(x)는 true
- 대칭성: x.equals(y)와 y.equals(x)는 같은 결과
- 추이성: x=y이고 y=z이면 x=z
- 일관성: 비교에 사용하는 상태가 변하지 않으면 결과도 유지
- null 비교: x.equals(null)은 false

객체 상속 구조에서 equals()를 재정의할 때는 대칭성과 추이성을 특히 주의해야 한다.

## 8. hashCode()와 HashSet 내부 동작

> HashSet은 hashCode()를 이용하여 검색 범위를 좁히고, 필요할 경우 equals()를 사용하여 동등성을 판단한다.

### 8-1. hashCode()의 의미

hashCode()는 객체의 해시값을 int 형태로 반환한다.

```java
@Override
public int hashCode() {
    return Objects.hash(city, district, detail);
}
```

hashCode()는 메모리 주소를 반환하는 메서드가 아니다.

또한 해시값이 같다고 반드시 동등한 객체는 아니다.

서로 다른 객체가 같은 해시값을 가질 수도 있다.

이를 해시 충돌(Hash Collision)이라고 한다.

### 8-2. equals()와 hashCode()의 관계

중요한 규칙:

```text
equals() == true
        ↓
hashCode()도 같아야 함
```

반대로 다음 관계는 항상 성립하지 않는다.

```text
hashCode()가 같음
        ↓
equals()가 반드시 true인 것은 아님
```

따라서 equals()를 재정의한다면 hashCode()도 일관되게 재정의해야 한다.

### 8-3. HashSet에 객체 저장

```java
Set<Address> set = new HashSet<>();

Address a1 = new Address("서울", "강남", "1번지");

set.add(a1);
```

개념적인 실행 과정:

1. a1의 hashCode() 계산
2. 해시값을 이용해 저장 위치 탐색
3. 기존 요소와 중복되는지 확인
4. 중복이 없다면 a1의 참조를 저장

HashSet은 객체를 저장할 때 Address 객체 전체를 복제하지 않는다.

기존 객체의 참조를 저장한다.

### 8-4. 다른 객체로 삭제할 수 있는 이유

```java
Address a1 = new Address("서울", "강남", "1번지");
Address a2 = new Address("서울", "강남", "1번지");

Set<Address> set = new HashSet<>();

set.add(a1);

System.out.println(set.remove(a2));
System.out.println(set.size());
```

실행 결과:

```text
true
0
```

의문:

a1을 저장했는데 왜 a2로 삭제할 수 있을까?

실행 과정:

1. set.add(a1)로 a1의 참조를 저장
2. set.remove(a2) 호출
3. a2의 hashCode() 계산
4. 저장된 요소를 검색할 위치 탐색
5. a1과 a2의 동등성 검사
6. equals() 기준으로 두 객체가 같다고 판단
7. 저장된 a1 요소 삭제
8. remove()가 true 반환

중요한 점:

remove()가 true라는 것은 같은 인스턴스라는 의미가 아니다.

동등한 요소를 찾아 실제로 삭제했다는 의미이다.

HashSet에서 삭제하더라도 외부 변수 a1이 객체를 계속 참조하고 있다면 객체 자체가 즉시 사라지는 것은 아니다.

### 8-5. equals()만 재정의하면?

equals()만 재정의하면 다음 상황이 발생할 수 있다.

```text
a1.equals(a2) == true

하지만

a1.hashCode() != a2.hashCode()
```

HashSet은 해시값을 이용해 검색하므로 동등한 객체를 찾지 못할 수 있다.

따라서 equals()와 hashCode()를 함께 재정의하는 것이 중요하다.

### 8-6. HashSet에 저장한 객체를 수정하면?

```java
Address a1 = new Address("서울", "강남", "1번지");

Set<Address> set = new HashSet<>();

set.add(a1);

a1.city = "부산";

System.out.println(set.contains(a1));
```

이 코드는 false가 출력될 수 있다.

이유:

1. 저장할 때는 서울을 기준으로 해시값을 계산
2. 객체의 city를 부산으로 변경
3. 검색할 때는 부산을 기준으로 해시값 계산
4. 해시값이 변경되어 검색 위치가 달라질 수 있음
5. 저장된 객체를 찾지 못할 수 있음

실무에서는 해시 기반 컬렉션의 키나 요소로 사용하는 객체의 동등성 관련 필드를 가급적 불변으로 설계한다.

변경이 필요하다면 기존 요소를 삭제하고 새로운 객체를 추가하는 방식도 고려할 수 있다.

## 9. Map과 HashMap

> Map은 유일한 키와 해당 키에 연결된 값을 관리하는 자료구조이다.

### 9-1. Map의 기본 구조

```text
Key       Value

hong  →    90
kim   →    80
lee   →    95
```

예제:

```java
Map<String, Integer> scores = new HashMap<>();

scores.put("홍길동", 90);
scores.put("김철수", 80);
scores.put("이순신", 95);
```

Map은 Collection을 직접 상속하지 않는다.

### 9-2. put()으로 데이터 저장

```java
Map<String, Integer> scores = new HashMap<>();

scores.put("홍길동", 90);
scores.put("홍길동", 100);

System.out.println(scores.get("홍길동"));
```

실행 결과:

```text
100
```

같은 키로 다시 저장하면 기존 값이 새로운 값으로 교체된다.

값은 중복될 수 있지만 키는 중복될 수 없다.

### 9-3. Map 주요 메서드

| 메서드 | 기능 |
|---|---|
| put(K, V) | 키와 값 저장 |
| get(K) | 키로 값 조회 |
| remove(K) | 키에 해당하는 항목 삭제 |
| containsKey(K) | 키 존재 여부 |
| containsValue(V) | 값 존재 여부 |
| keySet() | 키 집합 반환 |
| values() | 값 컬렉션 반환 |
| entrySet() | 키-값 항목 집합 반환 |
| getOrDefault() | 키가 없을 때 기본값 사용 |
| putIfAbsent() | 키에 대응하는 값이 없거나 null일 때 저장 |
| computeIfAbsent() | 필요할 때 값을 계산해 저장 |

### 9-4. keySet()과 entrySet()

keySet()은 모든 키를 Set으로 반환한다.

```java
Map<String, Integer> scores = new LinkedHashMap<>();

scores.put("홍길동", 90);
scores.put("김철수", 80);

for (String key : scores.keySet()) {
    System.out.println(key);
}
```

실행 결과:

```text
홍길동
김철수
```

LinkedHashMap을 사용했으므로 삽입 순서가 유지된다.

entrySet()은 Map.Entry 객체의 집합을 반환한다.

```java
for (Map.Entry<String, Integer> entry : scores.entrySet()) {
    System.out.println(
        entry.getKey() + " : " + entry.getValue()
    );
}
```

실행 결과:

```text
홍길동 : 90
김철수 : 80
```

### 9-5. Map.Entry 이해

```java
Map.Entry<String, Integer>
```

Map.Entry<K, V>는 하나의 키-값 항목을 표현한다.

```text
K = String
V = Integer
```

따라서 다음 메서드를 사용할 수 있다.

```java
entry.getKey()
entry.getValue()
```

Map.Entry는 Map 내부에 선언된 중첩 인터페이스이다.

### 9-6. HashMap과 HashSet의 관계

HashMap은 키를 해시 기반으로 관리한다.

HashSet도 내부적으로 해시 기반 구조를 사용하며, 일반적인 HashSet 구현은 HashMap을 활용한다.

개념적으로 다음처럼 이해할 수 있다.

```text
HashMap
    Key   → Value

HashSet
    Element → 내부 관리용 값
```

HashMap에서 사용자 정의 객체를 키로 사용한다면 HashSet과 마찬가지로 equals()와 hashCode()의 일관성이 중요하다.

### 9-7. Map 구현체 비교

| 구현체 | 특징 |
|---|---|
| HashMap | 키 기반 조회, 순서 보장 없음 |
| LinkedHashMap | 예측 가능한 순회 순서, 일반적으로 삽입 순서 유지 |
| TreeMap | 키의 정렬 순서 유지 |

HashMap은 null 키 하나와 null 값 여러 개를 허용한다.

TreeMap은 비교 기준에 따라 키를 관리하므로 사용자 정의 키를 사용할 때 적절한 정렬 기준이 필요하다.

## 10. Iterator와 컬렉션 순회

> Iterator는 컬렉션의 요소를 하나씩 순회하기 위한 인터페이스이다.

### 10-1. 향상된 for문

```java
List<String> names =
    List.of("홍길동", "김철수", "이순신");

for (String name : names) {
    System.out.println(name);
}
```

실행 결과:

```text
홍길동
김철수
이순신
```

단순 조회라면 향상된 for문이 간결하다.

### 10-2. Iterator

```java
Iterator<String> iterator = names.iterator();

while (iterator.hasNext()) {
    System.out.println(iterator.next());
}
```

주요 메서드:

- hasNext(): 다음 요소가 있는지 확인
- next(): 다음 요소 반환
- remove(): 마지막으로 반환한 요소를 조건에 맞게 삭제

실행 과정:

```text
iterator 생성
      |
      v
hasNext() → true
      |
      v
next() → 홍길동
      |
      v
hasNext() → true
      |
      v
next() → 김철수
      |
      v
hasNext() → true
      |
      v
next() → 이순신
      |
      v
hasNext() → false
      |
      v
반복 종료
```

주의:

next()를 호출할 다음 요소가 없다면 NoSuchElementException이 발생한다.

### 10-3. Enumeration

Enumeration은 이전부터 사용하던 순회 인터페이스이다.

주요 메서드:

```java
hasMoreElements()
nextElement()
```

최신 컬렉션 코드에서는 일반적으로 Iterator와 향상된 for문을 주로 사용한다.

## 11. 순회 도중 요소 삭제

### 11-1. ConcurrentModificationException

```java
List<String> names =
    new ArrayList<>(List.of("A", "B", "C"));

for (String name : names) {
    if (name.equals("B")) {
        names.remove(name);
    }
}
```

이런 방식은 반복 도중 컬렉션을 직접 구조적으로 수정하기 때문에 문제가 발생할 수 있다.

대표적으로 ConcurrentModificationException이 발생할 수 있다.

단, 모든 경우에 반드시 예외가 발생하는 것은 아니다.

일부 반복자는 fail-fast 방식으로 변경을 감지하지만, 검출이 보장되는 것은 아니기 때문이다.

### 11-2. Iterator.remove()

```java
List<String> names =
    new ArrayList<>(List.of("A", "B", "C"));

Iterator<String> iterator = names.iterator();

while (iterator.hasNext()) {
    String name = iterator.next();

    if (name.equals("B")) {
        iterator.remove();
    }
}

System.out.println(names);
```

실행 결과:

```text
[A, C]
```

Iterator의 remove()는 해당 반복자가 지원하는 경우 안전하게 요소를 삭제할 수 있다.

단, next() 호출 전에 remove()를 사용하거나 한 번의 next()에 대해 remove()를 두 번 호출하면 IllegalStateException이 발생할 수 있다.

### 11-3. removeIf()

실무에서는 조건에 따라 요소를 삭제할 때 removeIf()도 자주 사용한다.

```java
List<Integer> numbers =
    new ArrayList<>(List.of(1, 2, 3, 4, 5));

numbers.removeIf(n -> n % 2 == 0);

System.out.println(numbers);
```

실행 결과:

```text
[1, 3, 5]
```

람다식의 조건이 true인 요소를 삭제한다.

List<String> posts = new ArrayList<>();

목록 조회와 순서가 중요한 경우에 적합하다.

Set<String> tags = new HashSet<>();

## 13. 추가 심화 학습

### 13-1. 시간 복잡도

| 작업 | 대표적인 평균 시간 복잡도 |
|---|---|
| ArrayList 인덱스 조회 | O(1) |
| ArrayList 특정 값 탐색 | O(n) |
| ArrayList 중간 삽입 | O(n) |
| HashSet contains() | O(1) 기대 |
| HashMap get() | O(1) 기대 |
| TreeSet 검색 | O(log n) |
| TreeMap 검색 | O(log n) |

해시 기반 컬렉션의 시간 복잡도는 해시 분포, 충돌, 구현 방식 등에 영향을 받는다.

따라서 항상 O(1)이 보장되는 것은 아니다.

### 13-2. 불변 객체와 해시 기반 컬렉션

HashMap의 키나 HashSet의 요소로 사용자 정의 객체를 사용할 때는 동등성 판단에 사용하는 필드를 변경하지 않는 것이 중요하다.

이를 위해 다음 방법을 사용할 수 있다.

- final 필드
- 생성자를 통한 초기화
- Setter 제한
- record 사용
- 불변 객체 설계

record는 equals(), hashCode(), toString()을 자동 제공하므로 단순 값 객체에 유용하다.

하지만 record도 참조하는 내부 객체까지 자동으로 깊은 불변 상태로 만들지는 않는다.

### 13-3. 컬렉션의 null 정책

null 허용 여부는 인터페이스만으로 단정할 수 없다.

예를 들어:

- ArrayList: null 허용
- HashSet: null 하나 허용
- HashMap: null 키 하나와 여러 null 값 허용
- List.of(): null 불허
- TreeSet: 비교 기준에 따라 null 처리 가능 여부가 달라짐

### 13-4. 컬렉션 선택 기준

일반적인 선택 기준은 다음과 같다.

1. 순서 있는 목록이 필요한가? → List
2. 중복을 제거해야 하는가? → Set
3. 키로 데이터를 조회해야 하는가? → Map
4. 정렬된 상태를 유지해야 하는가? → TreeSet, TreeMap
5. 삽입 순서를 유지해야 하는가? → LinkedHashSet, LinkedHashMap
6. 앞뒤 삽입·삭제가 많은가? → Deque, ArrayDeque 등 검토

## 14. 복습 문제

### 문제 1. ArrayList 삭제

```java
List<Integer> numbers =
    new ArrayList<>(List.of(10, 20, 30));

numbers.remove(1);

System.out.println(numbers);
```

정답:

```text
[10, 30]
```

remove(1)은 인덱스 1의 요소를 삭제한다.

### 문제 2. HashSet 중복 저장

```java
Set<String> names = new HashSet<>();

names.add("A");
names.add("A");
names.add("B");

System.out.println(names.size());
```

정답:

```text
2
```

### 문제 3. Map 값 변경

```java
Map<String, Integer> map = new HashMap<>();

map.put("A", 10);
map.put("A", 20);
map.put("B", 30);

System.out.println(map.size());
System.out.println(map.get("A"));
```

```text
2
20
```

### 문제 4. 객체 동등성

Address 클래스에서 equals()와 hashCode()가 세 필드를 기준으로 올바르게 재정의되었다고 가정한다.

```java
Address a1 = new Address("서울", "강남", "1번지");
Address a2 = new Address("서울", "강남", "1번지");

Set<Address> set = new HashSet<>();

set.add(a1);

System.out.println(a1 == a2);
System.out.println(a1.equals(a2));
System.out.println(set.remove(a2));
System.out.println(set.size());
```

정답:

```text
false
true
true
0
```

실행 과정:

1. new를 두 번 실행해 서로 다른 객체 생성
2. 참조가 다르므로 == false
3. 필드 값이 같으므로 equals() true
4. hashCode() 기준도 일치
5. HashSet이 동등한 요소를 찾아 삭제
6. remove() true
7. 최종 요소 개수 0
