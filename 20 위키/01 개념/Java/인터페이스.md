# 인터페이스

## 한 문장 설명

인터페이스는 서로 다른 클래스가 반드시 제공해야 할 동작의 규약을 정의하는 타입이다.

## 핵심 원리

- 클래스는 하나의 클래스만 직접 상속하지만 여러 인터페이스를 구현할 수 있다.
- 본문 없는 메서드는 기본적으로 public abstract다.
- 필드는 public static final 상수다.
- default, static, private 메서드도 선언할 수 있다.

## 추상 클래스와 선택 기준

- 공통 규약과 구현체 교체가 중심이면 인터페이스가 자연스럽다.
- 공통 인스턴스 상태·생성자·구현을 공유해야 하면 추상 클래스를 검토한다.
- 둘은 경쟁 관계가 아니며 함께 사용할 수도 있다.

## 실무에서는 어떻게 쓰이나

Spring에서는 인터페이스 타입을 기준으로 구현 객체를 생성자에 주입할 수 있다. 구현체가 하나뿐인 작은 코드에서는 무조건 인터페이스를 만들기보다 교체 가능성·경계·테스트 필요성을 기준으로 판단한다.

## 흔한 실수

- 인터페이스에 인스턴스 필드를 둘 수 있다고 생각한다.
- 구현 메서드의 접근 범위를 public보다 좁게 작성한다.
- 다중 구현과 클래스 다중 상속을 같은 것으로 생각한다.
