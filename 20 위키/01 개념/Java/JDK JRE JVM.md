# JDK JRE JVM

## 자바 실행 구조와 기초 문법

### 자바 실행 구조와 기초 문법


### JDK 설치 구조와 모듈

> JDK는 실행 파일, 설정 파일, 네이티브 연동 헤더, 모듈, 라이브러리 및 라이선스 정보로 구성되며, 각 디렉터리는 자바 컴파일과 실행 환경을 분담합니다.

JDK 설치 경로에는 자바 개발과 실행에 필요한 파일이 역할별로 분리되어 있습니다. 설치 후 디렉터리 구조를 직접 확인하면 컴파일러, JVM 설정, 운영체제 연동 요소, 표준 API가 어떤 위치에서 관리되는지 파악할 수 있습니다.

| 디렉터리 또는 파일 | 주요 역할 | 확인 관점 |
|---|---|---|
| `bin` | `javac`, `java` 등 컴파일, 실행 명령어를 제공합니다. | 자바 소스 컴파일과 클래스 실행의 시작점입니다. |
| `conf` | JDK 및 JVM 실행 환경의 설정 파일을 포함합니다. | 런타임 동작과 환경 설정이 관리됩니다. |
| `include` | JNI 및 운영체제 네이티브 코드 연동용 헤더 파일을 제공합니다. | OS 데이터 타입과 자바 타입의 연결을 지원합니다. |
| `jmods` | 표준 API를 모듈 단위로 압축하여 포함합니다. | `java.base` 등의 모듈이 클래스와 패키지를 묶습니다. |
| `lib`, `legal` | 실행 라이브러리와 라이선스, 저작권 정보를 제공합니다. | 라이브러리는 실행에 필요하고, 라이선스는 배포 시 검토 대상입니다. |

`bin`의 실행 명령어는 `lib`의 내부 라이브러리와 JVM 설정을 참조하여 동작합니다. 따라서 실행 파일만 존재하거나 라이브러리만 존재하는 구성으로는 정상적인 자바 실행 환경이 완성되지 않습니다.

JDK 9부터는 클래스와 패키지가 크게 증가한 표준 라이브러리를 더 체계적으로 관리하기 위해 모듈 시스템이 도입되었습니다. 모듈은 여러 패키지를 상위 범주로 묶어 의존성과 공개 범위를 관리하는 단위입니다.


### JVM과 플랫폼 독립성

> JVM은 자바 프로그램 실행 시 운영체제가 제공한 메모리 공간에 생성되며, 클래스 로딩, 실행, 메모리 관리, 객체 회수를 담당합니다.

일반 프로그램은 운영체제 환경에 맞는 실행 파일과 메모리 구조에 의존하는 경우가 많습니다. 반면 자바는 소스 코드를 바이트코드인 `.class` 파일로 컴파일하고, 각 운영체제에 설치된 JVM이 이를 해석하거나 실행합니다.

자바의 실행 흐름은 소스 코드 작성, `javac` 컴파일, 클래스 파일 생성, `java` 명령을 통한 JVM 로딩과 클래스 실행으로 이어집니다. JVM은 프로그램 종료 이후 사용이 끝난 메모리를 정리합니다.

```text
.java 소스 파일 → javac 컴파일 → .class 바이트코드 → JVM 로딩 및 실행
```

운영체제의 메모리 맵은 일반적으로 코드 영역, 데이터 영역, 정적 영역, 힙 영역, 스택 영역으로 설명할 수 있습니다. 자바 JVM도 실행 과정에서 유사한 목적의 메모리 영역을 구성하며, 특히 스택과 힙의 특성을 구분하는 것이 중요합니다.

| 영역 | 저장 또는 관리 대상 | 특성 |
|---|---|---|
| 코드 영역 | 컴파일된 실행 코드와 클래스 관련 정보입니다. | 실행할 명령을 관리합니다. |
| 정적 영역 | `static` 데이터와 클래스 수준 정보를 관리합니다. | 선언과 함께 주소가 확보되는 정적 성격을 가집니다. |
| 스택 영역 | 메서드 호출, 매개변수, 지역 변수를 관리합니다. | 호출이 끝나면 관련 지역 데이터가 제거됩니다. |
| 힙 영역 | `new`로 생성한 객체와 동적 데이터를 관리합니다. | 객체 생명주기와 가비지 컬렉션의 대상입니다. |

플랫폼 독립성이란 자바 프로그램이 특정 운영체제용 실행 파일에 직접 종속되지 않고, JVM을 통해 실행된다는 의미입니다. Windows, macOS, Linux 등에서 JVM이 제공되면 동일한 바이트코드를 실행할 수 있으므로 크로스 플랫폼 지원이 가능합니다.


## 자바 참조와 자료형 기초

### JVM과 클래스 실행 단위

> 자바 소스 파일은 컴파일되어 바이트코드 클래스 파일이 되고, JVM은 클래스 파일을 로딩하여 프로그램을 실행합니다.

자바 프로그램은 일반적으로 `.java` 소스 파일을 작성한 뒤 컴파일 과정을 거쳐 `.class` 파일을 생성합니다. `.class` 파일에는 JVM이 실행할 수 있는 바이트코드가 저장됩니다.

```text
소스 코드(.java)
    ↓ javac 컴파일
바이트코드(.class)
    ↓ JVM 클래스 로딩
프로그램 실행
```

JVM은 Java Virtual Machine의 약자이며, 바이트코드를 로딩하고 실행하는 가상 실행 환경입니다. 자바가 운영체제에 직접 종속되지 않고 다양한 환경에서 실행될 수 있는 이유는 JVM이 운영체제와 자바 바이트코드 사이의 중간 실행 계층 역할을 하기 때문입니다.

- 클래스는 자바 프로그램의 기본 구성 단위이자 JVM의 주요 로딩 단위입니다.
- `main` 메소드는 프로그램 실행이 시작되는 진입점입니다.
- `.java` 파일 하나에는 여러 클래스를 선언할 수 있지만 공개 클래스에는 파일명 관련 규칙이 적용됩니다.
- 중첩 클래스는 바깥 클래스와 내부 클래스의 구조로 선언할 수 있습니다.

클래스 파일 생성 과정과 JVM 로딩 구조를 이해하면 컴파일 오류, 실행 오류, 클래스 경로 문제를 구분하는 기반이 됩니다. 또한 자바의 플랫폼 독립성과 바이트코드 기반 실행 모델을 이해하는 핵심이 됩니다.
