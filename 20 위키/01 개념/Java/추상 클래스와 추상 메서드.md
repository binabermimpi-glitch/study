# 추상 클래스와 추상 메서드

## 한 문장 설명

추상 클래스는 공통 상태와 구현을 제공하면서 일부 동작의 구체적인 구현을 자식 클래스에 맡기는 상위 설계다.

```java
abstract class Animal {
    abstract void sound();

    void eat(String food) {
        System.out.println(food + "을 먹습니다.");
    }
}

class Cat extends Animal {
    @Override
    void sound() {
        System.out.println("야옹");
    }
}
```

## 핵심 원리

- 추상 클래스는 `new Animal()`처럼 직접 생성할 수 없다.
- 일반 필드·생성자·일반 메서드와 추상 메서드를 함께 가질 수 있다.
- 구체 자식 클래스는 상속받은 추상 메서드를 구현해야 한다.
- 구현하지 않는 자식 클래스는 자신도 `abstract`여야 한다.

## 추상화와 캡슐화의 차이

- 추상화: 중요한 공통 특징과 동작을 뽑아 상위 개념으로 표현한다.
- 캡슐화: 객체 내부 상태를 숨기고 허용된 방법으로만 다루게 한다.

## 실무에서는 어떻게 쓰이나

공통 구현과 확장 지점을 함께 제공할 때 사용한다. 구현 계약만 필요하고 다중 구현 타입을 유연하게 다루려면 인터페이스가 더 적합할 수 있다. 다음 학습은 `interface`, 구현체, 의존성 주입 순서로 연결한다.

## 흔한 실수

- 추상 클래스에는 일반 메서드를 만들 수 없다고 생각한다.
- 추상 메서드에 본문을 작성한다.
- 상속만 사용하면 자동으로 좋은 추상화가 된다고 생각한다.
