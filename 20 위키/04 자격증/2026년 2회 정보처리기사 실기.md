# 2. Java 상속 / 오버라이딩 / `super` 🔥🔥

## 문제

다음 Java 프로그램의 실행 결과를 쓰시오.

```java
class A {
    int a;

    public A(int a) {
        this.a = a;
    }

    void print() {
        System.out.print(a + "a");
    }
}

class B extends A {
    int b;

    public B(int a, int b) {
        super(a);
        this.b = b;
    }

    void print() {
        super.print();
        System.out.print(b + "b");
    }
}

public class Test {
    public static void main(String[] args) {
        B obj = new B(10, 20);
        obj.print();
    }
}
```

## 정답

```text
10a20b
```

## 실행 과정

객체 생성:

```java
B obj = new B(10, 20);
```

`B` 생성자가 실행된다.

```java
public B(int a, int b) {
    super(a);
    this.b = b;
}
```

먼저:

```java
super(a);
```

가 실행되어 부모 클래스 `A`의 생성자를 호출한다.

```java
A(int a) {
    this.a = a;
}
```

따라서:

```text
A.a = 10
```

다음:

```java
this.b = b;
```

따라서:

```text
B.b = 20
```

객체 상태:

```text
a = 10
b = 20
```

---

## `obj.print()`

B 클래스가 `print()`를 오버라이딩했으므로 B의 `print()`가 실행된다.

```java
void print() {
    super.print();
    System.out.print(b + "b");
}
```

먼저:

```java
super.print();
```

부모 A의 `print()` 실행:

```java
System.out.print(a + "a");
```

출력:

```text
10a
```

다음:

```java
System.out.print(b + "b");
```

출력:

```text
20b
```

최종:

```text
10a20b
```

## 관련 개념

```text
super()
→ 부모 클래스 생성자 호출

super.메서드()
→ 부모 클래스의 메서드 호출

this
→ 현재 객체

오버라이딩
→ 부모의 메서드를 자식 클래스에서 재정의
```

# 3. 내용 결합도(Content Coupling) 🔥🔥

## 문제

다음 빈칸에 들어갈 가장 알맞은 용어를 작성하시오.

> `(       )`은/는 다른 모듈 내부에 있는 변수나 기능을 다른 모듈에서 사용하는 경우의 결합도이다.

## 정답

**내용 결합도(Content Coupling)**

## 개념

한 모듈이 다른 모듈의 **내부 데이터나 내부 기능을 직접 참조하거나 수정**하는 경우이다.

모듈 간 독립성이 가장 낮기 때문에 **가장 강한 결합도**이다.

예:

```text
모듈 A
↓
모듈 B 내부 변수 직접 변경
```

이렇게 되면 B의 내부 구조를 변경했을 때 A까지 영향을 받는다.

---

## 결합도 강한 순 → 약한 순 🔥🔥

```text
내용 결합도
↓
공통 결합도
↓
외부 결합도
↓
제어 결합도
↓
스탬프 결합도
↓
자료 결합도
```

암기:

```text
내공외제스자
```

### 내용 결합도

다른 모듈 내부를 직접 참조.

### 공통 결합도

여러 모듈이 공통 데이터 영역을 사용.

### 외부 결합도

외부의 데이터 형식이나 통신 프로토콜 등에 의존.

### 제어 결합도

제어 플래그 등을 전달하여 다른 모듈의 동작을 제어.

### 스탬프 결합도

배열이나 객체·구조체 등 자료구조 전체를 전달.

### 자료 결합도

필요한 값만 매개변수로 전달.

→ 가장 바람직한 결합 형태.

# 4. OSPF 🔥🔥

## 문제

다음 설명에 해당하는 라우팅 프로토콜의 이름을 작성하시오.

- 대표적인 내부 라우팅 프로토콜(IGP)이다.
- 최단 경로 탐색에 다익스트라(Dijkstra) 알고리즘을 사용한다.
- 대규모 네트워크에 적합하다.
- 멀티패스(Multipath) 라우팅을 지원한다.

## 정답

**OSPF(Open Shortest Path First)**

## 개념

OSPF는 **링크 상태(Link State)** 기반의 내부 게이트웨이 프로토콜이다.

```text
OSPF
→ IGP
→ Link State
→ Dijkstra
→ Cost
```

라우터는 네트워크의 링크 상태 정보를 이용하여 최단 경로를 계산한다.

---

## RIP과 OSPF 비교 🔥🔥

### RIP

```text
알고리즘
→ Distance Vector

경로 판단
→ Hop Count

최대 홉
→ 15

16 Hop
→ 도달 불가능

적합
→ 소규모 네트워크
```

### OSPF

```text
알고리즘
→ Link State

최단 경로
→ Dijkstra

경로 판단
→ Cost

적합
→ 대규모 네트워크
```

OSPF는 단순히 라우터 개수만 보는 RIP과 달리 링크 비용을 이용하기 때문에 보다 효율적인 경로를 선택할 수 있다.

# 7. C 구조체 / 재귀 호출 🔥🔥

## 문제

다음 C 프로그램의 실행 결과를 쓰시오.

```c
typedef struct N {
    int v;
    struct N* a;
    struct N* b;
} N;

int c = 0;
int result = 0;

void func(N *n) {

    if (!n)
        return;

    func(n->a);
    func(n->b);

    if (++c == 3)
        result = n->v;
}

int main() {

    N ne = {35, 0, 0};
    N nd = {64, 0, 0};
    N nc = {53, 0, 0};

    N nb = {12, &ne, &nc};
    N na = {21, &nb, &nd};

    func(&na);

    printf("%d\n", result);

    return 0;
}
```

## 정답

```text
12
```

## 구조

```text
        21
       /  \
     12    64
    /  \
   35  53
```

함수에서:

```c
func(n->a);
func(n->b);

if (++c == 3)
```

순서이므로 **왼쪽 → 오른쪽 → 현재 노드** 순서로 처리한다.

즉 후위 순회(Postorder)와 같은 순서다.

```text
35
53
12
64
21
```

---

## c 증가

```text
35
→ c = 1

53
→ c = 2

12
→ c = 3
```

이때:

```c
if (++c == 3)
    result = n->v;
```

조건이 참이므로:

```text
result = 12
```

이후 값은 변경되지 않는다.

따라서:

```text
12
```

# 8. SRT 프로세스 스케줄링 🔥🔥

## 문제

다음 프로세스에 대해 SRT(Shortest Remaining Time) 스케줄링을 적용할 때 평균 대기 시간을 구하시오.

| 프로세스 | 도착 시간 | 실행 시간 |
|---|---:|---:|
| P1 | 0 | 8 |
| P2 | 1 | 4 |
| P3 | 2 | 9 |
| P4 | 3 | 5 |

## 정답

```text
6.5
```

## SRT

**Shortest Remaining Time**

현재 실행 가능한 프로세스 중 **남은 실행 시간이 가장 짧은 프로세스**를 선택하는 선점형 스케줄링이다.

---

## 실행 순서

### 0초

P1만 존재.

```text
P1 실행
```

### 1초

P2 도착.

```text
P1 남은 시간 = 7
P2 실행 시간 = 4
```

P2가 더 짧으므로 P1을 중단하고 P2 실행.

```text
0 ~ 1 : P1
1 ~ 5 : P2
```

P2 종료.

---

### 5초

남은 프로세스:

```text
P1 = 7
P3 = 9
P4 = 5
```

P4 실행.

```text
5 ~ 10 : P4
```

---

### 10초

```text
P1 = 7
P3 = 9
```

P1 실행.

```text
10 ~ 17 : P1
```

---

### 마지막

```text
17 ~ 26 : P3
```

---

## 대기시간

공식:

```text
대기시간
= 종료시간 - 도착시간 - 실행시간
```

### P1

```text
17 - 0 - 8
= 9
```

### P2

```text
5 - 1 - 4
= 0
```

### P3

```text
26 - 2 - 9
= 15
```

### P4

```text
10 - 3 - 5
= 2
```

평균:

```text
(9 + 0 + 15 + 2) / 4

= 26 / 4

= 6.5
```

# 9. C 포인터 / 값에 의한 호출 🔥🔥

## 문제

다음 C 프로그램의 실행 결과를 쓰시오.

```c
void fn1(int *n) {
    *n = 50;
}

void fn2(int n) {
    n = 60;
}

void fn3(int *p) {
    printf("%d\n", *p);
    printf("%d\n", *(p + 3));
}

int main() {

    int i = 10;
    int arr[] = {2, 4, 6, 8};

    fn1(&i);
    printf("%d\n", i);

    fn2(i);
    printf("%d\n", i);

    fn3(arr);

    return 0;
}
```

```text
50
50
2
8
```

```c
void fn1(int *n) {
    *n = 50;
}
```

`i`의 주소를 전달한다.

따라서 실제 `i` 값이 변경된다.

```text
i
10 → 50
```

첫 번째 출력:

```text
50
```

```c
void fn2(int n) {

}
```

값 자체가 복사된다.


두 번째 출력:

```text
50
```

## `fn3(arr)`

```c
*p
```

```text
2
```

```text
8
```

# 11. Abstract Factory Pattern 🔥🔥

## 문제

다음 설명에 해당하는 디자인 패턴을 보기에서 고르시오.

> 구체적인 클래스에 의존하지 않고 서로 연관되거나 의존적인 객체들의 조합을 생성하기 위한 인터페이스를 제공한다. 연관된 서브 클래스를 묶어 한 번에 교체하는 것이 가능하며 다른 이름으로 `Kit`이라고도 불린다.

## 정답

**Abstract Factory Pattern(추상 팩토리 패턴)**

## 개념

서로 관련된 여러 객체들을 **구체적인 클래스에 직접 의존하지 않고 하나의 제품군(Family) 단위로 생성**하는 패턴이다.

예:

```text
Windows UI

Button
Checkbox
Menu
```

와:

```text
Mac UI

Button
Checkbox
Menu
```

처럼 관련 객체 세트를 통째로 생성할 수 있다.

---

## Factory Method와 차이

### Factory Method

```text
객체 하나의 생성
→ 하위 클래스에 위임
```

### Abstract Factory

```text
서로 관련된 객체 여러 개
→ 제품군 단위 생성
```

암기:

```text
Factory Method
→ 하나

Abstract Factory
→ 가족/세트
```

# 12. SQL `LIKE` / `ORDER BY` 🔥🔥

회원 테이블에서 **이름이 '이'로 시작하는 회원을 가입일 기준 내림차순으로 정렬**하는 SQL문을 완성하시오.

# 13. SQL 상관 서브쿼리 / AVG / COUNT 🔥🔥

## 문제

### A

| id | x |
|---:|---:|
| 1 | 10 |
| 2 | 20 |
| 3 | 30 |
| 4 | 40 |

### B

| id | y |
|---:|---:|
| 1 | 5 |
| 1 | 15 |
| 2 | 20 |
| 3 | 35 |
| 5 | 50 |

```sql
SELECT COUNT(*) AS RESULT
FROM A
WHERE x > (
    SELECT AVG(y)
    FROM B
    WHERE B.id IN (
        SELECT A2.id
        FROM A AS A2
        WHERE A2.x < A.x
    )
);
```

## 정답

```text
3
```

## 핵심

이 문제는 **상관 서브쿼리(Correlated Subquery)**이다.

안쪽 쿼리에서:

```sql
A.x
```

를 사용하고 있다.

즉 바깥쪽 A 테이블의 현재 행에 따라 서브쿼리 결과가 달라진다.

---

## `x = 10`

조건:

```sql
A2.x < 10
```

해당 행 없음.

따라서 평균도 구할 값이 없어:

```text
AVG = NULL
```

```text
10 > NULL
```

은 참이 아니므로 제외.

---

## `x = 20`

```text
A2.x < 20
```

해당 id:

```text
1
```

B에서 id=1:

```text
5
15
```

평균:

```text
(5 + 15) / 2
= 10
```

비교:

```text
20 > 10
→ 참
```

---

## `x = 30`

A2:

```text
id 1
id 2
```

B의 y:

```text
5, 15, 20
```

평균:

```text
40 / 3
≈ 13.33
```

```text
30 > 13.33
→ 참
```

---

## `x = 40`

A2:

```text
id 1
id 2
id 3
```

B:

```text
5, 15, 20, 35
```

평균:

```text
75 / 4
= 18.75
```

```text
40 > 18.75
→ 참
```

따라서 조건 만족 행:

```text
20
30
40
```

총:

```text
3개
```

# 14. SQL RIGHT OUTER JOIN 🔥🔥

## 문제

### A

| id | x |
|---:|---:|
| 1 | 10 |
| 1 | 20 |
| 2 | 30 |

### B

| id | y |
|---:|---:|
| 1 | 100 |
| 3 | 300 |
| 4 | 400 |

```sql
SELECT COUNT(*) AS RESULT
FROM A
RIGHT OUTER JOIN B
    ON A.id = B.id
WHERE A.id IS NULL;
```

## 정답

```text
2
```

## RIGHT OUTER JOIN

오른쪽 테이블 `B`의 모든 행을 유지한다.

B의 id:

```text
1
3
4
```

### id = 1

A에도 id=1이 존재한다.

실제로 A에 id=1이 두 개이므로 두 행과 조인된다.

```text
A.id = 1
```

이므로:

```sql
WHERE A.id IS NULL
```

조건에는 포함되지 않는다.

---

### id = 3

A에 없음.

따라서:

```text
A.id = NULL
```

조건 만족.

---

### id = 4

A에 없음.

```text
A.id = NULL
```

조건 만족.

따라서:

```text
2개
```

---

## 이 패턴 중요

```sql
LEFT JOIN ...
WHERE 오른쪽테이블.id IS NULL
```

→ 왼쪽에만 존재하는 데이터.

```sql
RIGHT JOIN ...
WHERE 왼쪽테이블.id IS NULL
```

→ 오른쪽에만 존재하는 데이터.

# 15. Java 접근제어자 / 오버라이딩 🔥🔥

## 문제

다음 Java 프로그램의 실행 결과를 쓰시오.

```java
class A {

    int a;
    private int b;
    protected int c;

    A(int a, int b, int c) {

        this.a = a;
        this.b = b;
        this.c = c;
    }

    int func() {
        return a + b + c;
    }
}

class B extends A {

    B(int a, int b, int c) {
        super(a, b, c);
    }

    public int func() {
        return a * c;
    }
}

public class Main {

    public static void main(String[] args) {

        A a = new A(1, 5, 3);

        B b = new B(10, 30, 50);

        System.out.print(
            a.func() + b.func()
        );
    }
}
```

## 정답

```text
509
```

## `a.func()`

```text
a = 1
b = 5
c = 3
```

A의 `func()`:

```java
return a + b + c;
```

따라서:

```text
1 + 5 + 3
= 9
```

---

## `b.func()`

B 객체:

```text
a = 10
b = 30
c = 50
```

하지만 B에서 `func()`를 오버라이딩했다.

```java
public int func() {
    return a * c;
}
```

따라서:

```text
10 × 50
= 500
```

최종:

```text
9 + 500
= 509
```

---

## 접근 제어자

```text
public
→ 어디서든 접근

protected
→ 같은 패키지 + 상속 관계

default
→ 같은 패키지

private
→ 해당 클래스 내부에서만
```

B에서는 부모 A의:

```text
a
c
```

를 사용할 수 있다.

하지만:

```text
private int b;
```

는 B에서 직접 접근할 수 없다.

## 문제

`10.0.0.0/27` 네트워크를 **2개의 동일한 크기의 서브넷**으로 분할하였다.

IP 주소:

```text
10.0.0.10
```

이 속한 서브넷의 프리픽스 비트 수를 쓰시오.

```text
/28
```

```text
28
```

```text
/27
```

# 17. 암호학적 해시 함수 🔥🔥

## 문제

다음 빈칸에 들어갈 가장 알맞은 용어를 작성하시오.

> 암호학적 `(   )` 함수는 임의 길이의 입력 데이터를 고정된 길이의 출력값으로 변환하는 함수이다.

특징:

- 단방향성: `(   )` 값으로부터 원래 입력값을 역산하는 것이 계산적으로 불가능해야 한다.
- 충돌 저항성: 서로 다른 두 입력이 동일한 `(   )` 값을 생성하는 경우를 찾기 어려워야 한다.

## 정답

**해시(Hash)**

따라서 세 빈칸 모두:

```text
Hash
```

## 해시 함수

```text
임의 길이 입력
↓
Hash Function
↓
고정 길이 출력
```

출력값을:

```text
Hash Value
Digest
Message Digest
```

라고 한다.

---

## 단방향성(Preimage Resistance)

```text
원문
→ Hash
```

는 쉽게 계산할 수 있지만:

```text
Hash
→ 원문
```

을 알아내는 것은 매우 어려워야 한다.

---

## 충돌 저항성(Collision Resistance)

다른 데이터:

```text
A
B
```

가 있을 때:

```text
Hash(A) = Hash(B)
```

가 되는 입력을 찾기 어려워야 한다.

이러한 현상을:

```text
Collision
충돌
```

이라고 한다.

---

## 대표 해시 알고리즘

```text
MD5
SHA-1
SHA-2
SHA-3
HAS-160
```

단, MD5와 SHA-1은 충돌 취약점 때문에 현대 보안 용도로는 권장되지 않는다.

# 20. 정규화 / 제3정규형(3NF) 🔥🔥

## 문제

다음 릴레이션이 만족하는 최고 정규형을 작성하시오.

### 릴레이션

| 고객아이디 | 강좌명 | 강사번호 |
|---|---|---|
| apple | 영어회화 | P001 |
| banana | 기초토익 | P002 |
| carrot | 영어회화 | P001 |
| carrot | 기초토익 | P004 |
| orange | 영어회화 | P003 |
| orange | 기초토익 | P004 |

복합 기본키:

```text
(고객아이디, 강좌명)
```

함수적 종속:

```text
(고객아이디, 강좌명)
→ 강사번호
```

```text
강사번호
→ 강좌명
```

## 정답

**제3정규형(3NF)**

## 이유

먼저 기본키로 제시된 것은:

```text
(고객아이디, 강좌명)
```

이다.

그리고:

```text
강사번호 → 강좌명
```

이라는 함수적 종속이 존재한다.

---

## 후보키 확인

다음을 보자.

```text
(고객아이디, 강사번호)
```

강사번호가 있으면:

```text
강사번호 → 강좌명
```

이므로 강좌명을 구할 수 있다.

따라서:

```text
고객아이디 + 강사번호
↓
강좌명
```

결국 모든 속성을 결정할 수 있다.

따라서 후보키는:

```text
(고객아이디, 강좌명)

(고객아이디, 강사번호)
```

가 될 수 있다.

즉:

```text
고객아이디
강좌명
강사번호
```

모두 후보키를 구성하는 **주요 속성(Prime Attribute)**이다.

---

## 3NF 조건

함수적 종속:

```text
X → Y
```

에서 다음 중 하나를 만족하면 3NF이다.

```text
X가 슈퍼키
또는
Y가 주요 속성
```

문제의:

```text
강사번호 → 강좌명
```

에서 강사번호는 단독 슈퍼키는 아니다.

하지만:

```text
강좌명
```

은 후보키를 구성하는 주요 속성이다.

따라서 **3NF는 만족**한다.

---

## BCNF는 왜 만족하지 못하는가?

BCNF의 조건:

```text
모든 결정자는 반드시 후보키 또는 슈퍼키
```

이어야 한다.

그런데:

```text
강사번호 → 강좌명
```

에서:

```text
강사번호
```

는 단독으로 릴레이션 전체를 결정하지 못한다.

즉 슈퍼키가 아니다.

따라서:

```text
BCNF X
```

이다.

결론:

```text
3NF O
BCNF X
```

따라서 최고 정규형은:

**제3정규형(3NF)**

---

## 정규화 단계

```text
제1정규형(1NF)
→ 속성값 원자화

제2정규형(2NF)
→ 부분 함수 종속 제거

제3정규형(3NF)
→ 이행적 함수 종속 제거

BCNF
→ 모든 결정자가 후보키

제4정규형(4NF)
→ 다치 종속 제거

제5정규형(5NF)
→ 조인 종속 제거
```
