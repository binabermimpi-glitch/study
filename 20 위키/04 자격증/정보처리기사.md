### 1. 데이터 모델링 절차와 3요소

- 절차: 개념 데이터 모델링 → 논리 데이터 모델링 → 물리 데이터 모델링
- 데이터 구조: 데이터를 어떤 구조로 표현할지 정의
- 연산: 데이터를 처리하는 작업 정의
- 제약조건: 허용되는 데이터의 논리적 범위와 규칙

### 2. 개념 모델링과 ER 모델

- ER 모델은 피터 첸이 제안한 개념적 데이터 모델이다.
- 핵심 요소는 개체, 속성, 관계다.
- ER 다이어그램은 모델링 결과를 그림으로 표현한 것이다.
- 전통적인 Chen 표기에서 개체는 사각형, 관계는 마름모, 속성은 타원으로 표시한다.
- 유도 속성은 다른 속성으로 계산할 수 있는 값이다. 예: 가격과 할인율로 구한 판매가격

### 3. 논리 데이터 모델과 관계 모델

- 엔터티: 관리 대상
- 속성: 관리할 구체적인 정보
- 관계: 엔터티 사이의 대응
- 관계 데이터 모델은 데이터를 릴레이션, 즉 2차원 테이블 형태로 표현한다.

| 용어 | 의미 |
|---|---|
| 튜플 | 행 |
| 애트리뷰트 | 열 |
| 도메인 | 속성이 가질 수 있는 값의 집합 |
| 차수 | 속성의 개수 |
| 카디널리티 | 튜플의 개수 |

릴레이션의 이론적 특성은 튜플의 유일성·무순서, 속성의 무순서·원자성이다.

### 4. 관계대수와 관계해석

- 관계대수: 처리 절차를 표현하는 절차적 방식
- 관계해석: 원하는 결과의 조건을 표현하는 비절차적 방식
- 일반 집합 연산: 합집합, 교집합, 차집합, 카티션 프로덕트
- 순수 관계 연산: 셀렉트, 프로젝트, 조인, 디비전
- 셀렉트는 조건에 맞는 튜플, 프로젝트는 지정한 속성을 선택한다.

### 5. 데이터베이스 키

- 슈퍼키: 유일성 만족
- 후보키: 유일성과 최소성 만족
- 기본키: 후보키 중 대표로 선택한 키
- 대체키: 기본키로 선택하지 않은 나머지 후보키
- 외래키: 다른 릴레이션의 키를 참조하여 관계 표현

이름이나 주소는 중복될 수 있으므로 실제 규칙에서 유일성을 보장하지 않으면 후보키가 아니다.

### 6. 무결성 제약조건

- 개체 무결성: 기본키를 구성하는 속성은 NULL일 수 없다.
- 참조 무결성: 외래키 값은 참조 대상에 존재하거나, 허용된 경우 NULL이어야 한다.

### 7. 정규화와 이상 현상

- 정규화는 중복과 삽입·갱신·삭제 이상을 줄이기 위해 릴레이션을 분해하는 과정이다.
- 삽입 이상: 필요한 데이터를 넣기 위해 불필요한 데이터도 넣어야 하는 문제
- 갱신 이상: 중복 데이터 일부만 수정되어 불일치가 생기는 문제
- 삭제 이상: 한 데이터를 삭제하면서 필요한 다른 데이터도 손실되는 문제

| 정규형 | 핵심 |
|---|---|
| 1NF | 원자값 |
| 2NF | 부분 함수 종속 제거 |
| 3NF | 이행 함수 종속 제거 |
| BCNF | 모든 결정자가 후보키 |
| 4NF | 다치 종속 문제 제거 |
| 5NF | 조인 종속 문제 제거 |

### 8. 물리 모델링과 반정규화

- 물리 모델링은 특정 DBMS를 고려하여 테이블, 칼럼, 키, 인덱스와 뷰 등을 설계한다.
- 반정규화는 측정된 성능 문제를 해결하기 위해 정규화 원칙을 의도적으로 일부 완화하는 설계다.
- 인덱스는 검색을 빠르게 할 수 있지만 저장 공간과 쓰기 작업의 유지 비용이 증가한다.
- 뷰는 하나 이상의 테이블을 기반으로 정의한 가상 테이블이다.

### 3. 결합도와 응집도

- 좋은 모듈은 결합도가 낮고 응집도가 높다.
- 결합도(좋음 → 나쁨): 자료 → 스탬프 → 제어 → 외부 → 공통 → 내용
- 응집도(좋음 → 나쁨): 기능적 → 순차적 → 통신적 → 절차적 → 시간적 → 논리적 → 우연적
- 순차적 응집도는 앞 작업의 출력이 다음 작업의 입력이 되는 경우이고, 절차적 응집도는 정해진 실행 순서로 묶인 경우다.
- Java 연결: 필요한 값만 매개변수로 넘기고 클래스가 하나의 책임에 집중하도록 설계하는 이유와 연결된다.

### 4. 애플리케이션 성능 지표

- 처리량: 일정 시간 동안 처리한 작업의 양
- 응답 시간: 요청 후 응답을 받기까지 걸리는 시간
- 경과 시간(반환 시간): 요청부터 전체 처리가 완료될 때까지의 시간
- 자원 사용률: CPU, 메모리, 네트워크 등 사용량
- 시험 자료마다 응답 시간의 종료 기준 표현이 다를 수 있으므로 출제 문장을 기준으로 판단한다.

### 5. SQL `DISTINCT`

- `SELECT dept`는 중복을 포함한 모든 행을 반환한다.
- `SELECT DISTINCT dept`는 중복 학과를 제거한다.
- `COUNT(DISTINCT dept)`는 중복을 제거한 값의 개수를 하나의 집계 결과로 반환한다.
- Database 국비수업의 조회·집계 함수 및 이후 JPA 조회 결과 이해와 연결된다.

### 6. 보안 공격

- LAND Attack: 출발지와 목적지 IP를 공격 대상과 같게 조작해 자기 자신에게 응답하도록 유도한다.
- DoS/DDoS, Smurf, SYN·UDP·Ping Flooding, Ping of Death, Teardrop 등 서비스 거부 공격의 특징을 구분한다.
- Phishing·Pharming·Smishing·Spear Phishing은 사용자를 속이는 경로와 대상을 구분한다.
- SQL Injection, XSS, CSRF는 백엔드 웹 보안에서 특히 중요한 실무 핵심이다.
- Ransomware, Key Logger, APT, Zero-Day, Back Door, Rainbow Table과 TOCTOU의 정의를 학습했다.

### 7. 통신 프로토콜과 네트워크

- 프로토콜 3요소: 구문(Syntax), 의미(Semantics), 타이밍(Timing)
- OSI 7계층: 물리 → 데이터링크 → 네트워크 → 전송 → 세션 → 표현 → 응용
- 물리 계층은 비트를 전송하며 대표 장비로 허브와 리피터가 있다.
- ARP는 IP 주소로 MAC 주소를 찾고, RARP는 MAC 주소로 IP 주소를 찾는 것으로 시험에서 구분한다.

### 8. 프로세스 스케줄링

- HRN 우선순위: `(대기 시간 + 서비스 시간) / 서비스 시간`
- HRN은 계산값이 큰 프로세스를 먼저 선택하는 비선점 방식이다.
- 비선점 예: FCFS, SJF, HRN
- 선점 예: SRT, RR, MLQ, MFQ

### 9. 트랜잭션 ACID

- 원자성(Atomicity): 모두 수행하거나 모두 수행하지 않는다.
- 일관성(Consistency): 수행 전후 데이터베이스 규칙이 유지된다.
- 격리성(Isolation): 동시에 실행되는 트랜잭션이 서로 부적절하게 간섭하지 않도록 한다.
- 지속성(Durability): 커밋된 결과는 장애가 발생해도 보존되어야 한다.
- Database 트랜잭션과 Spring의 `@Transactional` 학습에 직접 연결된다.

- 데이터 마이닝: 대량 데이터에서 유용한 규칙과 패턴을 찾아내는 과정

- 대칭키 예: AES, ARIA, SEED / 공개키 예: RSA, ElGamal, ECC / 해시 예: SHA 계열

### 1. 개발 방법론

- 애자일은 짧은 주기로 결과를 만들고 피드백과 요구사항 변화를 반영하는 접근이다.
- 폭포수는 단계를 순차적으로 진행하고, 프로토타입은 견본으로 요구사항을 확인한다.
- 나선형은 계획 → 위험 분석 → 개발 → 고객 평가를 반복하며 위험 분석이 핵심이다.
- XP 핵심 가치: 의사소통, 단순성, 피드백, 용기, 존중
- Scrum은 짧은 Sprint를 반복하고 Daily Scrum으로 진행 상황과 장애물을 공유한다.
- 실무에서는 애자일을 회의나 속도만의 의미로 보지 않고, 작게 검증하고 개선하는 방식으로 이해한다.

### 2. SOAP 웹 서비스

- SOAP는 XML 메시지를 사용해 분산 환경에서 정보를 교환하는 프로토콜이다.
- WSDL은 웹 서비스의 기능과 호출 방법을 설명하고, UDDI는 서비스를 등록·검색하는 레지스트리다.
- 시험 암기: `UDDI = 찾기`, `WSDL = 설명`, `SOAP = 통신`
- 현대적인 신규 웹 API는 JSON 기반 REST 방식을 더 흔히 사용하지만, SOAP는 기업·공공·레거시 연동에서 만날 수 있다.

### 3. 형상 관리와 Git

- 형상 관리는 소스뿐 아니라 문서·설정·빌드 환경·라이브러리와 변경 이력을 식별하고 통제하는 활동이다.
- 절차: 형상 식별 → 형상 통제 → 형상 감사 → 형상 기록
- SVN은 중앙 집중식, Git은 분산 버전 관리 방식이다.
- 지금 이 Wiki를 Git으로 기록하고 GitHub Actions로 배포하는 과정도 형상 관리의 실제 예다.

### 4. AJAX와 UI 원칙

- AJAX는 JavaScript가 서버와 비동기적으로 데이터를 교환하여 전체 페이지 새로고침 없이 일부 화면을 갱신하는 접근이다.
- 이름에 XML이 있지만 JSON도 흔히 사용한다.
- UI 설계 원칙: 직관성, 유효성, 학습성, 유연성
- 백엔드 API는 AJAX·`fetch` 요청에 JSON을 반환하는 서버 역할을 담당한다.

### 5. 소프트웨어 테스트 분류

- 정적 테스트는 프로그램을 실행하지 않고 리뷰·워크스루·인스펙션·정적 분석 등으로 결함을 찾는다.
- 동적 테스트는 프로그램을 실행하여 결과를 확인한다.
- 화이트박스는 내부 구조·조건·분기·경로를 보고, 블랙박스는 입력과 출력 및 기능을 중심으로 테스트한다.
- 회귀 테스트는 변경 후 기존 기능에 문제가 생기지 않았는지 다시 확인한다.
- Verification은 제품을 올바르게 만들고 있는지, Validation은 올바른 제품을 만들었는지 확인한다.

### 6. SQL IN과 트랜잭션 명령

```sql
SELECT 학번, 이름
FROM 학생
WHERE 학년 IN (3, 4);
```

- `IN`은 목록 중 하나와 일치하는지 검사하고 `NOT IN`은 목록의 값을 제외한다.
- `COMMIT`은 트랜잭션 변경을 확정하고 `ROLLBACK`은 확정하지 않은 변경을 취소한다.
- 시험에서 COMMIT·ROLLBACK을 DCL로 제시하기도 하지만 SQL 표준·DB 문맥에서는 TCL로 구분하는 경우가 많으므로 문제의 분류를 따른다.
- `NOT IN` 목록에 `NULL`이 들어가면 예상과 다른 결과가 날 수 있으므로 SQL의 3값 논리를 별도로 학습한다.

### 7. IPSec

- IPSec은 IP 계층에서 패킷의 기밀성·무결성·인증 등을 제공하는 보안 프로토콜 모음이다.
- AH는 인증·무결성을 제공하지만 암호화에 의한 기밀성은 제공하지 않는다.
- ESP는 기밀성을 위한 암호화를 제공하며 구성에 따라 인증·무결성도 제공한다.

### 8. Linux 권한과 Android

- Linux 권한 숫자는 읽기 4, 쓰기 2, 실행 1을 더해 소유자·그룹·기타 사용자 순으로 표현한다.
- `chmod 751 a.txt`는 `rwx r-x --x` 권한을 지정한다.
- Android는 Linux 커널 기반 모바일 플랫폼이며 앱은 Java·Kotlin 등으로 개발한다.
- Linux 권한은 [[20 위키/04 자격증/리눅스마스터 2급]]의 파일 권한 학습과 연결한다.

### 9. RTO와 RPO

- RTO(목표 복구 시간): 장애 후 서비스를 언제까지 복구해야 하는가
- RPO(목표 복구 시점): 어느 시점의 데이터까지 복구할 수 있어야 하는가
- 백엔드에서는 백업 주기, 장애 복구 절차와 서비스 수준 목표를 정할 때 사용한다.

### 10. Observer Pattern

- 한 객체의 상태가 변경되면 그 객체를 구독하는 여러 객체에 알리는 일대다 의존 관계다.
- Java 이벤트 리스너와 Spring의 애플리케이션 이벤트를 이해하는 데 연결된다.
- 알림이 자동이라는 장점이 있지만 구독 해제, 실행 순서와 예외 처리에 주의한다.

### 11. Linked Open Data와 REST

- LOD는 HTTP·URI·RDF 등 웹 표준으로 데이터를 식별하고 연결하여 공개·재사용할 수 있게 한다.
- REST는 자원을 URI로 식별하고 HTTP 메서드로 상태를 주고받는 아키텍처 스타일이다.
- 기본 연결: 조회 `GET`, 생성 `POST`, 전체 교체 `PUT`, 부분 변경 `PATCH`, 삭제 `DELETE`
- REST는 단순히 CRUD URL 규칙만 뜻하지 않으며 무상태성·캐시·균일한 인터페이스 같은 제약을 함께 이해해야 한다.

### 1. 위험 대응 방식

- 위험 회피: 위험을 만드는 활동이나 원인을 제거한다.
- 위험 감소: 방화벽·백업·이중화·교육 등으로 발생 가능성이나 피해 규모를 낮춘다.
- 위험 전가: 보험·계약 등으로 손실이나 책임을 다른 주체에 이전한다.
- 위험 수용: 위험을 인지한 상태에서 비용 등을 고려해 감수한다.
- 백엔드 운영에서는 백업·다중화·접근 통제가 위험 감소의 실제 예다.

### 2. 시큐어 코딩

- 개발 단계에서 입력 검증, 인증·인가, 오류 처리와 중요 정보 보호를 적용해 코드 취약점을 예방하는 활동이다.
- 대표 대상: SQL Injection, XSS, 경로 조작, 중요 정보 노출과 잘못된 권한 처리
- Java에서는 SQL 문자열 연결을 피하고 `PreparedStatement`나 프레임워크의 매개변수 바인딩을 사용한다.
- 시큐어 코딩은 특정 API 하나가 아니라 설계·구현·검토 전반의 보안 활동이다.

### 3. UML 시퀀스·클래스 다이어그램

- 시퀀스 다이어그램은 객체들이 시간 순서에 따라 주고받는 메시지를 표현한다.
- 클래스 다이어그램은 클래스의 속성·메서드·관계를 표현한다.
- UML 가시성: `+ public`, `- private`, `# protected`, `~ package`
- 국비 프로젝트에서 Controller → Service → Repository 호출 흐름을 시퀀스 다이어그램으로 표현할 수 있다.

### 4. 테스트 오라클

- 테스트 오라클은 실제 결과가 올바른지 판단할 기대 결과나 판정 기준이다.
- 참 오라클: 모든 입력에 정확한 기대 결과를 제공
- 샘플링 오라클: 일부 입력에만 기대 결과 제공
- 휴리스틱 오라클: 일부 정확한 결과를 바탕으로 나머지를 추정
- 일관성 검사 오라클: 변경 전후 결과의 일관성을 확인

### 5. 세마포어와 뮤텍스

- 세마포어는 공유 자원에 동시에 접근할 수 있는 작업 수를 허가 개수로 제어하는 동기화 도구다.
- 뮤텍스는 상호 배제를 위한 소유권 기반 잠금으로 보통 한 작업만 임계 구역에 들어가게 한다.
- `세마포어는 여러 개, 뮤텍스는 한 개`라는 암기는 출발점일 뿐이며 소유권과 사용 목적도 다르다.
- Java의 `Semaphore`, 스레드 풀과 데이터베이스 커넥션 풀 제한을 이해하는 선행지식이다.

### 6. 퍼사드 패턴

- 복잡한 여러 하위 시스템 앞에 단순한 통합 인터페이스를 제공하는 구조 패턴이다.
- 호출자는 내부 구성 요소의 세부 순서와 의존성을 모두 알 필요가 없어 결합과 사용 복잡도가 줄어든다.
- Spring의 서비스 계층이 여러 저장소·외부 API 호출을 하나의 업무 메서드로 묶는 구조와 비교해볼 수 있다.

### 7. Kerberos

- MIT Athena 프로젝트에서 개발된 대칭키 기반 티켓 인증 프로토콜이다.
- KDC는 일반적으로 AS와 TGS 역할로 구성된다.
- 사용자는 AS에서 TGT를 받은 뒤 TGS를 통해 서비스 티켓을 발급받아 서비스에 접근한다.
- 비밀번호 자체를 매 요청마다 네트워크로 보내지 않고 티켓을 사용하는 인증 흐름이 핵심이다.

### 8. Lean

- 낭비를 제거하고 가치 흐름과 효율을 개선하는 방식으로 도요타 생산 방식과 연결된다.
- 시험에서는 `도요타`, `낭비 제거`를 핵심 단서로 기억한다.
- 실무에서는 단순히 인력과 설비를 줄인다는 뜻보다 고객 가치가 없는 대기·재작업·불필요한 절차를 줄이는 관점이 중요하다.

### 9. Fan-In과 Fan-Out

- Fan-In: 해당 모듈을 호출하거나 사용하는 상위 모듈의 수
- Fan-Out: 해당 모듈이 호출하거나 제어하는 하위 모듈의 수
- Fan-In이 높으면 재사용되는 공통 모듈일 수 있지만 변경 영향도 커질 수 있다.
- Fan-Out이 지나치게 높으면 한 모듈의 책임이 너무 크거나 의존성이 복잡한지 검토한다.

### 10. 기능 점수 FP

- 소프트웨어가 제공하는 기능의 수와 복잡도에 가중치를 적용하여 규모와 비용을 산정하는 방법이다.
- 대표 기능 유형: 외부 입력(EI), 외부 출력(EO), 외부 조회(EQ), 내부 논리 파일(ILF), 외부 인터페이스 파일(EIF)
- `기능 + 가중치`가 시험 핵심이다.
- LOC는 코드 줄 수, COCOMO는 소프트웨어 규모, Putnam은 생명주기와 인력 분포를 중심으로 비용을 산정한다.
