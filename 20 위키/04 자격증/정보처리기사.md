### 1. 데이터 모델링 절차와 3요소

- 절차: 개념 데이터 모델링 → 논리 데이터 모델링 → 물리 데이터 모델링
- 데이터 구조: 데이터를 어떤 구조로 표현할지 정의
- 연산: 데이터를 처리하는 작업 정의
- 제약조건: 허용되는 데이터의 논리적 범위와 규칙

### 2. 개념 모델링과 ER 모델

- ER 모델은 피터 첸이 제안한 개념적 데이터 모델이다.
- 핵심 요소는 개체, 속성, 관계다.
- ER 다이어그램은 모델링 결과를 그림으로 표현한 것이다.
- 전통적인 Chen 표기에서 개체는 사각형, 관계는 마름모, 속성은 타원으로 표시한다.
- 유도 속성은 다른 속성으로 계산할 수 있는 값이다. 예: 가격과 할인율로 구한 판매가격

### 3. 논리 데이터 모델과 관계 모델

- 엔터티: 관리 대상
- 속성: 관리할 구체적인 정보
- 관계: 엔터티 사이의 대응
- 관계 데이터 모델은 데이터를 릴레이션, 즉 2차원 테이블 형태로 표현한다.

| 용어 | 의미 |
|---|---|
| 튜플 | 행 |
| 애트리뷰트 | 열 |
| 도메인 | 속성이 가질 수 있는 값의 집합 |
| 차수 | 속성의 개수 |
| 카디널리티 | 튜플의 개수 |

릴레이션의 이론적 특성은 튜플의 유일성·무순서, 속성의 무순서·원자성이다.

### 4. 관계대수와 관계해석

- 관계대수: 처리 절차를 표현하는 절차적 방식
- 관계해석: 원하는 결과의 조건을 표현하는 비절차적 방식
- 일반 집합 연산: 합집합, 교집합, 차집합, 카티션 프로덕트
- 순수 관계 연산: 셀렉트, 프로젝트, 조인, 디비전
- 셀렉트는 조건에 맞는 튜플, 프로젝트는 지정한 속성을 선택한다.

### 5. 데이터베이스 키

- 슈퍼키: 유일성 만족
- 후보키: 유일성과 최소성 만족
- 기본키: 후보키 중 대표로 선택한 키
- 대체키: 기본키로 선택하지 않은 나머지 후보키
- 외래키: 다른 릴레이션의 키를 참조하여 관계 표현

이름이나 주소는 중복될 수 있으므로 실제 규칙에서 유일성을 보장하지 않으면 후보키가 아니다.

### 6. 무결성 제약조건

- 개체 무결성: 기본키를 구성하는 속성은 NULL일 수 없다.
- 참조 무결성: 외래키 값은 참조 대상에 존재하거나, 허용된 경우 NULL이어야 한다.

### 7. 정규화와 이상 현상

- 정규화는 중복과 삽입·갱신·삭제 이상을 줄이기 위해 릴레이션을 분해하는 과정이다.
- 삽입 이상: 필요한 데이터를 넣기 위해 불필요한 데이터도 넣어야 하는 문제
- 갱신 이상: 중복 데이터 일부만 수정되어 불일치가 생기는 문제
- 삭제 이상: 한 데이터를 삭제하면서 필요한 다른 데이터도 손실되는 문제

| 정규형 | 핵심 |
|---|---|
| 1NF | 원자값 |
| 2NF | 부분 함수 종속 제거 |
| 3NF | 이행 함수 종속 제거 |
| BCNF | 모든 결정자가 후보키 |
| 4NF | 다치 종속 문제 제거 |
| 5NF | 조인 종속 문제 제거 |

### 8. 물리 모델링과 반정규화

- 물리 모델링은 특정 DBMS를 고려하여 테이블, 칼럼, 키, 인덱스와 뷰 등을 설계한다.
- 반정규화는 측정된 성능 문제를 해결하기 위해 정규화 원칙을 의도적으로 일부 완화하는 설계다.
- 인덱스는 검색을 빠르게 할 수 있지만 저장 공간과 쓰기 작업의 유지 비용이 증가한다.
- 뷰는 하나 이상의 테이블을 기반으로 정의한 가상 테이블이다.
