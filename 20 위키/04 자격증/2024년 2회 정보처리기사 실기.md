# 1. Java 배열 객체 / `==` 연산자 🔥🔥

## 문제

다음 Java 프로그램의 실행 결과를 쓰시오.

```java
public class Gisafirst {

    public static void check(int[] x, int[] y) {

        if (x == y)
            System.out.print("O");
        else
            System.out.print("N");
    }

    public static void main(String[] args) {

        int a[] = new int[] {1, 2, 3, 4};
        int b[] = new int[] {1, 2, 3, 4};
        int c[] = new int[] {1, 2, 3};

        check(a, b);
        check(b, c);
        check(a, c);
    }
}
```

## 정답

```text
NNN
```

## 핵심

Java에서 배열은 **객체**이다.

```java
int a[] = new int[] {1, 2, 3, 4};
int b[] = new int[] {1, 2, 3, 4};
```

`a`와 `b`의 값은 똑같지만 `new`를 각각 실행했기 때문에 서로 다른 배열 객체가 생성된다.

```text
Stack                     Heap

a ───────────────────→ [1, 2, 3, 4]
                         서로 다른 객체

b ───────────────────→ [1, 2, 3, 4]

c ───────────────────→ [1, 2, 3]
```

`==`는 배열의 내용을 비교하는 것이 아니라 **참조값(주소 개념)**을 비교한다.

따라서:

```text
a == b
→ false
→ N

b == c
→ false
→ N

a == c
→ false
→ N
```

최종:

```text
NNN
```

## 배열 내용 비교

배열의 실제 값들을 비교하려면:

```java
Arrays.equals(a, b)
```

를 사용할 수 있다.

```text
==
→ 같은 객체인가?

Arrays.equals()
→ 배열의 내용이 같은가?
```

# 2. 반정규화 / 비정규화 / 역정규화 🔥🔥

## 문제

- 시스템의 성능 향상과 개발·운영의 단순화를 위해 데이터 모델에 중복, 통합, 분리 등을 수행하는 데이터 모델링 기법
- 적정 수준의 정규화 이후 질의 성능 향상을 위해 일부 데이터의 중복을 허용하는 작업
- 정규화된 엔티티, 속성, 관계에 대해 시스템의 성능 향상과 개발 및 운영의 단순화를 위해 데이터 모델을 조정하는 프로세스

## 정답

**반정규화(Denormalization)**

다른 표현:

```text
비정규화
역정규화
```

## 개념

정규화를 하면 데이터 중복은 줄어들지만 테이블이 많이 분리되어 `JOIN`이 증가할 수 있다.

이때 성능을 향상하기 위해 의도적으로:

```text
테이블 통합
테이블 분할
중복 데이터 추가
중복 컬럼 추가
```

등을 수행할 수 있다.

```text
정규화
→ 중복 감소 / 무결성 향상

반정규화
→ 일부 중복 허용 / 조회 성능 향상
```

## 주의

반정규화는 처음부터 아무렇게나 중복을 허용하는 것이 아니다.

```text
적절한 정규화 수행
↓
성능 문제 확인
↓
필요한 부분만 반정규화
```

# 4. Cardinality / Degree 🔥

## 문제

관계형 데이터베이스에서 카디널리티(Cardinality)와 차수(Degree)의 의미를 쓰시오.

## 정답

```text
Cardinality
→ 튜플(Row)의 수

Degree
→ 속성(Column)의 수
```

예:

| 학번 | 이름 | 학과 |
|---|---|---|
| 1 | 철수 | 컴퓨터 |
| 2 | 영희 | 기계 |
| 3 | 민수 | 전자 |

여기서:

```text
튜플 = 3개
→ Cardinality = 3

속성 = 학번, 이름, 학과
→ Degree = 3
```

## 암기

```text
Cardinality
→ 행 개수

Degree
→ 열 개수
```

# 5. IPSec 🔥🔥

## 문제

- 네트워크 계층의 보안을 위해 Authentication Header와 ESP 프로토콜을 이용하여 보안 서비스를 제공한다.
- VPN 구현에 사용되는 터널링 관련 보안 프로토콜이다.
- 암호화 및 인증을 사용하여 두 시스템 사이의 안전한 통신을 제공한다.

## 정답

**IPSec(Internet Protocol Security)**

## 특징

IPSec는 **네트워크 계층(IP 계층)**에서 보안을 제공한다.

주요 프로토콜:

```text
AH
→ Authentication Header

ESP
→ Encapsulating Security Payload
```

---

## AH

**Authentication Header**

주요 기능:

```text
인증
무결성
```

하지만:

```text
암호화를 통한 기밀성 제공 X
```

---

## ESP

**Encapsulating Security Payload**

주요 기능:

```text
암호화
→ 기밀성

인증
무결성도 지원 가능
```

## 암기

```text
AH
→ 인증 / 무결성

ESP
→ 암호화 / 기밀성
```

---

## IPSec 모드

### 전송 모드(Transport Mode)

원래 IP Header는 유지하고 **데이터 부분(Payload)**을 보호한다.

### 터널 모드(Tunnel Mode)

기존 IP 패킷 전체를 감싸고 새로운 IP Header를 추가한다.

```text
전송 모드
→ Payload 보호

터널 모드
→ 기존 IP 패킷 전체 보호
→ VPN에서 많이 사용
```

# 7. Iterator Pattern 🔥🔥

## 문제

- 행위 패턴의 한 종류로 Cursor라고도 한다.
- 집합 객체의 요소들에 순서대로 접근하는 방법을 제공한다.
- 배열, ArrayList, Hash Table과 같은 객체를 처리할 때 사용할 수 있다.
- 서로 다른 자료구조에 대해 동일한 방식으로 순회할 수 있다.

## 정답

**Iterator Pattern(이터레이터 패턴)**

## 분류

```text
GoF
→ 행위 패턴(Behavioral Pattern)
```

## 핵심

컬렉션의 내부 구현 방법을 외부에 노출하지 않고 각 요소에 순차적으로 접근할 수 있게 한다.

```text
ArrayList
LinkedList
Set
기타 자료구조

        ↓

Iterator

        ↓

next()
next()
next()
```

Java에서도:

```java
Iterator<String> iterator = list.iterator();

while (iterator.hasNext()) {
    String value = iterator.next();
}
```

처럼 사용한다.

## 핵심 문장

```text
컬렉션 내부 구조 노출 X
+
순차 접근
→ Iterator Pattern
```

# 8. Python 문자열 포매팅 / 부분 문자열 개수 🔥🔥

## 문제

```python
def cnt(str, p):
    result = 0

    for i in range(len(str) - len(p) + 1):

        sub = str[i:i+len(p)]

        if sub == p:
            result += 1

    return result


str = "abdcabcabca"
p1 = "ca"
p2 = "ab"

print(f'ab{cnt(str, p1)}' f'ca{cnt(str, p2)}')
```

## 정답

```text
ab3ca3
```

## `cnt()` 함수

```python
for i in range(len(str) - len(p) + 1):
```

문자열을 한 칸씩 이동하면서 길이 `len(p)`만큼 잘라 비교한다.

```python
sub = str[i:i+len(p)]
```

---

## `p1 = "ca"`

문자열:

```text
abdcabcabca
```

`ca`가 등장하는 위치를 찾으면:

```text
abdcabcabca
   ca
      ca
         ca
```

총:

```text
3회
```

따라서:

```python
cnt(str, p1)
```

결과:

```text
3
```

---

## `p2 = "ab"`

```text
abdcabcabca
ab
    ab
       ab
```

총:

```text
3회
```

---

## f-string

```python
f'ab{cnt(str, p1)}'
```

결과:

```text

```

그리고:

```python
f'ca{cnt(str, p2)}'
```

결과:

# 9. 패킷 교환 방식 🔥🔥

## 문제

### (1)

연결형 교환 방식으로 정보 전송 전에 제어 패킷에 의해 가상 경로를 설정한 뒤 통신한다.

송신 순서와 수신 순서가 동일하며 연속적인 대량 데이터 전송에 적합하다.

### (2)

비연결형 방식으로 미리 경로를 설정하지 않는다.

각 패킷은 독립적으로 전달되며 서로 다른 경로로 이동할 수 있고 도착 순서가 바뀔 수 있다.

## 정답

```text
(1) 가상회선(Virtual Circuit)

(2) 데이터그램(Datagram)
```

---

## 가상회선 방식

통신 전에 논리적인 경로를 먼저 설정한다.

```text
경로 설정
↓
패킷 전송
↓
같은 경로 사용
```

특징:

```text
연결형
경로 사전 설정
패킷 순서 보장
```

---

## 데이터그램 방식

각 패킷이 독립적으로 이동한다.

```text
Packet 1 → 경로 A
Packet 2 → 경로 B
Packet 3 → 경로 C
```

특징:

```text
비연결형
경로 사전 설정 X
각 패킷 독립 전송
도착 순서가 달라질 수 있음
```

## 비교

```text
가상회선
→ 연결형
→ 경로 설정 O
→ 같은 경로
→ 순서 유지

데이터그램
→ 비연결형
→ 경로 설정 X
→ 독립적인 경로
→ 순서 달라질 수 있음
```

# 11. C 값 전달 / switch-case Fall Through 🔥🔥

## 문제

```c
#include <stdio.h>

void swap(int a, int b) {

    int t = a;
    a = b;
    b = t;
}

int main() {

    int a = 11;
    int b = 19;

    swap(a, b);

    switch(a) {

        case 1:
            b += 1;

        case 11:
            b += 2;

        default:
            b += 3;
            break;
    }

    printf("%d", a - b);
}
```

## 정답

```text
-13
```

## `swap(a, b)`

C의 기본 매개변수 전달은 **값에 의한 전달(Call by Value)**이다.

```c
swap(a, b);
```

호출 당시:

```text
main의 a = 11
main의 b = 19
```

함수에는 값이 복사된다.

```text
swap 내부

a = 11
b = 19
```

교환 후:

```text
swap 내부 a = 19
swap 내부 b = 11
```

그러나 main의 변수에는 영향을 주지 않는다.

따라서 함수 종료 후:

```text
main

a = 11
b = 19
```

---

## switch

```c
switch(a)
```

`a = 11`

따라서:

```c
case 11:
```

부터 시작한다.

```c
b += 2;
```

```text
19 + 2
= 21
```

`break`가 없으므로 `default`까지 이어서 실행된다.

```c
b += 3;
```

```text
21 + 3
= 24
```

따라서:

```text
a - b
= 11 - 24
= -13
```

## 핵심

```text
C 매개변수
→ 값 복사

switch에서 break 없음
→ 아래 case까지 계속 실행
→ Fall Through
```

# 13. Java 인터페이스 / 홀수·짝수 합 🔥🔥

## 문제

```java
interface Number {

    int sum(int[] a, boolean odd);
}

public class Gisafirst {

    public static void main(String[] args) {

        int a[] = {1, 2, 3, 4, 5, 6, 7, 8, 9};

        OENumber OE = new OENumber();

        System.out.print(
            OE.sum(a, true) + ", " + OE.sum(a, false)
        );
    }
}

class OENumber implements Number {

    public int sum(int[] a, boolean odd) {

        int result = 0;

        for (int i = 0; i < a.length; i++) {

            if ((odd && a[i] % 2 != 0)
                || (!odd && a[i] % 2 == 0))

                result += a[i];
        }

        return result;
    }
}
```

## 정답

```text
25, 20
```

## `odd = true`

조건:

```java
odd && a[i] % 2 != 0
```

즉 홀수만 더한다.

```text
1 + 3 + 5 + 7 + 9
= 25
```

---

## `odd = false`

이 부분:

```java
!odd && a[i] % 2 == 0
```

`odd = false`이면:

```text
!odd = true
```

따라서 짝수만 더한다.

```text
2 + 4 + 6 + 8
= 20
```

최종:

```text
25, 20
```

## 인터페이스 관계

```java
class OENumber implements Number
```

`Number` 인터페이스가 정의한:

```java
int sum(int[] a, boolean odd);
```

를 `OENumber`가 구현한다.

```text
extends
→ 클래스 상속

implements
→ 인터페이스 구현
```

# 14. RIP 라우팅 경로 🔥🔥

## 문제

RIP 방식으로 A에서 F까지의 경로를 구하시오.

## 정답

```text
A → D → C → F
```

## 핵심

RIP는 **거리 벡터(Distance Vector)** 기반 라우팅 프로토콜이다.

경로를 선택할 때:

```text
Hop Count
→ 거치는 라우터 수
```

를 기준으로 사용한다.

### 중요

그림에 링크마다 `1`, `2`, `5` 등의 값이 있어도 RIP 문제에서는 기본적으로 **링크 비용 합계보다 홉 수**를 본다.

예를 들어:

```text
A → D → C → F
```

는 목적지까지 거치는 링크 수가 적다.

반면:

```text
A → D → C → E → F
```

는 숫자 가중치의 합은 더 작아 보일 수 있지만 홉 수는 더 많다.

RIP는:

```text
가중치 합 X
Hop Count O
```

기준으로 경로를 선택한다.

## RIP 특징

```text
IGP
Distance Vector
Hop Count
최대 15 Hop
30초 주기 정보 교환
소규모 네트워크
```

```text
16 Hop
→ 도달 불가능
```

## OSPF와 비교

```text
RIP
→ Hop Count

OSPF
→ Cost
→ Link State
→ Dijkstra
```

# 16. SRT 프로세스 스케줄링 🔥🔥

## 문제

다음 프로세스들의 평균 대기시간을 구하시오.

| 프로세스 | 도착 시간 | 실행 시간 |
|---|---:|---:|
| P1 | 0 | 8 |
| P2 | 1 | 4 |
| P3 | 2 | 9 |
| P4 | 3 | 5 |

스케줄링 방식은 **SRT**이다.

## 정답

```text
6.5
```

## SRT

**Shortest Remaining Time**

현재 실행 가능한 프로세스 중 **남은 실행 시간이 가장 짧은 프로세스**를 선택한다.

```text
SJF
→ 비선점

SRT
→ SJF의 선점형 버전
```

---

## 실행 과정

### 시간 0

P1만 존재한다.

```text
0 ~ 1
→ P1
```

P1의 남은 시간:

```text
7
```

### 시간 1

P2 도착.

```text
P1 남은 시간 = 7
P2 실행 시간 = 4
```

P2가 더 짧으므로 P1을 중단하고 P2 실행.

```text
1 ~ 5
→ P2
```

P2 종료.

### 시간 5

현재:

```text
P1 남음 = 7
P3 = 9
P4 = 5
```

P4가 가장 짧다.

```text
5 ~ 10
→ P4
```

### 시간 10

현재:

```text
P1 = 7
P3 = 9
```

P1 실행.

```text
10 ~ 17
→ P1
```

### 시간 17

P3만 남음.

```text
17 ~ 26
→ P3
```

전체:

```text
0   1       5        10          17               26
| P1 |  P2   |   P4   |    P1     |       P3       |
```

---

## 대기시간

공식:

```text
대기시간
= 종료시간 - 도착시간 - 실행시간
```

### P1

```text
17 - 0 - 8
= 9
```

### P2

```text
5 - 1 - 4
= 0
```

### P3

```text
26 - 2 - 9
= 15
```

### P4

```text
10 - 3 - 5
= 2
```

평균:

```text
(9 + 0 + 15 + 2) / 4

= 26 / 4

= 6.5
```

## 핵심

```text

→ 가장 짧은 실행시간
→ 비선점

→ 가장 짧은 남은 시간
→ 선점
```

# 17. 제어 결합도(Control Coupling) 🔥🔥

## 문제

어떤 모듈이 다른 모듈의 내부 논리 조직을 제어하기 위해 제어 신호를 이용하여 통신하는 경우이다.

하위 모듈에서 상위 모듈로 제어 신호가 전달되어 상위 모듈의 처리를 제어하는 권리 전도 현상이 발생할 수 있다.

## 정답

**제어 결합도(Control Coupling)**

## 개념

한 모듈이 다른 모듈에:

```text
Flag
Switch
제어값
```

등을 전달하여 상대 모듈의 실행 흐름을 결정하게 한다.

예:

```java
process(true);
```

여기서 `true`라는 값에 따라 내부 실행 방식이 달라지는 구조가 대표적이다.

## 결합도 순서

강한 것 → 약한 것:

```text
내용
→ 공통
→ 외부
→ 제어
→ 스탬프
→ 자료
```

### 암기

```text
내공외제스자
```

**내용 결합도**

한 모듈이 다른 모듈 내부 내용을 직접 사용.

**공통 결합도**

여러 모듈이 전역 데이터를 공유.

**외부 결합도**

외부 장치나 데이터 포맷 등을 공유.

**제어 결합도**

제어 신호 전달.

**스탬프 결합도**

자료구조 전체 전달.

**자료 결합도**

필요한 단순 데이터만 전달.

```text
자료 결합도
→ 가장 약함
→ 가장 좋은 결합도
```

# 18. Java 재귀 / 문자열 역순 + 중복 제거 🔥🔥

## 문제

```java
public class Gisafirst {

    public static String rf(
            String str,
            int index,
            boolean[] seen) {

        if (index < 0)
            return "";

        char c = str.charAt(index);

        String result = rf(str, index - 1, seen);

        if (!seen[c]) {

            seen[c] = true;

            return c + result;
        }

        return result;
    }

    public static void main(String[] args) {

        String str = "abacabcd";

        int length = str.length();

        boolean[] seen = new boolean[256];

        System.out.print(
            rf(str, length - 1, seen)
        );
    }
}
```

## 정답

```text
dcba
```

## 재귀 구조

처음:

```text
index = 7
```

하지만 바로 문자를 결과에 넣지 않고:

```java
rf(str, index - 1, seen)
```

을 먼저 호출한다.

즉 재귀호출이 계속 진행되어:

```text
7
→ 6
→ 5
→ 4
→ 3
→ 2
→ 1
→ 0
→ -1
```

까지 내려간다.

`index < 0`:

```java
return "";
```

이후 재귀가 돌아오면서 결과를 만든다.

---

## seen 배열

```java
boolean[] seen = new boolean[256];
```

처음에는 전부:

```text
false
```

문자를 처음 만났을 때:

```java
seen[c] = true;
```

로 변경한다.

따라서 같은 문자가 다시 나오면 결과에 추가하지 않는다.

---

## 실행 결과 흐름

문자열:

```text
a b a c a b c d
```

재귀에서 돌아오면서:

```text
a
→ a

b
→ ba

a
→ 이미 있음 → ba

c
→ cba

a
→ 이미 있음

b
→ 이미 있음

c
→ 이미 있음

d
→ dcba
```

따라서:

```text
dcba
```

## 핵심

```text
재귀
+
seen 배열
→ 중복 제거

c + result
→ 앞쪽에 문자 추가
→ 결과적으로 역순 형태
```

# 19. C 구조체 / 포인터 / 연결 리스트 🔥🔥

## 문제

```c
#include <stdio.h>

struct node {

    int n1;
    struct node *n2;
};

int main() {

    struct node *head = NULL;

    struct node a = {10, 0};
    struct node b = {20, 0};
    struct node c = {30, 0};

    head = &a;

    a.n2 = &b;
    b.n2 = &c;

    printf("%d", head->n2->n1);
}
```

## 정답

```text
20
```

## 연결 구조

처음:

```text
a
n1 = 10

b
n1 = 20

c
n1 = 30
```

다음:

```c
head = &a;
```

따라서:

```text
head → a
```

다음:

```c
a.n2 = &b;
```

```text
a → b
```

그리고:

```c
b.n2 = &c;
```

```text
b → c
```

최종:

```text
head
 ↓

[a]
n1 = 10
n2 ─────→ [b]
           n1 = 20
           n2 ─────→ [c]
                      n1 = 30
```

---

## `head->n2->n1`

먼저:

```c
head->n2
```

`head`가 가리키는 `a`의 `n2`.

즉:

```text
b의 주소
```

그 다음:

```c
head->n2->n1
```

`b`의 `n1`:

```text
20
```

따라서:

```text
20
```

## 연결 리스트

각 노드가:

```text
데이터
+
다음 노드를 가리키는 포인터
```

를 가지는 자료구조이다.

```text
10 → 20 → 30 → NULL
```
