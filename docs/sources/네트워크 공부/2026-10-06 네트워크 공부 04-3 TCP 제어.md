# 04-3 TCP의 오류 제어·흐름 제어·혼잡 제어

## 1. TCP가 제공하는 제어 기능

TCP는 신뢰성 있는 통신을 위해 다음 세 가지 핵심 제어 기능을 제공한다.

| 기능 | 목적 | 핵심 기준 |
|---|---|---|
| 오류 제어 | 손실되거나 잘못 전달된 데이터 복구 | ACK, 순서 번호, 타임아웃, 재전송 |
| 흐름 제어 | 수신자가 처리할 수 있는 만큼만 전송 | 수신 윈도우 |
| 혼잡 제어 | 네트워크 혼잡도에 맞춰 전송량 조절 | 혼잡 윈도우 |

### 핵심 구분

- 오류 제어: 데이터가 정상적으로 전달되었는가?
- 흐름 제어: 수신자가 데이터를 처리할 수 있는가?
- 혼잡 제어: 네트워크가 데이터를 감당할 수 있는가?

# 04-3-1 TCP 오류 제어

## 2. 오류 제어

TCP는 다음과 같은 문제를 감지하고 해결해야 한다.

- 세그먼트 손상
- 세그먼트 손실
- ACK 손실
- 세그먼트 중복
- 세그먼트 순서 변경

TCP는 다음 정보를 이용하여 오류를 제어한다.

- 체크섬
- 순서 번호
- 확인 응답 번호
- ACK 세그먼트
- 재전송 타이머
- 타임아웃
- 중복 ACK

---

## 3. TCP 체크섬의 역할과 한계

TCP 헤더에는 체크섬(Checksum) 필드가 있다.

체크섬은 TCP 세그먼트가 전송 과정에서 손상되었는지 검사하는 오류 검출 정보이다.

### 체크섬으로 할 수 있는 것

- TCP 헤더의 비트 오류 검출
- TCP 페이로드의 비트 오류 검출
- 일부 전송 오류 감지

### 체크섬만으로 부족한 이유

체크섬은 수신한 세그먼트가 손상되었는지는 확인할 수 있지만, 다음 문제를 혼자 해결할 수는 없다.

- 세그먼트가 중간에 완전히 사라진 경우
- ACK가 손실된 경우
- 세그먼트가 순서대로 도착하지 않은 경우
- 손실된 세그먼트를 언제 재전송해야 하는지 판단하는 경우

TCP가 신뢰성을 제공하려면 송신자가 문제 발생을 인지하고 해당 세그먼트를 다시 전송할 수 있어야 한다.

---

## 4. TCP가 재전송하는 대표적인 상황

TCP는 대표적으로 다음 두 상황에서 세그먼트를 재전송한다.

1. 중복 ACK를 연속해서 수신했을 때
2. 타임아웃이 발생했을 때

| 재전송 조건 | 의미 |
|---|---|
| 중복 ACK 수신 | 특정 순서 번호의 데이터가 누락되었을 가능성 |
| 타임아웃 발생 | 정해진 시간 안에 ACK를 받지 못함 |

---

## 5. 정상적인 ACK 수신 과정

송신 호스트 A가 수신 호스트 B에게 세그먼트를 순서대로 전송한다고 가정한다.

| 단계 | 송신 호스트 A | 방향 | 수신 호스트 B |
|---:|---|---|---|
| 1 | n번째 세그먼트 전송 | A → B | n번째 세그먼트 수신 |
| 2 | ACK 수신 | A ← B | n+1번째를 요구하는 ACK 전송 |
| 3 | n+1번째 세그먼트 전송 | A → B | n+1번째 세그먼트 수신 |
| 4 | ACK 수신 | A ← B | n+2번째를 요구하는 ACK 전송 |
| 5 | n+2번째 세그먼트 전송 | A → B | n+2번째 세그먼트 수신 |
| 6 | ACK 수신 | A ← B | n+3번째를 요구하는 ACK 전송 |

TCP의 ACK 번호는 다음으로 받고 싶은 데이터의 순서 번호를 의미한다.

---

## 6. 중복 ACK가 발생하는 상황

송신자가 여러 세그먼트를 연속해서 전송하던 중 특정 세그먼트가 손실될 수 있다.

예를 들어 다음과 같은 상황을 가정한다.

- 세그먼트 1: 정상 수신
- 세그먼트 2: 손실
- 세그먼트 3: 수신
- 세그먼트 4: 수신

수신자는 세그먼트 2를 받지 못했으므로 세그먼트 3과 4가 도착하더라도 계속 세그먼트 2를 요구하는 동일한 ACK 번호를 보낸다.

### 중복 ACK 발생 흐름

| 단계 | 송신 호스트 A | 방향 | 수신 호스트 B |
|---:|---|---|---|
| 1 | 세그먼트 1 전송 | A → B | 정상 수신 |
| 2 | 2번을 요구하는 ACK 수신 | A ← B | ACK 2 전송 |
| 3 | 세그먼트 2 전송 | A → B | 전송 중 손실 |
| 4 | 세그먼트 3 전송 | A → B | 세그먼트 2가 없으므로 ACK 2 전송 |
| 5 | 중복 ACK 2 수신 | A ← B | 세그먼트 2를 다시 요구 |
| 6 | 세그먼트 4 전송 | A → B | 다시 ACK 2 전송 |
| 7 | 중복 ACK 2 수신 | A ← B | 세그먼트 2를 계속 요구 |

### 중복 ACK의 의미

동일한 ACK 번호가 반복해서 도착한다는 것은 다음을 의미할 수 있다.

> ACK가 요구하는 세그먼트는 도착하지 않았지만 그 이후의 세그먼트는 계속 도착하고 있다.

일반적으로 송신자가 같은 ACK 번호를 **3번 중복 수신**하면 해당 세그먼트가 손실되었다고 판단하고 타임아웃을 기다리지 않고 재전송한다.

이를 **빠른 재전송(Fast Retransmit)**이라고 한다.

> 최초의 정상 ACK를 제외하고 동일한 ACK가 추가로 3번 도착하는 것을 보통 3개의 중복 ACK라고 한다.

---

## 7. 중복 세그먼트를 수신한 경우

ACK가 전송 과정에서 손실되면 송신자는 원래 세그먼트가 손실되었다고 판단하여 같은 세그먼트를 다시 보낼 수 있다.

하지만 수신자는 이미 해당 세그먼트를 받은 상태이므로 중복된 세그먼트를 수신하게 된다.

수신자는 순서 번호를 확인하여 다음과 같이 처리한다.

1. 중복된 세그먼트임을 확인한다.
2. 중복 데이터를 다시 응용 프로그램에 전달하지 않는다.
3. 중복된 세그먼트를 폐기한다.
4. 필요한 ACK를 다시 전송한다.

따라서 TCP의 순서 번호는 다음 기능에도 사용된다.

- 데이터 순서 정렬
- 누락된 데이터 확인
- 중복 데이터 확인
- 중복 데이터 제거

---

## 8. 재전송 타이머와 타임아웃

송신 호스트는 세그먼트를 전송하면서 재전송 타이머를 시작한다.

정해진 시간 안에 해당 데이터에 대한 ACK를 받지 못하면 타임아웃이 발생한다.

### 타임아웃 발생 과정

| 단계 | 송신 호스트 A | 방향 | 수신 호스트 B |
|---:|---|---|---|
| 1 | n번째 세그먼트 전송 및 타이머 시작 | A → B | 전송 중 손실 |
| 2 | ACK를 기다림 |  | 세그먼트를 받지 못함 |
| 3 | 타임아웃 발생 |  |  |
| 4 | n번째 세그먼트 재전송 | A → B | 재전송된 세그먼트 수신 |
| 5 | ACK 수신 | A ← B | ACK 전송 |

### 타임아웃이 발생할 수 있는 상황

- 데이터 세그먼트가 손실됨
- ACK 세그먼트가 손실됨
- 네트워크가 혼잡하여 ACK가 늦게 도착함
- 수신 호스트나 중간 장비의 처리가 지연됨

---

## 9. RTO와 RTT

### RTT

RTT는 **Round Trip Time**의 약자이다.

송신자가 메시지를 전송한 시점부터 그에 대한 응답을 받을 때까지 걸린 왕복 시간이다.

`RTT = 데이터 전송 시간 + ACK가 돌아오는 시간`

### RTO

RTO는 **Retransmission Timeout**의 약자이다.

ACK를 얼마 동안 기다린 후 재전송할지를 결정하는 시간이다.

RTO가 너무 짧으면 다음 문제가 발생한다.

- 정상적으로 이동 중인 세그먼트를 불필요하게 재전송
- 중복 세그먼트 증가
- 네트워크 혼잡 증가

RTO가 너무 길면 다음 문제가 발생한다.

- 손실된 세그먼트의 재전송이 늦어짐
- 전체 통신 성능 저하

따라서 TCP는 측정된 RTT를 바탕으로 RTO를 동적으로 조절한다.

---

## 10. ARQ

ARQ는 **Automatic Repeat reQuest**, 즉 자동 재전송 요구를 의미한다.

수신 호스트의 응답과 타임아웃을 이용하여 문제를 확인하고, 문제가 발생한 메시지를 재전송하여 신뢰성을 확보하는 방식이다.

ARQ의 대표적인 방식은 다음과 같다.

1. Stop-and-Wait ARQ
2. Go-Back-N ARQ
3. Selective Repeat ARQ

---

## 11. Stop-and-Wait ARQ

Stop-and-Wait ARQ는 하나의 메시지를 전송한 뒤 ACK를 받을 때까지 다음 메시지를 전송하지 않는 방식이다.

### 동작 과정

`세그먼트 1 전송 → ACK 1 수신 → 세그먼트 2 전송 → ACK 2 수신`

| 송신자 | 방향 | 수신자 |
|---|---|---|
| 세그먼트 1 전송 | → | 세그먼트 1 수신 |
| ACK 대기 | ← | ACK 전송 |
| 세그먼트 2 전송 | → | 세그먼트 2 수신 |
| ACK 대기 | ← | ACK 전송 |

### 장점

- 동작 방식이 단순하다.
- 구현이 쉽다.
- 한 번에 하나만 전송하므로 관리가 쉽다.
- 비교적 높은 신뢰성을 제공한다.

### 단점

- ACK가 도착할 때까지 새로운 데이터를 보낼 수 없다.
- 대기 시간이 길어진다.
- 네트워크 이용 효율이 낮다.
- 전송 성능이 저하될 수 있다.

---

## 12. 파이프라이닝

파이프라이닝(Pipelining)은 각 세그먼트에 대한 ACK가 도착하기 전에도 여러 세그먼트를 연속해서 전송하는 기술이다.

### Stop-and-Wait

`세그먼트 1 → ACK 1 → 세그먼트 2 → ACK 2 → 세그먼트 3`

### 파이프라이닝

`세그먼트 1 → 세그먼트 2 → 세그먼트 3 → ACK 수신`

파이프라이닝을 사용하면 ACK를 기다리는 동안에도 다음 데이터를 전송할 수 있으므로 네트워크 이용 효율을 높일 수 있다.

대표적인 파이프라이닝 기반 ARQ:

- Go-Back-N ARQ
- Selective Repeat ARQ

---

## 13. Go-Back-N ARQ

Go-Back-N ARQ는 여러 세그먼트를 연속해서 전송하다가 오류가 발생하면 손실된 세그먼트부터 그 이후에 전송한 세그먼트를 모두 재전송하는 방식이다.

### 예제

송신자가 다음 세그먼트를 보냈다고 가정한다.

`1 → 2 → 3 → 4 → 5`

이때 세그먼트 3이 손실되었다.

Go-Back-N ARQ는 다음과 같이 재전송한다.

`3 → 4 → 5 재전송`

### 누적 확인 응답

Go-Back-N ARQ는 누적 확인 응답을 사용한다.

누적 확인 응답은 해당 번호 이전까지의 데이터가 모두 정상적으로 수신되었다는 의미이다.

예를 들어 ACK 번호가 4라면 다음과 같은 의미이다.

> 3번까지 정상적으로 받았으며, 다음에는 4번을 받기 원한다.

이를 **Cumulative ACK, 누적 확인 응답**이라고 한다.

### 특징

- ACK 관리가 비교적 단순하다.
- 손실된 세그먼트 이후의 정상 세그먼트도 다시 전송할 수 있다.
- 불필요한 재전송이 발생할 수 있다.

---

## 14. Selective Repeat ARQ

Selective Repeat ARQ는 손실되거나 오류가 발생한 세그먼트만 선택적으로 재전송하는 방식이다.

### 예제

전송한 세그먼트:

`1 → 2 → 3 → 4 → 5`

세그먼트 3만 손실된 경우:

`3만 재전송`

### 특징

- 손실된 세그먼트만 재전송한다.
- Go-Back-N보다 네트워크 이용 효율이 높다.
- 수신자는 순서가 바뀌어 도착한 세그먼트를 보관할 수 있어야 한다.
- 송수신 측의 구현과 관리가 상대적으로 복잡하다.

TCP에서는 기본적으로 누적 ACK를 사용하고, **SACK(Selective Acknowledgment) 옵션**을 이용하면 수신된 데이터 구간을 선택적으로 알릴 수 있다.

오늘날 대부분의 TCP 구현은 SACK 옵션을 지원한다.

---

## 15. ARQ 비교

| 구분 | Stop-and-Wait | Go-Back-N | Selective Repeat |
|---|---|---|---|
| 연속 전송 | 불가능 | 가능 | 가능 |
| 파이프라이닝 | 사용하지 않음 | 사용 | 사용 |
| 오류 발생 시 | 해당 데이터 재전송 | 손실 지점부터 모두 재전송 | 손실된 데이터만 재전송 |
| ACK 방식 | 개별 확인 | 누적 확인 | 선택적 확인 가능 |
| 전송 효율 | 낮음 | 중간 | 높음 |
| 구현 복잡도 | 낮음 | 중간 | 높음 |

# 04-3-2 TCP 흐름 제어

## 16. 흐름 제어란?

흐름 제어(Flow Control)는 송신자가 수신자의 처리 능력을 고려하여 데이터 전송량을 조절하는 기능이다.

송신자가 수신자의 처리 속도보다 빠르게 데이터를 보내면 다음과 같은 문제가 발생할 수 있다.

- 수신 버퍼가 가득 참
- 새로운 데이터를 저장할 공간 부족
- 세그먼트 손실
- 불필요한 재전송
- 전체 통신 성능 저하

따라서 흐름 제어의 목적은 다음과 같다.

> 수신자가 처리할 수 있는 만큼만 데이터를 전송한다.

---

## 17. 흐름 제어의 기준

흐름 제어에서는 수신 호스트의 처리 능력이 중요하다.

| 구분 | 역할 |
|---|---|
| 수신 호스트 | 자신이 추가로 받을 수 있는 데이터양을 알림 |
| 송신 호스트 | 수신자가 알려준 범위 안에서 데이터 전송 |

수신 호스트는 TCP 헤더의 윈도우 필드를 이용하여 수신 윈도우를 송신자에게 알린다.

---

## 18. 수신 윈도우

수신 윈도우(Receive Window, rwnd)는 수신자가 현재 추가로 받을 수 있는 데이터의 양을 의미한다.

수신 호스트가 자신의 TCP 수신 버퍼 상태를 바탕으로 계산한다.

- 수신 버퍼에 공간이 많으면 수신 윈도우가 커진다.
- 수신 버퍼에 공간이 적으면 수신 윈도우가 작아진다.
- 수신 버퍼에 공간이 없으면 수신 윈도우가 0이 될 수 있다.

수신자는 ACK 세그먼트의 TCP 헤더에 수신 윈도우 값을 넣어 송신자에게 전달한다.

---

## 19. 송신 윈도우

송신 윈도우는 송신자가 ACK를 기다리지 않고 연속해서 보낼 수 있는 데이터의 범위를 의미한다.

송신자는 수신자가 알려준 수신 윈도우와 네트워크 혼잡 상태를 고려하여 실제 전송량을 결정한다.

### 기본 관계

`실제 전송 가능 윈도우 = 수신 윈도우와 혼잡 윈도우 중 작은 값`

기호로 나타내면 다음과 같다.

`전송 윈도우 = min(rwnd, cwnd)`

| 값 | 의미 |
|---|---|
| rwnd | 수신자가 처리할 수 있는 데이터양 |
| cwnd | 네트워크 혼잡 없이 보낼 수 있다고 판단한 데이터양 |

아직 ACK를 받지 못한 전송 중 데이터가 있다면 실제로 새로 보낼 수 있는 양은 다음과 같이 생각할 수 있다.

`새로 전송 가능한 양 = min(rwnd, cwnd) - 아직 ACK를 받지 못한 데이터양`

---

## 20. 슬라이딩 윈도우

슬라이딩 윈도우(Sliding Window)는 ACK를 받지 않고도 윈도우 크기만큼 데이터를 연속해서 전송할 수 있게 하는 TCP 흐름 제어 기법이다.

### 윈도우의 의미

윈도우는 다음 범위를 나타낸다.

> 송신자가 현재 ACK를 받지 않고도 연속해서 전송할 수 있는 데이터의 범위

예를 들어 윈도우 크기가 세그먼트 4개라면 송신자는 네 개의 세그먼트를 연속해서 보낼 수 있다.

### 최초 윈도우

| 윈도우 내부 | 윈도우 외부 |
|---|---|
| 세그먼트 1, 2, 3, 4 | 세그먼트 5, 6, 7, 8, 9, 10 |

송신자는 세그먼트 1~4를 ACK 없이 연속해서 전송할 수 있다.

### 세그먼트 1의 ACK를 받은 경우

세그먼트 1에 대한 ACK를 받으면 윈도우가 오른쪽으로 이동한다.

| ACK 완료 | 새로운 윈도우 | 아직 전송 불가 |
|---|---|---|
| 세그먼트 1 | 세그먼트 2, 3, 4, 5 | 세그먼트 6 이후 |

이제 세그먼트 5를 추가로 전송할 수 있다.

### 세그먼트 2의 ACK도 받은 경우

| ACK 완료 | 새로운 윈도우 | 아직 전송 불가 |
|---|---|---|
| 세그먼트 1, 2 | 세그먼트 3, 4, 5, 6 | 세그먼트 7 이후 |

이처럼 ACK가 도착할 때마다 전송 가능한 범위가 오른쪽으로 움직인다.

이를 창문이 옆으로 미끄러지는 모습에 비유하여 슬라이딩 윈도우라고 한다.

---

## 21. 슬라이딩 윈도우의 실제 단위

슬라이딩 윈도우 그림에서는 이해하기 쉽게 세그먼트 개수로 표현하기도 하지만, TCP의 윈도우는 기본적으로 **바이트 단위**로 관리된다.

예를 들어 수신 윈도우가 4000바이트라면 송신자는 수신자의 처리 능력 측면에서 최대 4000바이트 범위까지 ACK 없이 전송할 수 있다.

> TCP의 순서 번호, ACK 번호, 윈도우는 기본적으로 바이트를 기준으로 이해해야 한다.

---

## 22. 윈도우 크기가 0인 경우

수신 버퍼가 가득 차면 수신자는 윈도우 크기를 0으로 알릴 수 있다.

이를 **제로 윈도우(Zero Window)**라고 한다.

송신자는 수신 윈도우가 0이면 일반 데이터 전송을 멈추고 수신 버퍼에 공간이 생기기를 기다린다.

이후 수신자는 버퍼에 공간이 생기면 새로운 윈도우 크기를 알린다.

송신자는 윈도우가 다시 열렸는지 확인하기 위해 작은 탐색 세그먼트를 전송할 수 있다.

---

## 23. Stop-and-Wait와 흐름 제어

Stop-and-Wait 방식에서는 하나의 세그먼트를 보내고 ACK를 받은 후 다음 세그먼트를 전송한다.

따라서 한 번에 많은 데이터를 보내 수신자를 압도할 가능성이 작다.

반면 파이프라이닝 방식에서는 여러 세그먼트를 한꺼번에 전송할 수 있으므로 수신자의 처리 능력을 반드시 고려해야 한다.

| 전송 방식 | 별도의 흐름 제어 필요성 |
|---|---|
| Stop-and-Wait | 상대적으로 낮음 |
| Go-Back-N | 필요 |
| Selective Repeat | 필요 |
| TCP 슬라이딩 윈도우 | 수신 윈도우를 이용하여 흐름 제어 |

---

# 04-3-3 TCP 혼잡 제어

## 24. 혼잡이란?

혼잡(Congestion)은 네트워크에 지나치게 많은 트래픽이 몰려 패킷의 처리 속도가 느려지거나 패킷이 손실될 가능성이 커진 상태이다.

### 혼잡 발생 시 나타날 수 있는 현상

- 라우터의 대기 큐 증가
- 패킷 지연 증가
- 패킷 손실
- 타임아웃 발생
- 재전송 증가
- 네트워크 성능 저하

재전송이 지나치게 증가하면 트래픽이 더 늘어나 혼잡이 더욱 심해질 수 있다.

---

## 25. 혼잡 제어란?

혼잡 제어(Congestion Control)는 송신자가 네트워크의 혼잡 정도에 맞춰 전송량을 조절하는 기능이다.

### 흐름 제어와 혼잡 제어 비교

| 구분 | 흐름 제어 | 혼잡 제어 |
|---|---|---|
| 보호 대상 | 수신 호스트 | 네트워크 |
| 주요 문제 | 수신자가 처리하지 못함 | 네트워크에 트래픽이 몰림 |
| 주요 기준 | 수신 윈도우 | 혼잡 윈도우 |
| 윈도우 기호 | rwnd | cwnd |
| 계산 주체 | 수신 호스트 | 송신 호스트 |
| 목적 | 수신자의 처리 능력에 맞춤 | 네트워크 혼잡도에 맞춤 |

> 흐름 제어는 수신자가 감당할 수 있는지를 확인하고, 혼잡 제어는 네트워크가 감당할 수 있는지를 확인한다.

---

## 26. 혼잡 윈도우

혼잡 윈도우(Congestion Window, cwnd)는 송신자가 네트워크에 혼잡을 발생시키지 않고 전송할 수 있다고 판단한 데이터의 양이다.

- 혼잡 윈도우가 크면 한 번에 많은 데이터를 전송할 수 있다.
- 혼잡 윈도우가 작으면 한 번에 적은 데이터를 전송한다.
- 혼잡 윈도우는 송신자가 계산하고 관리한다.
- 수신자가 TCP 헤더로 직접 알려주는 값이 아니다.

### 수신 윈도우와 혼잡 윈도우

| 윈도우 | 결정 주체 | 의미 |
|---|---|---|
| 수신 윈도우 rwnd | 수신 호스트 | 수신자가 추가로 처리할 수 있는 데이터양 |
| 혼잡 윈도우 cwnd | 송신 호스트 | 네트워크가 혼잡 없이 처리할 수 있다고 추정한 데이터양 |

송신자는 두 값 중 작은 범위까지만 전송한다.

`실제 전송량 = min(rwnd, cwnd)`

### 예제

| 수신 윈도우 | 혼잡 윈도우 | 실제 최대 전송 윈도우 |
|---:|---:|---:|
| 8000바이트 | 4000바이트 | 4000바이트 |
| 3000바이트 | 7000바이트 | 3000바이트 |
| 6000바이트 | 6000바이트 | 6000바이트 |

---

## 27. 혼잡을 판단하는 대표적인 신호

TCP는 일반적으로 다음 상황을 네트워크 혼잡의 신호로 판단할 수 있다.

- 타임아웃 발생
- 중복 ACK 반복 수신
- ECN을 통한 명시적 혼잡 알림

### 타임아웃

ACK가 정해진 시간 안에 도착하지 않은 상황이다.

비교적 심한 혼잡이나 패킷 손실로 판단하여 전송량을 크게 줄일 수 있다.

### 중복 ACK

일부 세그먼트가 손실되었지만 그 이후의 세그먼트는 도착하고 있는 상황일 수 있다.

타임아웃보다는 네트워크가 여전히 일부 데이터를 전달하고 있다는 신호로 볼 수 있다.

---

## 28. AIMD

AIMD는 **Additive Increase/Multiplicative Decrease**의 약자이다.

우리말로는 **합 증가·곱 감소**라고 할 수 있다.

### 동작 방식

- 혼잡이 감지되지 않으면 혼잡 윈도우를 조금씩 증가시킨다.
- 혼잡이 감지되면 혼잡 윈도우를 큰 폭으로 감소시킨다.

대표적인 형태:

- 증가: RTT마다 혼잡 윈도우를 선형적으로 증가
- 감소: 혼잡 발생 시 혼잡 윈도우를 절반 정도로 감소

### 예제

혼잡이 발생하지 않는 동안:

`4 → 5 → 6 → 7 → 8`

혼잡이 발생하면:

`8 → 4`

다시 혼잡이 없다면:

`4 → 5 → 6 → 7`

### AIMD의 목적

- 네트워크에 여유가 있으면 전송량을 서서히 늘린다.
- 혼잡이 발생하면 전송량을 빠르게 줄인다.
- 여러 TCP 연결이 네트워크 대역폭을 비교적 공정하게 나눠 사용하도록 돕는다.

---

## 29. 느린 시작

느린 시작(Slow Start)은 TCP 통신 초기에 혼잡 윈도우를 작은 값에서 시작하여 빠르게 증가시키는 알고리즘이다.

전통적인 설명에서는 혼잡 윈도우를 1 MSS부터 시작한다고 배우지만, 실제 초기 혼잡 윈도우 값은 TCP 구현과 표준에 따라 여러 MSS가 될 수 있다.

### 동작 방식

- 혼잡 윈도우를 작은 값으로 시작한다.
- 정상적인 ACK를 받을 때마다 혼잡 윈도우를 증가시킨다.
- 결과적으로 약 한 RTT마다 혼잡 윈도우가 2배로 증가한다.

### 예제

초기 혼잡 윈도우를 1 MSS라고 가정한다.

| RTT | 혼잡 윈도우 | 전송 가능한 세그먼트 수 |
|---:|---:|---:|
| 시작 | 1 MSS | 1개 |
| 1 RTT 후 | 2 MSS | 2개 |
| 2 RTT 후 | 4 MSS | 4개 |
| 3 RTT 후 | 8 MSS | 8개 |
| 4 RTT 후 | 16 MSS | 16개 |

증가 흐름:

`1 → 2 → 4 → 8 → 16`

이를 **지수적 증가**라고 한다.

### 이름과 실제 동작

이름은 느린 시작이지만 혼잡 윈도우는 RTT마다 약 2배로 증가하므로 실제 증가 속도는 빠르다.

느린 시작이라는 이름은 처음부터 네트워크 용량 전체를 사용하는 대신 작은 값에서 시작한다는 의미에 가깝다.

---

## 30. 느린 시작 임계치

느린 시작 임계치를 **ssthresh(Slow Start Threshold)**라고 한다.

TCP는 일반적으로 혼잡 윈도우가 ssthresh에 도달하기 전까지 느린 시작을 사용한다.

- `cwnd < ssthresh`: 느린 시작
- `cwnd ≥ ssthresh`: 혼잡 회피

| 구간 | 혼잡 윈도우 증가 방식 |
|---|---|
| 느린 시작 | 지수적으로 증가 |
| 혼잡 회피 | 선형적으로 증가 |

---

## 31. 혼잡 회피

혼잡 회피(Congestion Avoidance)는 혼잡 윈도우가 임계치에 도달한 후 증가 속도를 낮추는 단계이다.

느린 시작에서는 혼잡 윈도우가 RTT마다 약 2배로 증가하지만, 혼잡 회피 단계에서는 일반적으로 RTT마다 약 1 MSS씩 증가한다.

### 예제

느린 시작:

`1 → 2 → 4 → 8`

ssthresh가 8이라고 가정하면 이후 혼잡 회피:

`8 → 9 → 10 → 11 → 12`

| 알고리즘 | 증가 방식 |
|---|---|
| 느린 시작 | 지수적 증가 |
| 혼잡 회피 | 선형적 증가 |

---

## 32. 빠른 재전송

빠른 재전송(Fast Retransmit)은 일반적으로 동일한 ACK가 3번 중복 수신되면 타임아웃을 기다리지 않고 누락된 세그먼트를 재전송하는 기능이다.

### 동작 과정

1. 특정 세그먼트가 손실된다.
2. 이후의 세그먼트가 수신자에게 도착한다.
3. 수신자는 누락된 세그먼트를 요구하는 동일한 ACK를 반복 전송한다.
4. 송신자는 3개의 중복 ACK를 수신한다.
5. 송신자는 타임아웃 전에 누락된 세그먼트를 재전송한다.

### 장점

- 타임아웃까지 기다리지 않는다.
- 손실된 세그먼트를 빠르게 복구한다.
- 전송 지연을 줄일 수 있다.

---

## 33. 빠른 회복

빠른 회복(Fast Recovery)은 중복 ACK로 손실을 감지했을 때 혼잡 윈도우를 완전히 처음부터 시작하지 않고 줄어든 값에서 전송을 회복하는 방식이다.

일반적인 개념:

- 타임아웃: 비교적 심한 혼잡으로 판단
- 중복 ACK: 네트워크가 일부 데이터를 계속 전달하고 있다고 판단

따라서 타임아웃이 발생했을 때보다 중복 ACK가 발생했을 때 혼잡 윈도우를 덜 크게 줄이는 방식이 사용될 수 있다.

정확한 동작은 TCP Tahoe, TCP Reno, TCP CUBIC 등 혼잡 제어 알고리즘에 따라 달라질 수 있다.

---

## 34. 혼잡 상황에 따른 동작 비교

| 상황 | 의미 | 대표적인 TCP 동작 |
|---|---|---|
| ACK 정상 수신 | 네트워크가 데이터를 처리 중 | 혼잡 윈도우 증가 |
| 3개의 중복 ACK | 일부 세그먼트 손실 가능성 | 빠른 재전송 |
| 타임아웃 | 심한 지연 또는 손실 가능성 | 재전송 및 전송량 큰 폭 감소 |
| 수신 윈도우 감소 | 수신 버퍼 부족 | 송신량 감소 |
| 수신 윈도우 0 | 수신 불가능 | 일반 데이터 전송 일시 중지 |

---

## 35. 전체 동작 예제

다음과 같이 가정한다.

- 수신 윈도우: 8 MSS
- 혼잡 윈도우: 4 MSS
- 아직 ACK를 받지 못한 데이터: 1 MSS

### 전송 윈도우 계산

`min(8 MSS, 4 MSS)=4 MSS`

현재 ACK를 받지 못한 데이터가 1 MSS이므로 새로 전송할 수 있는 양:

`4 MSS-1 MSS=3 MSS`

따라서 송신자는 현재 추가로 최대 3 MSS를 전송할 수 있다.

### 수신 윈도우가 줄어든 경우

- 수신 윈도우: 2 MSS
- 혼잡 윈도우: 4 MSS

`min(2 MSS, 4 MSS)=2 MSS`

수신자의 처리 능력이 더 작으므로 최대 전송 범위는 2 MSS가 된다.

### 혼잡 윈도우가 줄어든 경우

- 수신 윈도우: 8 MSS
- 혼잡 윈도우: 2 MSS

`min(8 MSS, 2 MSS)=2 MSS`

수신자는 더 받을 수 있지만 네트워크 혼잡을 고려하여 2 MSS까지만 전송한다.

# 정보처리기사 핵심 정리

1. TCP는 오류 제어, 흐름 제어, 혼잡 제어를 제공한다.
2. 오류 제어는 데이터가 정상적으로 전달되었는지를 확인한다.
3. 흐름 제어는 수신자의 처리 능력을 고려한다.
4. 혼잡 제어는 네트워크의 혼잡 정도를 고려한다.
5. TCP 체크섬은 TCP 세그먼트의 오류를 검출한다.
6. TCP는 중복 ACK 또는 타임아웃을 바탕으로 세그먼트를 재전송할 수 있다.
7. 동일한 ACK를 3번 중복 수신하면 빠른 재전송을 수행할 수 있다.
8. 재전송 타이머가 만료될 때까지 ACK를 받지 못하면 타임아웃이 발생한다.
9. RTT는 메시지를 보내고 응답을 받기까지의 왕복 시간이다.
10. RTO는 재전송을 시작하기 전 ACK를 기다리는 시간이다.
11. ARQ는 수신자의 응답과 타임아웃을 이용한 자동 재전송 방식이다.
12. Stop-and-Wait는 ACK를 받아야 다음 데이터를 전송한다.
13. 파이프라이닝은 ACK를 받기 전에도 여러 데이터를 연속해서 전송한다.
14. Go-Back-N은 손실 지점부터 이후 세그먼트를 모두 재전송한다.
15. Selective Repeat는 손실된 세그먼트만 선택적으로 재전송한다.
16. TCP는 기본적으로 누적 ACK를 사용하며 SACK 옵션을 지원할 수 있다.
17. 슬라이딩 윈도우는 윈도우 크기만큼 ACK 없이 연속 전송하는 기법이다.
18. ACK를 받으면 윈도우가 오른쪽으로 이동한다.
19. TCP의 윈도우는 기본적으로 바이트 단위이다.
20. 수신 윈도우는 수신자가 추가로 처리할 수 있는 데이터양이다.
21. 혼잡 윈도우는 송신자가 네트워크 상태를 바탕으로 계산한다.
22. 실제 전송 윈도우는 수신 윈도우와 혼잡 윈도우 중 작은 값이다.
23. 흐름 제어는 수신자를 보호하고 혼잡 제어는 네트워크를 보호한다.
24. AIMD는 혼잡이 없으면 선형적으로 증가하고 혼잡이 발생하면 큰 폭으로 감소한다.
25. 느린 시작은 혼잡 윈도우를 작은 값에서 시작해 RTT마다 약 2배로 증가시킨다.
26. 혼잡 회피에서는 혼잡 윈도우를 선형적으로 증가시킨다.
27. ssthresh는 느린 시작과 혼잡 회피를 구분하는 임계치이다.
28. 빠른 재전송은 타임아웃 전에 손실된 세그먼트를 재전송한다.
29. 빠른 회복은 중복 ACK 발생 후 전송 속도를 회복하는 방식이다.
30. 실제 혼잡 제어 동작은 TCP 구현 알고리즘에 따라 달라질 수 있다.

# 핵심 암기 문장

> 오류 제어는 ACK와 재전송, 흐름 제어는 수신 윈도우, 혼잡 제어는 혼잡 윈도우를 사용한다.

> 중복 ACK는 특정 데이터가 누락되었음을 의미할 수 있고, 타임아웃은 정해진 시간 안에 ACK를 받지 못한 상황이다.

> Stop-and-Wait는 하나씩 보내고, Go-Back-N은 손실 지점부터 다시 보내며, Selective Repeat는 손실된 것만 다시 보낸다.

> 슬라이딩 윈도우는 ACK를 기다리지 않고 윈도우 크기만큼 연속 전송하고, ACK를 받으면 오른쪽으로 이동한다.

> 실제 전송 가능량은 수신 윈도우와 혼잡 윈도우 중 작은 값으로 결정한다.

> 느린 시작은 지수적 증가, 혼잡 회피는 선형적 증가, 혼잡 감지 시에는 전송량을 감소시킨다.
