# 자바 실행 구조와 기초 문법

## 금일 학습 요약
JDK 설치 디렉터리의 역할과 Java API, 모듈 구조를 살펴보고, 운영체제 메모리와 JVM 메모리 영역의 관계를 통해 자바의 플랫폼 독립성과 크로스 플랫폼 실행 원리를 정리합니다. 또한 Oracle JDK와 OpenJDK의 차이, LTS와 라이선스, 지원 정책을 비교합니다.

인텔리J 프로젝트의 SDK, 모듈, 소스 루트, 컴파일 출력 경로를 설정하는 방법을 다루고, 클래스, 패키지, 메서드, 지역 변수, 전역 변수의 실행 흐름을 확인합니다. 이어서 기본형과 참조형, 형 변환, 래퍼 클래스, 표준 입출력, 지역 변수 타입 추론, 연산자의 기초 동작을 코드로 검증합니다.

## JDK 설치 구조와 모듈

> JDK는 실행 파일, 설정 파일, 네이티브 연동 헤더, 모듈, 라이브러리 및 라이선스 정보로 구성되며, 각 디렉터리는 자바 컴파일과 실행 환경을 분담합니다.

JDK 설치 경로에는 자바 개발과 실행에 필요한 파일이 역할별로 분리되어 있습니다. 설치 후 디렉터리 구조를 직접 확인하면 컴파일러, JVM 설정, 운영체제 연동 요소, 표준 API가 어떤 위치에서 관리되는지 파악할 수 있습니다.

| 디렉터리 또는 파일 | 주요 역할 | 확인 관점 |
|---|---|---|
| `bin` | `javac`, `java` 등 컴파일, 실행 명령어를 제공합니다. | 자바 소스 컴파일과 클래스 실행의 시작점입니다. |
| `conf` | JDK 및 JVM 실행 환경의 설정 파일을 포함합니다. | 런타임 동작과 환경 설정이 관리됩니다. |
| `include` | JNI 및 운영체제 네이티브 코드 연동용 헤더 파일을 제공합니다. | OS 데이터 타입과 자바 타입의 연결을 지원합니다. |
| `jmods` | 표준 API를 모듈 단위로 압축하여 포함합니다. | `java.base` 등의 모듈이 클래스와 패키지를 묶습니다. |
| `lib`, `legal` | 실행 라이브러리와 라이선스, 저작권 정보를 제공합니다. | 라이브러리는 실행에 필요하고, 라이선스는 배포 시 검토 대상입니다. |

`bin`의 실행 명령어는 `lib`의 내부 라이브러리와 JVM 설정을 참조하여 동작합니다. 따라서 실행 파일만 존재하거나 라이브러리만 존재하는 구성으로는 정상적인 자바 실행 환경이 완성되지 않습니다.

JDK 9부터는 클래스와 패키지가 크게 증가한 표준 라이브러리를 더 체계적으로 관리하기 위해 모듈 시스템이 도입되었습니다. 모듈은 여러 패키지를 상위 범주로 묶어 의존성과 공개 범위를 관리하는 단위입니다.

### 핵심 키워드
`JDK` `bin` `include` `jmods` `java.base`

## JVM과 플랫폼 독립성

> JVM은 자바 프로그램 실행 시 운영체제가 제공한 메모리 공간에 생성되며, 클래스 로딩, 실행, 메모리 관리, 객체 회수를 담당합니다.

일반 프로그램은 운영체제 환경에 맞는 실행 파일과 메모리 구조에 의존하는 경우가 많습니다. 반면 자바는 소스 코드를 바이트코드인 `.class` 파일로 컴파일하고, 각 운영체제에 설치된 JVM이 이를 해석하거나 실행합니다.

자바의 실행 흐름은 소스 코드 작성, `javac` 컴파일, 클래스 파일 생성, `java` 명령을 통한 JVM 로딩과 클래스 실행으로 이어집니다. JVM은 프로그램 종료 이후 사용이 끝난 메모리를 정리합니다.

```text
.java 소스 파일 → javac 컴파일 → .class 바이트코드 → JVM 로딩 및 실행
```

운영체제의 메모리 맵은 일반적으로 코드 영역, 데이터 영역, 정적 영역, 힙 영역, 스택 영역으로 설명할 수 있습니다. 자바 JVM도 실행 과정에서 유사한 목적의 메모리 영역을 구성하며, 특히 스택과 힙의 특성을 구분하는 것이 중요합니다.

| 영역 | 저장 또는 관리 대상 | 특성 |
|---|---|---|
| 코드 영역 | 컴파일된 실행 코드와 클래스 관련 정보입니다. | 실행할 명령을 관리합니다. |
| 정적 영역 | `static` 데이터와 클래스 수준 정보를 관리합니다. | 선언과 함께 주소가 확보되는 정적 성격을 가집니다. |
| 스택 영역 | 메서드 호출, 매개변수, 지역 변수를 관리합니다. | 호출이 끝나면 관련 지역 데이터가 제거됩니다. |
| 힙 영역 | `new`로 생성한 객체와 동적 데이터를 관리합니다. | 객체 생명주기와 가비지 컬렉션의 대상입니다. |

플랫폼 독립성이란 자바 프로그램이 특정 운영체제용 실행 파일에 직접 종속되지 않고, JVM을 통해 실행된다는 의미입니다. Windows, macOS, Linux 등에서 JVM이 제공되면 동일한 바이트코드를 실행할 수 있으므로 크로스 플랫폼 지원이 가능합니다.

### 핵심 키워드
`JVM` `바이트코드` `플랫폼 독립성` `크로스 플랫폼` `메모리 맵`

## 힙과 가비지 컬렉션

> 힙은 객체가 동적으로 생성되는 메모리 영역이며, 가비지 컬렉터는 더 이상 사용되지 않는 객체를 식별하고 회수합니다.

스택은 메서드 호출에 따라 생성되고 종료되는 고정적인 호출 영역입니다. 반면 힙은 객체 생성과 사용량 변화에 대응하는 동적 메모리 영역으로, 프로그램 실행 중 객체가 생성되는 주요 공간입니다.

객체를 `new`로 생성하면 객체 본체는 힙에 생성되고, 객체를 가리키는 참조값은 변수의 위치에 저장됩니다. 지역 참조 변수는 대체로 스택 프레임에서 관리되며, 객체가 더 이상 참조되지 않으면 가비지 컬렉션 대상이 됩니다.

가비지 컬렉션은 객체를 즉시 완전 삭제하는 단순 동작이 아니라, 객체 생명주기와 메모리 세대별 상태를 고려하여 회수합니다. 객체 생성 직후의 영역과 오래 유지된 객체 영역을 구분하는 개념이 대표적입니다.

- `Eden` 영역은 새로 생성된 객체가 우선 배치되는 영역입니다.
- `Old` 영역은 장기간 생존한 객체가 관리되는 영역입니다.
- 가비지 컬렉터는 참조되지 않는 객체를 찾아 메모리 회수 후보로 처리합니다.
- 프로그램 종료 시 JVM 자체의 실행 메모리도 운영체제에 반환됩니다.

메모리 누수는 더 이상 필요하지 않은 객체가 참조를 유지하여 회수되지 못하는 상황과 관련됩니다. 서버처럼 장시간 실행되고 동시 요청이 많은 환경에서는 힙 사용량과 가비지 컬렉션 동작을 관찰하는 것이 성능 관리의 핵심이 됩니다.

### 핵심 키워드
`힙` `스택` `Eden` `Old 영역` `가비지 컬렉션`

## JDK 버전과 배포 정책

> Oracle JDK와 OpenJDK는 공통 기반을 공유하지만, 라이선스, 기술 지원, 업데이트 정책, 벤더별 확장 방식에서 차이가 있습니다.

자바는 버전별로 언어 기능과 런타임 구조가 확장되어 왔습니다. 특히 Java 8은 람다와 제네릭 활용이 보편화된 주요 버전이며, Java 9부터 모듈 시스템이 도입되었습니다. Java 21과 Java 25는 현대 자바 개발에서 주요 LTS 선택지로 사용됩니다.

| 구분 | 특징 | 선택 시 고려 사항 |
|---|---|---|
| Java 8 | 기존 엔터프라이즈 시스템에서 널리 사용되는 기반 버전입니다. | 레거시 환경과 라이브러리 호환성을 확인해야 합니다. |
| Java 9 이상 | 모듈 시스템과 확장된 플랫폼 구조를 제공합니다. | `jmods` 기반의 모듈 구성을 이해해야 합니다. |
| Java 21 | 장기 지원 기반의 현대 자바 기능을 제공합니다. | 가상 스레드 등 최신 기능의 적용 여부를 검토합니다. |
| Java 25 | 최신 장기 지원 버전으로 런타임과 가비지 컬렉션 기능이 강화됩니다. | 장기 운영 환경과 지원 정책을 함께 검토합니다. |

Oracle JDK는 Oracle의 라이선스와 상용 기술 지원 정책을 따릅니다. OpenJDK는 공개된 자바 기반을 바탕으로 벤더와 커뮤니티가 확장할 수 있으며, Amazon Corretto, Eclipse Temurin, Azul Zulu 등 다양한 배포판이 존재합니다.

JDK 선택 시에는 단순히 버전만 확인해서는 부족합니다. 상용 배포 여부, 라이선스 조건, LTS 지원 기간, 운영체제와 클라우드 환경, 보안 업데이트 정책, 벤더의 기술 지원 범위를 함께 검토해야 합니다.

### 핵심 키워드
`Oracle JDK` `OpenJDK` `LTS` `Java 21` `Java 25`

## 인텔리J 프로젝트 구조

> 인텔리J의 자바 프로젝트는 SDK, 모듈, 소스 루트, 출력 경로가 모두 연결되어야 소스 인식과 컴파일 결과 생성이 정상적으로 이루어집니다.

인텔리J에서 프로젝트 이름은 작업 단위를 식별하는 최상위 설정입니다. 프로젝트 SDK는 어떤 JDK를 사용하여 컴파일하고 실행할지를 지정하며, Language Level은 사용할 자바 문법 수준을 결정합니다.

모듈은 프로젝트 내부의 실제 컴파일 단위입니다. 프로젝트에 SDK를 지정했더라도 모듈에 SDK와 언어 수준이 연결되지 않으면 라이브러리 인식, 컴파일, 실행 구성이 불완전할 수 있습니다.

- `src` 디렉터리는 소스 루트로 지정하여 자바 소스 파일 위치로 인식해야 합니다.
- `out` 디렉터리는 컴파일된 `.class` 파일이 생성되는 출력 경로로 지정할 수 있습니다.
- 외부 라이브러리 목록에는 연결된 JDK의 표준 모듈과 클래스가 표시됩니다.
- 프로젝트와 모듈의 SDK 설정은 서로 일치하는지 함께 확인해야 합니다.

워크스페이스와 프로젝트 경로는 영문 및 공백 없는 이름을 권장합니다. 경로에 공백이나 비ASCII 문자가 포함되면 명령행 도구, 빌드 도구, 라이브러리 경로 처리 과정에서 예상하지 못한 오류가 발생할 수 있습니다.

인텔리J는 `.idea` 디렉터리와 `.iml` 파일 등에 프로젝트 설정을 XML 형식으로 저장합니다. 이러한 설정 파일에는 모듈 경로, SDK 연결 정보, 출력 디렉터리 등 IDE가 프로젝트를 인식하기 위한 메타데이터가 포함됩니다.

### 핵심 키워드
`IntelliJ IDEA` `SDK` `모듈` `src` `out`

## 클래스와 변수 생명주기

> 클래스는 필드와 메서드를 포함하는 사용자 정의 자료형이며, 지역 변수는 메서드 실행 범위에서만 생성, 사용, 소멸합니다.

패키지는 관련 있는 클래스를 묶는 논리적 단위이며, 패키지 선언은 자바 파일의 첫 줄에 위치해야 합니다. 공개 클래스의 이름과 파일 이름은 대소문자까지 일치해야 합니다.

```java
package type01.example;

public class Sample {
    public static void main(String[] args) {
        System.out.println("실행");
    }
}
```

클래스 내부에는 필드, 생성자, 메서드, 중첩 클래스 등의 멤버를 선언할 수 있습니다. `main` 메서드는 자바 애플리케이션의 진입점이며, JVM은 이 메서드부터 실행 흐름을 시작합니다.

지역 변수는 메서드 내부에 선언하는 변수입니다. 지역 변수는 메서드가 호출될 때 생성되고 메서드 실행이 끝나면 소멸하며, 외부 메서드나 다른 클래스에서 직접 접근할 수 없습니다.

- 지역 변수는 사용 전에 반드시 초기화되어야 합니다.
- 지역 변수의 값 변경은 기존 저장 공간에 새 값을 덮어쓰는 재대입입니다.
- 메서드 내부에서 선언한 지역 변수는 해당 메서드 범위에서만 유효합니다.
- 메서드 호출이 반복되면 지역 변수용 스택 프레임도 호출마다 새롭게 구성됩니다.

클래스 내부의 필드는 전역 변수 또는 멤버 변수로 볼 수 있습니다. 기본형 필드는 명시적 초기화가 없어도 기본값을 가지지만, 지역 변수는 초기화하지 않은 상태에서 값을 읽을 수 없습니다.

`static` 멤버는 클래스 수준에서 관리되어 객체 생성 없이 클래스 이름으로 접근할 수 있습니다. 반면 일반 인스턴스 멤버는 객체 생성 후 참조를 통해 접근해야 합니다.

### 핵심 키워드
`패키지` `지역 변수` `전역 변수` `static` `메서드 호출`

## 자료형과 형 변환

> 자바 자료형은 값 자체를 저장하는 기본형과 객체 주소를 저장하는 참조형으로 나뉘며, 타입 크기에 따라 묵시적 또는 명시적 형 변환이 발생합니다.

기본형은 논리형, 문자형, 정수형, 실수형으로 구성됩니다. 참조형은 배열, 클래스, 문자열 객체 등 객체의 주소를 저장하는 타입입니다. `String`은 클래스이므로 참조형이지만 리터럴 형태로 편리하게 사용할 수 있습니다.

| 분류 | 주요 타입 | 크기 또는 특성 |
|---|---|---|
| 정수형 | `byte`, `short`, `int`, `long` | 각각 1, 2, 4, 8바이트를 사용합니다. |
| 실수형 | `float`, `double` | 각각 4, 8바이트를 사용합니다. |
| 논리, 문자형 | `boolean`, `char` | 논리값과 유니코드 문자 값을 표현합니다. |
| 참조형 | 배열, 클래스, `String` | 객체가 저장된 메모리 위치를 참조합니다. |

작은 범위의 타입에서 큰 범위의 타입으로 변환하는 과정은 프로모션 또는 업캐스팅입니다. 예를 들어 `byte` 값을 `int` 변수에 대입하는 경우 값 표현 범위가 넓어지므로 일반적으로 자동 변환이 가능합니다.

큰 범위의 타입을 작은 범위로 변환하는 과정은 디모션 또는 다운캐스팅입니다. 데이터 손실 가능성이 있으므로 개발자가 변환 의도를 명시해야 합니다.

```java
byte small = 10;
int promoted = small;

int number = 100;
byte demoted = (byte) number;
```

래퍼 클래스는 기본형 값을 객체로 다룰 수 있게 하는 클래스입니다. `int`에는 `Integer`, `double`에는 `Double`, `boolean`에는 `Boolean` 등이 대응합니다. 기본형을 래퍼 객체로 바꾸는 과정을 박싱, 반대 과정을 언박싱이라고 합니다.

### 핵심 키워드
`기본형` `참조형` `프로모션` `디모션` `래퍼 클래스`

## 표준 입출력과 연산자

> 표준 출력은 `System.out`, 표준 입력은 `System.in`을 기반으로 하며, 연산자는 우선순위와 전위, 후위 실행 시점에 따라 결과가 달라집니다.

`System.out.print()`는 줄 바꿈 없이 출력하고, `System.out.println()`은 출력 후 줄을 바꿉니다. `printf()`는 서식 지정자를 사용하여 숫자 폭, 정렬, 소수점 자릿수 등을 제어할 수 있습니다.

```java
String name = "동훈";
double pi = 3.141592;

System.out.printf("이름: %s%n원주율: %.2f%n", name, pi);
```

이스케이프 시퀀스는 문자열에서 특수 동작을 표현합니다. `\n`은 줄 바꿈, `\t`는 탭 공백을 의미합니다. 서식 지정자와 문자열 처리 기능은 Java API 문서의 `Formatter`, `String.format()` 설명에서 확인할 수 있습니다.

키보드 입력은 `Scanner`와 `System.in` 조합으로 처리할 수 있습니다. Java 25에서는 `IO.readln()`과 `IO.println()`처럼 표준 입출력을 간소화한 API도 사용할 수 있습니다.

```java
Scanner scanner = new Scanner(System.in);
String input = scanner.nextLine();
System.out.println(input);
```

`var`는 지역 변수 타입 추론 기능입니다. 선언과 동시에 초기화해야 하며, 컴파일 시 초기값의 타입이 결정됩니다. `var` 자체는 동적 타입이 아니므로 초기화 뒤에 다른 타입의 값을 대입할 수 없습니다.

- 산술 연산자는 덧셈, 뺄셈, 곱셈, 나눗셈, 나머지 계산에 사용됩니다.
- 증감 연산자는 전위형과 후위형에 따라 값 증가와 반환의 순서가 달라집니다.
- 논리 부정 연산자 `!`는 `true`와 `false`를 반전합니다.
- 시프트 연산자는 비트를 좌우로 이동하며 정수 연산과 메모리 표현을 이해하는 데 사용됩니다.

괄호는 연산자 우선순위를 명시적으로 변경합니다. 또한 `++value`는 값을 먼저 변경한 뒤 사용하고, `value++`는 현재 값을 먼저 사용한 뒤 증가시키므로 복합 수식에서는 실행 순서를 단계적으로 추적해야 합니다.

### 핵심 키워드
`System.out` `Scanner` `var` `증감 연산자` `시프트 연산자`
