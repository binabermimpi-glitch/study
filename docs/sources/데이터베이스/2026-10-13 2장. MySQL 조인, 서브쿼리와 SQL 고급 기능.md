# 2장. MySQL 조인, 서브쿼리와 SQL 고급 기능

## 1. EMP와 DEPT 테이블 구조

SQL의 JOIN과 서브쿼리를 이해하기 위해 EMP와 DEPT 테이블의 관계를 살펴본다.

### 1-1. EMP 테이블

| 컬럼 | 의미 |
|---|---|
| EMPNO | 사원 번호 |
| ENAME | 사원 이름 |
| JOB | 직무 |
| MGR | 관리자 사원 번호 |
| HIREDATE | 입사일 |
| SAL | 급여 |
| COMM | 커미션 |
| DEPTNO | 부서 번호 |

### 1-2. DEPT 테이블

| 컬럼 | 의미 |
|---|---|
| DEPTNO | 부서 번호 |
| DNAME | 부서명 |
| LOC | 근무 지역 |

EMP.DEPTNO와 DEPT.DEPTNO를 통해 사원과 부서를 연결할 수 있다.

또한 EMP.MGR은 같은 EMP 테이블의 EMPNO를 참조하는 자기참조 관계를 표현한다.

예를 들어 MGR이 7902라면, EMPNO가 7902인 사원이 해당 직원의 관리자라는 의미다.

최고 관리자는 상사가 없으므로 MGR이 NULL일 수 있다.

## 2. NULL의 의미와 처리

NULL은 값이 존재하지 않거나 알려지지 않았음을 나타내는 특별한 표시다.

NULL은 다음 값들과 다르다.

- 숫자 0
- 빈 문자열 ''
- 공백 문자 ' '

예를 들어 커미션이 0인 것과 NULL인 것은 다른 의미를 가질 수 있다.

### 2-1. IS NULL

```sql
SELECT ename, comm
FROM emp
WHERE comm IS NULL;
```

커미션이 NULL인 사원을 조회한다.

NULL을 검사할 때는 일반적인 `=` 비교 대신 `IS NULL`을 사용한다.

### 2-2. IS NOT NULL

```sql
SELECT ename, comm
FROM emp
WHERE comm IS NOT NULL;
```

### 2-3. NULL과 산술 연산

```sql
SELECT 100 + NULL;
```

결과는 NULL이다.

일반적인 산술 연산에 NULL이 포함되면 결과도 NULL이 된다.

### 2-4. NULL과 비교 연산

```sql
SELECT *
FROM emp
WHERE comm = NULL;
```

이 코드는 NULL 값을 찾는 올바른 방법이 아니다.

SQL은 TRUE, FALSE 외에 UNKNOWN이라는 논리 결과를 사용한다.

NULL과의 일반 비교는 UNKNOWN이 될 수 있고, WHERE는 TRUE인 행만 반환한다.

### 2-5. COUNT와 NULL

```sql
SELECT COUNT(*)
FROM emp;
```

COUNT(*)는 전체 행 수를 계산한다.

```sql
SELECT COUNT(comm)
FROM emp;
```

COUNT(comm)은 comm이 NULL이 아닌 행의 개수를 계산한다.

AVG, SUM 등도 일반적으로 NULL을 제외하고 계산한다.

## 3. GROUP BY와 HAVING

GROUP BY는 같은 값을 가진 행들을 그룹으로 묶는다.

```sql
SELECT deptno, AVG(sal)
FROM emp
GROUP BY deptno;
```

부서별 평균 급여를 계산한다.

### 3-1. WHERE와 HAVING의 차이

WHERE:
그룹화하기 전에 개별 행을 필터링한다.

HAVING:
그룹화한 뒤 그룹 결과를 필터링한다.

```sql
SELECT
    deptno,
    ROUND(AVG(sal), 1) AS avg_sal
FROM emp
GROUP BY deptno
HAVING AVG(sal) >= 2000;
```

논리적인 처리 순서는 다음과 같다.

1. FROM에서 테이블을 가져온다.
2. WHERE가 있다면 개별 행을 필터링한다.
3. GROUP BY로 그룹을 만든다.
4. AVG(sal)을 계산한다.
5. HAVING으로 그룹을 필터링한다.
6. SELECT 결과를 반환한다.

GROUP BY와 집계 함수를 사용할 때 일반 컬럼은 그룹 기준에 포함하거나 함수 종속 관계 등 MySQL의 GROUP BY 규칙을 만족해야 한다.

## 4. JOIN의 기본 구조

JOIN은 두 개 이상의 테이블에서 조건에 맞는 행들을 결합한다.

예를 들어 다음과 같은 테이블이 있다고 가정한다.

employees

| emp_id | emp_name | dept_id |
|---|---|---|
| 1 | 홍길동 | 10 |
| 2 | 김개발 | 20 |

departments

| dept_id | dept_name |
|---|---|
| 10 | 개발팀 |
| 20 | 인사팀 |

JOIN을 사용하면 직원 이름과 부서 이름을 함께 조회할 수 있다.

```sql
SELECT
    e.emp_name,
    d.dept_name
FROM employees AS e
JOIN departments AS d
    ON e.dept_id = d.dept_id;
```

결과:

| emp_name | dept_name |
|---|---|
| 홍길동 | 개발팀 |
| 김개발 | 인사팀 |

### 4-1. ON

ON은 두 테이블을 어떤 조건으로 연결할지 정의한다.

```sql
ON e.dept_id = d.dept_id
```

직원의 dept_id와 부서의 dept_id가 같은 행을 연결한다.

### 4-2. USING

두 테이블의 연결 컬럼 이름이 같다면 USING을 사용할 수 있다.

```sql
SELECT ename, deptno, dname
FROM emp
JOIN dept
USING (deptno);
```

USING에 지정한 컬럼은 결과에서 하나로 합쳐져 표현된다.

### 4-3. 별칭(AS)

```sql
FROM emp AS e
JOIN dept AS d
```

e는 emp 테이블의 별칭이다.

d는 dept 테이블의 별칭이다.

이후 다음과 같이 작성할 수 있다.

```sql
SELECT e.ename, d.dname
```

별칭은 여러 테이블에 같은 컬럼명이 존재할 때 특히 유용하다.

### 4-4. 묵시적 JOIN

```sql
SELECT e.ename, d.dname
FROM emp AS e, dept AS d
WHERE e.deptno = d.deptno;
```

이전 방식에서는 FROM에 테이블을 나열하고 WHERE에 연결 조건을 작성했다.

명시적 JOIN 문법은 테이블 연결 조건과 일반 검색 조건을 분리해 표현할 수 있다.

---

## 5. INNER JOIN

INNER JOIN은 양쪽 테이블에서 연결 조건이 일치하는 행만 반환한다.

```sql
SELECT e.ename, d.dname
FROM emp AS e
INNER JOIN dept AS d
    ON e.deptno = d.deptno;
```

INNER JOIN에서는 INNER를 생략할 수 있다.

```sql
SELECT e.ename, d.dname
FROM emp AS e
JOIN dept AS d
    ON e.deptno = d.deptno;
```

두 문장은 동일한 내부 조인을 표현한다.

조인 조건이 여러 행과 일치하면 결과 행이 증가할 수 있다.

JOIN은 단순히 두 테이블을 나란히 붙이는 것이 아니라, 조건을 만족하는 행의 조합을 생성하는 연산이다.

---

## 6. OUTER JOIN

OUTER JOIN은 조건이 일치하지 않는 행도 포함할 수 있다.

### 6-1. LEFT JOIN

왼쪽 테이블의 모든 행을 유지한다.

```sql
SELECT e.ename, d.dname
FROM emp AS e
LEFT JOIN dept AS d
    ON e.deptno = d.deptno;
```

연결되는 부서가 없는 사원이 있다면 그 사원도 조회된다.

다만 부서 정보는 NULL로 표시된다.

### 6-2. RIGHT JOIN

오른쪽 테이블의 모든 행을 유지한다.

```sql
SELECT e.ename, d.dname
FROM emp AS e
RIGHT JOIN dept AS d
    ON e.deptno = d.deptno;
```

사원이 한 명도 없는 부서도 조회할 수 있다.

### 6-3. INNER JOIN과 OUTER JOIN 비교

| JOIN | 반환 기준 |
|---|---|
| INNER JOIN | 양쪽에서 일치하는 행 |
| LEFT JOIN | 왼쪽 전체 + 오른쪽 일치 행 |
| RIGHT JOIN | 오른쪽 전체 + 왼쪽 일치 행 |
| FULL OUTER JOIN | 양쪽의 모든 행 |

MySQL은 FULL OUTER JOIN 문법을 직접 지원하지 않는다.

### 6-4. FULL OUTER JOIN 구현

```sql
SELECT *
FROM x
LEFT JOIN y
    ON x.x1 = y.y1

UNION

SELECT *
FROM x
RIGHT JOIN y
    ON x.x1 = y.y1;
```

LEFT JOIN과 RIGHT JOIN 결과를 UNION으로 결합한다.

이 예제는 중복을 제거한 결과를 만든다.

중복 행까지 보존해야 한다면 UNION ALL과 한쪽의 미일치 행만 반환하는 조건을 조합해야 한다.

---

## 7. CROSS JOIN

CROSS JOIN은 두 테이블의 모든 행 조합을 생성한다.

이를 데카르트 곱(Cartesian Product)이라고 한다.

예시:

A 테이블: 3행
B 테이블: 4행

결과:

3 × 4 = 12행

```sql
SELECT *
FROM join_a AS a
CROSS JOIN join_b AS b;
```

MySQL에서는 조인 조건이 없는 일반 JOIN도 모든 행 조합을 생성할 수 있다.

```sql
SELECT *
FROM join_a AS a
JOIN join_b AS b;
```

JOIN에서 ON 조건이 없는 이유를 이해하려면 각 테이블의 모든 행을 서로 연결한다고 생각하면 된다.

---

## 8. NATURAL JOIN

NATURAL JOIN은 양쪽 테이블에 이름이 같은 컬럼을 자동으로 찾아 동등 비교 조건을 구성한다.

```sql
SELECT *
FROM emp
NATURAL JOIN dept;
```

양쪽에 deptno라는 컬럼이 있다면 자동으로 연결 기준이 된다.

다만 공통 컬럼이 여러 개라면 그 컬럼들이 모두 조인 조건에 포함된다.

공통 컬럼이 없다면 CROSS JOIN과 같은 결과가 발생할 수 있다.

NATURAL JOIN은 컬럼 이름이 변경되거나 추가될 때 조인 조건 자체가 달라질 수 있다는 특징이 있다.

---

## 9. SELF JOIN

SELF JOIN은 같은 테이블을 서로 다른 역할로 두 번 참조하는 JOIN이다.

대표적으로 사원과 관리자의 관계를 조회할 때 사용한다.

```sql
SELECT
    e.ename AS employee_name,
    m.ename AS manager_name
FROM emp AS e
LEFT JOIN emp AS m
    ON e.mgr = m.empno;
```

e:
일반 사원 역할

m:
관리자 역할

조건:

```sql
ON e.mgr = m.empno
```

사원의 관리자 번호와 관리자의 사원 번호가 같은 행을 연결한다.

LEFT JOIN을 사용하면 관리자가 없는 최고 관리자도 결과에 포함된다.

INNER JOIN을 사용하면 관리자 정보가 일치하지 않는 사원은 제외된다.

## 10. 범위 JOIN

JOIN 조건은 반드시 같은 값인지 비교하는 `=` 연산만 사용해야 하는 것은 아니다.

범위를 기준으로 연결할 수도 있다.

```sql
SELECT
    e.ename,
    e.sal,
    s.grade
FROM emp AS e
JOIN salgrade AS s
    ON e.sal BETWEEN s.losal AND s.hisal;
```

BETWEEN은 양쪽 경계값을 포함한다.

```sql
e.sal BETWEEN s.losal AND s.hisal
```

이는 다음 조건과 같은 의미다.

```sql
e.sal >= s.losal
AND e.sal <= s.hisal
```

급여가 어느 등급 범위에 해당하는지 확인할 수 있다.

## 11. 집합 연산

집합 연산은 여러 SELECT 결과를 행 방향으로 결합한다.

JOIN이 컬럼을 가로 방향으로 확장한다면 집합 연산은 결과 행을 세로 방향으로 결합한다.

### 11-1. UNION

중복 행을 제거하여 결과를 결합한다.

```sql
SELECT deptno
FROM emp

UNION

SELECT deptno
FROM dept;
```

### 11-2. UNION ALL

중복 행을 제거하지 않는다.

```sql
SELECT deptno
FROM emp

UNION ALL

SELECT deptno
FROM dept;
```

### 11-3. UNION과 UNION ALL 비교

| 연산 | 중복 처리 |
|---|---|
| UNION | 중복 제거 |
| UNION ALL | 중복 유지 |

UNION은 중복 제거 과정에 추가 비용이 들 수 있다.

### 11-4. INTERSECT

두 SELECT 결과에 공통으로 존재하는 행을 반환한다.

```sql
SELECT deptno
FROM emp

INTERSECT

SELECT deptno
FROM dept;
```

MySQL 8.0.31 이상에서 지원한다.

### 11-5. EXCEPT

첫 번째 결과에서 두 번째 결과에 포함된 행을 제외한다.

```sql
SELECT deptno
FROM dept

EXCEPT

SELECT deptno
FROM emp;
```

MySQL 8.0.31 이상에서 지원한다.

### 11-6. 집합 연산의 규칙

- 각 SELECT의 컬럼 수가 같아야 한다.
- 같은 위치의 컬럼은 호환 가능한 데이터 타입이어야 한다.
- 결과 컬럼명은 첫 번째 SELECT의 이름이나 별칭을 따른다.
- 결과 순서는 별도 ORDER BY가 없다면 보장되지 않는다.

예시:

```sql
SELECT
    empno,
    ename,
    hiredate,
    CAST(NULL AS DECIMAL(10, 2)) AS comm
FROM emp

UNION ALL

SELECT
    deptno,
    dname,
    CAST(NULL AS DATE),
    CAST(NULL AS DECIMAL(10, 2))
FROM dept;
```

NULL이나 CAST()를 사용해 컬럼의 위치와 타입을 맞출 수 있다.

다만 MySQL의 집합 연산 결과 타입은 각 SELECT의 표현식을 종합하여 결정된다.

## 12. COALESCE와 IFNULL

### 12-1. COALESCE()

여러 값 중 처음으로 NULL이 아닌 값을 반환한다.

```sql
SELECT
    ename,
    COALESCE(comm, 0) AS commission
FROM emp;
```

comm이 NULL이면 0을 반환한다.

```sql
SELECT COALESCE(NULL, NULL, 100, 200);
```

결과:

100

### 12-2. IFNULL()

두 개의 값을 비교한다.

```sql
SELECT IFNULL(NULL, 100);
```

결과:

100

IFNULL(a, b)는 a가 NULL이면 b를 반환한다.

## 13. 서브쿼리(Subquery)

서브쿼리는 SQL 문장 내부에 포함된 또 다른 SELECT문이다.

예를 들어 JONES보다 급여가 높은 사원을 조회한다고 가정한다.

먼저 JONES의 급여를 조회한다.

```sql
SELECT sal
FROM emp
WHERE ename = 'JONES';
```

그 결과를 바깥쪽 쿼리의 조건에 사용한다.

```sql
SELECT ename, sal
FROM emp
WHERE sal > (
    SELECT sal
    FROM emp
    WHERE ename = 'JONES'
);
```

서브쿼리는 괄호로 감싸서 작성한다.

---

## 14. 단일 행 서브쿼리

단일 행 서브쿼리는 결과가 한 행인 서브쿼리다.

특히 한 행과 한 컬럼을 반환하는 경우 일반 비교 연산자를 사용할 수 있다.

```sql
SELECT ename, sal
FROM emp
WHERE sal > (
    SELECT AVG(sal)
    FROM emp
);
```

전체 평균 급여보다 급여가 높은 사원을 조회한다.

AVG(sal)은 하나의 값을 반환한다.

비교 연산자:
- =
- >
- <
- >=
- <=
- <>

서브쿼리가 여러 행을 반환한다면 단일 값을 기대하는 비교 연산에서 오류가 발생할 수 있다.

---

## 15. 다중 행 서브쿼리

다중 행 서브쿼리는 두 행 이상의 결과를 반환할 수 있는 서브쿼리다.

### 15-1. IN

```sql
SELECT ename, sal
FROM emp
WHERE sal IN (
    SELECT sal
    FROM emp
    WHERE job = 'SALESMAN'
);
```

SALESMAN 직무의 사원들이 받는 급여 목록 중 하나와 일치하는 사원을 조회한다.

### 15-2. ANY

ANY는 서브쿼리 결과 중 하나 이상과 비교 조건을 만족하면 참이 된다.

```sql
SELECT ename, sal
FROM emp
WHERE sal > ANY (
    SELECT sal
    FROM emp
    WHERE job = 'SALESMAN'
);
```

NULL을 제외한 비교 가능한 값이 존재한다면, `> ANY`는 그중 최솟값보다 큰지 비교하는 것과 같은 효과가 있다.

### 15-3. ALL

ALL은 모든 값과 비교 조건을 만족해야 한다.

```sql
SELECT ename, sal
FROM emp
WHERE sal > ALL (
    SELECT sal
    FROM emp
    WHERE job = 'SALESMAN'
);
```

비교 가능한 모든 SALESMAN 급여보다 높은 사원을 찾는다.

ANY와 ALL은 빈 결과 및 NULL 포함 여부에 따라 판정이 달라질 수 있다.

### 15-4. NOT IN

```sql
SELECT ename
FROM emp
WHERE deptno NOT IN (
    SELECT deptno
    FROM dept
);
```

NOT IN에서는 서브쿼리 결과에 NULL이 들어 있으면 UNKNOWN 때문에 예상과 다르게 행이 반환되지 않을 수 있다.

---

## 16. 다중 컬럼 서브쿼리

다중 컬럼 서브쿼리는 여러 컬럼을 하나의 조합으로 비교한다.

```sql
SELECT ename, deptno, sal
FROM emp
WHERE (deptno, sal) IN (
    SELECT deptno, sal
    FROM emp
    WHERE job = 'SALESMAN'
);
```

deptno와 sal을 하나의 쌍으로 비교한다.

예를 들어 서브쿼리 결과가 다음과 같다고 가정한다.

(10, 2000)
(20, 3000)

그렇다면 다음 조합은 일치하지 않는다.

(10, 3000)

부서 번호와 급여가 각각 목록에 존재하더라도 같은 행에서 나온 조합이 아니기 때문이다.

## 17. 상관 서브쿼리

상관 서브쿼리는 내부 서브쿼리에서 바깥쪽 쿼리의 컬럼을 참조한다.

```sql
SELECT
    e.ename,
    e.sal,
    e.deptno
FROM emp AS e
WHERE e.sal > (
    SELECT AVG(e2.sal)
    FROM emp AS e2
    WHERE e2.deptno = e.deptno
);
```

바깥쪽 쿼리의 e.deptno를 내부에서 사용한다.

논리적인 이해 과정:

1. 바깥쪽 사원의 부서 번호를 확인한다.
2. 같은 부서의 평균 급여를 계산한다.
3. 현재 사원의 급여와 평균 급여를 비교한다.
4. 조건에 맞는 사원을 반환한다.

실제 DBMS는 옵티마이저가 쿼리를 변환할 수 있으므로 반드시 행마다 물리적으로 서브쿼리를 다시 실행하는 것은 아니다.

## 18. EXISTS와 SELECT 1

EXISTS는 서브쿼리의 결과 행이 존재하는지 확인한다.

```sql
SELECT d.dept_name
FROM departments AS d
WHERE EXISTS (
    SELECT 1
    FROM dept_emp AS de
    JOIN titles AS t
        ON de.emp_no = t.emp_no
    WHERE de.dept_no = d.dept_no
      AND t.title = 'Staff'
);
```

이 쿼리는 Staff 직함을 가진 직원의 배정 이력이 존재하는 부서를 조회한다.

### 18-1. EXISTS 실행 원리

EXISTS는 서브쿼리가 하나 이상의 행을 반환하면 TRUE가 된다.

행이 존재하지 않으면 FALSE가 된다.

### 18-2. SELECT 1의 의미

```sql
SELECT 1
```

숫자 1이라는 상수를 선택한다는 뜻이다.

EXISTS에서는 실제로 선택한 값보다 결과 행이 존재하는지가 중요하다.

따라서 다음 표현도 존재 여부를 검사하는 용도로 사용할 수 있다.

```sql
SELECT 0
```

```sql
SELECT NULL
```

```sql
SELECT *
```

모두 결과 행의 존재 여부를 확인한다는 점은 같다.

### 18-3. EXISTS와 JOIN의 차이

JOIN은 일치하는 행들을 결합한다.

EXISTS는 조건을 만족하는 행이 있는지 확인한다.

JOIN은 여러 일치 행 때문에 결과가 증가할 수 있다.

EXISTS는 바깥쪽 행의 포함 여부를 판단하므로 존재 여부만 필요한 경우 사용할 수 있다.

## 19. 인라인 뷰

인라인 뷰는 FROM 절 내부에 작성한 서브쿼리다.

```sql
SELECT v.deptno, v.avg_sal
FROM (
    SELECT
        deptno,
        AVG(sal) AS avg_sal
    FROM emp
    GROUP BY deptno
) AS v
WHERE v.avg_sal >= 2000;
```

내부 SELECT 결과를 임시 테이블처럼 사용한다.

v는 인라인 뷰의 별칭이다.

MySQL에서 FROM 절의 파생 테이블에는 별칭이 필요하다.

## 20. CTE(Common Table Expression)

CTE는 WITH 절로 정의하는 이름이 있는 임시 결과 집합이다.

```sql
WITH dept_avg AS (
    SELECT
        deptno,
        AVG(sal) AS avg_sal
    FROM emp
    GROUP BY deptno
)
SELECT
    e.ename,
    e.deptno,
    e.sal,
    d.avg_sal
FROM emp AS e
JOIN dept_avg AS d
    ON e.deptno = d.deptno
WHERE e.sal > d.avg_sal;
```

CTE는 복잡한 SQL을 여러 단계로 나누어 표현할 수 있다.

### 20-1. 여러 CTE

```sql
WITH production_dept AS (
    SELECT dept_no
    FROM departments
    WHERE dept_name = 'Production'
),
production_manager AS (
    SELECT dm.emp_no
    FROM dept_manager AS dm
    JOIN production_dept AS pd
        ON dm.dept_no = pd.dept_no
    WHERE dm.to_date = '9999-01-01'
)
SELECT e.*
FROM employees AS e
JOIN production_manager AS pm
    ON e.emp_no = pm.emp_no;
```

앞에서 정의한 CTE를 뒤에서 사용할 수 있다.

CTE가 반드시 실제 임시 테이블로 생성되는 것은 아니다. MySQL 옵티마이저가 병합하거나 내부적으로 구체화할 수 있다.

## 21. 재귀 CTE

재귀 CTE는 자기 자신을 참조하여 반복적인 결과를 생성한다.

```sql
WITH RECURSIVE nums AS (
    SELECT 1 AS n

    UNION ALL

    SELECT n + 1
    FROM nums
    WHERE n < 4
)
SELECT n
FROM nums;
```

결과:

| n |
|---|
| 1 |
| 2 |
| 3 |
| 4 |

### 21-1. 실행 과정

앵커 멤버:

```sql
SELECT 1 AS n
```

최초 값 1을 생성한다.

재귀 멤버:

```sql
SELECT n + 1
FROM nums
WHERE n < 4
```

이전 단계에서 생성된 n을 기반으로 새로운 값을 만든다.

진행 과정:

1단계:
n = 1

2단계:
1 < 4 → 2 생성

3단계:
2 < 4 → 3 생성

4단계:
3 < 4 → 4 생성

5단계:
4 < 4 → FALSE

재귀 종료

### 21-2. 재귀 CTE의 구성

앵커 멤버:
최초 결과를 생성한다.

재귀 멤버:
이전 단계 결과를 참조하여 다음 결과를 생성한다.

UNION ALL:
생성된 결과를 결합한다.

종료 조건:
더 이상 다음 행을 생성하지 않도록 한다.

### 21-3. 조직도 조회

사원의 관리자 번호를 이용하면 조직 계층을 조회할 수 있다.

```sql
WITH RECURSIVE org AS (
    SELECT
        empno,
        ename,
        mgr,
        1 AS level
    FROM emp
    WHERE mgr IS NULL

    UNION ALL

    SELECT
        e.empno,
        e.ename,
        e.mgr,
        o.level + 1
    FROM emp AS e
    JOIN org AS o
        ON e.mgr = o.empno
)
SELECT *
FROM org;
```

최고 관리자부터 시작하여 하위 사원을 반복적으로 조회한다.

상위 관리자를 찾는 역방향 계층 조회는 현재 사원의 MGR을 다음 단계의 EMPNO에 연결하는 방식으로 구성할 수 있다.

MySQL에는 재귀 실행 제한이 있으며, `cte_max_recursion_depth` 설정이 영향을 준다.

## 22. 윈도우 함수

윈도우 함수는 원본 행을 유지하면서 집계나 순위 결과를 각 행에 추가한다.

GROUP BY는 행을 그룹 단위로 줄이지만, 윈도우 함수는 각 행을 유지한다.

### 22-1. OVER()

```sql
SELECT
    ename,
    deptno,
    sal,
    ROUND(
        AVG(sal) OVER (PARTITION BY deptno),
        2
    ) AS dept_avg_sal
FROM emp;
```

각 사원의 정보와 같은 부서의 평균 급여를 함께 조회한다.

### 22-2. PARTITION BY

윈도우 계산의 그룹을 구분한다.

```sql
PARTITION BY deptno
```

부서별로 독립적인 계산 범위를 구성한다.

### 22-3. ORDER BY

윈도우 내부에서 계산 순서를 지정한다.

```sql
OVER (
    PARTITION BY deptno
    ORDER BY sal DESC
)
```

---

## 23. 순위 함수

### 23-1. ROW_NUMBER()

각 행에 서로 다른 번호를 부여한다.

### 23-2. RANK()

동점에 같은 순위를 부여하고 다음 순위는 건너뛴다.

### 23-3. DENSE_RANK()

동점에 같은 순위를 부여하되 다음 순위를 건너뛰지 않는다.

### 23-4. 순위 비교

급여가 다음과 같다고 가정한다.

5000
4000
4000
3000

| 급여 | ROW_NUMBER | RANK | DENSE_RANK |
|---|---|---|---|
| 5000 | 1 | 1 | 1 |
| 4000 | 2 | 2 | 2 |
| 4000 | 3 | 2 | 2 |
| 3000 | 4 | 4 | 3 |

ROW_NUMBER의 동점자 순서는 추가 정렬 기준이 없다면 일정하다고 보장할 수 없다.

### 23-5. NTILE(n)

정렬한 행들을 지정한 개수의 그룹으로 나눈다.

```sql
SELECT
    ename,
    sal,
    NTILE(4) OVER (ORDER BY sal DESC) AS salary_group
FROM emp;
```

---

## 24. 윈도우 함수 결과 필터링

부서별 급여 1위를 조회한다고 가정한다.

```sql
SELECT
    deptno,
    ename,
    sal
FROM (
    SELECT
        deptno,
        ename,
        sal,
        RANK() OVER (
            PARTITION BY deptno
            ORDER BY sal DESC
        ) AS salary_rank
    FROM emp
) AS ranked_emp
WHERE salary_rank = 1;
```

윈도우 함수 결과를 WHERE에서 직접 필터링하지 않고, 인라인 뷰로 감싸서 사용한다.

RANK()를 사용했기 때문에 공동 1위가 존재하면 여러 행이 반환될 수 있다.

ROW_NUMBER()를 사용하면 각 부서에서 하나의 행에 1번을 부여한다.

## 25. 누적 합계와 윈도우 프레임

```sql
SELECT
    ename,
    hiredate,
    sal,
    SUM(sal) OVER (
        ORDER BY hiredate, empno
        ROWS BETWEEN UNBOUNDED PRECEDING
                 AND CURRENT ROW
    ) AS running_sal
FROM emp;
```

현재 행까지의 누적 급여를 계산한다.

### 25-1. ROWS

행의 위치를 기준으로 계산 범위를 지정한다.

### 25-2. RANGE

ORDER BY의 정렬 값과 관련된 범위를 기준으로 계산한다.

같은 정렬 값을 가진 행은 동일한 범위에 포함될 수 있다.

### 25-3. UNBOUNDED PRECEDING

윈도우의 시작 지점을 첫 행으로 지정한다.

### 25-4. CURRENT ROW

현재 행을 의미한다.

따라서 다음 표현은 첫 행부터 현재 행까지를 뜻한다.

```sql
ROWS BETWEEN UNBOUNDED PRECEDING
         AND CURRENT ROW
```

## 26. LAG와 LEAD

LAG는 이전 행의 값을 참조한다.

LEAD는 다음 행의 값을 참조한다.

```sql
SELECT
    empno,
    ename,
    sal,
    LAG(sal) OVER (
        ORDER BY empno
    ) AS previous_sal,
    LEAD(sal) OVER (
        ORDER BY empno
    ) AS next_sal
FROM emp;
```

이전 행과 다음 행의 급여를 함께 조회한다.

주요 활용:
- 이전 달 매출과 현재 매출 비교
- 전월 대비 증가율 계산
- 이전 상태와 현재 상태 비교
- 이전 입사자와 다음 입사자 비교

## 27. VIEW

VIEW는 SELECT 문에 이름을 붙여 생성한 가상 테이블이다.

일반적인 뷰는 데이터를 별도로 복사하여 저장하지 않는다.

### 27-1. VIEW 생성

```sql
CREATE OR REPLACE VIEW vw_emp_public AS
SELECT
    e.empno,
    e.ename,
    e.job,
    d.dname,
    d.loc
FROM emp AS e
JOIN dept AS d
USING (deptno);
```

### 27-2. VIEW 조회

```sql
SELECT *
FROM vw_emp_public;
```

일반 테이블과 유사하게 SELECT에 사용할 수 있다.

### 27-3. VIEW 삭제

```sql
DROP VIEW vw_emp_public;
```

VIEW를 삭제해도 원본 테이블은 삭제되지 않는다.

### 27-4. VIEW 정의 확인

```sql
SHOW CREATE VIEW vw_emp_public;
```

### 27-5. VIEW 수정 가능 여부

단순 뷰는 조건에 따라 INSERT, UPDATE, DELETE가 가능하다.

그러나 GROUP BY, DISTINCT, 집계 함수 등은 수정 가능성을 제한한다.

JOIN을 사용한 뷰라고 해서 모든 수정 작업이 무조건 불가능한 것은 아니며, 실제 수정 가능 여부는 뷰의 구조와 수정 대상에 따라 달라진다.

### 27-6. WITH CHECK OPTION

뷰를 통해 삽입하거나 수정한 행이 뷰의 검색 조건을 만족하도록 제한한다.

LOCAL:
현재 뷰의 조건을 검사한다.

CASCADED:
상위 뷰의 조건까지 연쇄적으로 검사한다.

### 27-7. INFORMATION_SCHEMA.VIEWS

```sql
SELECT *
FROM information_schema.views;
```

뷰 정의와 관련 메타데이터를 조회할 수 있다.

## 28. 인덱스(Index)

인덱스는 데이터 검색을 빠르게 수행하도록 돕는 별도의 탐색 구조다.

책의 맨 뒤에 있는 색인을 떠올리면 이해하기 쉽다.

인덱스가 없다면 조건에 맞는 행을 찾기 위해 테이블 전체를 검사할 수 있다.

### 28-1. B-Tree

MySQL InnoDB의 일반적인 인덱스는 B+Tree 계열의 구조를 사용한다.

구성:
- 루트 노드
- 내부 노드
- 리프 노드

인덱스는 탐색 범위를 줄이고 필요한 데이터에 접근하도록 돕는다.

### 28-2. 클러스터형 인덱스

InnoDB의 클러스터형 인덱스는 기본키를 기준으로 행 데이터를 저장한다.

기본키가 없다면 InnoDB는 적절한 UNIQUE 인덱스 또는 내부적으로 생성한 식별자를 이용할 수 있다.

### 28-3. 보조 인덱스

보조 인덱스는 별도로 생성한 검색 구조다.

InnoDB의 보조 인덱스 레코드에는 일반적으로 해당 행을 찾기 위한 기본키 값이 함께 저장된다.

### 28-4. 인덱스 생성

```sql
CREATE INDEX idx_emp_job_sal
ON emp (job, sal);
```

job과 sal로 구성된 복합 인덱스를 생성한다.

### 28-5. 복합 인덱스

복합 인덱스는 여러 컬럼을 순서대로 묶은 인덱스다.

```sql
(job, sal)
```

인덱스 컬럼의 순서가 중요하다.

일반적으로 선두 컬럼인 job을 사용하는 조건에서 활용하기 쉽다.

sal만 사용하는 쿼리에서도 MySQL이 일부 인덱스 접근 방식을 선택할 수 있지만, 선두 컬럼을 사용하는 경우와 효율이 다를 수 있다.

### 28-6. 커버링 인덱스

조회에 필요한 컬럼들이 인덱스에 모두 존재하여 추가 테이블 접근을 줄일 수 있는 인덱스 활용 방식이다.

## 29. EXPLAIN

EXPLAIN은 SQL의 실행 계획을 확인하는 명령이다.

```sql
EXPLAIN
SELECT *
FROM emp
WHERE empno = 7369;
```

또는

```sql
EXPLAIN FORMAT=TREE
SELECT
    e.ename,
    e.sal,
    d.dname
FROM emp AS e
JOIN dept AS d
USING (deptno);
```

### 29-1. 주요 항목

| 항목 | 의미 |
|---|---|
| type | 테이블 접근 방식 |
| possible_keys | 사용할 수 있는 인덱스 후보 |
| key | 실제 선택된 인덱스 |
| rows | 예상 검사 행 수 |
| Extra | 추가 실행 정보 |

### 29-2. 접근 방식

const:
기본키 또는 UNIQUE 인덱스 조건으로 최대 한 행을 찾을 수 있는 경우 등에 사용된다.

ref:
비고유 인덱스 등의 동등 비교에 사용할 수 있다.

range:
인덱스 범위를 탐색한다.

ALL:
테이블 전체를 스캔한다.

### 29-3. Using filesort

인덱스 순서만으로 정렬을 해결하지 못하고 별도의 정렬 작업이 필요한 경우 표시될 수 있다.

반드시 디스크 파일을 생성한다는 의미는 아니다.

### 29-4. Using temporary

쿼리를 처리하기 위해 내부 임시 테이블을 사용하는 경우 표시될 수 있다.

### 29-5. 날짜 범위 조건

다음 코드는 날짜 컬럼에 함수를 적용한다.

```sql
SELECT *
FROM emp
WHERE YEAR(hiredate) = 1987;
```

일반적인 hiredate 인덱스를 활용한 범위 검색에는 다음 형태가 더 적합할 수 있다.

```sql
SELECT *
FROM emp
WHERE hiredate >= '1987-01-01'
  AND hiredate < '1988-01-01';
```

## 30. 인덱스와 실행 계획의 관계

SQL을 작성하면 MySQL 옵티마이저는 여러 실행 방법 중 비용이 적절한 계획을 선택한다.

실행 계획은 다음 요소의 영향을 받는다.

- 테이블의 행 수
- 검색 조건
- 인덱스 구조
- JOIN 조건
- 정렬 여부
- 통계 정보

JOIN에서는 중첩 루프 방식 등이 사용될 수 있다.

중첩 루프 조인은 한쪽 테이블의 행을 기준으로 다른 테이블을 반복 탐색하는 방식이다.

EXPLAIN을 이용하면 MySQL이 어떤 테이블을 어떤 방식으로 접근하는지 확인할 수 있다.
