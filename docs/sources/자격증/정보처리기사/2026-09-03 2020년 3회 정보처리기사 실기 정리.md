# 1. 형상 통제 🔥 빈출

## 문제

형상 통제에 대해 간략히 설명하시오.

형상 관리 절차

```text
형상 식별 → 형상 통제 → 형상 감사 → 형상 기록
```

## 정답

**소프트웨어 형상 변경 요청을 검토하고 승인하여 현재의 베이스라인에 반영될 수 있도록 통제하는 활동**

## 시험용 답안

형상 항목에 대한 변경 요청을 검토·승인하고, 승인된 변경 사항이 베이스라인에 반영되도록 통제하는 활동이다.

## 형상 관리 절차

```text
형상 식별
→ 형상 통제
→ 형상 감사
→ 형상 기록
```

### 형상 식별

관리할 형상 항목을 식별하고 이름과 버전을 부여한다.

### 형상 통제

형상 변경 요청을 검토하고 승인하여 변경을 통제한다.

### 형상 감사

변경된 형상이 요구사항에 맞게 올바르게 변경되었는지 확인한다.

### 형상 기록

형상의 변경 내용과 현재 상태를 기록하고 보고한다.

## 같이 알아둘 것

### 베이스라인(Baseline)

공식적으로 검토·승인되어 이후 변경의 기준이 되는 상태이다.

```text
변경 요청 검토·승인
→ 형상 통제
```

# 2. EAI 구축 유형 🔥 빈출

## 문제

다음은 EAI 구축 유형에 대한 설명이다. 1, 2에 해당하는 유형을 쓰시오.

### (1)

* 중간에 미들웨어를 두지 않고 각 애플리케이션 간 직접 연결
* 솔루션 구매 없이 통합하여 상대적으로 저렴하게 통합 가능
* 변경 및 재사용 어려움

### (2)

* 단일 접점인 허브 시스템을 통해 데이터를 전송하는 중앙 집중적 방식
* 모든 데이터 전송 보장
* 확장 및 유지보수 용이
* 허브 장애 시 전체 시스템에 영향

## 정답

(1) **Point-to-Point**

(2) **Hub & Spoke**

---

# EAI

**Enterprise Application Integration**

기업 내부의 서로 다른 애플리케이션을 연결하여 데이터와 업무 프로세스를 통합하는 방식이다.

---

## ① Point-to-Point

애플리케이션끼리 직접 연결하는 방식이다.

```text
A ───── B
│       │
│       │
C ───── D
```

### 특징

* 직접 연결
* 미들웨어 없음
* 초기 구축 비용이 비교적 낮음
* 시스템 수가 증가하면 연결이 복잡해짐
* 변경 및 재사용이 어려움

```text
직접 연결
미들웨어 X
→ Point-to-Point
```

---

## ② Hub & Spoke

중앙의 Hub를 통해 모든 애플리케이션을 연결하는 방식이다.

```text
      A
      │
B ── HUB ── C
      │
      D
```

### 특징

* 중앙 집중 방식
* 유지보수 용이
* 확장 용이
* 허브 장애 시 전체 시스템에 영향

```text
중앙 허브
→ Hub & Spoke
```

---

## ③ Message Bus

애플리케이션 사이에 미들웨어를 두고 버스를 이용하여 연결하는 방식이다.

```text
A ─┐
B ─┼── Message Bus
C ─┘
```

### 특징

* 미들웨어를 통한 통합
* 뛰어난 확장성
* 대용량 처리 가능

※ ESB와 관련이 깊지만 EAI의 Message Bus와 ESB를 완전히 같은 용어라고 외우지는 않는다.

---

## ④ Hybrid

Hub & Spoke와 Message Bus 방식 등의 장점을 결합한 방식이다.

### 특징

* 유연한 통합
* 데이터 병목 최소화
* 다양한 통합 환경에 대응

## 초압축

```text
직접 연결
→ Point-to-Point

중앙 허브
→ Hub & Spoke

미들웨어 버스
→ Message Bus

여러 방식 결합
→ Hybrid
```

# 4. 코드 커버리지(Code Coverage) 🔥🔥 매우 중요

※ 제공한 필기에는 4번 문제 본문은 없고 코드 커버리지 관련 내용이 정리되어 있음.

## 코드 커버리지

테스트를 수행했을 때 프로그램의 코드가 얼마나 실행되었는지를 측정하는 기준이다.

---

## ① 구문 커버리지

**Statement Coverage**

코드 내 모든 구문을 한 번 이상 실행하도록 하는 테스트 커버리지이다.

```text
모든 구문
→ 한 번 이상 실행
```

---

## ② 조건 커버리지

**Condition Coverage**

결정문 내부의 모든 개별 조건식이 각각 한 번 이상 True와 False가 되도록 한다.

예:

```java
if (A && B)
```

A가

```text
True / False
```

B도

```text
True / False
```

를 각각 한 번 이상 가져야 한다.

---

## ③ 결정 커버리지

**Decision Coverage / Branch Coverage**

결정문의 전체 결과가 각각 한 번 이상 True와 False가 되도록 한다.

예:

```java
if (A && B)
```

전체 조건의 결과가

```text
True
False
```

각각 한 번 이상 나오면 된다.

---

## ④ 조건/결정 커버리지

**Condition / Decision Coverage**

조건 커버리지와 결정 커버리지를 모두 만족한다.

```text
개별 조건식
→ T / F

전체 결정 결과
→ T / F
```

---

## ⑤ 변경 조건/결정 커버리지

**MC/DC**

각 개별 조건이 다른 조건의 영향을 받지 않고 **독립적으로 전체 결정 결과에 영향을 주는지** 확인하는 커버리지이다.

### 핵심

```text
각 조건이 독립적으로
전체 결과를 변경시켜야 함
```

단순히 각각의 조건이 True/False가 되는 것만으로는 부족하다.

---

## ⑥ 다중 조건 커버리지

**Multiple Condition Coverage**

결정문 안의 모든 개별 조건식의 가능한 조합을 전부 테스트한다.

예:

```text
A B
T T
T F
F T
F F
```

```text
가능한 모든 조건 조합
→ 다중 조건 커버리지
```

---

# 5. 블랙박스 테스트 🔥🔥 매우 빈출

## 문제

소프트웨어 테스트 기법 중 소프트웨어 기능이 완전히 작동하는 것을 입증하는 테스트로, 동치분할/경계값 분석을 이용하여 테스트 하는 기법을 쓰시오.

## 정답

**블랙박스 테스트(Black Box Test)**

## 개념

프로그램 내부 구조는 보지 않고 입력값과 출력값을 이용하여 요구사항대로 기능이 동작하는지 검사하는 테스트이다.

```text
내부 코드 X
입력 / 출력 O
→ 블랙박스
```

---

# 블랙박스 테스트 기법

## ① 동등 분할 / 동치 분할

**Equivalence Partitioning**

입력 데이터를 동일한 결과를 낼 것으로 예상되는 그룹으로 나누어 대표값을 테스트하는 기법이다.

---

## ② 경계값 분석

**Boundary Value Analysis**

입력 조건의 경계값에서 오류가 발생할 가능성이 높다는 점을 이용하여 경계 근처의 값을 테스트한다.

예:

```text
정상 범위 1 ~ 100

0
1
2
99
100
101
```

---

## ③ 원인-효과 그래프 검사

입력 조건과 출력 결과 사이의 관계를 분석하여 효율적인 테스트 케이스를 선정한다.

---

## ④ 오류 예측 검사

과거의 경험이나 테스터의 직관을 이용하여 오류가 발생할 가능성이 높은 부분을 테스트한다.

---

## ⑤ 비교 검사

여러 버전의 프로그램에 동일한 테스트 데이터를 입력하여 결과가 동일하게 나오는지 비교한다.

---

# 화이트박스 vs 블랙박스

```text
화이트박스
→ 내부 구조
→ 코드
→ 분기
→ 경로

블랙박스
→ 입력
→ 출력
→ 기능
```

---

# 6. ALTER TABLE 🔥 빈출

## 문제

`<학생>` 테이블에 `주소` 칼럼을 추가하는 SQL문을 완성하는 빈 칸 1~2에 알맞은 예약어를 쓰시오.


(1) **ALTER**

(2) **ADD**

---

# ALTER TABLE

## 속성 추가

```sql
ALTER TABLE 테이블명
ADD 컬럼명 데이터타입;
```

예:

```sql
ALTER TABLE 학생
```

## 속성 변경

DBMS에 따라 문법은 조금씩 다르지만 시험에서는 흔히:


---

## 속성 삭제

```sql

```

## 암기

```text

→ 추가

```

# 7. GROUP BY / HAVING 🔥🔥 매우 중요

## 정답

```sql
SELECT 과목이름,
       MIN(점수) AS 최소점수,
       MAX(점수) AS 최대점수
FROM 성적
GROUP BY 과목이름
HAVING AVG(점수) >= 90;
```

---

## 해석

### SELECT

```sql
SELECT 과목이름,
       MIN(점수),
       MAX(점수)
```

과목별 최소점수와 최대점수를 출력한다.

---

## GROUP BY

```sql
GROUP BY 과목이름
```

같은 과목끼리 그룹으로 묶는다.

---

## HAVING

```sql
HAVING AVG(점수) >= 90
```

과목별 평균 점수가 90점 이상인 그룹만 출력한다.

---

# WHERE vs HAVING 🔥

## WHERE

그룹화하기 전에 각각의 행에 조건을 적용한다.

```sql
WHERE 점수 >= 90
```

→ 점수가 90점 이상인 학생만 선택

## HAVING

GROUP BY를 수행한 후 그룹에 조건을 적용한다.

```sql
HAVING AVG(점수) >= 90
```

→ 평균 점수가 90점 이상인 과목만 선택

### 암기

```text
WHERE
→ 행 조건

HAVING
→ 그룹 조건
```

---

# 집계 함수

```text
COUNT = 개수
SUM   = 합계
AVG   = 평균
MAX   = 최댓값
MIN   = 최솟값
```

# 8. DELETE 🔥 빈출

## 문제

`<학생>` 테이블에서 이름이 `'민수'`인 학생 튜플을 삭제하는 SQL문을 작성하시오.

단 다음의 요구사항을 참고하여 작성하시오.

### 요구사항

1. 이름 속성의 데이터는 문자형이다. 문자형 데이터는 작은 따옴표(`' '`)로 표시하시오.
2. SQL 명령문은 대/소문자를 구분하지 않는다.
3. SQL 명령문의 종결 문자인 세미콜론은 생략 가능하다.

## 정답

```sql
DELETE FROM 학생
WHERE 이름 = '민수';
```

---

# DELETE 기본 문법

```sql
DELETE FROM 테이블명
WHERE 조건;
```

### 주의

```sql
DELETE FROM 학생;
```

처럼 WHERE 조건을 작성하지 않으면 테이블의 모든 행이 삭제된다.

```text
특정 행 삭제
→ WHERE 확인
```

---

# DELETE / TRUNCATE / DROP

## DELETE

특정 행 또는 전체 행 데이터를 삭제한다.

```sql
DELETE FROM 학생
WHERE 이름 = '민수';
```

## TRUNCATE

테이블 구조는 남기고 전체 데이터를 제거한다.

```sql
TRUNCATE TABLE 학생;
```

## DROP

테이블 자체를 제거한다.

```sql
DROP TABLE 학생;
```

### 암기

```text
DELETE
→ 행 삭제

TRUNCATE
→ 전체 데이터 제거

DROP
→ 테이블 자체 제거
```

# 9. 스키마(Schema) 🔥 빈출

## 문제

데이터베이스 스키마(Schema)에 대해 간략히 서술하시오.

## 정답

**데이터베이스의 전체적인 구조와 제약조건에 대한 명세를 기술하고 정의한 것이다.**

## 시험용 답안

데이터베이스의 구조, 데이터 사이의 관계 및 제약조건 등을 정의한 명세이다.

---

# 3단계 스키마

```text
외부 스키마
     ↓
개념 스키마
     ↓
내부 스키마
```

## 외부 스키마

사용자 또는 응용 프로그램 각각이 바라보는 데이터베이스 구조이다.

```text
사용자 관점
```

## 개념 스키마

데이터베이스 전체의 논리적인 구조이다.

```text
전체 DB 논리 구조
```

## 내부 스키마

데이터가 물리적인 저장장치에 어떻게 저장되는지를 나타낸다.

```text
물리적 저장 구조
```

---

# 데이터 독립성 🔥

## 논리적 데이터 독립성

**개념 스키마가 변경되어도 외부 스키마에 영향을 주지 않는 것**

```text
개념 스키마 변경
↓
외부 스키마 영향 X
```

## 물리적 데이터 독립성

**내부 스키마가 변경되어도 개념 스키마에 영향을 주지 않는 것**

```text
내부 스키마 변경
↓
개념 스키마 영향 X
```

## 암기

```text
논리적 독립성
개념 → 외부 영향 X

물리적 독립성
내부 → 개념 영향 X
```

# 11. OSPF 🔥🔥 매우 빈출

## 문제

다음 설명에 해당하는 라우팅 프로토콜을 쓰시오.

* 최단 경로 탐색에 다익스트라 알고리즘 기반 방식 사용
* 최적 경로 선택을 위해 비용을 사용하며 대역폭 등을 반영
* 링크 상태 변화 시 라우팅 정보 전송

## 정답

**OSPF**

## OSPF

**Open Shortest Path First**

링크 상태(Link State)를 기반으로 최단 경로를 찾는 라우팅 프로토콜이다.

## 핵심 키워드

```text
Dijkstra
Link State
Cost
→ OSPF
```

---

# 라우팅 영역에 따른 분류

## IGP

**Interior Gateway Protocol**

하나의 AS 내부에서 사용하는 라우팅 프로토콜이다.

대표:

* RIP
* OSPF
* IGRP

---

## RIP

```text
Distance Vector
Hop Count
```

거리 벡터 방식이며 홉 수를 기준으로 최적 경로를 선택한다.

---

## OSPF

```text
Link State
Dijkstra
Cost
```

링크 상태 방식이며 다익스트라 알고리즘을 이용한다.

---

## EGP

**Exterior Gateway Protocol**

AS와 AS 사이에서 사용하는 라우팅 프로토콜이다.

대표적으로:

```text
BGP
```

### 비교

```text
RIP
→ 거리 벡터
→ Hop Count

OSPF
→ 링크 상태
→ Dijkstra
→ Cost

BGP
→ AS와 AS 사이
→ 경로 벡터
```

## 문제

## 정답

## ICMP

**Internet Control Message Protocol**

## 핵심

```text
IP 오류 보고
+
네트워크 상태 진단
→ ICMP
```

## 대표 명령어

```text
ping
→ ICMP 사용
```

## 같이 알아둘 프로토콜

```text
ARP
IP → MAC

RARP
MAC → IP

ICMP
IP 오류 / 네트워크 상태 진단

IGMP
멀티캐스트 그룹 관리
```

# 20. C++ 생성자 ⭐ 중요

## 문제

C++에서 생성자에 대해 간략히 설명하시오.

## 정답

**객체가 생성될 때 자동으로 호출되며 객체의 멤버 변수를 초기화하기 위해 주로 사용하는 특별한 함수이다.**

## 핵심

```text
객체 생성
↓
생성자 자동 호출
↓
멤버 변수 초기화
```

## C++ 생성자 특징

* 클래스 이름과 동일한 이름을 갖는다.
* 반환형을 작성하지 않는다.
* 객체가 생성될 때 자동 호출된다.
* 오버로딩이 가능하다.

예:

```cpp
class Student {
public:
    Student() {
    }
};
```

---

# Java와 연결

```java
class Student {

    Student() {
        System.out.println("생성자 호출");
    }
}
```

```java
Student s = new Student();
```

진행:

```text
new Student()
↓
객체 생성
↓
Student() 생성자 자동 호출
```
