
# 정보처리기사 실기 - 네트워크·암호화·웹 보안·데이터베이스

# 1. 네트워크 계층 주요 프로토콜

## 1-1. RARP (Reverse Address Resolution Protocol)

RARP는 ARP와 반대로, 물리 주소(MAC 주소)는 알지만 IP 주소를 모르는 경우에 사용하던 프로토콜입니다.

주로 디스크가 없는 워크스테이션 등이 부팅 시 자신의 IP 주소를 알아내기 위해 사용했습니다.

### ARP와 RARP 비교

| 프로토콜 | 변환 방향 |
|---|---|
| ARP | IP 주소 → MAC 주소 |
| RARP | MAC 주소 → IP 주소 |

### 특징

- 자신의 MAC 주소를 이용하여 IP 주소를 알아냄
- 오래된 네트워크 환경에서 사용
- 현재는 DHCP 등의 기술로 대체

※ DHCP(Dynamic Host Configuration Protocol)는 IP 주소뿐 아니라 서브넷 마스크, 기본 게이트웨이, DNS 서버 등의 정보도 자동으로 제공하는 응용 계층 프로토콜입니다.

## 1-2. ICMP (Internet Control Message Protocol)

ICMP는 IP 패킷을 처리할 때 발생하는 문제를 보고하거나 네트워크 상태를 진단하기 위한 제어 메시지를 전송하는 프로토콜입니다.

IP 자체에는 충분한 오류 보고 기능이 없기 때문에 ICMP가 이를 보완합니다.

### 주요 메시지 유형

| 메시지 | 설명 |
|---|---|
| Echo Request | 응답 요청 |
| Echo Reply | 응답 반환 |
| Destination Unreachable | 목적지에 도달할 수 없음 |
| Time Exceeded | TTL 만료 등으로 패킷 폐기 |
| Redirect | 다른 경로를 알려줌 |

### 대표 명령어

~~~bash
ping google.com
~~~

`ping`은 ICMP Echo Request와 Echo Reply를 사용하여 네트워크 연결 상태를 확인합니다.

### 핵심

- 네트워크 오류 보고
- 네트워크 상태 진단
- ping 명령어
- 목적지 도달 불가
- TTL 만료

## 1-3. IGMP (Internet Group Management Protocol)

IGMP는 호스트가 IPv4 멀티캐스트 그룹에 가입하거나 탈퇴할 때 사용하는 프로토콜입니다.

### 멀티캐스트란?

특정 그룹에 속한 여러 호스트에게 데이터를 전송하는 방식입니다.

### 특징

- 멀티캐스트 그룹 멤버십 관리
- 그룹 가입 및 탈퇴 정보 전달
- 멀티캐스트 라우터가 그룹 수신자의 존재를 파악하는 데 사용

### 활용 예시

- IPTV
- 실시간 영상 전송
- 멀티캐스트 기반 네트워크 서비스

### 전송 방식 비교

| 방식 | 설명 |
|---|---|
| 유니캐스트 | 한 송신자에서 한 수신자로 전송 |
| 브로드캐스트 | 같은 브로드캐스트 영역의 모든 호스트로 전송 |
| 멀티캐스트 | 특정 그룹에 속한 호스트들로 전송 |

## 1-4. NAT (Network Address Translation)

NAT는 IP 주소를 변환하는 기술입니다.

일반적으로 사설 IP 주소를 사용하는 내부 네트워크의 장치가 인터넷에 접속할 때 공인 IP 주소로 변환하는 데 사용합니다.

### 동작 방식

1. 내부 장치가 사설 IP 주소를 사용하여 패킷 전송
2. NAT 장비가 출발지 주소를 공인 IP 주소로 변환
3. 외부 서버가 응답
4. NAT 장비가 주소를 다시 변환하여 내부 장치로 전달

### 특징

- 사설 IP와 공인 IP 사이의 주소 변환
- 공인 IPv4 주소 절약
- 여러 장치가 공인 IP 주소를 공유할 수 있음

※ 여러 장치가 하나의 공인 IP를 공유할 때는 일반적으로 포트 번호까지 변환하는 PAT(NAPT)가 사용됩니다.

NAT 자체를 방화벽과 동일한 보안 기술로 이해하면 안 됩니다.

# 2. 네트워크 전달 방식

## 문제

다음은 네트워크 전달 방식에 대한 설명이다. 괄호 안에 들어갈 용어를 쓰시오.

① 데이터를 패킷 단위로 분할하여 전송하며, 회선 효율성이 높고 여러 사용자가 네트워크를 공유할 수 있는 방식이다.

② 통신 전에 송신자와 수신자 간 전용 회선을 설정하고, 통신이 끝날 때까지 해당 회선을 독점적으로 사용하는 방식이다.

## 정답

① 패킷 교환 (Packet Switching)

② 회선 교환 (Circuit Switching, 서킷 교환)

## 해설

### 2-1. 패킷 교환

데이터를 패킷 단위로 나누어 전송하는 방식입니다.

- 네트워크 자원을 여러 사용자가 공유
- 회선 이용 효율이 높음
- 패킷마다 경로가 달라질 수 있음
- 패킷의 지연이나 손실이 발생할 수 있음

대표적으로 IP 네트워크에서 사용합니다.

### 패킷 교환의 종류

- 데이터그램 방식
- 가상회선 방식

### 2-2. 회선 교환

통신 전에 전용 통신 경로를 설정하고 통신이 종료될 때까지 해당 자원을 사용하는 방식입니다.

- 통신 전에 연결 설정
- 일정한 대역폭 확보 가능
- 회선 자원을 독점적으로 사용
- 전통적인 전화망에서 사용

### 비교

| 구분 | 패킷 교환 | 회선 교환 |
|---|---|---|
| 전송 방식 | 패킷 단위 | 연속적인 데이터 흐름 |
| 연결 설정 | 데이터그램은 불필요 | 필요 |
| 회선 사용 | 공유 | 예약·독점 |
| 회선 효율 | 높음 | 유휴 시간에도 자원 점유 |
| 대표 사례 | 인터넷 | 전통적인 전화망 |

※ 패킷 교환과 회선 교환은 통신망의 교환 방식에 대한 구분이므로, 특정 OSI 계층에만 한정하여 정의하지 않습니다.

# 3. 주요 응용 계층 프로토콜 및 포트 번호

| 프로토콜 | 기본 포트 | 핵심 키워드 |
|---|---|---|
| SSH | 22 | 암호화된 원격 접속 |
| Telnet | 23 | 원격 접속, 평문 통신 |
| HTTP | 80 | 웹 요청·응답 |
| HTTPS | 443 | TLS 기반 보안 웹 통신 |
| FTP | 21 | 파일 전송 제어 |
| SMTP | 25 | 이메일 전송 |
| POP3 | 110 | 이메일 다운로드 |
| IMAP | 143 | 이메일 동기화 |
| DNS | 53 | 도메인 이름 조회 |
| DHCP | 67/68 | 동적 IP 주소 할당 |

※ 대표적인 기본 포트이며, 실제 환경에서는 다른 포트나 TLS 전용 포트를 사용할 수 있습니다.

## 3-1. FTP (File Transfer Protocol)

FTP는 클라이언트와 서버 사이에서 파일을 전송하기 위한 프로토콜입니다.

### 주요 연결

- 제어 연결(Control Connection): 명령과 응답 전달
- 데이터 연결(Data Connection): 실제 파일 데이터 전송

### 포트

- TCP 21번: 제어 연결
- TCP 20번: 전통적인 Active Mode의 서버 측 데이터 연결

※ Passive Mode에서는 데이터 전송에 일반적으로 별도의 동적 포트를 사용합니다.

### 주요 기능

- 파일 업로드
- 파일 다운로드
- 서버 파일 목록 조회

## 3-2. 이메일 프로토콜

### SMTP (Simple Mail Transfer Protocol)

이메일을 전송하는 프로토콜입니다.

- 메일 전송
- 메일 서버 간 메시지 전달
- 기본 포트: 25

### POP3 (Post Office Protocol Version 3)

메일 서버에서 클라이언트로 이메일을 다운로드하는 프로토콜입니다.

- 이메일 수신
- 다운로드 중심
- 기본 포트: 110

※ 다운로드 후 서버의 메일을 삭제할 수 있지만, 반드시 삭제되는 것은 아닙니다. 클라이언트 설정에 따라 서버에 보관할 수 있습니다.

### IMAP (Internet Message Access Protocol)

메일을 서버에 보관하면서 여러 장치에서 동기화하여 관리하는 프로토콜입니다.

- 이메일 수신 및 관리
- 서버 중심 동기화
- 여러 장치에서 동일한 메일 상태 확인
- 기본 포트: 143

### SMTP, POP3, IMAP 비교

| 프로토콜 | 역할 | 주요 특징 |
|---|---|---|
| SMTP | 메일 전송 | 송신 중심 |
| POP3 | 메일 수신 | 다운로드 중심 |
| IMAP | 메일 수신 및 관리 | 서버 동기화 중심 |

## 기출·예상문제

다음 설명에 해당하는 프로토콜을 작성하시오.

① 25번 포트를 사용하며 메일 서버 간 전자 메일을 전송한다.

② 143번 포트를 사용하며 메일을 서버에서 동기화 방식으로 수신한다.

③ 53번 포트를 사용하며 도메인 이름을 IP 주소로 변환하는 데 사용된다.

### 정답

① SMTP

② IMAP

③ DNS

# 4. 데이터 링크 계층 프로토콜 - HDLC와 PPP

## 문제

다음 설명에 해당하는 프로토콜을 작성하시오.

① 비트 중심 프로토콜로 점대점 및 다중점 링크를 지원한다. 비트 스터핑을 이용하며 정보 프레임, 감독 프레임, 비번호 프레임으로 구성된다.

② 점대점 방식의 데이터 링크 프로토콜로 ISP와 사용자 사이의 연결 등에 사용된다. 인증, 압축 등의 기능을 지원한다.

## 정답

① HDLC

② PPP

## 4-1. HDLC (High-level Data Link Control)

비트 중심의 데이터 링크 계층 프로토콜입니다.

### 특징

- 점대점 및 다중점 링크 지원
- 비트 스터핑 사용
- 데이터 전송 및 흐름·오류 제어 기능
- 여러 종류의 프레임 사용

### 프레임 종류

| 프레임 | 설명 |
|---|---|
| I-frame | 정보 데이터 전송 |
| S-frame | 흐름 제어 및 오류 제어 |
| U-frame | 링크 관리 등의 제어 기능 |

### 비트 스터핑 (Bit Stuffing)

데이터에 플래그와 동일한 비트 패턴이 나타나는 문제를 방지하는 기법입니다.

HDLC 플래그:

~~~text
01111110
~~~

전송 데이터에서 연속된 1이 다섯 번 나타나면 0을 삽입하여 플래그와 구분합니다.

## 4-2. PPP (Point-to-Point Protocol)

두 장치 사이의 점대점 링크에서 데이터를 전송하기 위한 데이터 링크 계층 프로토콜입니다.

### 특징

- 점대점 통신
- 사용자 인증 지원
- 오류 검출
- 다양한 네트워크 계층 프로토콜 수용

### 주요 인증 방식

- PAP (Password Authentication Protocol)
- CHAP (Challenge Handshake Authentication Protocol)

※ PPP는 기본적으로 암호화 기능을 제공하지 않으며, 확장이나 다른 보안 기술과 결합해야 암호화를 사용할 수 있습니다.

# 5. URL 구조

## URL이란?

URL(Uniform Resource Locator)은 인터넷에서 자원의 위치와 접근 방법을 나타내는 주소입니다.

### 기본 구조

~~~text
scheme://authority/path?query#fragment
~~~

| 구분 | 설명 |
|---|---|
| scheme | 자원에 접근하는 방식 또는 프로토콜 |
| authority | 호스트명, 포트 번호 등의 정보 |
| path | 자원의 경로 |
| query | 요청에 전달하는 추가 매개변수 |
| fragment | 문서 내부의 특정 위치 등을 가리키는 식별자 |

## 문제

다음 URL의 각 구간에 해당하는 이름을 작성하시오.

~~~text
foo://localhost:8080/over/there?name=ferret#nose
~~~

① foo

② localhost:8080

③ /over/there

④ name=ferret

⑤ nose

## 정답

| 번호 | 정답 |
|---|---|
| ① | scheme |
| ② | authority |
| ③ | path |
| ④ | query |
| ⑤ | fragment |

## 해설

~~~text
foo://localhost:8080/over/there?name=ferret#nose
│      │             │          │           │
scheme authority     path       query       fragment
~~~

### 구분 기호

- `://`: scheme과 authority 구분
- `/`: 경로 시작
- `?`: query 시작
- `#`: fragment 시작

※ fragment는 일반적인 HTTP 요청에서 서버로 전송되지 않으며, 주로 브라우저 등 클라이언트에서 해석합니다.

# 6. 대칭키 암호화 알고리즘

## 대칭키 암호화란?

암호화와 복호화에 동일한 비밀키를 사용하는 방식입니다.

### 특징

- 암호화와 복호화에 같은 키 사용
- 일반적으로 공개키 암호화보다 처리 속도가 빠름
- 대량 데이터 암호화에 적합
- 비밀키의 안전한 공유와 관리가 중요

## 종류

### 블록 암호화

데이터를 일정한 크기의 블록으로 나누어 암호화하는 방식입니다.

대표 알고리즘:

- DES
- AES
- SEED
- IDEA
- Skipjack

### 스트림 암호화

데이터를 비트 또는 바이트 흐름 단위로 암호화하는 방식입니다.

대표 알고리즘:

- RC4
- ChaCha20

## 주요 대칭키 알고리즘

| 알고리즘 | 키 길이 | 블록 크기 | 주요 특징 |
|---|---|---|---|
| DES | 56비트 | 64비트 | 과거 표준, 현재 취약 |
| AES | 128/192/256비트 | 128비트 | 널리 사용되는 표준 블록 암호 |
| SEED | 128비트 | 128비트 | 국내 개발 블록 암호 |
| IDEA | 128비트 | 64비트 | 8라운드 구조 |
| Skipjack | 80비트 | 64비트 | NSA 개발, 음성 보안 장비 관련 |

## 6-1. DES

Data Encryption Standard

- IBM이 개발한 암호 알고리즘을 기반으로 표준화
- 56비트 유효 키 사용
- 64비트 블록 암호
- 현재는 키 길이가 짧아 안전하지 않음

## 6-2. AES

Advanced Encryption Standard

- 미국 NIST에서 표준화
- Rijndael 알고리즘을 채택
- 128/192/256비트 키 지원
- 128비트 블록 사용
- 현재 널리 사용되는 대칭키 암호 알고리즘

※ AES의 128비트는 키 길이 중 하나이면서 블록 크기이기도 합니다.

## 6-3. SEED

- 1999년 한국정보보호센터에서 개발

# 7. 비대칭키 암호화 알고리즘

## 비대칭키 암호화란?

서로 다른 공개키와 개인키를 사용하는 암호화 방식입니다.

### 특징

- 공개키와 개인키 사용
- 공개키는 외부에 공개 가능
- 개인키는 소유자가 비밀로 보관
- 암호화, 전자서명 및 키 교환 기술에 활용
- 일반적으로 대칭키 암호보다 연산 비용이 큼

## 주요 알고리즘

| 알고리즘 | 핵심 특징 |
|---|---|
| 디피-헬만 | 공개키 기반 키 교환, 이산 로그 문제 |
| RSA | 큰 정수의 소인수분해 문제와 관련 |
| ECC | 타원곡선 이산 로그 문제, 짧은 키 길이 |

## 7-1. 디피-헬만 (Diffie-Hellman)

공개된 통신 채널을 이용하여 두 사용자가 공통 비밀키를 설정할 수 있게 하는 키 교환 방식입니다.

### 특징

- 공개키 기반 키 교환
- 이산 로그 문제와 관련
- 대칭키 통신에 사용할 공유 비밀을 설정

※ 디피-헬만은 데이터를 직접 암호화하는 일반적인 공개키 암호 알고리즘이 아니라 키 합의 방식입니다.

## 7-2. RSA

Rivest-Shamir-Adleman

- 공개키 암호 알고리즘
- 큰 정수의 소인수분해 어려움과 관련
- 암호화와 전자서명에 활용
- 대표적인 비대칭키 알고리즘

## 7-3. ECC

Elliptic Curve Cryptography

타원곡선 암호 기술입니다.

### 특징

- 타원곡선 이산 로그 문제 기반
- RSA보다 짧은 키 길이로 유사한 보안 수준 제공 가능
- 상대적으로 적은 저장 공간과 통신량
- 모바일, 스마트카드, IoT 환경에 유리

※ ECC는 하나의 암호화 알고리즘이 아니라 타원곡선 기반 공개키 암호 기술의 계열입니다.

## 문제

# 8. 해시 알고리즘

## 해시 함수란?

임의 길이의 데이터를 고정된 길이의 해시 값으로 변환하는 단방향 함수입니다.

### 특징

- 단방향성
- 고정된 출력 길이
- 데이터 무결성 검증
- 충돌 저항성

### 단방향성

해시 값에서 원래 입력 데이터를 복원하는 것이 계산적으로 어렵습니다.

### 충돌 저항성

서로 다른 두 입력에서 동일한 해시 값이 나오는 경우를 찾기 어렵도록 설계됩니다.

※ 서로 다른 입력이 절대로 같은 해시 값을 만들지 않는다는 뜻은 아닙니다. 해시 충돌은 이론적으로 존재합니다.

## 주요 해시 알고리즘

| 알고리즘 | 출력 길이 | 특징 |
|---|---|---|
| MD5 | 128비트 | 충돌 취약, 보안 목적 사용 부적합 |
| SHA-1 | 160비트 | 충돌 취약, 보안 목적 사용 지양 |
| SHA-256 | 256비트 | SHA-2 계열 |
| SHA-384 | 384비트 | SHA-2 계열 |
| SHA-512 | 512비트 | SHA-2 계열 |

## MD5

Message Digest Algorithm 5

- 128비트 해시 값 생성
- 충돌 공격에 취약
- 전자서명 등 충돌 저항성이 중요한 보안 용도로 부적합

## SHA-2

Secure Hash Algorithm 2

- SHA-256
- SHA-384
- SHA-512 등의 알고리즘 포함
- 무결성 검증 등에 널리 사용

※ 비밀번호 저장에는 SHA-256을 단순 적용하기보다 Argon2, bcrypt, scrypt 등 비밀번호 전용 해싱 방식을 사용하는 것이 안전합니다.

# 9. 무선랜 보안 프로토콜

## 9-1. WEP

Wired Equivalent Privacy

초기 무선랜 보안 방식입니다.

### 특징

- RC4 기반 암호화
- 초기 Wi-Fi 보안 방식
- 키 재사용 및 무결성 보호 취약점 존재
- 현재는 안전하지 않음

## 9-2. TKIP

Temporal Key Integrity Protocol

한국어로 임시 키 무결성 프로토콜이라고 합니다.

WEP의 취약점을 보완하기 위해 도입된 무선랜 보안 프로토콜입니다.

### 특징

- 패킷별 키 혼합
- MIC(Message Integrity Check) 사용
- WEP 취약점 일부 개선
- WPA에서 사용된 과도기적 방식

### 키 믹싱

패킷별로 암호화에 사용되는 키 스트림이 반복되는 문제를 줄이기 위한 기술입니다.

### MIC

전송되는 메시지의 위조 및 변조를 탐지하기 위한 무결성 검사 기능입니다.

## 9-3. CCMP

- AES 기반 보안 방식
- 무선 통신의 기밀성과 무결성 제공
- TKIP보다 강력한 보안 제공

### 비교

| 방식 | 특징 |
|---|---|
| WEP | 초기 보안 방식, 취약 |
| TKIP | WEP 취약점 보완, 현재 사용 지양 |
| CCMP | AES 기반의 강화된 보안 |

# 13. SQL - LEFT OUTER JOIN과 COUNT

## 문제

다음 학생 테이블과 수강 테이블이 있다.

### 학생 테이블

| 학번 | 이름 |
|---|---|
| 1 | 김감자 |
| 2 | 이고구마 |
| 3 | 박옥수수 |

### 수강 테이블

| 학번 | 과목 |
|---|---|
| 1 | DB |
| 1 | 네트워크 |
| 2 | DB |

### SQL

~~~sql
SELECT 학생.이름, COUNT(수강.과목) AS 수강수
FROM 학생
LEFT OUTER JOIN 수강
    ON 학생.학번 = 수강.학번
GROUP BY 학생.학번, 학생.이름
ORDER BY 학생.학번;
~~~

### 결과

| 이름 | 수강수 |
|---|---|
| ① | ② |
| ③ | ④ |
| ⑤ | ⑥ |

빈칸 ① ~ ⑥에 들어갈 값을 작성하시오.

## 정답

① 김감자

② 2

③ 이고구마

④ 1

⑤ 박옥수수

⑥ 0

## 해설

### 1단계: LEFT OUTER JOIN

LEFT OUTER JOIN은 왼쪽 테이블의 모든 행을 유지하면서 오른쪽 테이블과 결합합니다.

### JOIN 결과

| 학번 | 이름 | 과목 |
|---|---|---|
| 1 | 김감자 | DB |
| 1 | 김감자 | 네트워크 |
| 2 | 이고구마 | DB |
| 3 | 박옥수수 | NULL |

박옥수수는 수강 기록이 없지만 LEFT JOIN이므로 결과에서 제외되지 않습니다.

### 2단계: GROUP BY

학생별로 그룹을 만듭니다.

### 3단계: COUNT(수강.과목)

COUNT(컬럼명)은 NULL을 제외하고 개수를 계산합니다.

| 이름 | 수강수 |
|---|---|
| 김감자 | 2 |
| 이고구마 | 1 |
| 박옥수수 | 0 |

### COUNT(*)와 COUNT(컬럼명) 비교

| 함수 | 특징 |
|---|---|
| COUNT(*) | 행 개수 계산 |
| COUNT(컬럼명) | NULL이 아닌 값의 개수 계산 |

박옥수수의 JOIN 결과에는 NULL 과목을 가진 행이 하나 있습니다.

- COUNT(*) → 1
- COUNT(수강.과목) → 0

### 4단계: ORDER BY

학번을 기준으로 오름차순 정렬합니다.

최종 결과:

~~~text
김감자    2
이고구마  1
박옥수수  0
~~~

# 15. AJAX, Fetch API, WebSocket, GraphQL

## 15-1. AJAX

Asynchronous JavaScript and XML

웹페이지 전체를 새로고침하지 않고 비동기적으로 서버와 데이터를 주고받아 화면 일부를 갱신하는 개발 기법입니다.

### 특징

- 비동기 통신
- 화면 일부 갱신
- 사용자 경험 개선
- XMLHttpRequest 또는 Fetch API로 구현 가능

## 15-2. Fetch API

JavaScript에서 HTTP 요청을 보내고 응답을 처리하는 웹 API입니다.

### 특징

- Promise 기반
- 비동기 요청 처리
- async/await와 함께 사용 가능

### AJAX와 Fetch API 차이

| 구분 | AJAX | Fetch API |
|---|---|---|
| 개념 | 비동기 화면 갱신 기법 | HTTP 요청 웹 API |
| 역할 | 개발 방식 | 요청을 수행하는 수단 |
| 관계 | Fetch API로 구현 가능 | AJAX 구현에 사용 가능 |

※ 문제에서 비동기 화면 갱신 기법을 물으면 AJAX, Promise 기반 HTTP 요청 API를 물으면 Fetch API입니다.

## 15-3. WebSocket

클라이언트와 서버 사이에서 양방향 실시간 통신을 지원하는 프로토콜입니다.

### 특징

- 지속적인 연결
- 양방향 통신
- 서버 푸시 가능
- 실시간 서비스에 적합

### 활용 예시

- 채팅
- 온라인 게임
- 실시간 주식 시세
- 실시간 알림

## 15-4. GraphQL

GraphQL은 API를 위한 쿼리 언어이자 해당 쿼리를 처리하기 위한 런타임입니다.

### 특징

- 클라이언트가 필요한 데이터 필드를 선택
- Over-fetching 감소
- Under-fetching 완화
- 유연한 API 데이터 요청

### Over-fetching

필요하지 않은 데이터까지 많이 받아오는 문제입니다.

### Under-fetching

필요한 데이터를 한 번에 충분히 받지 못해 추가 요청이 필요한 문제입니다.

## 문제

클라이언트가 필요한 데이터만 요청하여 Over-fetching 및 Under-fetching 문제를 줄이는 API 쿼리 언어는 무엇인가?

### 정답

GraphQL

# 16. JSON, XML, YAML

## 16-1. JSON

JavaScript Object Notation

데이터를 키와 값의 형태로 표현하는 경량 데이터 교환 형식입니다.

### 특징

- Key-Value 구조
- 객체와 배열 지원
- API 통신에 널리 사용
- 표준 JSON은 주석을 지원하지 않음

### 예시

~~~json
{
  "name": "Kim",
  "age": 25
}
~~~

## 16-2. XML

Extensible Markup Language

태그를 이용하여 데이터의 구조를 계층적으로 표현하는 마크업 언어입니다.

### 특징

- 사용자가 직접 태그 정의 가능
- 트리 구조
- 복잡한 데이터 표현
- DTD, XSD를 통한 구조 검증
- SOAP 메시지 등에 사용

### 예시

~~~xml
<student>
    <name>Kim</name>
    <age>25</age>
</student>
~~~

## 16-3. YAML

YAML Ain't Markup Language

사람이 쉽게 읽고 작성할 수 있도록 설계된 데이터 직렬화 형식입니다.

### 특징

- 들여쓰기로 계층 구조 표현
- 주석 지원
- 설정 파일에 널리 사용
- Docker Compose, Kubernetes 등에서 사용

### 예시

~~~yaml
student:
  name: Kim
  age: 25
~~~

## 비교

| 구분 | JSON | XML | YAML |
|---|---|---|---|
| 구조 | Key-Value, 배열 | 태그 | 들여쓰기 |
| 가독성 | 높음 | 태그로 길어질 수 있음 | 간결함 |
| 주석 | 표준에서 미지원 | 지원 | 지원 |
| 주요 사용처 | API 데이터 교환 | 문서·웹 서비스 | 설정 파일 |
| 구조 검증 | JSON Schema 등 | DTD, XSD | 별도 스키마 도구 |

## 문제

JSON과 비교했을 때 XML은 DTD나 XSD를 이용하여 데이터 구조의 유효성을 검증할 수 있다.

이러한 XML의 특징과 관련된 개념은 무엇인가?

### 원문 정답

확장성

### 해설

XML은 사용자 정의 태그를 통해 데이터 구조를 확장할 수 있으며, DTD나 XSD를 사용하여 문서 구조의 유효성을 검증할 수 있습니다.

다만 **DTD와 XSD를 통한 검증 자체를 직접 가리키는 정확한 표현은 '유효성 검증(Validation)' 또는 '스키마 기반 검증'** 입니다.

시험에서는 문제에 제시된 선택지와 질문의 표현을 구분하여 판단해야 합니다.

# 17. 웹 서비스 인터페이스 - SOAP, REST, WSDL, UDDI

| 용어 | 핵심 키워드 |
|---|---|
| SOAP | XML 기반 메시지, 프로토콜 |
| REST | URI 자원 식별, 아키텍처 스타일 |
| WSDL | 웹 서비스 명세서 |
| UDDI | 웹 서비스 등록 및 검색 |
| JSON | 경량 데이터 교환 형식 |

## 17-1. SOAP

Simple Object Access Protocol

XML 기반 메시지를 이용하여 구조화된 정보를 교환하는 프로토콜입니다.

### 특징

- XML 기반
- 정형화된 메시지 구조
- HTTP 등 여러 전송 프로토콜 활용 가능
- 기업 시스템 연동 등에 활용

## 17-2. WSDL

Web Services Description Language

웹 서비스가 제공하는 기능과 사용 방법을 정의하는 XML 기반 명세 언어입니다.

### 주요 정보

- 서비스가 제공하는 기능
- 연산 이름
- 매개변수
- 데이터 타입
- 서비스 접근 위치

## 17-3. UDDI

Universal Description, Discovery and Integration

웹 서비스를 등록하고 검색하기 위한 디렉터리 기술입니다.

### 핵심

- 웹 서비스 등록
- 웹 서비스 검색
- 서비스 디렉터리
- 전화번호부 역할

## SOAP, WSDL, UDDI 관계

1. UDDI: 서비스를 검색
2. WSDL: 서비스의 사용 방법 확인
3. SOAP: 정해진 메시지 형식으로 통신

## 17-4. REST

Representational State Transfer

URI로 자원을 식별하고 HTTP 메서드 등 통일된 인터페이스를 이용하여 자원을 다루는 아키텍처 스타일입니다.

### 특징

- 자원 중심 설계
- URI 사용
- HTTP 메서드 활용
- 무상태성
- JSON 등의 표현 형식 사용 가능

### HTTP 메서드

| 메서드 | 역할 |
|---|---|
| GET | 조회 |
| POST | 생성 또는 처리 요청 |
| PUT | 생성 또는 전체 교체 |
| PATCH | 부분 수정 |
| DELETE | 삭제 |

## SOAP와 REST 비교

| 구분 | SOAP | REST |
|---|---|---|
| 개념 | 프로토콜 | 아키텍처 스타일 |
| 데이터 | XML 메시지 | JSON, XML 등 |
| 특징 | 엄격한 메시지 규약 | 자원 중심, 통일된 인터페이스 |
| 통신 | HTTP 등 사용 가능 | 일반적으로 HTTP 활용 |

# 18. 인터페이스 보안 및 VPN 기술

## VPN (Virtual Private Network)

VPN은 인터넷 등의 공중 네트워크를 이용하여 사설망처럼 통신할 수 있도록 구성하는 기술입니다.

### 특징

- 공중망 활용
- 사설망 연결
- 터널링
- 암호화 기술과 결합하여 안전한 통신 지원

※ VPN은 다양한 방식으로 구현되므로 모든 VPN이 동일한 암호화 방식이나 보안 수준을 제공하는 것은 아닙니다.

## 주요 프로토콜

| 프로토콜 | 주요 특징 |
|---|---|
| PPTP | 초기 VPN 터널링 프로토콜 |
| L2F | Cisco 개발, 2계층 터널링 |
| L2TP | 2계층 터널링, 자체 암호화 없음 |
| IPSec | 네트워크 계층 보안 |
| SSL/TLS | 보안 통신 채널 제공 |
| S-HTTP | HTTP 메시지 단위 보안 |
| HTTPS | HTTP over TLS |

## 18-1. PPTP

Point-to-Point Tunneling Protocol

- 초기 VPN 터널링 프로토콜
- PPP 기반
- 현재는 보안 취약점으로 사용을 권장하지 않음

## 18-2. L2F

Layer 2 Forwarding

- Cisco에서 개발
- 데이터 링크 계층 터널링
- UDP 기반 전달 방식 사용

## 18-3. L2TP

Layer 2 Tunneling Protocol

- 2계층 터널링 프로토콜
- PPTP와 L2F의 특징을 통합
- 자체 암호화 기능 없음
- 일반적으로 IPSec과 결합하여 사용

### L2TP/IPSec

- L2TP: 터널링
- IPSec: 암호화 및 보안

## 18-4. IPSec

Internet Protocol Security

IP 계층에서 데이터의 기밀성, 무결성, 인증 등을 제공하는 보안 프로토콜 모음입니다.

### 특징

- 네트워크 계층
- IP 패킷 보호
- VPN 구성에 사용
- AH와 ESP 사용

## 18-5. SSL/TLS

Secure Sockets Layer / Transport Layer Security

클라이언트와 서버 간 통신을 암호화하는 보안 프로토콜입니다.

### 특징

- 인증
- 기밀성
- 무결성
- 핸드셰이크로 보안 연결 수립

※ SSL은 오래된 기술이며 현재는 후속 표준인 TLS를 사용합니다.

## 18-6. S-HTTP

Secure Hypertext Transfer Protocol

- HTTP 메시지 단위의 보안 제공
- 개별 메시지나 내용 보호
- 현재는 거의 사용되지 않음

## 18-7. HTTPS

Hypertext Transfer Protocol Secure

HTTP에 TLS 보안을 적용한 통신 방식입니다.

### 특징

- 웹 통신 암호화
- 전송 데이터 무결성 보호
- 서버 인증
- 기본 포트 443

※ HTTPS는 통신 내용을 보호하지만 모든 피싱이나 악성 웹사이트를 막아 주는 것은 아닙니다.

# 19. IPSec - AH와 ESP

## IPSec 핵심 구성 요소

| 프로토콜 | 주요 기능 |
|---|---|
| AH | 무결성, 송신자 인증 |
| ESP | 기밀성, 선택적인 무결성 및 인증 |

## 19-1. AH (Authentication Header)

인증 헤더입니다.

### 주요 기능

- 데이터 무결성
- 송신자 인증
- 재전송 공격 방지

### 특징

**암호화 기능이 없습니다.**

따라서 AH만으로는 데이터의 내용을 숨길 수 없습니다.

## 19-2. ESP (Encapsulating Security Payload)

캡슐화 보안 페이로드입니다.

### 주요 기능

- 기밀성
- 데이터 암호화
- 무결성 및 인증 지원
- 재전송 공격 방지

### AH와 ESP 비교

| 구분 | AH | ESP |
|---|---|---|
| 주요 목적 | 인증·무결성 | 암호화·기밀성 |
| 암호화 | 지원하지 않음 | 지원 |
| 무결성 | 지원 | 지원 가능 |
| 재전송 공격 방지 | 지원 | 지원 |

※ ESP는 보안 설정과 알고리즘 구성에 따라 제공 기능이 달라질 수 있습니다.

# 20. IPSec 전송 모드와 터널 모드

## 20-1. 전송 모드 (Transport Mode)

IP 패킷의 페이로드를 보호하는 방식입니다.

### 특징

- 기존 IP 헤더 유지
- IP 페이로드 보호
- 호스트 간 통신에서 주로 사용

### 구조

~~~text
[기존 IP 헤더][보호된 페이로드]
~~~

## 20-2. 터널 모드 (Tunnel Mode)

원래 IP 패킷 전체를 새로운 IP 패킷 안에 캡슐화하는 방식입니다.

### 특징

- 새로운 IP 헤더 추가
- 원래 IP 패킷 보호
- 네트워크 간 VPN에서 주로 사용

### 구조

~~~text
[새 IP 헤더][보호된 원래 IP 패킷]
~~~

## 비교

| 구분 | 전송 모드 | 터널 모드 |
|---|---|---|
| 보호 대상 | 주로 페이로드 | 원래 IP 패킷 전체 |
| IP 헤더 | 기존 헤더 사용 | 새 헤더 추가 |
| 주 사용처 | 호스트 간 통신 | 네트워크 간 VPN |
| 특징 | 오버헤드가 비교적 적음 | 원래 IP 헤더까지 보호 가능 |

※ AH와 ESP는 보호 범위와 방식이 다르며, 암호화 여부는 ESP 등의 사용에 따라 달라집니다.

## 문제 1

IP 계층에서 무결성과 인증을 제공하는 AH, 기밀성을 제공하는 ESP 등을 활용하는 VPN 보안 기술은?

### 정답

IPSec

## 문제 2

PPTP와 L2F의 특징을 통합하였으며 인터넷에서 가상 터널을 구성하는 프로토콜은?

### 정답

L2TP

## 문제 3

공중 네트워크를 이용하여 전용 회선을 사용하는 것처럼 사설 네트워크를 구축할 수 있는 기술은?

### 정답

VPN

## 웹 애플리케이션 공격이란?

웹 애플리케이션의 취약점이나 사용자 행동을 악용하여 정보를 탈취하거나 시스템을 침해하는 공격입니다.

- XSS

# 22. SQL Injection

## SQL Injection이란?

사용자 입력값을 SQL 질의에 안전하게 처리하지 않고 포함시켜 공격자가 SQL 구문의 의미를 변경하는 공격입니다.

### 공격 원리

1. 사용자 입력값을 받음
2. 입력값이 SQL 문자열에 직접 연결됨
3. 공격자가 SQL 구문을 포함한 입력값 전달
4. 원래 SQL 질의의 동작이 변경됨

### 발생 가능한 문제

- 인증 우회
- 데이터 유출
- 데이터 변경
- 데이터 삭제

### 대응 방법

- Prepared Statement
- 파라미터 바인딩
- 입력값 검증
- 최소 권한 원칙

### 핵심

**입력값에 SQL 구문을 삽입하여 원래 질의를 조작하는 공격**

# 23. XSS (Cross-Site Scripting)

## XSS란?

공격자가 웹페이지에 악성 스크립트를 삽입하고 해당 페이지를 방문하는 다른 사용자의 브라우저에서 실행되도록 만드는 공격입니다.

### 공격 원리

1. 공격자가 악성 스크립트 삽입
2. 사용자가 해당 페이지 방문
3. 사용자 브라우저에서 스크립트 실행
4. 사용자의 정보나 동작에 영향을 미침

### 발생 가능한 피해

- 세션 정보 탈취
- 웹페이지 변조
- 악성 사이트로 이동
- 사용자 계정으로 요청 수행

### 대응 방법

- 출력 데이터 이스케이프
- HTML 인코딩
- Content Security Policy(CSP)
- 안전한 DOM API 사용

### 핵심

**다른 사용자의 브라우저에서 악성 스크립트를 실행하는 공격**

---

# 24. CSRF (Cross-Site Request Forgery)

## CSRF란?

로그인된 사용자의 브라우저가 사용자의 의도와 무관하게 특정 요청을 보내도록 유도하는 공격입니다.

### 공격 원리

1. 사용자가 정상 사이트에 로그인
2. 공격자가 만든 페이지나 링크에 접근
3. 브라우저가 인증 쿠키 등을 포함하여 요청
4. 서버가 정상 사용자의 요청으로 오인할 수 있음

### 발생 가능한 피해

- 비밀번호 변경
- 계정 설정 변경
- 게시글 작성
- 송금 요청

### 대응 방법

- CSRF 토큰
- SameSite 쿠키
- Origin 또는 Referer 검증
- 중요한 작업의 재인증

## XSS와 CSRF 차이

| 구분 | XSS | CSRF |
|---|---|---|
| 핵심 | 악성 스크립트 실행 | 사용자 의도와 다른 요청 |
| 주요 대상 | 사용자 브라우저 | 인증된 사용자 세션 |
| 방어 | 출력 이스케이프, CSP | CSRF 토큰, SameSite |

# 29. 페이지 교체 알고리즘 - LFU

## LFU (Least Frequently Used)

페이지 참조 횟수가 가장 적은 페이지를 교체하는 알고리즘입니다.

### 핵심 원리

- 각 페이지의 참조 횟수 기록
- 페이지가 다시 참조되면 횟수 증가
- 페이지 부재 발생 시 참조 횟수가 가장 적은 페이지 교체

### 예시

프레임이 3개이며 다음 상태라고 가정합니다.

| 페이지 | 참조 횟수 |
|---|---|
| 1 | 4 |
| 2 | 2 |
| 3 | 1 |

새로운 페이지 4가 들어와야 한다면 참조 횟수가 가장 적은 3번 페이지를 교체합니다.

### 결과

| 페이지 | 참조 횟수 |
|---|---|
| 1 | 4 |
| 2 | 2 |
| 4 | 1 |

### 참조 횟수가 같은 경우

문제에서 별도의 조건이 주어졌다면 그 조건을 따릅니다.

예를 들어 참조 횟수가 같으면 FIFO를 적용한다고 했다면 가장 먼저 들어온 페이지를 교체합니다.

※ LFU의 동률 처리 방식은 구현이나 문제 조건에 따라 다를 수 있으므로 반드시 제시된 조건을 확인해야 합니다.

## 반드시 구분할 개념

### 1. HDLC vs PPP

- HDLC: 비트 중심, 비트 스터핑, I/S/U 프레임
- PPP: 점대점 연결, PAP/CHAP 인증

### 2. SMTP vs POP3 vs IMAP

- SMTP: 보내기
- POP3: 다운로드
- IMAP: 동기화

### 3. 대칭키 vs 비대칭키 vs 해시

- 대칭키: 동일한 비밀키로 암호화와 복호화
- 비대칭키: 공개키와 개인키 사용
- 해시: 단방향 변환, 복호화 개념 없음

### 4. AH vs ESP

- AH: 인증과 무결성, 암호화 없음
- ESP: 암호화와 기밀성 제공 가능

### 5. 전송 모드 vs 터널 모드

- 전송 모드: 기존 IP 헤더 유지
- 터널 모드: 새로운 IP 헤더 추가

### 6. SQL Injection vs XSS vs CSRF

- SQL Injection: DB 질의 조작
- XSS: 브라우저에서 악성 스크립트 실행
- CSRF: 인증된 사용자의 의도하지 않은 요청 발생

### 7. SOAP vs REST

- SOAP: 메시징 프로토콜
- REST: 아키텍처 스타일

### 8. XML vs JSON vs YAML

- XML: 태그 기반 구조
- JSON: Key-Value 데이터 교환
- YAML: 들여쓰기 기반 설정 파일

### 9. COUNT(*) vs COUNT(컬럼명)

- COUNT(*): 행 개수
- COUNT(컬럼명): NULL을 제외한 값의 개수

### 10. Scrum vs XP vs Kanban vs Lean

- Scrum: 스프린트, 백로그
- XP: 페어 프로그래밍, TDD
- Kanban: 작업 시각화, WIP 제한
- Lean: 낭비 제거
