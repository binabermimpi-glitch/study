# 1. INSERT 문 🔥🔥

## 문제

학생 테이블에 다음 튜플을 삽입하시오.

```text
학번 : 98170823
이름 : 한국산
학년 : 3
전공 : 경영학개론
번호 : 050-1234-1234
```

학생 테이블:

```text
학번    이름    학년    전공          번호
```

자료형:

```text
학번 → INT
이름 → VARCHAR
학년 → INT
전공 → VARCHAR
번호 → VARCHAR
```

## 정답 1

```sql
INSERT INTO 학생
VALUES (98170823, '한국산', 3, '경영학개론', '050-1234-1234');
```

## 정답 2

```sql
INSERT INTO 학생(학번, 이름, 학년, 전공, 번호)
VALUES (98170823, '한국산', 3, '경영학개론', '050-1234-1234');
```

## 핵심

숫자는 따옴표 없이:

```sql
98170823
3
```

문자열은 작은따옴표:

```sql
'한국산'
'경영학개론'
'050-1234-1234'
```

## INSERT 기본 형식

```sql
INSERT INTO 테이블명
VALUES (값1, 값2, 값3);
```

또는:

```sql
INSERT INTO 테이블명(컬럼1, 컬럼2)
VALUES (값1, 값2);
```

## 문제

```sql
DROP VIEW 고객 (    );
```

## 정답

**CASCADE**

```sql
DROP VIEW 고객 CASCADE;
```

```text
CASCADE

```

```text
RESTRICT
→ 다른 객체가 참조하고 있으면 삭제 제한
```

# 대칭키 암호

암호화와 복호화에 **같은 비밀키**를 사용한다.



```text

```

라고 외우는 것은 피하는 게 좋다.

정확하게는:

```text
대칭키
→ 같은 비밀키(Secret Key)를 사용
```

```text
(1) Stub
(2) Driver
```

하위 모듈 역할을 대신한다.

```text
상위 모듈
↓
Stub
```

주로:

```text
하향식 통합 테스트
→ Stub
```

---

# Driver

상위 모듈 역할을 대신하여 테스트 대상 모듈을 호출한다.

```text
Driver
↓
하위 모듈
```

주로:

```text
상향식 통합 테스트
→ Driver
```

## 암기

```text
Top-Down
→ Stub

→ Driver
```

# 6. C언어 반복문 / 4의 배수 개수 🔥

## 문제

```c
#include <stdio.h>

int main() {

    int c = 0;

    for(int i = 1; i <= 2023; i++) {

        if(i % 4 == 0)
            c++;
    }

    printf("%d", c);
}
```

## 정답

```text
505
```

## 실행 원리

조건:

```c
i % 4 == 0
```

은:

```text
i를 4로 나눈 나머지가 0
→ 4의 배수
```

라는 의미이다.

범위:

```text
1 ~ 2023
```

4의 배수:

```text
4
8
12
16
...
2020
```

몇 개 있는지만 구하면 된다.

```text
2023 / 4
```

정수 나눗셈:

```text
505
```

왜냐하면:

```text
4 × 505 = 2020
4 × 506 = 2024
```

2024는 범위를 초과한다.

따라서:

```text
505개
```

## 정답

**조건 커버리지(Condition Coverage)**

## 핵심

```text
개별 조건식 각각
True / False
```

# 구조적 커버리지 비교

```text
모든 문장

```

전체 결정 결과가 True / False

```text
전체 조건식 결과
T / F
```

각 개별 조건식이 True / False

```text
개별 조건
T / F

```

## 조건/결정 커버리지

```text
개별 조건 T/F
+
전체 결정 T/F
```

# 9. Java String / == / equals() 🔥🔥

## 문제

```java
class Gisafirst {

    public static void main(String[] args) {

        String str1 = "Programming";
        String str2 = "Programming";

        String str3 = new String("Programming");

        System.out.println(str1 == str2);
        System.out.println(str1 == str3);

        System.out.println(str1.equals(str3));
        System.out.println(str2.equals(str3));
    }
}
```

## 정답

```text
true
false
true
true
```

---

# str1 / str2

```java
String str1 = "Programming";
String str2 = "Programming";
```

문자열 리터럴은 String Constant Pool을 사용한다.

같은 문자열 리터럴이면 기존 객체를 재사용한다.

```text
str1 ─┐
      ↓
"Programming"
      ↑
str2 ─┘
```

따라서:

```java
str1 == str2
```

는:

```text
true
```

---

# str3

```java
String str3 = new String("Programming");
```

`new`를 사용했기 때문에 새로운 String 객체를 생성한다.

```text
str1 ─→ "Programming"  [String Pool]

str3 ─→ "Programming"  [새 객체]
```

따라서:

```java
str1 == str3
```

은 참조 주소가 다르므로:

```text
false
```

---

# equals()

```java
str1.equals(str3)
```

은 문자열 **내용**을 비교한다.

내용은 둘 다:

```text
Programming
```

이므로:

```text
true
```

## 핵심

```text
==
→ 참조값 비교

equals()
→ 문자열 내용 비교
```

# 11. C switch Fall-through 🔥🔥

```c

int main() {

    int n[3] = {73, 95, 82};

    for(int i = 0; i < 3; i++) {
        sum += n[i];

    switch(sum / 30) {

        case 10:

        case 9:
            printf("A");

        case 8:
            printf("B");

        case 7:

        case 6:
            printf("C");

        default:
            printf("D");
    }
}
```

```text
BCD
```

```text
= 250
```


```text

```


```text
B
```

---

# case 7

---

# case 6

```text
C 출력
```

---

# default


따라서:

```text
BCD
```

# 13. C 전역 배열 / 문자열 포인터 🔥🔥

## 문제

```c
#include <stdio.h>

char n[30];

char* getname() {

    printf("입력:");

    gets(n);

    return n;
}

int main() {

    char* n1 = getname();
    char* n2 = getname();
    char* n3 = getname();

    printf("%s\n", n1);
    printf("%s\n", n2);
    printf("%s", n3);

    return 0;
}
```

입력:

```text
홍길동
김철수
박영희
```

## 정답

```text
박영희
박영희
박영희
```

---

# 핵심은 전역 배열 n

```c
char n[30];
```

함수 밖에 선언되어 있기 때문에 하나의 전역 배열이다.

```text
n이라는 배열 공간은 하나만 존재
```

---

# 첫 번째 호출

```c
char* n1 = getname();
```

입력:

```text
홍길동
```

배열 `n`에는:

```text
홍길동
```

이 저장된다.

그리고:

```c
return n;
```

배열 `n`의 시작 주소를 반환한다.

따라서:

```text
n1
→ n 배열의 주소
```

---

# 두 번째 호출

```c
char* n2 = getname();
```

입력:

```text
김철수
```

새로운 배열을 만드는 것이 아니다.

같은 `n` 배열에:

```text
김철수
```

가 덮어써진다.

```text
n1 ─┐
    ↓
전역 배열 n = "김철수"
    ↑
n2 ─┘
```

---

# 세 번째 호출

입력:

```text
박영희
```

같은 배열에 또 덮어쓴다.

최종:

```text
전역 배열 n
→ "박영희"
```

그리고:

```text
n1
n2
n3
```

모두 같은 배열 주소를 가지고 있다.

```text
n1 ─┐
n2 ─┼→ n 배열 → "박영희"
n3 ─┘
```

따라서 출력:

```text
박영희
박영희
박영희
```

## 핵심

```text
포인터 3개가
각각 다른 문자열을 저장한 것이 아님

모두 같은 전역 배열 n을 가리킴
```

# 15. C 선택 정렬 🔥🔥

## 문제

```c
#include <stdio.h>

int main() {

    int E[] = {64, 25, 12, 22, 11};

    int n = sizeof(E) / sizeof(E[0]);

    int i = 0;

    do {

        int j = i + 1;

        do {

            if(E[i] (①) E[j]) {

                int tmp = E[i];

                E[i] = E[j];

                E[j] = tmp;
            }

            j++;

        } while(j < n);

        i++;

    } while(i < n - 1);

    for(int i = 0; i <= 4; i++)
        printf("%d ", E[i]);
}
```

## 정답

```text
① >
```

## 실행 결과

```text
11 12 22 25 64
```

---

# 왜 `>`인가?

오름차순 정렬을 만들려면:

```text
앞의 값 > 뒤의 값
```

일 때 교환해야 한다.

예:

```text
64 > 25
```

참이므로:

```text
64 25
↓
25 64
```

교환한다.

---

# 이 코드의 방식

현재 위치 `i`의 값과 뒤에 있는 모든 값을 비교한다.

더 작은 값이 발견되면 계속 교환한다.

결과적으로 현재 위치에는 작은 값이 남는다.

```text
64 25 12 22 11
↓
11 12 22 25 64
```

## 핵심

```text
오름차순
→ 앞 > 뒤 이면 교환

내림차순
→ 앞 < 뒤 이면 교환
```

# 16. Hash 🔥🔥

## 문제

단방향 암호화는 평문에서 암호문으로 변환할 수 있지만 암호문을 평문으로 복호화하기 어렵다.

단방향 암호화에서는 (   )를 이용한다.

(   )란 임의 길이의 입력 데이터를 받아 고정된 길이의 값으로 변환하는 방식이다.

대표 알고리즘으로 HAVAL, SHA-1 등이 있다.

## 정답

**Hash(해시)**

## 개념

임의 길이의 데이터를 일정 길이의 해시값 또는 다이제스트로 변환한다.

```text
평문
↓
Hash Function
↓
Digest
```

일반적인 암호화처럼:

```text
암호문 → 평문
```

으로 복호화하는 개념이 아니다.

---

# 특징

```text
같은 입력
→ 같은 해시값
```

대표:

```text
MD5
SHA-1
SHA-2
SHA-3
HAVAL
```

---

# Salt

```text
Password
+
Salt
↓
Hash
```

## 핵심

```text
Hash
→ 단방향

→ Digest
```

# 19. HDLC 🔥🔥

## 문제

HDLC는 데이터링크 계층의 대표적인 프로토콜이다.

제어부 형식에 따라 3가지 프레임이 존재하며, 전송 모드로 NRM, (4), (5)가 있다.

## 정답

```text
(1) 정보
(2) 감독
(3) 비번호
(4) 비동기 균형(ABM)
(5) 비동기 응답(ARM)
```

---

# HDLC

**High-Level Data Link Control**

데이터링크 계층의 비트 지향 프로토콜이다.

프레임 구조:

```text
Flag
Address
Control
Data
Checksum
Flag
```

---

# HDLC 프레임 종류

## I-Frame

**Information Frame**

```text
사용자 데이터
+
일부 제어 정보
```

즉:

```text
정보 프레임
```

---

## S-Frame

**Supervisory Frame**

사용자 데이터보다는 흐름 제어, 오류 제어 등의 제어 정보에 사용

```text
감독 프레임
```

---

## U-Frame

**Unnumbered Frame**

링크의 설정·관리 등 링크 관리에 사용

```text
비번호 프레임
```

---

# HDLC 전송 모드

## NRM

**Normal Response Mode**

기본국이 통신을 제어하며 종속국은 기본국의 허가나 명령에 따라 전송한다.

```text
기본국 중심
→ NRM
```

---

## ABM

**Asynchronous Balanced Mode**

두 장치가 서로 대등한 관계에서 명령과 응답을 주고받는다.

```text
대등한 관계
가장 널리 사용
→ ABM
```

---

## ARM

**Asynchronous Response Mode**

종속국이 기본국의 명시적 허가 없이도 데이터를 전송할 수 있다.

```text
허가 없이 전송 가능
→ ARM
```

---


# 20. 오류 제어 - Hamming / FEC / BEC / Parity / CRC 🔥🔥

## 문제

데이터 전송 시 오류를 검출하고 수정하는 오류 제어 방법에 대한 문제이다.

(1) 코드는 데이터에 여러 검사 비트를 추가하여 오류 검출과 수정까지 수행할 수 있다.

재전송 없이 수신 측에서 스스로 수정하는 방식을 (2)라 한다.

오류 발생 시 송신 측에 재전송을 요구하는 방식인 (3)의 종류에는 (4), (5) 등이 있다.

## 정답

```text
(1) Hamming
(2) FEC
(3) BEC
(4) Parity
(5) CRC
```

---

# Hamming Code

여러 개의 패리티 비트를 추가하여 오류를 검출하고 수정한다.

일반적인 해밍 코드에서는:

```text
1bit 오류
→ 수정 가능

2bit 오류
→ 검출 가능
```

```text
오류 검출 + 수정
→ Hamming Code
```

---

# FEC

**Forward Error Correction**

오류가 발생해도 재전송을 요청하지 않고 수신 측이 스스로 오류를 검출·수정한다.

```text
재전송 X
수신 측에서 자체 복구
→ FEC
```

대표:

```text
Hamming Code
```

---

# BEC

**Backward Error Correction**

오류를 발견하면 송신 측에 재전송을 요청한다.

```text
오류 검출
↓
송신 측에 재전송 요청
→ BEC
```

---

# Parity Check

데이터에 **1개의 패리티 비트**를 추가하여 오류를 검출한다.

## 짝수 패리티

전체 `1`의 개수가 짝수가 되도록 패리티 비트를 추가

## 홀수 패리티

전체 `1`의 개수가 홀수가 되도록 한다.

```text
1bit 검사 비트
→ Parity
```

---

# CRC

**Cyclic Redundancy Check**

송신 측과 수신 측이 동일한 생성 다항식을 이용하여 오류를 검출한다.

```text
다항식
+
XOR 연산
→ CRC
```

네트워크에서 매우 널리 사용하는 오류 검출 방식이다.

---

# 오류 제어 정리

```text
FEC
→ 재전송 없이 자체 수정
→ Hamming 등
```

```text
BEC
→ 오류 발견
→ 재전송 요구
```

```text
Parity
→ 패리티 비트 이용
```

```text
CRC
→ 다항식 / XOR
```

```text
Hamming
→ 오류 검출 + 수정
```
