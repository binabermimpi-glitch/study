# 1. UML 클래스 다이어그램 접근제어자 🔥🔥

## 문제

클래스 다이어그램에서 `protected` 접근제어자 표기 방법

## 정답

```text
#
```

## UML 접근제어자 전체

```text
+ = public
- = private
# = protected
~ = package
```

Java와 연결하면:

```java
public int a;       → + a : int
private int b;      → - b : int
protected int c;    → # c : int
```

### 다른 다이어그램은 표기방법이 다른가?

`+`, `-`, `#`, `~`는 주로 **클래스 다이어그램에서 클래스의 속성이나 메서드 가시성(Visibility)**을 표시할 때 사용한다.

다른 UML 다이어그램에서는 접근제어자 자체를 표시할 필요가 없는 경우가 많다.

```text
클래스 다이어그램
→ public / private / protected 표현

시퀀스 다이어그램
→ 객체 간 메시지 흐름 표현

활동 다이어그램
→ 업무 흐름 표현

유스케이스 다이어그램
→ 사용자와 기능 관계
```

# 2. 동료 검토(Peer Review) 🔥

## 문제

작성자가 내용을 직접 설명하고 동료들이 이를 들으면서 결함을 발견하는 것

## 정답

**동료 검토(Peer Review)**

다만 이 설명은 교재에 따라 **워크스루(Walkthrough)**의 설명으로 출제되기도 한다.

### Walkthrough

작성자가 직접 문서나 코드를 설명하고 참석자들이 질문하거나 오류를 찾는다.

```text
작성자가 직접 설명
→ Walkthrough
```

### Inspection

훈련된 검토자가 체크리스트와 절차를 이용해 공식적으로 검토한다.

### Peer Review

동료 개발자가 코드나 문서를 검토하는 포괄적인 개념.

### 시험 구별

```text
작성자가 직접 설명
→ Walkthrough

공식적 / 체크리스트 / 역할 분담
→ Inspection

동료가 검토
→ Peer Review
```

# 3. Watering Hole 🔥

## 문제

**Watering Hole Attack**

## 개념

```text
공격 대상 조사
↓
자주 방문하는 사이트 해킹
↓
대상 접속 대기
↓
감염
```

### 핵심

```text
자주 방문하는 사이트
미리 감염
기다림
→ Watering Hole
```

# 4. OSI 데이터 단위 🔥🔥

## 문제

OSI 7계층 중 데이터링크 계층의 데이터 흐름 단위

## 정답

**Frame(프레임)**

## OSI 계층별 데이터 단위

```text
7 응용
6 표현
5 세션
→ Data

4 전송
→ Segment

3 네트워크
→ Packet

2 데이터링크
→ Frame

1 물리
→ Bit
```

### 암기

```text
전송 = Segment
네트워크 = Packet
데이터링크 = Frame
물리 = Bit
```

※ TCP에서는 전송 계층의 데이터 단위를 Segment라고 하고, UDP에서는 Datagram이라는 표현도 사용한다.
