# 1. 애자일 방법론

## 문제

일정한 주기를 가지고 계속 검토해 나가며 필요할 때마다 요구사항을 더하고 수정하여 커다랗게 살을 붙이면서 개발하는 프로세스 모델 방식이다.

미리 정해진 몇개의 단계에 따라 엄격한 순서대로 이루어지는 일직선의 과정인 폭포수의 프로세스와는 비교가 많이 되는 반대의 개념이다.

이 소프트웨어 개발 방법론을 쓰시오.

## 정답

**애자일 방법론(Agile Methodology)**

## 시험용 답안

고객과 지속적으로 소통하며 요구사항의 변화를 수용하고, 짧은 개발 주기를 반복하여 소프트웨어를 점진적으로 개발하는 방법론이다.

## 핵심

```text
짧은 주기
반복 개발
요구사항 변경 수용
고객과 지속적인 소통
```

## 생명 주기 모형

### 폭포수 모형

```text

→ 요구사항 분석
→ 설계
→ 구현
→ 테스트

```

특징:

* 순차적 개발
* 단계가 명확함
* 요구사항 변경이 어려움

### 프로토타입 모형

실제 시스템 개발 전 **견본을 먼저 만들어** 최종 결과를 예측하고 요구사항을 확인한다.

### 나선형 모형

```text

→ 공학적 개발
```

# 3. SOAP

## 문제

일반적으로 널리 알려진 HTTP, HTTPS, SMTP 등을 통해 XML기반의 메시지를 컴퓨터 네트워크 상에서 교환하는 프로토콜이다.

(      )은 웹 서비스에서 기본적인 메시지를 전달하는 기반이 되는데, (   )에는 몇 가지 형태의 메시지 패턴이 있지만, 보통의 경우 원격 프로시저 호출(RPC)패턴으로, 네트워크 노드(클라이언트)에서 다른 쪽 노드(서버)로 메시지를 요청 하고, 서버는 메시지를 즉시 응답하게 되는 형식입니다.

즉 (   )는 XML을 이용해서 분산처리 환경에서 정보교환을 쉽게 할 수 있도록 도와준다.

## 정답

**SOAP**

## SOAP

**Simple Object Access Protocol**

XML 기반 메시지를 이용하여 분산 환경에서 정보를 교환하는 프로토콜이다.

### 특징

* XML 기반
* HTTP / HTTPS / SMTP 사용 가능
* 웹 서비스 메시지 교환
* 플랫폼 독립적

```text
XML
HTTP
RPC
웹 서비스
→ SOAP
```

## SOAP / WSDL / UDDI

### SOAP

실제 메시지를 주고받는 통신 규약

```text
SOAP = 통신
```

### WSDL

**Web Services Description Language**

웹 서비스의 기능, 호출 방법, 입력값, 출력값 등을 XML로 설명한다.

```text
WSDL = 웹 서비스 설명서
```

### UDDI

**Universal Description, Discovery and Integration**

웹 서비스를 등록하고 검색하기 위한 레지스트리이다.

```text
UDDI = 웹 서비스 찾기
```

### 암기

```text
UDDI = 찾기
WSDL = 설명
SOAP = 통신
```

관리 대상:

* 소스 코드
* 문서
* 설정 파일
* 빌드 환경
* 개발 환경
* 라이브러리
* 변경 이력

```text
형상 식별

→ 형상 기록
```

### 형상 식별

### 형상 통제

변경 요청을 검토하고 승인한다.

### 형상 감사

변경이 올바르게 이루어졌는지 확인한다.

### 형상 기록

형상 변경 내용과 상태를 기록한다.

## 버전 관리 도구

# 8. SQL IN 연산자

## 문제

아래 보기의 `<학생>` 테이블을 대상으로 `<요구사항>`을 적용하여 출력하는 SQL문을 작성하시오.

### 요구사항

1. 3학년이거나 4학년 학생의 학번과 이름을 검색하시오.
2. 단, 조건절 작성 시 `IN` 예약어를 사용하여 작성하시오.

### 학생 테이블

| 학번     | 이름  | 학년 |
| ------ | --- | -: |
| 181101 | KKK |  1 |
| 171201 | HHH |  2 |
| 161107 | YYY |  3 |
| 151403 | OOO |  4 |

## 정답

```sql
SELECT 학번, 이름
FROM 학생
WHERE 학년 IN (3, 4);
```

## 풀이

```text
학번과 이름 검색
→ SELECT 학번, 이름

학생 테이블
→ FROM 학생

3학년 또는 4학년
→ WHERE 학년 IN (3, 4)
```

## IN 연산자

여러 값 중 하나와 일치하는지 검사한다.

```sql
WHERE 컬럼명 IN (값1, 값2, 값3);
```

이번 문제:

```sql
WHERE 학년 IN (3, 4);
```

의미:

```sql
WHERE 학년 = 3
   OR 학년 = 4;
```

즉:

```text
IN (3, 4)
=
3 또는 4
```

## NOT IN

지정한 값을 제외한다.

```sql
WHERE 학년 NOT IN (3, 4);
```

```text
IN = 포함
NOT IN = 제외
```

# 11. ROLLBACK

## 문제

SQL 제어어(DCL) 중 ROLLBACK 명령에 대해 간략히 설명하시오.

## 정답

데이터베이스 내의 연산이 비정상적으로 종료되거나 정상 수행되었다 하더라도 수행되기 이전 상태로 되돌리기 위한 명령이다.

## 시험용 답안

트랜잭션 수행 중 변경된 내용을 취소하고 데이터베이스를 이전 상태로 되돌리는 명령어이다.

## COMMIT

```text
변경 내용 영구 저장
```

## ROLLBACK

```text
변경 내용 취소
```

암기:

```text
COMMIT = 저장
ROLLBACK = 취소
```

※ DB 이론에서는 COMMIT/ROLLBACK을 TCL로 분류하기도 하지만 시험에서는 문제에서 제시한 분류를 따른다.

# 12. IPSec

## 문제

네트워크 계층(Network Layer, 3계층)인 IP 계층에서 IP패킷 단위의 데이터 변조 방지 및 암호화 기능을 제공하는 통신규약을 쓰시오.

## 정답

**IPSec**

## IPSec

**Internet Protocol Security**

IP 계층에서 기밀성, 무결성, 인증 등의 보안 기능을 제공한다.

```text
OSI 3계층
IP
암호화
무결성
→ IPSec
```

## AH

**Authentication Header**

* 인증
* 무결성
* 변조 방지

```text
AH = 인증 + 무결성
```

기밀성은 제공하지 않는다.

## ESP

**Encapsulating Security Payload**

* 암호화
* 기밀성
* 필요에 따라 인증/무결성도 제공

```text
ESP = 암호화 + 기밀성
```

# 14. Linux chmod

## 문제

리눅스 또는 유닉스에서 `a.txt` 파일에 대해 다음 조건을 만족하는 권한을 부여하고자 한다.

### 조건

사용자에게는 읽기, 쓰기, 실행의 세 개 권한을 모두 부여한다.

그룹에게는 읽기, 실행 두 개의 권한을 부여한다.

그룹 외 사용자에게는 실행 권한을 부여한다.

한 줄로 명령문이 작성되어야 하며, 8진수로 권한을 부여한다.

## 정답

```bash
chmod 751 a.txt
```

## 권한 값

```text
r = 4
w = 2
x = 1
```

사용자:

```text
rwx
4 + 2 + 1 = 7
```

그룹:

```text
r-x
4 + 1 = 5
```

기타:

```text
--x
1
```

따라서:

```text
751
```

## 권한표

| 숫자 | 권한  |
| -: | --- |
|  0 | --- |
|  1 | --x |
|  2 | -w- |
|  3 | -wx |
|  4 | r-- |
|  5 | r-x |
|  6 | rw- |
|  7 | rwx |

## 파일 권한 구조

```text
-rwxr-x--x
```

```text
-    rwx    r-x    --x
│     │      │      │
│     │      │      └ 기타 사용자
│     │      └ 그룹
│     └ 소유자
└ 파일 종류
```

파일 종류:

```text
- = 일반 파일
d = 디렉터리
l = 심볼릭 링크
```

# 15. RTO

## 문제

다음은 IP 인프라 서비스 관리 실무와 관련된 `<실무 사례>`에 대한 설명이다. 가장 적합한 용어를 한글 또는 영문으로 쓰시오.

A는 한국아이티 보안관제실에서 정보시스템의 정보관리를 위해 모니터링을 담당하며 근무하고 있다. 시스템 운영 중 자연재해나 시스템 장애 등의 이유로 대고객 서비스가 불가능한 경우가 종종 발생한다. A는 이런 장애 발생시 서비스를 정상적으로 수행하기 위해 구축 시스템을 관리하는 역할을 한다.

이 용어는 이런 비상 상황이 발생했을 때 **"서비스 중단 시점과 서비스 복원 시점 간에 허용되는 최대 지연 시간"**을 가리킨다.

## 정답

**RTO(Recovery Time Objective)**
**목표 복구 시간**

## RTO

장애 발생 후 서비스를 얼마나 빠른 시간 안에 복구해야 하는지를 나타낸다.

```text
장애 발생
↓
[ RTO ]
↓
서비스 복구
```

## RPO

**Recovery Point Objective**

장애 발생 시 어느 시점의 데이터까지 복구해야 하는지를 나타낸다.

```text
RTO = 복구 시간
RPO = 복구 시점
```

암기:

```text
T = Time
P = Point
```

# 16. Observer Pattern

## 문제

한 객체의 상태가 바뀌면 그 객체에 의존하는 다른 객체들한테 연락이 가고, 자동으로 내용이 갱신되는 방식으로 일대다(one-to-many) 의존성을 정의하는 디자인 패턴명을 영문으로 쓰시오.

## 정답

**Observer Pattern**

## 개념

한 객체의 상태가 변경될 때 그 객체를 관찰하는 여러 객체에 자동으로 변경 사실을 알리는 패턴이다.

```text
Subject
  ↓
Observer A
Observer B
Observer C
```

핵심:

```text
일대다
상태 변화
자동 알림
자동 갱신
```

예:

```text
유튜브 채널
↓
새 영상 업로드
↓
구독자 알림
```

# 17. Linked Open Data

## 문제

다음에서 설명하는 용어를 쓰시오.

자유롭게 사용이 가능하며, 저작권 표시 및 변경 허락 조건하에 재배포 가능한 링크 기반 개방형 데이터

연계 데이터와 오픈데이터가 결합된 단어로, 웹에 게시되는 데이터에 식별자를 부여하고 관련 정보를 구조적으로 제공하는 연계 데이터를 저작권 없이 무료로 제공하여 사용자가 정보를 다양하고 효율적으로 활용할 수 있도록 한다.

하이퍼텍스트 전송 규약(HTTP), 자원 기술 프레임워크(RDF)와 인터넷 식별자(URI)등의 웹 표준 기술을 이용하여 시맨틱 웹을 구축하고, 출처가 서로 다르지만 인터넷 식별자(URI)를 통해 데이터를 서로 연결한다.

데이터를 재사용할 수 있고, 데이터 중복을 줄일 수 있는 장점이 있다.

## 정답

**Linked Open Data**

또는

**LOD**

## 개념

웹상의 여러 데이터를 연결하여 누구나 자유롭게 사용하고 재사용할 수 있도록 공개한 데이터이다.

### 주요 기술

* HTTP
* URI
* RDF

```text
Linked Data
+
Open Data
=
Linked Open Data
```

## URI

인터넷상의 자원을 식별하는 식별자이다.

## RDF

**Resource Description Framework**

웹 자원과 자원 사이의 관계를 표현하기 위한 데이터 모델이다.

## LOD 장점

* 데이터 재사용
* 데이터 중복 감소
* 데이터 연결
* 새로운 정보 생성

# REST

## REST

**Representational State Transfer**

웹상의 자원을 URI로 식별하고 HTTP Method를 이용하여 해당 자원의 상태를 주고받는 아키텍처 스타일이다.

## HTTP Method

```text
GET    = 조회
POST   = 생성
PUT    = 전체 수정
PATCH  = 일부 수정
DELETE = 삭제
```

## CRUD

| CRUD   | HTTP Method |
| ------ | ----------- |
| Create | POST        |
| Read   | GET         |
| Update | PUT / PATCH |
| Delete | DELETE      |

예:

```text
GET /users/10
```

→ 10번 사용자 조회

```text
DELETE /users/10
```

→ 10번 사용자 삭제

## RESTful

REST 원칙을 잘 준수하여 만든 웹 서비스나 API

```text
REST = 아키텍처 스타일
RESTful = REST 원칙을 잘 지킨 서비스
```
