
# 정보처리기사 실기 - 시스템 공격·디자인 패턴·데이터베이스·보안 기술

# 1. 시스템 공격 (System Attack)

## 시스템 공격이란?

시스템 공격(System Attack) 또는 호스트 공격(Host Attack)은 운영체제, 프로세스, 파일시스템 등 호스트 내부의 자원과 취약점을 대상으로 수행하는 공격입니다.

공격자는 취약점을 악용하여 권한을 획득하거나, 이미 확보한 접근 권한을 이용하여 추가적인 공격을 수행할 수 있습니다.

### 주요 목적

- 권한 상승: 일반 사용자 권한에서 관리자 권한 획득
- 지속성 확보: 재부팅 이후에도 시스템 접근 유지
- 정보 탈취: 비밀번호, 개인정보, 기밀 정보 수집
- 흔적 은폐: 악성 프로세스, 파일, 로그 등 숨김

## 정보보호 공격 유형

| 공격 계열 | 주요 공격 대상 | 대표 공격 |
|---|---|---|
| 네트워크 공격 | 네트워크 트래픽 및 프로토콜 | 스니핑, 스푸핑, 세션 하이재킹 |
| 서비스 거부 공격 | 시스템 가용성 | SYN Flooding, Smurf, LAND, Teardrop |
| 사회공학 공격 | 사용자의 심리와 행동 | 피싱, 파밍, 스미싱 |
| 악성코드 | 시스템 및 프로그램 | 바이러스, 웜, 트로이 목마, 랜섬웨어 |
| 시스템 공격 | 운영체제, 프로세스, 파일시스템 | 레이스 컨디션, 권한 상승, 백도어, 루트킷 |
| 소프트웨어 취약점 공격 | 프로그램 구현 결함 | 버퍼 오버플로, 정수 오버플로, 경로 조작 |
| 웹 공격 | 웹 애플리케이션 및 세션 | SQL Injection, XSS, CSRF |

# 2. 레이스 컨디션 (Race Condition)

## 개념

레이스 컨디션은 둘 이상의 프로세스 또는 스레드가 공유 자원에 접근할 때, 실행 순서나 타이밍에 따라 결과가 달라지는 상황입니다.

공격자는 이러한 경쟁 상태를 악용하여 정상적인 프로그램의 동작을 변경할 수 있습니다.

### 핵심 특징

- 공유 자원에 동시 접근
- 실행 순서에 따라 결과 변화
- 검사 시점과 사용 시점의 차이 악용
- 파일 및 권한 처리 과정에서 발생 가능

## TOCTOU (Time-Of-Check to Time-Of-Use)

TOCTOU는 레이스 컨디션을 악용하는 대표적인 공격 유형입니다.

프로그램이 자원을 검사한 시점(Check)과 실제 사용한 시점(Use) 사이의 시간 차이를 악용합니다.

### 동작 원리

1. 프로그램이 파일의 존재 여부나 접근 권한을 검사
2. 공격자가 검사 이후 해당 파일이나 링크를 변경
3. 프로그램이 변경된 파일을 사용
4. 의도하지 않은 파일에 접근하거나 권한을 악용

### 핵심

- Check: 검사
- Use: 사용
- 검사와 사용 사이의 시간 차이
- 자원 바꿔치기

# 3. 심볼릭 링크와 하드 링크

## 3-1. 심볼릭 링크 (Symbolic Link)

심볼릭 링크는 다른 파일이나 디렉터리의 경로를 가리키는 특수한 파일입니다.

Soft Link라고도 부릅니다.

### 특징

- 원본의 경로를 참조
- 다른 파일시스템의 파일도 가리킬 수 있음
- 디렉터리도 참조 가능
- 원본 경로가 사라지면 링크가 깨질 수 있음
- TOCTOU 공격에 악용될 수 있음

### Linux 명령어

~~~bash
ln -s original.txt shortcut.txt
~~~

`shortcut.txt`는 `original.txt`의 경로를 가리키는 심볼릭 링크입니다.

## 3-2. 하드 링크 (Hard Link)

하드 링크는 동일한 inode를 가리키는 또 다른 파일 이름입니다.

### 특징

- 원본 파일과 같은 inode 참조
- 일반적으로 동일한 파일시스템에서만 생성 가능
- 원본 파일 이름을 삭제해도 다른 하드 링크가 남아 있다면 데이터 유지
- 일반 사용자는 디렉터리 하드 링크를 생성할 수 없음

### Linux 명령어

~~~bash
ln original.txt hardlink.txt
~~~

## 심볼릭 링크와 하드 링크 비교

| 구분 | 심볼릭 링크 | 하드 링크 |
|---|---|---|
| 참조 대상 | 경로 | inode |
| 원본 이름 삭제 | 링크가 깨질 수 있음 | 데이터 유지 |
| 다른 파일시스템 | 가능 | 불가능 |
| 디렉터리 링크 | 가능 | 일반적으로 불가능 |
| 링크 생성 명령어 | ln -s | ln |

# 4. 권한 상승 (Privilege Escalation)

## 개념

권한 상승은 낮은 권한을 가진 사용자나 프로세스가 허용된 범위를 넘어 더 높은 권한을 획득하는 공격입니다.

### 예시

- 일반 사용자 → 관리자
- 일반 프로세스 → root 권한
- 제한된 계정 → 더 높은 접근 권한

### 공격에 악용될 수 있는 취약점

- 레이스 컨디션
- 버퍼 오버플로
- 운영체제 커널 취약점
- 잘못 설정된 파일 권한

### 대응 방법

- 최소권한 원칙
- 운영체제 보안 패치
- 접근 권한 관리
- 중요 시스템 파일 무결성 검사

# 5. 백도어 (Backdoor)

## 개념

백도어는 정상적인 인증 및 보안 절차를 우회하여 시스템에 접근할 수 있도록 만들어진 숨겨진 접근 통로입니다.

### 주요 목적

- 시스템에 재접근
- 인증 절차 우회
- 지속적인 접근 권한 유지
- 원격 제어

## 백도어의 형태

### 1. 하드코딩된 비밀번호

프로그램 내부에 일반 사용자에게 알려지지 않은 특별한 인증 정보를 넣어 두는 방식입니다.

### 2. 리버스 셸 (Reverse Shell)

피해 시스템에서 공격자 측 시스템으로 먼저 연결을 시도하는 방식입니다.

일반적인 원격 접속과 연결 방향이 반대라는 특징이 있습니다.

### 3. 커널 백도어

운영체제 커널 내부에 악의적인 접근 기능을 삽입하는 형태입니다.

커널 수준에서 동작할 경우 탐지가 매우 어려울 수 있습니다.

### 대응 방법

- 코드 리뷰
- 시스템 파일 무결성 검사
- 네트워크 이상 트래픽 감시
- 접근 권한 및 계정 점검

# 6. 루트킷 (Rootkit)

## 개념

루트킷은 공격자가 시스템에 침입한 사실이나 악성 활동을 숨기고 높은 수준의 접근 권한을 유지하는 데 사용되는 도구 또는 악성코드의 집합입니다.

### 핵심 특징

- 공격자 존재 은폐
- 악성 프로세스 숨김
- 파일 및 로그 은폐
- 권한 유지
- 보안 도구의 탐지 회피

## 루트킷의 종류

### 6-1. 유저 모드 루트킷

사용자 영역에서 프로그램이나 라이브러리를 변조하여 악성 활동을 숨기는 방식입니다.

### 특징

- 사용자 영역에서 동작
- 명령어나 라이브러리 조작
- 프로세스 및 파일 정보 은폐

### 6-2. 커널 모드 루트킷

운영체제 커널 영역에서 동작하여 시스템 정보나 동작을 변조하는 방식입니다.

### 특징

- 커널 수준 동작
- 시스템 콜 조작 가능
- 운영체제 내부 정보 은폐
- 일반적인 탐지 방식으로 발견하기 어려울 수 있음

## 루트킷 관련 문제

### 문제

다음 설명에 해당하는 보안 용어를 작성하시오.

- 공격자의 존재를 숨기면서 시스템 접근 권한을 유지한다.
- 침입 사실을 은폐한다.
- 시스템 호출을 조작하여 악성코드 실행 여부를 숨길 수 있다.
- 악성 소프트웨어 및 도구의 모음이다.

### 정답

**Rootkit (루트킷)**

### 해설

문제에서 다음 표현이 나오면 루트킷을 먼저 생각합니다.

- 공격자 존재 은폐
- 관리자 권한 유지
- 악성 프로그램 모음
- 시스템 콜 조작
- 커널 수준 은폐

## 백도어와 루트킷 비교

| 구분 | 백도어 | 루트킷 |
|---|---|---|
| 목적 | 숨겨진 접근 통로 제공 | 악성 활동과 존재 은폐 |
| 핵심 기능 | 인증 우회 및 재접근 | 은폐와 지속성 유지 |
| 특징 | 비밀 접근 경로 | 탐지 회피 도구 |
| 관계 | 루트킷과 함께 사용 가능 | 백도어를 숨길 수 있음 |

# 7. 키로거와 스파이웨어

## 7-1. 키로거 (Keylogger)

키로거는 사용자의 키보드 입력을 기록하는 소프트웨어 또는 하드웨어입니다.

악의적인 목적으로 사용될 경우 비밀번호와 개인정보를 탈취할 수 있습니다.

### 수집 가능한 정보

- 비밀번호
- 카드번호
- 입력한 메시지
- 기타 키보드 입력 정보

## 7-2. 스파이웨어 (Spyware)

스파이웨어는 사용자의 동의 없이 정보를 수집하거나 감시하는 악성 프로그램입니다.

### 주요 특징

- 개인정보 수집
- 브라우징 기록 수집
- 화면 캡처
- 키보드 입력 감시
- 수집한 정보 외부 전송

## 문제

사용자의 동의 없이 설치되어 개인정보나 기밀 정보를 수집하고, 키로거·화면 캡처·브라우징 기록 수집 등을 통해 정보를 유출하는 악성 프로그램은?

### 정답

**Spyware (스파이웨어)**

# 8. 시스템 공격 공통 대응책

| 대응 기술 | 주요 기능 |
|---|---|
| 최소권한 원칙 | 필요한 최소 권한만 부여 |
| DEP | 데이터 영역의 코드 실행 방지 |
| ASLR | 메모리 주소 배치 무작위화 |
| Stack Canary | 스택 메모리 변조 탐지 |
| 무결성 검사 | 중요 파일 변경 탐지 |
| 로그 모니터링 | 비정상적인 시스템 활동 감시 |
| 보안 패치 | 알려진 취약점 수정 |
| EDR/HIDS | 호스트 내부 악성 활동 탐지 |

### DEP (Data Execution Prevention)

데이터가 저장되는 메모리 영역에서 악성 코드가 실행되는 것을 방지하는 기술입니다.

### ASLR (Address Space Layout Randomization)

프로그램의 메모리 주소 배치를 무작위화하여 공격자가 특정 주소를 예측하기 어렵게 만드는 기술입니다.

### Stack Canary

스택에 특수한 값을 배치하여 함수 반환 전에 해당 값이 변조되었는지 검사하는 보호 기법입니다.

# 9. 디자인 패턴 (Design Pattern)

## 디자인 패턴이란?

소프트웨어 설계에서 반복적으로 발생하는 문제를 해결하기 위한 재사용 가능한 설계 방법입니다.

### 디자인 패턴의 종류

1. 생성 패턴 (Creational Pattern)
2. 구조 패턴 (Structural Pattern)
3. 행위 패턴 (Behavioral Pattern)

| 구분 | 주요 목적 | 대표 패턴 |
|---|---|---|
| 생성 패턴 | 객체 생성 방식 관리 | Singleton, Abstract Factory |
| 구조 패턴 | 객체와 클래스의 구조 구성 | Adapter, Bridge, Flyweight, Proxy |
| 행위 패턴 | 객체 사이의 역할과 상호작용 | Observer, Strategy, Mediator |

# 10. Flyweight 패턴 (플라이웨이트)

## 문제

다수의 객체를 생성할 경우 모두가 갖는 본질적인 요소를 공유함으로써 메모리를 절약하고, 객체의 경량화를 목적으로 하는 디자인 패턴은?

## 정답

**Flyweight (플라이웨이트)**

## 해설

Flyweight는 여러 객체가 공통으로 사용하는 데이터를 공유하여 메모리 사용량을 줄이는 구조 패턴입니다.

### 핵심 개념

- 공통 데이터 공유
- 객체 경량화
- 메모리 절약
- 대량 객체 생성에 유리

### 내재적 상태 (Intrinsic State)

여러 객체가 공통으로 공유할 수 있는 상태입니다.

예시:

- 동일한 글꼴 정보
- 이미지 텍스처
- 공통 모델 데이터

### 외재적 상태 (Extrinsic State)

객체마다 달라지는 상태로, 외부에서 전달하거나 관리합니다.

예시:

- 객체의 위치
- 크기
- 개별 좌표

### 예시

게임에서 나무 10,000개를 생성한다고 가정합니다.

각 나무마다 동일한 3D 모델을 별도로 저장하면 메모리 사용량이 증가합니다.

Flyweight를 사용하면 공통 3D 모델을 공유하고, 위치 등의 정보만 개별적으로 관리할 수 있습니다.

### 핵심

**객체의 공통 요소를 공유하여 메모리를 절약하는 패턴**

# 11. 주요 구조 디자인 패턴

| 패턴 | 핵심 개념 |
|---|---|
| Adapter | 호환되지 않는 인터페이스 변환 |
| Bridge | 추상화와 구현 분리 |
| Composite | 부분-전체 트리 구조 |
| Decorator | 객체에 기능을 동적으로 추가 |
| Facade | 복잡한 시스템에 단순한 통합 인터페이스 제공 |
| Flyweight | 공통 객체 공유로 메모리 절약 |
| Proxy | 대리 객체를 통한 접근 제어 |

## 11-1. Adapter (어댑터)

서로 호환되지 않는 인터페이스를 연결하여 함께 사용할 수 있도록 하는 구조 패턴입니다.

### 핵심

- 인터페이스 변환
- 기존 클래스 재사용
- 호환되지 않는 구조 연결

## 11-2. Bridge (브리지)

추상화와 구현을 분리하여 각각 독립적으로 변경하고 확장할 수 있도록 하는 구조 패턴입니다.

### 핵심

- 추상화와 구현 분리
- 독립적인 확장
- 결합도 감소

## 11-3. Composite (컴포지트)

객체를 트리 구조로 구성하여 개별 객체와 복합 객체를 동일한 방식으로 다루도록 하는 구조 패턴입니다.

### 핵심

- 트리 구조
- 부분-전체 관계
- 개별 객체와 복합 객체의 일관된 처리

## 11-4. Decorator (데코레이터)

기존 객체를 감싸서 기능을 동적으로 추가하는 구조 패턴입니다.

### 핵심

- 객체를 감싸는 구조
- 기존 코드 수정 최소화
- 동적인 기능 확장

## 11-5. Facade (퍼사드)

복잡한 하위 시스템을 쉽게 사용할 수 있도록 하나의 단순한 통합 인터페이스를 제공하는 구조 패턴입니다.

### 핵심

- 복잡한 내부 구조 숨김
- 사용법 단순화
- 통합 인터페이스

## 11-6. Proxy (프록시)

실제 객체를 대신하는 대리 객체를 두어 접근을 제어하거나 추가적인 처리를 수행하는 구조 패턴입니다.

### 핵심

- 대리 객체
- 접근 제어
- 실제 객체에 대한 간접 접근
- 지연 로딩 등에 활용

## Proxy 관련 문제

### 문제

특정 객체에 대한 접근을 제어하거나 추가적인 기능을 제공하기 위해 해당 객체의 대리 객체를 사용하는 디자인 패턴을 영어로 작성하시오.

### 정답

**Proxy**

### 해설

- 대리 객체
- 접근 제어
- 간접 접근

위 표현이 나오면 Proxy 패턴을 생각합니다.

# 13. 주요 행위 디자인 패턴

## 13-1. Observer (옵저버)

어떤 객체의 상태가 변경되었을 때 해당 객체를 관찰하는 다른 객체들에게 변경 사실을 자동으로 알리는 패턴입니다.

### 핵심

- 일대다 의존 관계
- 상태 변화 알림
- 자동 통지

## 13-2. Strategy (전략)

여러 알고리즘을 각각 캡슐화하여 상황에 맞게 교체할 수 있도록 하는 패턴입니다.

### 핵심

- 알고리즘 캡슐화
- 실행 중 전략 교체 가능
- 알고리즘 독립성

## 13-3. Mediator (중재자)

여러 객체 사이의 복잡한 상호작용을 중재자 객체를 통해 관리하는 패턴입니다.

### 핵심

- 객체 간 직접 의존 감소
- 중앙 집중식 상호작용 관리
- 중재자 객체 활용

## 13-4. Template Method (템플릿 메서드)

알고리즘의 전체적인 골격은 상위 클래스에서 정의하고, 일부 세부 단계는 하위 클래스에서 구현하도록 하는 패턴입니다.

### 핵심

- 알고리즘 골격 정의
- 일부 단계 재정의
- 상속 활용

# 15. 데이터베이스 3단계 스키마

## 개념

데이터베이스 3단계 스키마는 데이터베이스의 구조를 외부, 개념, 내부의 세 단계로 구분하는 모델입니다.

### 구성

1. 외부 스키마
2. 개념 스키마
3. 내부 스키마

## 15-1. 외부 스키마 (External Schema)

사용자나 응용 프로그램이 필요로 하는 데이터 구조를 정의하는 스키마입니다.

### 특징

- 사용자 관점
- 개별 사용자 또는 응용 프로그램의 데이터 구조
- 뷰(View)와 관련

## 15-2. 개념 스키마 (Conceptual Schema)

데이터베이스 전체의 논리적 구조를 정의하는 스키마입니다.

### 특징

- 전체 데이터베이스의 논리적 구조
- 데이터 간 관계
- 제약 조건
- 모든 사용자가 공유하는 통합된 데이터 구조

## 15-3. 내부 스키마 (Internal Schema)

데이터베이스가 물리적으로 저장되는 방식을 정의하는 스키마입니다.

### 특징

- 물리적 저장 구조
- 인덱스
- 저장 블록
- 파일 구성 및 저장 방식

## 비교

| 구분 | 관점 | 주요 내용 |
|---|---|---|
| 외부 스키마 | 사용자 | 사용자별 데이터 구조, 뷰 |
| 개념 스키마 | 전체 DB | 논리적 구조 |
| 내부 스키마 | 저장 시스템 | 물리적 저장 구조 |

## 문제

다음 설명에 해당하는 스키마를 작성하시오.

① 데이터베이스의 물리적 저장 구조를 정의하며 실제 저장 방식, 인덱스, 블록 크기 등을 기술한다.

② 사용자나 응용 프로그램이 필요한 데이터 구조만 정의하며 뷰(View)가 이에 해당한다.

③ 데이터베이스 전체의 논리적 구조를 정의하며 모든 사용자가 공유하는 스키마이다.

## 정답

① 내부 스키마

② 외부 스키마

③ 개념 스키마

# 22. Kerberos 인증 프로토콜

## 개념

Kerberos는 티켓(Ticket)을 이용하여 사용자와 서버를 인증하는 네트워크 인증 프로토콜입니다.

### 특징

- 티켓 기반 인증
- 대칭키 암호화 사용
- 사용자와 서비스의 상호 인증 지원
- SSO(Single Sign-On) 지원
- 시간 동기화 필요

## 주요 구성 요소

| 구성 요소 | 역할 |
|---|---|
| AS | Authentication Server, 인증 서버 |
| TGS | Ticket Granting Server, 서비스 티켓 발급 서버 |
| KDC | Key Distribution Center, 키 배포 센터 |
| TGT | Ticket Granting Ticket, 티켓 발급용 티켓 |
| ST | Service Ticket, 서비스 접근 티켓 |

## 동작 흐름

1. 사용자가 AS에 인증 요청
2. AS가 TGT 발급
3. 사용자가 TGT를 이용하여 TGS에 서비스 티켓 요청
4. TGS가 서비스 티켓 발급
5. 사용자가 서비스 티켓을 이용하여 서비스 서버에 접근

### 흐름

~~~text
사용자 → AS → TGT 발급
               ↓
             TGS → ST 발급
                        ↓
                     서비스 접근
~~~

중앙 집중식 키 관리 서버(KDC)를 통해 사용자를 인증하고, 티켓을 기반으로 서비스에 접근하도록 하는 네트워크 인증 프로토콜을 영어로 작성하시오.

# 23. OAuth

## 개념

OAuth는 사용자가 자신의 비밀번호를 제3자 애플리케이션에 제공하지 않고도 특정 자원에 대한 접근 권한을 위임할 수 있도록 하는 개방형 인가(Authorization) 프레임워크입니다.

### 특징

- 접근 권한 위임
- 비밀번호 직접 공유 불필요
- 접근 범위(Scope) 지정 가능
- 액세스 토큰 사용

### 활용 예시

- 구글 계정과 연동된 외부 서비스
- 외부 애플리케이션에 일부 데이터 접근 허용

※ OAuth는 기본적으로 인증(Authentication)이 아니라 인가(Authorization)를 위한 기술입니다.

'구글 계정으로 로그인'과 같은 로그인 기능에서는 일반적으로 OAuth 2.0을 기반으로 하는 OpenID Connect(OIDC)가 사용됩니다.

## Kerberos와 OAuth 비교

| 구분 | Kerberos | OAuth |
|---|---|---|
| 핵심 목적 | 네트워크 인증 | 접근 권한 위임 |
| 주요 방식 | 티켓 | 액세스 토큰 |
| 주요 사용처 | 조직 내부 인증 환경 | 웹·모바일 API 권한 위임 |
| 특징 | KDC 사용 | 권한 범위 위임 |

# 24. APT 공격 (Advanced Persistent Threat)

## 개념

APT는 지능형 지속 위협으로, 특정 조직이나 대상을 장기간에 걸쳐 은밀하게 침투하고 정보를 수집하거나 탈취하는 공격입니다.

### APT의 3가지 요소

| 요소 | 의미 |
|---|---|
| Advanced | 다양한 고도화된 공격 기법 사용 |
| Persistent | 장기간 지속적으로 공격 수행 |
| Threat | 명확한 공격 목표와 위협 주체 |

## 특징

- 특정 표적 공격
- 장기간 은밀한 활동
- 여러 공격 기법 결합
- 지속적인 접근 권한 확보
- 중요 정보 수집 및 유출

## APT 공격 프로세스

### 1단계: 침투 (Infiltration)

공격 대상 내부에 초기 접근 경로를 확보합니다.

대표적인 수단:

- 스피어 피싱
- 워터링 홀
- 제로데이 취약점
- 공급망 공격

### 2단계: 검색 (Discovery)

침투한 시스템의 내부 구조와 중요 자산을 파악합니다.

- 내부 네트워크 구조 확인
- 서버 및 계정 탐색
- 권한 수준 조사
- 중요 데이터 위치 확인

### 3단계: 수집 (Collection)

공격 목표에 해당하는 정보를 수집합니다.

- 문서 수집
- 키로깅
- 화면 캡처
- 중요 데이터 정리

### 4단계: 유출 (Exfiltration)

수집한 정보를 외부로 반출합니다.

- 외부 서버로 전송
- 암호화된 통신 채널 악용
- 탐지 회피를 위한 은밀한 전송

### 정리

~~~text
침투 → 검색 → 수집 → 유출
~~~

※ 실제 APT 공격은 권한 상승, 내부 이동, 지속성 확보 등의 단계도 포함하며 반복적으로 수행될 수 있습니다.

# 25. 정보보호의 3요소 - CIA

## CIA란?

정보보호에서 가장 기본이 되는 세 가지 요소입니다.

1. 기밀성 (Confidentiality)
2. 무결성 (Integrity)
3. 가용성 (Availability)

## 25-1. 기밀성 (Confidentiality)

인가된 사용자만 정보에 접근할 수 있도록 보호하는 성질입니다.

### 예시

외부인이 고객 데이터베이스를 열람하지 못하도록 접근을 제한합니다.

## 25-2. 무결성 (Integrity)

정보가 허가되지 않은 방법으로 변경되거나 손상되지 않도록 보호하는 성질입니다.

### 예시

공격자가 학생 성적 데이터를 임의로 변경하지 못하도록 보호합니다.

## 25-3. 가용성 (Availability)

인가된 사용자가 필요할 때 정보와 시스템을 사용할 수 있도록 보장하는 성질입니다.

### 예시

DDoS 공격으로 웹 서비스가 중단되는 상황을 방지합니다.

## 비교

| 요소 | 영문 | 핵심 |
|---|---|---|
| 기밀성 | Confidentiality | 정보 유출 방지 |
| 무결성 | Integrity | 정보 위·변조 방지 |
| 가용성 | Availability | 정상적인 서비스 이용 보장 |

# 26. RTO와 RPO

## 개념

RTO와 RPO는 시스템 장애나 재해가 발생했을 때 복구 목표를 수치로 정의하기 위한 지표입니다.

## 26-1. RTO (Recovery Time Objective)

복구 목표 시간입니다.

장애가 발생한 이후 서비스를 복구하기까지 허용할 수 있는 목표 시간을 의미합니다.

### 예시

RTO = 2시간

시스템 장애가 발생하면 2시간 이내에 서비스를 복구하는 것을 목표로 합니다.

## 26-2. RPO (Recovery Point Objective)

복구 목표 시점입니다.

장애 발생 시 어느 시점까지의 데이터를 복구해야 하는지를 나타내며, 허용 가능한 데이터 손실 기간을 의미합니다.

### 예시

RPO = 30분

장애 시 최대 30분가량의 데이터 손실을 허용하는 복구 목표입니다.

## 비교

| 구분 | RTO | RPO |
|---|---|---|
| 영문 | Recovery Time Objective | Recovery Point Objective |
| 핵심 | 복구 시간 | 데이터 복구 시점 |
| 질문 | 얼마나 빨리 복구하는가? | 얼마나 과거 시점까지 복구하는가? |
| 주요 목적 | 서비스 중단 최소화 | 데이터 손실 최소화 |

# 27. BCP와 DRP

## 27-1. BCP (Business Continuity Plan)

업무 연속성 계획입니다.

재해나 장애가 발생해도 조직의 핵심 업무가 지속될 수 있도록 준비하는 종합적인 계획입니다.

### 포함 요소

- 인력
- 업무 절차
- 정보 시스템
- 외부 협력업체
- 대체 업무 환경

## 27-2. DRP (Disaster Recovery Plan)

재해 복구 계획입니다.

재해 발생 이후 정보 시스템과 IT 서비스를 복구하기 위한 계획입니다.

### 주요 요소

- 시스템 복구
- 데이터 백업 및 복원
- 재해 복구 센터
- 서버 및 네트워크 복구

## 비교

| 구분 | BCP | DRP |
|---|---|---|
| 대상 | 조직 전체 업무 | IT 시스템 및 데이터 |
| 목표 | 핵심 업무 지속 | 장애 발생 이후 복구 |
| 범위 | 넓음 | 상대적으로 좁음 |

### 관계

DRP는 일반적으로 BCP의 일부로 포함됩니다.

RTO와 RPO는 BCP 및 DRP를 설계할 때 활용되는 주요 복구 목표입니다.

# 28. 재전송 공격 (Replay Attack)

## 개념

재전송 공격은 정상적인 인증 메시지나 요청 패킷을 가로챈 후 동일한 데이터를 다시 전송하여 인증을 우회하거나 같은 요청을 반복 실행시키려는 공격입니다.

### 핵심 특징

- 정상 패킷 재사용
- 이전 인증 메시지 악용
- 동일한 요청 반복
- 패킷 내용을 해독하지 않아도 공격에 악용될 수 있음

## 대응 방법

### 1. 타임스탬프 (Timestamp)

메시지에 발생 시각을 포함하여 일정 시간이 지난 요청을 거부합니다.

### 2. Nonce

요청마다 한 번만 사용하는 값을 부여하여 중복 사용을 방지합니다.

### 3. 시퀀스 번호

메시지에 순서 번호를 부여하여 중복되거나 순서가 맞지 않는 요청을 탐지합니다.

### 추가 대응

- 요청 식별자 사용
- 재사용 방지 검증
- 인증된 메시지 무결성 검사

## 재전송 공격과 세션 하이재킹 차이

| 구분 | 재전송 공격 | 세션 하이재킹 |
|---|---|---|
| 공격 방법 | 과거 정상 메시지 재전송 | 활성 세션 탈취 |
| 주요 대상 | 인증 메시지, 요청 | 현재 진행 중인 세션 |
| 핵심 | 동일 메시지 재사용 | 세션 제어권 탈취 |

# 29. ARP 스푸핑 (ARP Spoofing)

## 개념

ARP 스푸핑은 ARP 정보를 위조하여 특정 IP 주소에 대응하는 MAC 주소를 공격자의 MAC 주소로 잘못 인식하도록 만드는 공격입니다.

# 30. 레인보우 테이블 공격

## 개념

레인보우 테이블 공격(Rainbow Table Attack)은 비밀번호 후보와 관련된 해시 연산 결과를 미리 계산하여 저장한 테이블을 이용해 해시 값으로부터 원래 비밀번호를 찾아내려는 공격입니다.

### 특징

- 사전 계산된 정보 활용
- 해시 값에 대한 비밀번호 추측
- 단순하고 빠른 해시 방식에 취약할 수 있음
- Salt를 적용하면 공격 비용이 크게 증가

## 문제

패스워드 후보의 해시 값을 미리 계산해 놓은 거대한 테이블을 이용하여 패스워드를 알아내는 공격 기법은?

## 정답

**Rainbow Table Attack (레인보우 테이블 공격)**

### 대응 방법

- 고유한 Salt 사용
- Argon2, bcrypt, scrypt 등 비밀번호 전용 해싱 알고리즘 사용
- 적절한 비밀번호 정책 적용

※ 레인보우 테이블은 단순한 해시 값 목록과는 달리 저장 공간을 줄이기 위한 해시 체인 등의 기법을 활용할 수 있습니다.

# 34. MDR

## Managed Detection and Response

MDR은 전문 보안 업체가 조직을 대신하여 보안 위협을 감시하고 탐지 및 대응 업무를 수행하는 관리형 보안 서비스입니다.

### 주요 특징

- 외부 전문 인력 활용
- 보안 위협 상시 감시
- 침해사고 분석
- 대응 지원

### 핵심

**보안 탐지와 대응을 전문 업체가 운영하는 서비스**

※ EDR과 XDR은 주로 기술·솔루션을 의미하고, MDR은 운영 서비스라는 점이 중요합니다.

---

# 35. SIEM

## Security Information and Event Management

SIEM은 여러 시스템과 보안 장비에서 발생하는 로그와 이벤트를 수집하여 통합 관리하고 분석하는 보안 솔루션입니다.

### 주요 기능

1. 로그 수집
2. 로그 정규화
3. 이벤트 상관 분석
4. 이상 징후 탐지
5. 경고 생성
6. 보안 보고서 작성

### 예시

여러 서버에서 짧은 시간 안에 동일한 IP의 로그인 실패가 반복되는 상황을 탐지할 수 있습니다.

### 핵심

**로그와 보안 이벤트를 모아 분석하는 시스템**

---

# 36. SOAR

## Security Orchestration, Automation and Response

SOAR는 보안 이벤트가 발생했을 때 사전에 정의된 절차를 이용하여 대응 작업을 자동화하는 솔루션입니다.

### 주요 기능

- 보안 도구 연동
- 대응 절차 자동화
- 플레이북 실행
- 보안 이벤트 처리

### 예시

1. 의심스러운 IP 탐지
2. 방화벽 차단 요청
3. 보안 담당자 알림
4. 관련 단말 격리

### SIEM과 SOAR 비교

| 구분 | SIEM | SOAR |
|---|---|---|
| 주요 역할 | 로그 분석 및 탐지 | 대응 절차 자동화 |
| 핵심 | 이벤트 상관 분석 | 플레이북 실행 |
| 주요 기능 | 수집, 분석, 경고 | 연동, 자동화, 대응 |

※ SIEM도 일부 자동 대응 기능을 가질 수 있고, SOAR도 이벤트를 분석할 수 있으므로 완전히 분리된 기능만 수행하는 것은 아닙니다.

# 38. DLP (Data Loss Prevention)

## 개념

DLP는 조직 내부의 중요 정보나 개인정보가 허가되지 않은 경로로 유출되는 것을 탐지하고 차단하는 기술입니다.

### 감시 대상

- 이메일 첨부파일
- 웹 업로드
- USB 저장
- 클라우드 파일 전송
- 메신저 전송

### 주요 기능

- 민감 정보 탐지
- 유출 시도 차단
- 정책 위반 경고
- 관리자 승인 절차

### 예시

개인정보가 포함된 문서를 외부 이메일로 전송하려는 경우 이를 탐지하여 차단합니다.

### 핵심

**데이터 유출 경로를 감시하고 차단**

---

# 39. DRM (Digital Rights Management)

## 개념

DRM은 디지털 문서와 콘텐츠에 접근 권한 및 사용 제한을 적용하여 허가되지 않은 이용을 방지하는 기술입니다.

### 주요 기능

- 문서 암호화
- 열람 권한 제어
- 복사 제한
- 인쇄 제한
- 공유 제한

### 활용

- 기업 내부 기밀 문서
- 전자책
- 유료 동영상
- 디지털 콘텐츠 보호

### 핵심

**파일 또는 콘텐츠의 사용 권한 관리**

## DLP와 DRM 비교

| 구분 | DLP | DRM |
|---|---|---|
| 주요 목적 | 데이터 유출 방지 | 콘텐츠 사용 권한 관리 |
| 보호 방식 | 유출 경로 감시·차단 | 암호화 및 권한 제어 |
| 핵심 | 외부 반출 방지 | 허가되지 않은 이용 제한 |

---

# 40. 템퍼프루핑 (Tamperproofing)

## 개념

템퍼프루핑은 소프트웨어의 코드나 실행 파일이 무단으로 변경되는 것을 어렵게 만들거나, 위·변조가 발생했을 때 이를 탐지하고 대응하도록 하는 기술입니다.

### 주요 목적

- 무단 코드 수정 방지
- 위·변조 탐지
- 소프트웨어 무결성 보호
- 불법적인 분석 및 조작 방해

## 주요 기법

### 1. 체크섬 및 해시 검증

실행 파일의 해시 값을 비교하여 원본과 달라졌는지 검사합니다.

### 2. 코드 난독화

코드의 구조와 의미를 분석하기 어렵게 변경합니다.

### 3. 안티 디버깅

디버거를 이용한 분석이나 조작을 탐지하고 대응합니다.

### 4. 자가 검증

프로그램 내부에 무결성 확인 기능을 배치합니다.

## 관련 기술 비교

| 기술 | 핵심 |
|---|---|
| 워터마킹 | 콘텐츠 식별 정보 삽입 |
| DRM | 콘텐츠 사용 권한 관리 |
| 템퍼프루핑 | 소프트웨어 무단 변조 방지 |

---

# 41. 취약점 관리 - CVE, CVSS, CWE

## 41-1. CVE

Common Vulnerabilities and Exposures

공개적으로 알려진 보안 취약점을 식별하기 위한 고유 식별 체계입니다.

### 핵심

**취약점 식별 번호**

### 예시

~~~text
CVE-2021-44228
~~~

## 41-2. CVSS

Common Vulnerability Scoring System

취약점의 심각도를 평가하기 위한 점수 체계입니다.

### 특징

- 취약점 위험도 평가
- 기본 점수는 0.0 ~ 10.0
- 취약점 대응 우선순위 결정에 활용

### 핵심

**취약점 심각도 점수**

## 41-3. CWE

Common Weakness Enumeration

소프트웨어와 하드웨어의 보안 약점 유형을 분류하는 체계입니다.

### 예시

| CWE | 약점 유형 |
|---|---|
| CWE-89 | SQL Injection |
| CWE-79 | XSS |
| CWE-120 | 버퍼 복사 시 크기 검사 미흡 |

### 핵심

**보안 약점의 종류 및 원인 분류**

## CVE, CVSS, CWE 비교

| 구분 | 역할 |
|---|---|
| CVE | 취약점을 식별 |
| CVSS | 취약점의 심각도를 평가 |
| CWE | 취약점의 원인이 되는 약점 유형 분류 |

| 보안 대응 자동화 | SOAR |

| 핵심 표현 | 정답 |
|---|---|
| 정보 유출 경로 차단 | DLP |
| 파일 사용 권한 관리 | DRM |
| 소프트웨어 위·변조 방지 | Tamperproofing |

## 취약점 관리

| 핵심 표현 | 정답 |
|---|---|
| 취약점 식별 번호 | CVE |
| 취약점 심각도 점수 | CVSS |
| 보안 약점 유형 분류 | CWE |

## 반드시 구분할 개념

### 1. Backdoor vs Rootkit

- Backdoor: 숨겨진 접근 통로
- Rootkit: 공격자의 존재와 악성 활동 은폐

### 2. Flyweight vs Proxy

- Flyweight: 객체 공유로 메모리 절약
- Proxy: 대리 객체로 접근 제어

### 3. Adapter vs Bridge

- Adapter: 호환되지 않는 인터페이스 연결
- Bridge: 추상화와 구현 분리

### 4. EDR vs XDR vs MDR

- EDR: 단말 중심 탐지·대응
- XDR: 여러 보안 영역 통합 탐지·대응
- MDR: 전문 업체가 제공하는 관리형 탐지·대응 서비스

### 5. SIEM vs SOAR

- SIEM: 로그와 이벤트 분석
- SOAR: 보안 대응 자동화

### 6. DLP vs DRM vs Tamperproofing

- DLP: 외부 유출 방지
- DRM: 사용 권한 관리
- Tamperproofing: 위·변조 탐지 및 방지

### 7. RTO vs RPO

- RTO: 복구까지 걸리는 시간
- RPO: 허용 가능한 데이터 손실 기간

### 8. CVE vs CVSS vs CWE

- CVE: 어떤 취약점인가?
- CVSS: 얼마나 심각한가?
- CWE: 어떤 종류의 약점인가?

### 9. 외부 스키마 vs 개념 스키마 vs 내부 스키마

- 외부: 사용자 관점
- 개념: 전체 논리 구조
- 내부: 물리적 저장 구조

### 10. Kerberos vs OAuth

- Kerberos: 티켓 기반 사용자 및 서비스 인증
- OAuth: 특정 자원에 대한 접근 권한 위임
