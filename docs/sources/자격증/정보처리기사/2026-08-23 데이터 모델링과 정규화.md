# 2026-08-23 정보처리기사 공부 내용

## 데이터 모델링 절차와 요소

- 데이터 모델링 절차: 개념 → 논리 → 물리 데이터 모델링 (2020년 2회 기출)
- 데이터 모델의 3요소: 연산, 데이터 구조(개체와 개체 간의 관계), 제약조건
- 연산: 실제 데이터를 처리하는 작업에 대한 명세
- 데이터 구조: 논리 데이터 모델에서 데이터를 어떻게 나타낼지 표현
- 제약조건: 데이터베이스에 저장될 수 있는 실제 데이터의 논리적인 범위 (2021년 1회 기출)

## 개념 데이터 모델링과 ER 모델

개념 데이터 모델링은 현실 세계를 데이터베이스에 저장할 수 있는 구조로 표현한 도구다.

개체-관계 모델(Entity-Relationship Model)은 피터 첸이 제안한 개념적 데이터 모델이다. 개체와 개체 간의 관계를 이용해 현실 세계를 개념적 구조로 표현하며 핵심 요소는 개체, 속성, 관계다.

개체-관계 다이어그램(ER 다이어그램)은 개체-관계 모델을 이용해 현실 세계를 개념적으로 모델링한 결과물을 그림으로 표현한 것이다.

### 유도 속성

과일의 가격과 할인율을 통해 판매가격을 알 수 있을 때 판매가격과 같이 다른 속성으로 계산할 수 있는 값을 유도 속성이라고 한다.

### 관계

관계는 개체와 개체가 맺고 있는 의미 있는 연관성이며 개체 집합들 사이의 대응, 즉 매핑을 의미한다. 전통적인 ER 다이어그램에서 관계는 마름모, 개체는 사각형으로 표현한다.

예: 고객 — 구매 — 빵 (`구매`를 관계로 표현)

## 논리 데이터 모델링

- 엔터티: 관리할 대상이 되는 실체
- 속성: 관리할 정보의 구체적 항목
- 관계: 엔터티 간의 대응 관계

### 데이터 모델의 종류

1. 계층 데이터 모델: 트리 형태, 개체 간 상하 관계, 부모와 자식 구조
2. 네트워크 데이터 모델: 논리적 구조가 그래프 형태이며 구조가 복잡함
3. 관계 데이터 모델: 일반적으로 많이 사용되며 논리적 구조가 2차원 테이블 형태

### 관계 데이터 모델의 기본 용어

- 튜플: 릴레이션의 행
- 애트리뷰트(속성): 릴레이션의 열
- 도메인: 하나의 속성이 가질 수 있는 모든 값의 집합. 예: 성별
- 차수: 하나의 릴레이션에서 속성의 전체 개수
- 카디널리티: 하나의 릴레이션에서 튜플의 전체 개수
- 2021년 1회 실기에서 카디널리티와 차수를 묻는 문제 출제

### 릴레이션의 특성

- 튜플의 유일성: 동일한 튜플이 존재할 수 없다.
- 튜플의 무순서: 튜플 사이의 순서는 무의미하다.
- 속성의 무순서: 속성 사이의 순서는 무의미하다.
- 속성의 원자성: 속성 값으로 원자 값만 사용할 수 있다.

## 관계 데이터 연산

원하는 데이터를 얻기 위해 릴레이션에 필요한 처리 요구를 수행하는 것이다.

- 관계대수: 데이터 처리 과정을 순서대로 기술하는 절차적 방식
- 관계해석: 원하는 데이터가 무엇인지만 기술하는 비절차적 방식

2022년 2회 실기: 관계해석은 관계 데이터 연산을 표현하는 방법으로 원하는 정보를 계산 수식으로 정의한다. 관계 데이터 모델 제안자인 Codd가 수학적 기반을 두고 제안했다. 튜플 관계해석과 도메인 관계해석이 있다.

### 관계대수 연산자

- 일반 집합 연산자: 합집합, 교집합, 차집합, 카티션 프로덕트
- 카티션 프로덕트: 두 릴레이션의 각 튜플을 모두 연결한 새로운 튜플 반환
- 순수 관계 연산자: 셀렉트, 프로젝트, 조인, 디비전
- 프로젝트: 릴레이션 R에서 지정한 속성으로 구성된 결과 반환
- 예: 고객 릴레이션에서 이름과 등급 속성만 반환

2022년 3회 실기에서 합집합, 차집합, 카티션 프로덕트, 프로젝트, 조인 관계대수를 묻는 문제 출제.

2020년 3회: 릴레이션 A, B가 있을 때 B 조건에 맞는 것들만 A에서 꺼내 프로젝션하는 연산은 디비전으로 정리함.

## 키

키는 릴레이션에서 튜플들을 유일하게 구별하는 속성 또는 속성들의 집합이다.

- 유일성: 하나의 릴레이션에서 모든 튜플은 서로 다른 키 값을 가져야 한다.
- 최소성: 꼭 필요한 최소한의 속성으로만 키를 구성한다.

### 키의 종류

- 슈퍼키: 유일성을 만족하는 속성 또는 속성 집합
- 후보키: 유일성과 최소성을 만족하는 속성 또는 속성 집합
- 기본키: 후보키 중 기본적으로 사용하기 위해 선택한 키
- 대체키: 기본키로 선택되지 않은 나머지 후보키

## 무결성 제약조건

무결성은 데이터를 정확하고 유효하게 유지하는 것이며, 무결성 제약조건은 데이터를 일관된 상태로 유지하기 위한 규칙이다.

- 개체 무결성: 기본키를 구성하는 모든 속성은 NULL 값을 가질 수 없다.
- 참조 무결성: 외래키는 참조할 수 없는 값을 가질 수 없다.

## 정규화와 이상 현상

정규화는 중복성을 최소화하고 정보의 일관성을 보장하기 위한 개념이다. 관계 구조가 바람직한지 판단하고 필요하면 분해한다. 정규화된 데이터 모델은 정확성, 일치성, 단순성, 비중복성과 안정성을 높인다.

정규화 수준이 높아지면 유연성과 정확성이 높아질 수 있지만 물리적 접근이 복잡해지고 조인이 늘어날 수 있다.

### 논리 데이터 모델 검증 포인트

1. 업무 시스템의 사용자 요구사항과 데이터 흐름이 누락되지 않았는가?
2. 모델링 표준을 준수했는가?
3. 중복 회피를 위한 정규화를 수행했는가?

### 이상 현상

- 삽입 이상: 새 데이터를 삽입하기 위해 불필요한 데이터도 함께 삽입해야 하는 문제
- 갱신 이상: 중복된 튜플 중 일부만 수정해 데이터 불일치가 생기는 문제
- 삭제 이상: 튜플을 삭제할 때 필요한 데이터까지 손실되는 문제

2022년 1회 실기에서 삭제 이상 서술 문제 출제.

### 정규형

- 제1정규형: 반복 속성이나 그룹 속성을 제거하고 모든 속성이 하나의 원자값을 갖게 한다.
- 제2정규형: 부분 함수 종속을 제거하고 일반 속성이 기본키 전체에 완전 함수 종속되게 한다.
- 제3정규형: 기본키에 대한 이행 함수 종속을 제거한다.
- BCNF: 모든 결정자가 후보키인 정규형
- 제4정규형: 다치 종속을 제거한 정규형
- 제5정규형: 조인 종속을 다루는 정규형

## 물리 데이터 모델링

설계 단계의 정보 요건을 특정 DBMS에 맞춰 실제 저장 구조로 표현한다. 테이블, 칼럼, 기본키, 외래키, 뷰와 인덱스 등을 설계한다.

### 반정규화

정규화로 인해 조회 성능 문제가 생기는 경우, 성능을 위해 의도적으로 데이터 중복이나 통합을 허용하는 설계 방식이다.

- 2020년 1회: 반정규화의 의미를 서술하는 문제
- 2021년 1회: 반정규화 용어를 적는 문제

### 물리 데이터 저장소 구성

물리 데이터 저장소 설계에 따라 실제 데이터가 저장될 공간을 구성한다.

예상 문제: 참조 무결성이란 관련 테이블에서 외래키 값이 참조 대상 테이블의 기본키 값으로 존재하거나 허용된 경우 NULL이어야 한다는 규칙이다.

### 인덱스 설계

인덱스는 테이블 검색 속도를 높이기 위한 자료구조로 책의 색인과 비슷한 역할을 한다.

- 인덱스가 많으면 삽입·수정·삭제 시 유지 비용과 저장 공간이 증가한다.
- 필요한 칼럼을 중심으로 설계한다.
- 테이블이 매우 작거나 검색 결과가 대부분의 행을 차지하면 효과가 낮을 수 있다.
- 선택도에 관한 고정 수치는 DBMS와 데이터 분포 및 실행 계획에 따라 달라질 수 있다.

### 뷰 설계

뷰는 하나 이상의 테이블을 기반으로 정의한 가상 테이블이다.

- `OR REPLACE`: 기존 뷰가 있으면 정의를 교체
- `FORCE`: 기본 객체가 없어도 뷰 정의 생성을 허용하는 Oracle 옵션
- `NOFORCE`: 기본 객체가 존재해야 뷰 생성
- `WITH CHECK OPTION`: 뷰를 통한 변경이 뷰의 조회 조건을 만족하도록 제한

## 예상 문제

지정한 칼럼 값의 순서대로 데이터 행을 물리적으로 가까운 블록에 저장하여 액세스 효율을 높이는 방법은 무엇인가?

확인할 답: 클러스터링(또는 DBMS 문맥에 따른 클러스터드 인덱스). 정확한 출제 문구와 선택지를 확인해 구분할 것.
