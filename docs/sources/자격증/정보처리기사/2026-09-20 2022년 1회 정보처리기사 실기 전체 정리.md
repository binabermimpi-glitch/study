# 1. RAID 0 🔥

## 문제

다음 설명에 맞는 RAID 단계를 쓰시오.

- 두 개 이상의 하드디스크를 병렬로 연결해 하나의 하드디스크처럼 이용하는 기술이다.
- 스트라이프 방식으로 구현한다.
- 데이터가 분산되어 저장되기 때문에 하나의 하드디스크에 문제가 생기면 전체 데이터 사용에 문제가 발생할 수 있다.

## 정답

**RAID 0**

## 개념

여러 디스크에 데이터를 나누어 동시에 저장하는 **스트라이핑(Striping)** 방식이다.
```text
Disk 1 : A1  A3  A5
Disk 2 : A2  A4  A6
```

### 장점

- 읽기/쓰기 속도 향상
- 디스크 용량을 모두 활용

### 단점

- 장애 복구 기능 없음
- 디스크 하나가 고장 나도 전체 데이터 손실 가능
```text
RAID 0
→ Striping
→ 성능 ↑
→ 복구 기능 X
```

---

# RAID 단계 비교

## RAID 0
```text
Striping
성능 향상
복구 기능 X
```

## RAID 1

두 개 이상의 디스크에 같은 데이터를 복제한다.
```text
Mirroring
→ 동일 데이터 복사
```

장애 안정성이 높지만 실제 사용 가능한 용량이 줄어든다.

---

## RAID 2

오류 검출 및 정정을 위해 \*\*해밍 코드(Hamming Code)\*\*를 사용한다.

---

## RAID 3

데이터를 여러 디스크에 분산하고 **별도의 한 디스크를 패리티 전용**으로 사용한다.

일반적으로 바이트 단위 스트라이핑 개념과 연결된다.

---

## RAID 4

RAID 3과 유사하지만 **블록 단위**로 데이터를 분산 저장하며 별도의 패리티 디스크를 둔다.

---

## RAID 5

3개 이상의 디스크를 사용하며 **패리티 정보를 여러 디스크에 분산 저장**한다.
```text
RAID 5
→ 분산 패리티 1개
```

디스크 하나의 장애까지 복구 가능하다.

---

## RAID 6

RAID 5와 비슷하지만 **서로 다른 두 개의 패리티 정보를 분산 저장**한다.
```text
RAID 6
→ 이중 분산 패리티
→ 디스크 2개 장애까지 견딜 수 있음
```

### 주의

`패리티 하나를 두 디스크에 복사한다`기보다는:
```text
서로 다른 2개의 패리티 정보를 분산 저장
```

한다고 이해하는 것이 정확하다.

---

# RAID 초압축
```text
RAID 0
→ Striping / 복구 X

RAID 1
→ Mirroring

RAID 2
→ Hamming Code

RAID 3
→ 전용 패리티 / 바이트 단위

RAID 4
→ 전용 패리티 / 블록 단위

RAID 5
→ 분산 패리티 1개

RAID 6
→ 분산 패리티 2개
```

# 2. REDO / UNDO 🔥🔥

## 문제

로그 기반 회복 기법에서 사용되는 명령이다.

(1) 트랜잭션 로그를 이용하여 오류가 발생한 트랜잭션을 재실행하여 복구한다.

(2) 트랜잭션 로그를 이용하여 오류와 관련된 내용을 취소하여 복구한다.

## 정답

(1) **REDO**

(2) **UNDO**

---

# REDO

이미 완료된 작업을 로그를 이용하여 다시 수행한다.
```text
REDO
→ 다시 실행
```

---

# UNDO

정상 완료되지 않은 트랜잭션의 변경 내용을 이전 상태로 되돌린다.
```text
UNDO
→ 취소 / 이전 상태 복원
```

---

# 즉시 갱신 / 지연 갱신

## 즉시 갱신

트랜잭션이 완료되기 전에도 DB에 변경 내용이 반영될 수 있다.
```text
Immediate Update
→ UNDO + REDO
```

## 지연 갱신

트랜잭션이 완료되기 전에는 DB에 실제 변경 내용을 반영하지 않는다.
```text
Deferred Update
→ REDO
→ UNDO 불필요
```

---

# 트랜잭션 ACID
```text
A = Atomicity
C = Consistency
I = Isolation
D = Durability
```

## 원자성

모두 수행되거나 모두 수행되지 않아야 한다.
```text
All or Nothing
```

COMMIT / ROLLBACK과 관련이 깊다.

## 일관성

트랜잭션 전후 데이터베이스가 일관된 상태를 유지해야 한다.

## 격리성

여러 트랜잭션이 서로 영향을 주지 않고 독립적으로 수행되어야 한다.

## 영속성

완료된 트랜잭션의 결과는 영구적으로 저장되어야 한다.

# 3. 삭제 이상 🔥🔥

## 문제

데이터베이스 이상 현상 중 삭제 이상에 대해 간략히 서술하시오.

## 정답

**한 튜플을 삭제할 때 삭제하려는 정보뿐 아니라 필요한 다른 정보까지 함께 삭제되는 현상이다.**

---

# 이상 현상

## 삽입 이상

새로운 데이터를 삽입하기 위해 불필요한 데이터까지 같이 입력해야 하는 현상
```text
원하는 데이터만 삽입할 수 없음
→ 삽입 이상
```

## 갱신 이상

중복된 데이터 중 일부만 수정되어 데이터 사이에 불일치가 발생하는 현상
```text
일부만 변경
→ 모순 발생
```

## 삭제 이상

하나의 데이터를 삭제하면서 필요한 다른 정보도 함께 삭제되는 현상
```text
삭제
→ 의도하지 않은 정보 손실
```

## 해결
```text
이상 현상
→ 정규화로 감소
```

# 4. TKIP ⭐

## 문제

아래 임시 키 무결성 프로토콜의 영문 약어를 쓰시오.

IEEE 802.11 무선 네트워크에서 사용되는 보안 프로토콜이며 WEP를 하드웨어 교체 없이 대체하기 위해 고안되었다.

## 정답

**TKIP(Temporal Key Integrity Protocol)**

### 철자 주의
```text
Integrity O
Integerity X
```

## 개념

WEP의 보안 취약점을 개선하기 위해 WPA에서 사용되었던 무선 보안 기술이다.
```text
WEP
↓ 개선
TKIP
↓ 더 발전
AES 기반 방식
```

---

# 무선 보안 같이 알아두기

## WEP

초기의 무선 LAN 보안 방식
```text
보안 취약
```

## WPA

WEP의 문제점을 개선
```text
WPA
→ TKIP 사용
```

## WPA2

보다 강력한 보안 사용
```text
WPA2
→ AES 기반 CCMP
```

## WPA3

WPA2보다 강화된 최신 무선 보안 방식

---

# 초압축
```text
WEP
→ 오래되고 취약

WPA
→ TKIP

WPA2
→ AES / CCMP

WPA3
→ 강화된 최신 방식
```

이 정도까지 알아두면 TKIP 하나만 따로 외우는 것보다 훨씬 기억하기 쉽다.

# 9. ISMS 🔥

## 문제

기업이 주요 정보자산을 보호하기 위해 수립·관리·운영하는 정보보호 관리체계가 인증 기준에 적합한지를 심사하여 인증을 부여하는 제도

## 정답

**ISMS(Information Security Management System)**

## 개념

조직이 정보자산을 체계적으로 보호하기 위한 관리체계를 갖추고 있는지를 인증하는 제도이다.

---

# PIMS도 같이 알아두기 ⭐

## PIMS

**Personal Information Management System**

개인정보 보호를 위한 관리체계를 의미한다.
```text
ISMS
→ 정보보호 관리체계

PIMS
→ 개인정보보호 관리체계
```

국내에서는 과거 ISMS와 PIMS가 별도 인증으로 운영되었지만 이후 **ISMS-P**로 통합된 형태가 중요하다.

## ISMS-P
```text
Information Security Management System
+
Personal Information
```

즉:
```text
정보보호
+
개인정보보호
→ ISMS-P
```

시험에서는 개념 구별 정도로 알아두면 된다.

# 13. ORDER BY 🔥🔥

## 문제

다음 결과가 출력되도록 SQL문을 완성하시오.
```text
NAME    SCORE
LEE     95
KIM     90
SONG    60
```
```sql
SELECT NAME, SCORE
FROM 성적
(1) BY (2) (3);
```

## 정답
```text
(1) ORDER
(2) SCORE
(3) DESC
```

## 완성
```sql
SELECT NAME, SCORE
FROM 성적
ORDER BY SCORE DESC;
```

---

# ORDER BY

## 오름차순
```sql
ORDER BY SCORE ASC;
```

## 내림차순
```sql
ORDER BY SCORE DESC;
```

---

# SQL 기본 작성 순서
```sql
SELECT
FROM
WHERE
GROUP BY
HAVING
ORDER BY
```

암기:
```text
조회
→ 테이블
→ 행 조건
→ 그룹
→ 그룹 조건
→ 정렬
```

예:
```sql
SELECT 학과, AVG(점수)
FROM 학생
WHERE 이름 LIKE '이%'
GROUP BY 학과
HAVING AVG(점수) >= 80
ORDER BY AVG(점수) DESC;
```

### WHERE와 HAVING
```text
WHERE
→ 그룹화 전 행 조건

HAVING
→ GROUP BY 이후 그룹 조건
```

# 14. Python 리스트 메서드 🔥

## 문제

다음 설명과 관련된 Python 함수를 쓰시오.

(1) 리스트를 확장해주는 역할

(2) 리스트에서 요소를 꺼내면서 해당 요소를 삭제하고 반환

# extend()

다른 반복 가능한 객체의 요소들을 하나씩 리스트 뒤에 추가한다.

### 중요 수정

```text

```

```python
a = [1, 2]
a.append([3, 4])
```

결과:
```text
[1, 2, [3, 4]]
```

반면:
```python
a = [1, 2]
a.extend([3, 4])
```

결과:
```text
[1, 2, 3, 4]
```

## 핵심
```text
append()
→ 객체 하나를 통째로 추가

extend()
→ 여러 요소를 풀어서 추가
```

# 16. Java Runnable / Thread 🔥🔥

## 문제

다음 Java 코드 중 빈칸에 들어갈 알맞은 코드를 작성하시오.
```java
class Car implements Runnable {
    int a;

    public void fun() {
        System.out.println("func call");
    }
}

public class Main {

    public static void main(String[] args) {

        Thread t1 = new Thread(new _______());

        t1.start();
    }
}
```

## 정답

**Car**

완성:
```java
Thread t1 = new Thread(new Car());
```

---

# 객체 생성 과정
```java
new Car()
```

먼저 Car 객체를 만든다.
```text
Car 객체
```

Car는:
```java
implements Runnable
```

이므로 `Runnable` 타입으로 Thread 생성자에 전달할 수 있다.
```java
new Thread(new Car());
```

---

# 원래 정상적인 Runnable 구현은
```java
class Car implements Runnable {

    @Override
    public void run() {
        System.out.println("func call");
    }
}
```

처럼 `run()`을 구현해야 한다.

그리고:
```java
Thread t1 = new Thread(new Car());
t1.start();
```

를 호출하면 내부적으로:
```text
start()
↓
새로운 스레드 생성
↓
run()
```

이 실행된다.

---

# 중요 주의 ⚠️

네가 적어준 코드에는:
```java
public void fun()
```

만 있고
```java
public void run()
```

이 없다.

`Runnable` 인터페이스는:
```java
void run();
```

을 구현해야 한다.

따라서 **문제의 빈칸 답은&#x20;****`Car`****가 맞지만**, 네가 적은 코드가 문제 원문 그대로라면 `Car` 클래스는 `run()`을 구현하지 않아 컴파일 오류가 발생한다.

시험 문제 원본에서는 `fun()`이 아니라 `run()`이었거나 다른 코드가 생략되었을 가능성이 있다.

---

# Thread 상속 방식과 비교

## Thread 상속
```java
class MyThread extends Thread {

    @Override
    public void run() {
    }
}

MyThread t = new MyThread();
t.start();
```

## Runnable 구현
```java
class Car implements Runnable {

    @Override
    public void run() {
    }
}

Runnable r = new Car();
Thread t = new Thread(r);
t.start();
```

또는:
```java
Thread t = new Thread(new Car());
t.start();
```

## 핵심
```text
extends Thread
→ 내가 Thread 객체

implements Runnable
→ 실행할 작업을 정의
→ Thread 객체에 전달
```

# 17. Java 객체 참조와 메서드 호출 🔥🔥

## 문제 코드
```java
class A {
    int a;
    int b;
}

public class Main {

    static void func1(A a) {
        a.a *= 10;
    }

    static void func2(A a) {
        a.a += a.b;
    }

    public static void main(String[] args) {

        A a = new A();
        a.a = 100;

        func1(m);

        a.b = a.a;

        func2(a);

        System.out.println(a.a);
    }
}
```

## 중요 확인

이미지에는:
```java
func1(m);
```

이라고 되어 있다.

현재 보이는 코드에는 `m`의 선언이 없다.

따라서 현재 보이는 코드가 전부라면:
```text
m 선언 없음
→ 컴파일 오류
```

이다.

---

# 만약 `m`이 `a`와 같은 객체를 참조한다면

예:
```java
A m = a;
```

라고 앞에서 선언되어 있었다면:
```text
a ───┐
     ↓
   A 객체
     ↑
m ───┘
```

둘 다 같은 객체를 가리킨다.

초기:
```text
a 필드 = 100
b 필드 = 0
```

---

## func1(m)
```java
static void func1(A a) {
    a.a *= 10;
}
```
```text
100 × 10
= 1000
```

객체:
```text
a = 1000
b = 0
```

---

## a.b = a.a
```text
a = 1000
b = 1000
```

---

## func2(a)
```java
static void func2(A a) {
    a.a += a.b;
}
```

즉:
```text
1000 + 1000
= 2000
```

따라서 `m`과 `a`가 같은 객체라면:
```text
출력 = 2000
```

---

# 핵심

# 20. C 소수 판별 + 최대 소수 약수 🔥🔥

## 문제
```c
int isPrime(int number) {

    int i;

    for(i = 2; i < number; i++) {

        if(number % i == 0)
            return 0;
    }

    return 1;
}

int main(void) {

    int number = 13195;
    int max_div = 0;
    int i;

    for(i = 2; i < number; i++)

        if(isPrime(i) == 1 && number % i == 0)

            max_div = i;

    printf("%d", max_div);

    return 0;
}
```

## 정답
```text
29
```

---

# isPrime()

소수를 판별하는 함수이다.
```text
return 1
→ 소수

return 0
→ 소수 아님
```

예:
```text
5 % 2 != 0
5 % 3 != 0
5 % 4 != 0

→ isPrime(5) = 1
```

반면:
```text
6 % 2 = 0

→ isPrime(6) = 0
```

---

# 핵심 조건
```c
if(isPrime(i) == 1 && number % i == 0)
```

첫 번째:
```text
isPrime(i) == 1
→ i가 소수인가?
```

두 번째:
```text
number % i == 0
→ i가 13195의 약수인가?
```

따라서:
```text
소수이면서
13195의 약수
```

를 찾는다.

---

# 13195 소인수분해
```text
13195 = 5 × 7 × 13 × 29
```

따라서 소수 약수는:

로 덮어쓴다.

```text
→ max_div = 7

```

29보다 큰 소수는 존재하지만:


이들은 13195를 나누어떨어지게 하지 않는다.

따라서 최종값:
