# 자바 메소드와 객체 생성

## 금일 학습 요약

JVM이 물리 메모리를 직접 관리하는 것이 아니라 운영체제가 제공하는 독립적 가상 주소 공간에서 실행된다는 구조를 정리했습니다. 이어서 클래스의 구성 요소인 필드와 메소드, `static`과 non-static의 사용 기준, 메소드 오버로딩, 매개변수 전달 및 자동 형변환을 다루었습니다.

반환형 메소드의 `return` 흐름과 타입 일치 조건을 확인하고, 모든 클래스의 상위 클래스인 `Object` 및 객체 생성 시 힙 영역과 참조 변수 사이에 형성되는 관계를 설명했습니다. 또한 생성자, 인스턴스 필드, `static` 필드, DTO와 `record` 타입의 기본 구조를 실습 중심으로 확장했습니다.

## JVM 가상 메모리와 프로세스

> JVM은 물리 RAM을 직접 점유, 관리하지 않으며, 운영체제가 각 JVM 프로세스에 할당한 독립적 가상 주소 공간에서 실행됩니다.

운영체제는 물리 메모리와 페이지 파일의 매핑을 관리합니다. JVM은 운영체제로부터 확보한 가상 주소 공간을 힙, 스택, 클래스 관련 영역 등 실행 메모리 용도로 사용합니다. 따라서 JVM이 실행될 때마다 실제 RAM 영역을 별도로 생성한다는 표현은 정확하지 않습니다.

하나의 자바 클래스를 실행하면 하나의 JVM 프로세스가 동작하며, 여러 프로그램을 실행하면 각각 별도의 JVM 프로세스와 가상 주소 공간이 만들어집니다. 각 프로세스의 주소는 서로 독립적이며, 이 실행 상태는 운영체제가 관리합니다.

| 구분 | 관리 주체 | 역할 |
|---|---|---|
| 물리 메모리(RAM) | 운영체제 | 실제 메모리 자원을 관리합니다. |
| 페이지 파일 | 운영체제 | 물리 메모리 부족 상황에서 보조 공간으로 활용됩니다. |
| JVM 가상 주소 공간 | 운영체제 할당, JVM 사용 | JVM별 힙, 스택 등의 실행 공간으로 사용됩니다. |
| JVM 프로세스 | 운영체제 | 실행 중인 자바 프로그램 단위로 관리됩니다. |

JVM 메모리 구조를 이해할 때는 “RAM은 OS가 관리하고, JVM은 OS가 제공한 독립적 가상 공간을 사용한다”는 관점이 핵심입니다. JVM 내부에는 힙, 스택, 클래스 관련 영역, 문자열 풀 등 다양한 세부 구조가 존재합니다.

### 핵심 키워드
`JVM` `가상 메모리` `물리 메모리` `페이지 파일` `프로세스`

## static과 non-static 설계

> `static` 멤버는 클래스 단위의 공용, 공통 데이터를 처리하고, non-static 멤버는 객체별로 달라지는 상태와 동작을 처리합니다.

클래스는 사용자 정의 자료형을 만드는 키워드이며, 일반적으로 필드와 메소드로 구성됩니다. 필드는 객체의 상태나 속성을 표현하고, 메소드는 클래스 또는 객체가 수행하는 기능을 표현합니다.

`static`은 특정 객체에 소속되지 않고 클래스에 소속됩니다. 따라서 객체를 생성하지 않아도 클래스 이름을 통해 접근할 수 있습니다. 공통 상수, 누적 개수, 공용 기능처럼 모든 객체가 함께 사용해야 하는 데이터와 기능에 적합합니다.

- `static` 필드는 모든 객체가 공유하는 하나의 값으로 관리됩니다.
- `static` 메소드는 클래스 이름으로 직접 호출할 수 있는 공용 기능입니다.
- non-static 필드와 메소드는 생성된 객체마다 독립적으로 존재합니다.
- 객체별 점수, 이름, 급여, 상태처럼 유동적인 값은 non-static으로 설계하는 것이 적절합니다.

예를 들어 학생별 국어, 영어, 수학 점수와 개인 총점은 각 레코드마다 달라지므로 non-static 데이터입니다. 반면 전체 학생 수, 전체 합계, 공용 기준값처럼 누적되거나 공유되는 데이터는 `static`으로 관리할 수 있습니다.

사과나무를 여러 작업자가 공유하는 상황에서도 나무의 사과 개수는 공용 상태이므로 `static`으로 볼 수 있습니다. 반면 작업자별 수확량이나 개별 상태는 객체마다 달라지므로 non-static 필드가 됩니다.

```java
class AppleTree {
    static int appleCount = 6;
    String workerName;
}
```

API 문서에서 `static`으로 선언된 멤버는 클래스 멤버로 즉시 접근할 수 있는 공용 기능임을 의미합니다. 반면 객체지향 설계에서는 객체별 상태를 다루기 위해 non-static 메소드가 더 빈번하게 사용됩니다.

### 핵심 키워드
`static` `non-static` `클래스 멤버` `인스턴스 멤버` `공용 데이터`

## 메소드 오버로딩과 값 전달

> 메소드 오버로딩은 같은 클래스 안에서 같은 이름의 메소드를 매개변수 타입 또는 개수로 구분하여 여러 개 선언하는 방식입니다.

메소드 선언부의 괄호 안에 작성하는 변수는 파라미터 또는 매개변수입니다. 메소드를 호출할 때 괄호 안에 전달하는 실제 값은 아규먼트 또는 전달값입니다. 호출 시 전달된 아규먼트는 파라미터 타입과 순서에 따라 매핑됩니다.

오버로딩은 반환형만 다르게 선언해서는 성립하지 않습니다. 동일한 메소드 이름을 사용할 경우에는 매개변수의 타입, 개수 또는 순서가 달라야 합니다.

```java
static void printData() {
    System.out.println("기본 출력");
}

static void printData(char ch, int number, double value, String text) {
    System.out.printf("%c %d %.2f %s%n", ch, number, value, text);
}
```

메소드 호출 시 전달값은 파라미터에 맞게 자동 형변환될 수 있습니다. 다만 모든 변환이 가능한 것은 아니며, 일반적으로 더 작은 표현 범위를 더 넓은 표현 범위로 전달하는 경우에 묵시적 형변환이 적용됩니다.

| 전달값 타입 | 파라미터 타입 | 처리 방식 |
|---|---|---|
| `char` | `int` | 유니코드 정수값으로 확장 변환될 수 있습니다. |
| `int` | `double` | `double`로 자동 확장 변환될 수 있습니다. |
| `int` | `char` | 값 손실 가능성이 있으므로 자동 변환되지 않습니다. |
| `double` | `int` | 명시적 형변환 없이는 자동 변환되지 않습니다. |

오버로딩된 메소드가 여러 개일 때는 먼저 정확하게 일치하는 타입의 메소드를 찾습니다. 정확한 타입이 없다면 가능한 범위에서 더 가까운 확장 변환 경로를 선택합니다. 따라서 타입별 변환 순서와 메소드 시그니처를 함께 확인해야 합니다.

`printf`의 포맷 지정자와 전달값도 타입 및 개수가 일대일로 맞아야 합니다. 포맷 문자열의 `%c`, `%d`, `%f`, `%s` 순서와 실제 아규먼트의 순서가 다르면 예외 또는 의도하지 않은 출력이 발생할 수 있습니다.

### 핵심 키워드
`오버로딩` `파라미터` `아규먼트` `자동 형변환` `printf`

## 반환형 메소드와 return

> 반환형 메소드는 선언된 타입의 값을 호출 위치로 반환하며, `return`은 값을 반환하면서 해당 메소드를 즉시 종료합니다.

`void` 메소드는 수행할 명령만 포함하며 호출 위치에 반환할 값이 없습니다. 반면 `int`, `double`, `String` 등 반환형이 선언된 메소드는 해당 타입과 호환되는 값을 `return`해야 합니다.

```java
public static int getA() {
    return 100;
}
```

반환형 메소드는 선언부의 반환 타입, `return` 뒤 값의 타입, 호출 결과를 받는 위치의 타입이 서로 호환되어야 합니다. 이를 통해 메소드 호출 결과가 안전하게 다음 연산이나 대입에 사용됩니다.

```java
int a = getA();
System.out.println(a);
```

- 메소드 선언의 반환형은 호출 결과의 데이터 타입을 결정합니다.
- `return` 값은 선언된 반환형과 호환되어야 합니다.
- 호출 결과를 변수에 대입할 경우 대입 대상의 타입도 호환되어야 합니다.
- `return` 이후의 실행 불가능한 문장은 컴파일 오류가 됩니다.

`return`은 메소드 내부에서만 사용할 수 있는 제어 키워드입니다. 값 없이 사용하면 메소드만 종료하고, 값과 함께 사용하면 값을 반환한 뒤 메소드를 종료합니다. `void` 메소드에서도 조기 종료 목적으로 값 없는 `return;`을 사용할 수 있습니다.

같은 클래스 내부의 `static` 메소드는 메소드 이름만으로 호출할 수 있습니다. 이는 같은 클래스 범위에서 클래스 이름이 생략될 수 있기 때문이며, 필요하다면 `클래스명.메소드명()` 형태로 명시할 수도 있습니다.

### 핵심 키워드
`return` `반환형 메소드` `void` `타입 호환` `메소드 종료`

## Object와 객체 생성

> 자바의 모든 클래스는 명시하지 않아도 `Object` 클래스를 최상위 상위 클래스로 상속하며, 객체 생성은 힙 영역에 인스턴스를 만들고 참조 변수에 주소를 저장하는 과정입니다.

`Object`는 자바 클래스 계층 구조의 최상위 루트 클래스입니다. 개발자가 `extends Object`를 직접 작성하지 않아도, 클래스를 선언하면 내부적으로 `Object`를 상속하는 구조가 적용됩니다.

```java
class UserClass {
    // 내부적으로 Object를 상속합니다.
}
```

`Object` 클래스는 모든 객체가 공통적으로 사용할 수 있는 기본 기능을 제공합니다. 대표적으로 객체 정보 확인, 문자열 표현, 동등성 비교, 해시 코드 확인과 관련된 메소드가 있습니다.

| 주요 메소드 | 역할 |
|---|---|
| `toString()` | 객체를 문자열로 표현합니다. |
| `getClass()` | 실행 중인 객체의 클래스 정보를 반환합니다. |
| `hashCode()` | 객체의 해시 코드 값을 반환합니다. |
| `equals()` | 두 객체의 동등성을 비교합니다. |
| `clone()` | 객체 복제를 위한 기능을 제공합니다. |

객체는 `new` 연산자를 통해 힙 영역에 동적으로 생성됩니다. 힙 영역에 생성된 객체의 시작 주소는 참조 변수에 저장되며, 참조 변수는 객체 자체가 아니라 객체의 주소를 보관합니다.

```java
UserClass user = new UserClass();
System.out.println(user.toString());
```

위 코드에서 `user`는 참조 변수이며, `new UserClass()`는 힙 영역에 객체를 생성합니다. 이후 `user.toString()`처럼 점 연산자를 사용하면 참조 변수가 보관한 주소를 기준으로 객체의 멤버를 찾아 접근합니다.

`toString()`의 기본 구현은 일반적으로 클래스 이름과 해시 코드 기반의 식별 정보를 문자열로 반환합니다. 객체에 의미 있는 정보를 출력하려면 `toString()`을 오버라이딩하여 원하는 문자열 형식으로 재정의할 수 있습니다.

### 핵심 키워드
`Object` `상속` `new` `힙 영역` `참조 변수`

## 클래스, 생성자, 인스턴스 필드

> 생성자는 `new` 연산자와 함께 호출되어 객체를 만들고, 객체가 보유할 인스턴스 필드를 초기화합니다.

클래스는 속성을 나타내는 필드와 기능을 나타내는 메소드로 구성됩니다. 클래스 내부에 `static` 없이 선언된 필드는 인스턴스 필드이며, 객체가 생성될 때마다 객체별로 독립적인 저장 공간을 갖습니다.

```java
public class Person {
    private String name;
    private int age;
}
```

생성자는 클래스와 이름이 같고 반환형을 작성하지 않는 특수한 메소드입니다. 생성자는 객체 생성 직후 필드를 초기화하는 역할을 담당합니다. 생성자도 매개변수 구성에 따라 오버로딩할 수 있습니다.

```java
public Person() {
    this.name = "홍길동";
    this.age = 0;
}

public Person(String name, int age) {
    this.name = name;
    this.age = age;
}
```

`this`는 현재 생성 중이거나 현재 메소드를 실행 중인 객체 자신을 의미합니다. 필드명과 파라미터명이 같을 때 `this.필드명`으로 객체 필드를 명확히 구분합니다.

- 생성자를 하나도 작성하지 않으면 기본 생성자가 자동으로 제공됩니다.
- 매개변수가 있는 생성자를 직접 작성하면 기본 생성자는 자동으로 추가되지 않습니다.
- 객체마다 별도의 값을 가져야 하는 필드는 인스턴스 필드로 선언합니다.
- 인스턴스 메소드는 참조 변수와 점 연산자를 사용하여 호출합니다.

```java
Person hong = new Person("홍길동", 30);
System.out.println(hong.getName());
```

필드를 `private`으로 선언하면 클래스 외부에서 직접 접근할 수 없습니다. 이때 `getter`는 필드 값을 반환하고, `setter`는 검증 규칙을 적용하여 필드 값을 변경하는 통로가 됩니다. 이러한 구조는 객체 내부 상태를 보호하는 캡슐화의 기본 형태입니다.

### 핵심 키워드

## static 필드와 객체별 상태

> 인스턴스 필드는 객체마다 독립적으로 존재하지만, `static` 필드는 클래스당 하나만 생성되어 모든 객체가 공유합니다.

인스턴스 필드는 힙 영역의 각 객체에 포함됩니다. 따라서 같은 클래스에서 여러 객체를 생성하면 객체마다 서로 다른 필드 값을 보유할 수 있습니다. 카운터 객체를 여러 개 만들면 각 객체의 non-static 카운트는 독립적으로 증가합니다.

```java
class Counter {
    private int count;

    public void add() {
        count++;
    }
}
```

반면 `static` 필드는 특정 인스턴스가 아니라 클래스 자체에 소속됩니다. 여러 객체가 생성되어도 저장 공간은 하나이며, 한 객체에서 변경한 값이 다른 객체에서도 동일하게 확인됩니다.

```java
class Counter {
    private static int count;

    public static void add() {
        count++;
    }
}
```

| 구분 | 인스턴스 필드 | static 필드 |
|---|---|---|
| 소속 | 생성된 객체에 소속됩니다. | 클래스에 소속됩니다. |
| 생성 개수 | 객체마다 별도로 생성됩니다. | 클래스당 하나만 생성됩니다. |
| 접근 방식 | `참조변수.필드`로 접근합니다. | `클래스명.필드`로 접근합니다. |
| 적합한 용도 | 객체별 상태를 저장합니다. | 전체 객체가 공유할 상태를 저장합니다. |

참조 변수에 `null`을 대입하면 해당 참조 변수와 객체 사이의 연결이 끊깁니다. 다만 객체가 즉시 삭제되는 것은 아니며, 더 이상 참조되지 않는 객체는 가비지 컬렉터가 판단하는 시점에 회수 대상이 됩니다.

### 핵심 키워드
`인스턴스 필드` `static 필드` `공유 상태` `null` `가비지 컬렉터`

## DTO와 record 타입

> DTO는 계층 간 데이터 전달을 위한 객체이며, `record`는 불변 데이터 객체를 간결하게 정의할 수 있는 자바 문법입니다.

DTO는 Data Transfer Object의 약자로, 계층 간에 데이터를 전달하기 위한 객체입니다. 일반적으로 여러 필드와 생성자, getter, setter를 포함하며 데이터 보관과 전달에 초점을 둡니다.

일반 클래스로 DTO를 구현하면 필드 선언, 생성자, getter, setter를 반복해서 작성해야 합니다. 데이터 변경이 필요한 가변 객체라면 일반 클래스와 setter 기반 구현이 적합할 수 있습니다.

```java
public class MemberDto {
    private String id;
    private String password;
    private String name;

    public MemberDto(String id, String password, String name) {
        this.id = id;
        this.password = password;
        this.name = name;
    }
}
```

`record`는 데이터 중심 객체를 간결하게 선언하기 위한 타입입니다. 레코드 컴포넌트를 선언하면 생성자와 접근자 성격의 메소드가 자동으로 제공되며, 구성 요소는 변경할 수 없는 불변 상태로 다뤄집니다.

```java
public record MemberRecord(
    String id,
    String password,
    String name,
    int age
) {
}
```

- 일반 DTO는 setter를 통해 상태를 변경할 수 있는 가변 객체로 구성할 수 있습니다.
- `record`의 컴포넌트는 기본적으로 불변 상태로 취급됩니다.
- `record`는 데이터 전달용 객체의 반복 코드를 줄이는 데 유용합니다.
- 데이터의 변경 여부와 도메인 요구사항에 따라 일반 클래스와 `record`를 선택해야 합니다.

DTO와 VO는 현업에서 혼용되는 경우도 있지만, 일반적으로 DTO는 데이터 전달 목적의 객체를 뜻하며 VO는 값 자체의 의미와 불변성을 강조하는 객체로 이해할 수 있습니다.

### 핵심 키워드
`DTO` `VO` `record` `불변 객체` `데이터 전달`
