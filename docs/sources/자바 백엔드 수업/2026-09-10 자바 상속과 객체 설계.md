# 자바 상속과 객체 설계

## 금일 학습 요약

이번 학습에서는 배열의 가변 구조, 참조 복사, 문자열 풀(String Pool)을 통해 자바의 참조형 데이터가 메모리에서 어떻게 관리되는지 정리했습니다. 특히 참조형에서 `==`는 두 참조가 같은 객체를 가리키는지 비교하고, 문자열의 내용 비교에는 `equals()`를 사용해야 한다는 점을 확인했습니다. 또한 문자열 리터럴, `new String()`, 문자열 결합 방식에 따른 객체 생성 차이도 함께 살펴보았습니다.

객체지향 설계에서는 절차 중심 코드와 책임 중심 객체 설계를 비교하고, 인터페이스, 추상 클래스, 일반 클래스가 각각 어떤 역할을 가지는지 연결해 학습했습니다. 또한 클래스의 단일 상속, 인터페이스의 다중 구현, 추상 메서드 구현 강제, 중첩 클래스, 봉인 클래스까지 자바의 상속 구조와 타입 설계 방식을 정리했습니다.

## 가변 배열과 참조 복사

> 가변 배열은 행의 개수는 고정한 뒤 각 행의 열 길이를 서로 다르게 생성할 수 있는 2차원 배열 구조입니다. 배열 복사는 동일 객체를 함께 참조하는 얕은 복사와 새로운 배열 객체를 생성하는 독립 복사로 구분할 수 있습니다.

가변 배열은 외부 배열의 각 요소가 서로 다른 길이의 내부 배열 객체를 참조하는 구조입니다.

```java
int[][] scores = new int[3][];

scores[0] = new int[2];
scores[1] = new int[3];
scores[2] = new int[1];
```

`new int[3][]`처럼 외부 배열만 생성하면 각 행의 초기값은 `null`입니다.

따라서 아직 생성하지 않은 내부 배열에 접근하면 `NullPointerException`이 발생할 수 있습니다.

```java
int[][] scores = new int[3][];

System.out.println(scores[0]);      // null
// System.out.println(scores[0][0]); // NullPointerException
```

외부 배열 자체의 범위를 초과하면 `ArrayIndexOutOfBoundsException`이 발생합니다.

| 구분       | 메모리 상태                  | 변경 영향                             |
| -------- | ----------------------- | --------------------------------- |
| 얕은 복사    | 여러 참조 변수가 동일한 배열 객체를 참조 | 한 곳에서 요소를 변경하면 다른 참조에서도 변경 결과가 보임 |
| 별도 배열 복사 | 새로운 배열 객체를 생성           | 배열 자체는 원본과 독립적으로 변경 가능            |

예를 들어 다음은 얕은 복사입니다.

```java
int[] original = {10, 20, 30};
int[] copy = original;

copy[0] = 100;

System.out.println(original[0]); // 100
```

반면 `Arrays.copyOf()`는 새로운 배열 객체를 생성합니다.

```java
int[] original = {10, 20, 30};
int[] copy = Arrays.copyOf(original, original.length);

copy[0] = 100;

System.out.println(original[0]); // 10
```

단, 객체 배열의 경우에는 배열 객체만 새로 생성될 뿐 내부 객체까지 자동으로 복제되는 것은 아닙니다.

### 핵심 키워드

`가변 배열` `지그재그 배열` `NullPointerException` `얕은 복사` `Arrays.copyOf()`

## 문자열 풀과 비교 연산

> 문자열 리터럴은 String Pool에서 공유될 수 있으며, 참조형에서 `==`는 같은 객체를 참조하는지 비교하고 `equals()`는 객체의 논리적 내용이 같은지를 비교합니다.

자바의 문자열 리터럴은 String Pool에서 관리됩니다.

동일한 문자열 리터럴을 여러 변수에 대입하면 기존 문자열 객체를 함께 참조할 수 있습니다.

```java
String str1 = "ABC";
String str2 = "ABC";

System.out.println(str1 == str2);      // true
System.out.println(str1.equals(str2)); // true
```

반면 `new String()`을 사용하면 별도의 `String` 객체가 생성됩니다.

```java
String str1 = "ABC";
String str2 = new String("ABC");

System.out.println(str1 == str2);      // false
System.out.println(str1.equals(str2)); // true
```

여기서 중요한 점은 다음과 같습니다.

* `==` : 두 참조가 같은 객체를 가리키는지 비교
* `equals()` : 객체의 논리적인 내용 비교
* `new String()` : 별도의 문자열 객체 생성
* 문자열 내용 비교에는 일반적으로 `equals()` 사용

문자열 리터럴끼리의 결합은 컴파일 과정에서 하나의 문자열 리터럴로 최적화될 수 있습니다.

```java
String a = "AB" + "C";
String b = "ABC";

System.out.println(a == b); // true가 될 수 있음
```

반면 변수와 문자열을 결합하면 실행 시점에 문자열 연결 작업이 발생할 수 있으므로 참조 동일성을 전제로 작성하면 안 됩니다.

```java
String a = "AB";
String b = a + "C";
String c = "ABC";

System.out.println(b.equals(c)); // true
```

### 핵심 키워드

`String Pool` `==` `equals()` `문자열 리터럴` `new String()`

## 절차지향과 책임 기반 객체 설계

> 절차 중심 코드는 실행 순서를 중심으로 작성하고, 객체지향 설계는 기능과 책임을 객체별로 분리하여 유지보수성과 확장성을 높입니다.

절차 중심 방식에서는 입력, 난수 생성, 조건 판별, 결과 출력과 같은 기능을 하나의 흐름으로 작성하는 경우가 많습니다.

간단한 프로그램에서는 이해하기 쉽지만 기능이 많아질수록 하나의 메서드나 클래스가 지나치게 많은 역할을 담당할 수 있습니다.

객체지향 설계에서는 기능을 실행 순서가 아니라 책임 단위로 나눕니다.

예를 들어 가위바위보 게임을 다음처럼 구분할 수 있습니다.

| 객체         | 주요 책임                |
| ---------- | -------------------- |
| `Computer` | 난수를 이용하여 컴퓨터의 선택 생성  |
| `Player`   | 사용자 입력 처리 및 선택 값 관리  |
| `Referee`  | 두 선택을 비교하여 승패 판정     |
| `GameMain` | 객체를 생성하고 전체 실행 흐름 제어 |

이렇게 책임을 분리하면 변경이 필요한 부분을 특정 객체 중심으로 수정할 수 있습니다.

예를 들어 승패 규칙이 바뀌면 `Referee`를 중심으로 수정하고, 입력 방식이 바뀌면 `Player`를 중심으로 수정할 수 있습니다.

이러한 설계는 SOLID 원칙 중 단일 책임 원칙(SRP)과도 연결됩니다.

단일 책임 원칙은 하나의 클래스가 가능한 한 하나의 주요 책임 또는 하나의 변경 이유를 가지도록 설계하는 것을 의미합니다.

### 핵심 키워드

`절차 중심` `객체지향` `책임 분리` `SRP` `SOLID`

## 인터페이스와 추상 클래스

> 인터페이스는 구현해야 할 공통 규약을 정의하는 데 적합하고, 추상 클래스는 공통 상태와 구현을 제공하면서 일부 기능을 하위 클래스에 구현하도록 강제할 수 있습니다.

자바 클래스는 하나의 클래스만 직접 상속할 수 있습니다.

```java
class Child extends Parent {
}
```

반면 하나의 클래스는 여러 인터페이스를 구현할 수 있습니다.

```java
class Griffin extends Lion implements Eagle, Fantasy {
}
```

예를 들어:

```java
interface Eagle {
    void fly();
}

interface Fantasy {
    void born();
}

class Griffin extends Lion implements Eagle, Fantasy {

    @Override
    public void fly() {
        System.out.println("그리핀이 날아갑니다.");
    }

    @Override
    public void born() {
        System.out.println("그리핀이 태어났습니다.");
    }
}
```

인터페이스의 필드는 기본적으로 `public static final`입니다.

```java
interface Animal {
    String COUNTRY = "주토피아";
}
```

이는 다음과 같은 의미입니다.

```java
public static final String COUNTRY = "주토피아";
```

본문 없이 선언한 인터페이스 메서드는 기본적으로 `public abstract`입니다.

```java
interface Animal {
    void bark();
}
```

다음과 같은 의미로 볼 수 있습니다.

```java
public abstract void bark();
```

또한 인터페이스에는 `default`, `static`, `private` 메서드도 선언할 수 있습니다.

```java
interface Animal {

    void bark();

    default void sleep() {
        System.out.println("자고 있습니다.");
    }

    static void eat() {
        System.out.println("냠냠");
    }
}
```

추상 클래스는 일반 클래스와 마찬가지로 생성자, 인스턴스 필드, 일반 메서드, 정적 메서드를 가질 수 있고 추가로 추상 메서드도 선언할 수 있습니다.

```java
abstract class Score {

    public abstract int getTotal();

    public void printInfo() {
        System.out.println("점수 정보");
    }
}
```

추상 클래스 자체는 직접 객체를 생성할 수 없습니다.

```java
// Score score = new Score(); // 오류
```

추상 메서드를 포함한 클래스를 상속받은 하위 클래스는 해당 메서드를 구현해야 합니다.

```java
class MidtermScore extends Score {

    @Override
    public int getTotal() {
        return 300;
    }
}
```

하위 클래스가 추상 메서드를 구현하지 않는다면 해당 클래스 역시 `abstract`로 선언해야 합니다.

| 구분       | 인터페이스                             | 추상 클래스           |
| -------- | --------------------------------- | ---------------- |
| 선언       | `interface`                       | `abstract class` |
| 직접 객체 생성 | 불가능                               | 불가능              |
| 관계       | `implements`                      | `extends`        |
| 다중 관계    | 여러 인터페이스 구현 가능                    | 클래스 상속은 하나만 가능   |
| 상태       | 주로 상수                             | 인스턴스 필드 보유 가능    |
| 생성자      | 없음                                | 있음               |
| 일반 메서드   | `default`, `static`, `private` 가능 | 자유롭게 선언 가능       |
| 추상 메서드   | 선언 가능                             | 선언 가능            |

추상 메서드를 공통 규약으로 만들면 서로 다른 하위 클래스라도 동일한 방식으로 호출할 수 있습니다.

```java
abstract class Score {
    public abstract int getTotal();
}
```

```java
class MidtermScore extends Score {
    @Override
    public int getTotal() {
        return 300;
    }
}
```

```java
class FinalScore extends Score {
    @Override
    public int getTotal() {
        return 400;
    }
}
```

이렇게 하면 `Score` 타입을 기준으로 서로 다른 객체를 동일한 방식으로 다룰 수 있으며, 이것이 다형성과 연결됩니다.

### 핵심 키워드

`interface` `abstract class` `implements` `extends` `추상 메서드` `다형성`

## 상속 구조와 클래스 제어

> 클래스 상속은 하나의 부모 클래스만 직접 상속할 수 있으며, 인터페이스는 여러 개를 구현할 수 있습니다. 또한 `abstract`, `final`, `sealed` 등의 키워드를 사용하여 상속 구조를 제어할 수 있습니다.

일반적인 클래스 상속은 `extends`를 사용합니다.

```java
class Parent {
}

class Child extends Parent {
}
```

자식 클래스는 접근이 허용된 부모 클래스의 멤버를 물려받아 사용할 수 있습니다.

인터페이스끼리도 `extends`를 사용할 수 있습니다.

```java
interface A {
}

interface B extends A {
}
```

클래스가 인터페이스를 구현할 때는 `implements`를 사용합니다.

```java
class Child extends Parent implements InterfaceA, InterfaceB {
}
```

즉 하나의 클래스는 다음과 같은 형태를 가질 수 있습니다.

```text
하나의 부모 클래스 상속
+
여러 인터페이스 구현
```

상속은 단순히 메서드를 재사용하기 위한 수단으로만 사용하는 것이 좋지 않습니다.

두 클래스가 명확한 `is-a` 관계가 아니라면 상속보다 합성(composition)을 고려하는 것이 더 적절할 수 있습니다.

예를 들어:

```text
Dog is an Animal
→ 상속 관계가 자연스러움

Car has an Engine
→ 필드로 포함하는 합성 관계가 자연스러움
```

상속 범위를 제어하는 대표적인 키워드는 다음과 같습니다.

| 키워드          | 의미                                    |
| ------------ | ------------------------------------- |
| `abstract`   | 직접 객체 생성을 제한하고 하위 클래스에서 구체화하도록 유도     |
| `final`      | 해당 클래스를 더 이상 상속할 수 없게 함               |
| `sealed`     | 지정한 타입만 직접 상속 또는 구현하도록 제한             |
| `non-sealed` | `sealed` 계층의 특정 하위 타입부터 다시 자유로운 상속 허용 |

봉인 클래스는 `permits`를 사용하여 직접 상속을 허용할 클래스를 지정할 수 있습니다.

```java
public abstract sealed class Animal
        permits Carnivore, Herbivore {
}
```

```java
public sealed class Carnivore extends Animal
        permits Tiger, Lion {
}
```

```java
public final class Tiger extends Carnivore {
}
```

`sealed` 타입을 직접 상속하는 하위 클래스는 일반적으로 다음 중 하나를 명시해야 합니다.

```text
final
sealed
non-sealed
```

이러한 구조는 프로그램에서 허용되는 하위 타입을 명확히 제한하고 싶을 때 유용합니다.

### 핵심 키워드

`단일 상속` `다중 구현` `final` `sealed` `permits` `non-sealed` `합성`

## 중첩 클래스의 종류

> 중첩 클래스는 다른 클래스 내부에 선언되는 클래스이며, 선언 위치와 `static` 여부에 따라 생성 방식과 접근 범위가 달라집니다.

클래스 내부에 또 다른 클래스를 선언할 수 있으며 이를 중첩 클래스라고 합니다.

대표적인 형태는 다음과 같습니다.

| 종류        | 선언 위치                 | 특징                 |
| --------- | --------------------- | ------------------ |
| 정적 중첩 클래스 | 클래스 내부에 `static`으로 선언 | 외부 클래스 객체 없이 생성 가능 |
| 내부 클래스    | 클래스 내부에 인스턴스 멤버로 선언   | 외부 클래스 객체가 필요      |
| 로컬 클래스    | 메서드 또는 블록 내부          | 선언된 범위 안에서만 사용     |
| 익명 클래스    | 이름 없이 선언과 동시에 객체 생성   | 일회성 구현에 적합         |

예:

```java
class Outer {

    static class StaticNested {
    }

    class Inner {
    }
}
```

정적 중첩 클래스는 외부 객체 없이 생성할 수 있습니다.

```java
Outer.StaticNested nested =
        new Outer.StaticNested();
```

반면 내부 클래스는 외부 객체가 필요합니다.

```java
Outer outer = new Outer();

Outer.Inner inner =
        outer.new Inner();
```

또는 다음과 같이 작성할 수 있습니다.

```java
Outer.Inner inner =
        new Outer().new Inner();
```

로컬 클래스는 메서드 내부에서만 사용할 수 있습니다.

```java
void test() {

    class LocalClass {
    }

    LocalClass local = new LocalClass();
}
```

익명 클래스는 이름 있는 별도의 클래스를 만들지 않고 인터페이스나 추상 클래스의 구현체를 즉시 생성할 때 사용할 수 있습니다.

```java
Runnable runnable = new Runnable() {
    @Override
    public void run() {
        System.out.println("실행");
    }
};
```

다만 구현 내용이 길어지거나 여러 곳에서 반복된다면 이름 있는 클래스로 분리하는 것이 유지보수에 더 적합합니다.

## 전체 핵심 정리

이번 학습 내용은 다음 흐름으로 연결해서 이해할 수 있습니다.

```text
참조형 데이터
   ↓
배열과 객체는 주소를 통해 참조
   ↓
얕은 복사와 독립 복사의 차이
   ↓
String Pool과 == / equals()
   ↓
객체를 책임 단위로 설계
   ↓
클래스와 인터페이스로 역할 분리
   ↓
extends / implements
   ↓
abstract / final / sealed로 구조 제어
   ↓
다형성을 이용해 공통 타입으로 여러 객체 처리
```

특히 중요한 부분은 다음입니다.

1. 참조형에서 `==`는 같은 객체를 참조하는지 확인합니다.
2. 문자열 내용 비교에는 `equals()`를 사용합니다.
3. 클래스 상속은 하나만 가능하지만 여러 인터페이스를 구현할 수 있습니다.
4. 추상 클래스는 공통 상태와 구현을 제공할 수 있습니다.
5. 인터페이스는 공통 규약을 정의하는 데 적합합니다.
6. `sealed`는 허용된 하위 타입을 제한할 수 있습니다.
7. 상속은 단순 재사용보다 타입 관계와 책임을 기준으로 설계하는 것이 중요합니다.
8. 공통 상위 타입으로 서로 다른 하위 객체를 다루는 구조가 다형성의 핵심입니다.
