# 자바 예외 처리 진행상황 및 핵심 복습

## 1. 예외 계층

자바 예외의 최상위 타입은 `Throwable`이다.

```text
Throwable
 ├─ Error
 └─ Exception
      └─ RuntimeException
```

* `Error` : JVM이나 실행 환경의 심각한 문제
* `Exception` : 프로그램에서 처리 가능한 예외
* `RuntimeException` : 실행 중 발생하는 언체크드 예외

예:

```text
NullPointerException
ArithmeticException
NumberFormatException
IllegalArgumentException
```

---

## 2. try - catch - finally

```java
try {
    // 예외가 발생할 수 있는 코드

} catch (ExceptionType e) {
    // 발생한 예외 처리

} finally {
    // 예외 발생 여부와 관계없이 실행
}
```

기본 흐름:

```text
try
 ↓
예외 발생
 ↓
맞는 catch로 이동
 ↓
catch 실행
 ↓
finally 실행
```

`finally`는 예외 발생 여부와 관계없이 실행되는 마무리 영역이다.

---

## 3. 여러 catch가 있을 때

예외는 위에서부터 검사하며 **처음으로 타입이 맞는 catch 하나만 실행**된다.

```java
try {
    Integer.parseInt("abc");

} catch (NullPointerException e) {
    System.out.println("A");

} catch (NumberFormatException e) {
    System.out.println("B");

} catch (RuntimeException e) {
    System.out.println("C");

} catch (Exception e) {
    System.out.println("D");
}
```

`Integer.parseInt("abc")`는 숫자 형태가 아닌 문자열을 `int`로 바꾸려고 하므로:

```text
NumberFormatException 발생
```

따라서:

```text
B 출력
```

### catch 순서

```text
자식 예외
 ↓
부모 예외
```

순서로 작성해야 한다.

예:

```java
catch (NullPointerException e) {
}

catch (RuntimeException e) {
}

catch (Exception e) {
}
```

부모 예외를 먼저 작성하면 자식 예외까지 부모가 모두 잡아버리기 때문에 아래 `catch`가 도달 불가능해진다.

## 4. throw와 throws

둘은 완전히 다르다.

### throw

```java
throw new ScoreException("점수 오류");
```

> 실제 예외 객체를 생성하고 지금 예외를 발생시킨다.

```text
throw
= 실제 예외 발생
```

---

### throws

```java
void checkScore(int score)
        throws ScoreException {
}
```

> 이 메서드에서 `ScoreException`이 발생할 수 있고, 현재 메서드에서 처리하지 않으면 호출한 쪽으로 넘긴다는 선언이다.

```text
throws
= 예외 발생 가능성을 선언
= 호출자에게 처리 책임을 넘길 수 있음
```

중요:

```text
throws가 있다고 해서
무조건 예외가 발생하는 것은 아니다.
```

실제로 예외가 발생하려면:

```java
throw new ...
```

가 실행되어야 한다.

## 5. 사용자 정의 예외

자바에서 제공하는 예외 외에 직접 의미 있는 예외 타입을 만들 수 있다.

```java
class ScoreException extends Exception {

    public ScoreException(String message) {
        super(message);
    }
}
```

이 코드는:

> `ScoreException`이라는 새로운 예외 종류를 만든다.

`Exception`을 상속했으므로 기존 예외 기능도 사용할 수 있다.

```text
Throwable
   ↑
Exception
   ↑
ScoreException
```

따라서:

```java
e.getMessage()
```

도 사용할 수 있다.

---

## 6. getMessage()가 메시지를 가져오는 과정

```java
throw new ScoreException("점수 오류");
```

여기서:

```text
"점수 오류"
```

를 생성자에 전달한다.

```java
public ScoreException(String message) {
    super(message);
}
```

`super(message)`가 부모 예외 객체에 메시지를 전달한다.

흐름:

```text
new ScoreException("점수 오류")
        ↓
message = "점수 오류"
        ↓
super(message)
        ↓
부모 Throwable 영역에 메시지 저장
```

그 예외가:

```java
catch (ScoreException e)
```

로 전달되면 `e`가 그 예외 객체를 참조한다.

그래서:

```java
e.getMessage()
```

를 호출하면:

```text
"점수 오류"
```

가 반환된다.

핵심:

```text
getMessage()
= Throwable에서 상속받은 기존 메서드

super(message)
= 예외 객체에 메시지를 전달
```

## 7. 사용자 정의 예외 기본 흐름

```java
class AgeException extends Exception {

    public AgeException(String message) {
        super(message);
    }
}
```

```java
static void checkAge(int age)
        throws AgeException {

    if (age < 0) {
        throw new AgeException("나이 오류");
    }

    System.out.println("정상 나이");
}
```

```java
try {
    checkAge(-3);

} catch (AgeException e) {
    System.out.println("예외 발생");
    System.out.println(e.getMessage());
}
```

흐름:

```text
checkAge(-3)
 ↓
age < 0
 ↓
true
 ↓
AgeException 객체 생성
 ↓
throw
 ↓
현재 메서드에서 처리 안 함
 ↓
호출자에게 예외 전파
 ↓
catch (AgeException e)
 ↓
예외 처리
```

출력:

```text
예외 발생
나이 오류
```

## 12. 마지막으로 학습한 예외 재던지기 코드

```java
class LearningException extends Exception {
    public LearningException(String message) {
        super(message);
    }
}

class QuizException extends LearningException {
    public QuizException(String message) {
        super(message);
    }
}

class RetryLimitException extends QuizException {
    public RetryLimitException(String message) {
        super(message);
    }
}

class QuizService {

    static void submit(int score, int retry)
            throws LearningException {

        try {

            if (score < 0 || score > 100) {
                throw new QuizException(
                        "점수 범위 오류"
                );
            }

            if (retry >= 3) {
                throw new RetryLimitException(
                        "재응시 횟수 초과"
                );
            }

            System.out.println("A");

        } catch (RetryLimitException e) {

            System.out.println("B");

            throw e;

        } finally {

            System.out.println("C");
        }

        System.out.println("D");
    }
}

public class Main {

    public static void main(String[] args) {

        try {

            QuizService.submit(80, 3);

            System.out.println("E");

        } catch (QuizException e) {

            System.out.println("F");
            System.out.println(e.getMessage());

        } catch (LearningException e) {

            System.out.println("G");
        }

        System.out.println("H");
    }
}
```

실행 흐름:

```text
submit(80, 3)
 ↓
score 정상
 ↓
retry >= 3
 ↓
RetryLimitException 발생
 ↓
catch (RetryLimitException e)
 ↓
B 출력
 ↓
throw e
 ↓
예외를 다시 호출자에게 던짐
 ↓
finally
 ↓
C 출력
 ↓
D는 실행하지 않음
 ↓
main으로 예외 전달
 ↓
RetryLimitException은
QuizException의 자식
 ↓
catch (QuizException e)
 ↓
F 출력
 ↓
e.getMessage()
 ↓
재응시 횟수 초과
 ↓
H 출력
```

최종 출력:

```text
B
C
F
재응시 횟수 초과
H
```

`D`는 출력되지 않는다.

이유:

```text
throw e
→ 예외가 다시 호출자에게 전달됨
→ finally는 실행
→ 그 아래 일반 코드 D는 실행되지 않음
```

### 이 코드에서 꼭 볼 것

```text
RetryLimitException
        ↓ 자식
QuizException
        ↓ 자식
LearningException
```

따라서 `RetryLimitException`이 main까지 전달되었을 때 정확한 타입의 `catch`가 없어도:

```java
catch (QuizException e)
```

처럼 부모 타입의 `catch`가 받을 수 있다.

또한:

```java
throw e;
```

는 새로운 예외를 만드는 것이 아니라 **현재 잡은 예외 객체를 다시 호출자에게 던지는 것**이다.
