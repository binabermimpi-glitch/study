# 2. XML

### 문제 핵심

* SGML의 단순화된 부분집합

* HTML의 한계를 보완

### 정답

**XML**

### XML

**eXtensible Markup Language**

웹에서 구조화된 문서를 표현하고 전송하기 위해 설계된 마크업 언어이다.

---

## 인터페이스 전송 데이터 형식

### JSON

**JavaScript Object Notation**

* JavaScript 객체 문법을 기반으로 구조화된 데이터를 표현하는 문자 기반 표준 형식
* **이름과 값의 쌍(Key-Value)**으로 구성
* XML보다 비교적 간결하고 용량이 작음

예:

```json
{
  "name": "홍길동",
  "age": 20
}
```

### XML

**eXtensible Markup Language**

* 태그를 이용하여 구조화된 데이터를 표현
* 시스템 간 데이터 교환에 사용

예:

```xml
<student>
    <name>홍길동</name>
    <age>20</age>
</student>
```

### CSV

**Comma Separated Values**

* 여러 필드를 쉼표(,)로 구분하는 텍스트 데이터 형식

예:

```text
홍길동,20,컴퓨터공학과
```

### YAML

* 사람이 읽기 쉽게 만들어진 데이터 직렬화 형식
* 설정 파일 등에서 많이 사용

예:

```yaml
name: 홍길동
age: 20
```

# 3. 살충제 패러독스(Pesticide Paradox)

### 실기 답안

**동일한 테스트 케이스를 반복적으로 수행하면 새로운 결함을 발견하기 어려워진다는 원리이다.**

즉, 새로운 결함을 찾기 위해서는 테스트 케이스를 지속적으로 검토하고 개선해야 한다.

---

## 소프트웨어 테스트의 7가지 원리

1. **테스팅은 결함이 존재함을 밝히는 활동이다.**
2. **완벽한 테스팅은 불가능하다.**
3. **테스팅은 개발 초기에 시작해야 한다.**
4. **결함 집중(Defect Clustering)**

   * 결함은 특정 모듈에 집중되어 발생한다.
   * 파레토 법칙과 관련됨.
5. **살충제 패러독스**

   * 같은 테스트를 반복하면 새로운 결함을 찾기 어렵다.
6. **테스팅은 정황(Context)에 의존한다.**
7. **오류-부재의 궤변**

   * 오류가 없더라도 사용자의 요구사항을 만족하지 못하면 좋은 소프트웨어가 아니다.

# 4. 결합도와 응집도

### 문제

모듈의 독립성을 판단하는 두 가지 지표

### 정답

1. **결합도(Coupling)**
2. **응집도(Cohesion)**

### 핵심

좋은 모듈 설계:

**결합도는 낮게 ↓**

**응집도는 높게 ↑**

---

# 결합도(Coupling)

모듈과 모듈 사이의 **상호 의존 정도**

### 좋은 순서 → 나쁜 순서

**자료 → 스탬프 → 제어 → 외부 → 공통 → 내용**

즉,

```text
자료 < 스탬프 < 제어 < 외부 < 공통 < 내용
```

결합도는 **낮을수록 좋다.**

---

## ① 자료 결합도(Data Coupling)

모듈 간에 필요한 **단순 데이터 값만 전달**하는 경우

예:

```java
sum(10, 20);
```

가장 좋은 결합도

---

## ② 스탬프 결합도(Stamp Coupling)

배열, 객체, 구조체 등의 **자료구조 전체를 전달**하는 경우

예:

```java
printStudent(student);
```

---

## ③ 제어 결합도(Control Coupling)

다른 모듈의 처리 방법을 결정하는 **제어 정보**를 전달하는 경우

예:

```text
flag = 1이면 등록
flag = 2이면 삭제
```

---

## ④ 외부 결합도(External Coupling)

두 모듈이 외부에서 도입된 데이터 형식, 통신 프로토콜, 장치 인터페이스 등을 공유하는 경우

---

## ⑤ 공통 결합도(Common Coupling)

여러 모듈이 **전역 변수와 같은 공통 데이터 영역을 공유**하는 경우

---

## ⑥ 내용 결합도(Content Coupling)

한 모듈이 다른 모듈의 **내부 데이터나 내부 기능을 직접 참조하거나 변경**하는 경우

가장 나쁜 결합도

---

# 응집도(Cohesion)

한 모듈 내부의 구성 요소들이 **얼마나 밀접하게 관련되어 있는지**를 나타내는 정도

### 좋은 순서 → 나쁜 순서

```text
기능적 > 순차적 > 통신적 > 절차적 > 시간적 > 논리적 > 우연적
```

응집도는 **높을수록 좋다.**

---

## ① 기능적 응집도(Functional Cohesion)

모듈의 모든 기능이 **하나의 목적을 위해 수행**되는 경우

가장 좋은 응집도

---

## ② 순차적 응집도(Sequential Cohesion)

한 활동의 **출력값이 다음 활동의 입력값**으로 사용되는 경우

```text
A의 결과 → B의 입력
```

---

## ③ 통신적 응집도(Communication Cohesion)

동일한 입력이나 출력을 사용하는 여러 기능들이 하나의 모듈에 존재하는 경우

---

## ④ 절차적 응집도(Procedural Cohesion)

여러 기능이 **정해진 순서에 따라 수행**되는 경우

> 주의
> 단순히 "순서대로 실행된다"는 설명이면 **절차적 응집도**일 가능성이 높다.

---

## ⑤ 시간적 응집도(Temporal Cohesion)

특정 시점에 함께 수행되어야 하는 기능들이 모인 경우

예:

```text
프로그램 시작 시 초기화
프로그램 종료 시 정리
```

---

## ⑥ 논리적 응집도(Logical Cohesion)

유사한 성격이나 같은 범주의 기능들을 하나의 모듈에 모아둔 경우

---

## ⑦ 우연적 응집도(Coincidental Cohesion)

모듈 내부의 기능들이 서로 아무런 관련이 없는 경우

가장 나쁜 응집도

# 8. SQL DISTINCT

학생 데이터

* 전자과: 50명
* 전기과: 100명
* 건축과: 50명

총 학생 수 = **200명**

---

### ①

```sql
SELECT dept
FROM STUDENT;
```

결과 행 수:

**200**

---

### ②

```sql
SELECT DISTINCT dept
FROM STUDENT;
```

학과 종류만 출력

결과 행 수:

**3**

---

### ③

```sql
SELECT COUNT(DISTINCT dept)
FROM STUDENT
WHERE dept = '건축과';
```

결과:

```text
1
```

그리고 `COUNT()`는 집계 함수이므로 **결과 튜플 자체도 1개**이다.

# 9. LAND Attack

### 문제 특징

* 출발지 IP = 목적지 IP
* 자기 자신에게 SYN 요청이 반복됨
* 서버 자원 고갈

### 정답

**LAND Attack**

### 실기용 정의

**출발지 IP와 목적지 IP를 공격 대상의 IP 주소로 동일하게 설정한 패킷을 보내 서버가 자기 자신에게 응답하도록 만들어 자원을 고갈시키는 공격**

---

# 서비스 거부 및 보안 공격 유형 정리

## DoS

**Denial of Service**

하나의 공격자가 대량의 트래픽이나 비정상적인 요청을 보내 시스템 자원을 고갈시켜 정상적인 서비스를 방해하는 공격

---

## DDoS

**Distributed Denial of Service**

여러 대의 감염된 시스템을 이용하여 동시에 공격 대상에 대량의 트래픽을 보내 서비스를 마비시키는 공격

---

## Smurf Attack

공격 대상의 IP를 출발지 주소로 위조한 ICMP 요청을 브로드캐스트 주소로 보내 다수의 응답이 공격 대상에게 전달되도록 하는 공격

---

## SYN Flooding

TCP의 3-Way Handshake 과정에서 대량의 SYN 패킷을 보내고 최종 ACK를 보내지 않아 서버의 연결 자원을 고갈시키는 공격

---

## UDP Flooding

대량의 UDP 패킷을 전송하여 서버와 네트워크 자원을 고갈시키는 공격

---

## Ping Flooding

대량의 ICMP Echo Request(Ping)를 보내 네트워크와 시스템 자원을 고갈시키는 공격

---

## Ping of Death

허용 크기를 초과한 비정상적인 ICMP 패킷을 전송하여 시스템에 장애를 발생시키는 공격

---

## Teardrop Attack

IP 패킷의 Fragment Offset 값을 조작하여 패킷 재조립 과정에서 오류를 발생시키는 공격

---

## LAND Attack

출발지 IP와 목적지 IP를 동일하게 만들어 공격 대상이 자기 자신에게 응답하도록 하는 공격

---

## Phishing

가짜 이메일이나 웹사이트를 이용하여 사용자를 속이고 개인정보나 금융정보를 탈취하는 공격

---

## Pharming

DNS 등을 조작하여 사용자가 정상 주소를 입력해도 가짜 사이트로 접속하도록 유도하는 공격

---

## Sniffing

네트워크를 통해 전송되는 패킷을 가로채어 정보를 훔쳐보는 공격

---

## Smishing

SMS 문자메시지를 이용한 피싱 공격

---

## Qshing / QR Phishing

악성 QR 코드를 이용해 피싱 사이트나 악성 페이지로 유도하는 공격

---

## Ransomware

파일이나 시스템을 암호화한 뒤 복구를 조건으로 금전을 요구하는 악성코드

---

## Key Logger

사용자가 키보드로 입력하는 정보를 몰래 기록하여 계정이나 비밀번호 등을 탈취하는 공격

---

## SQL Injection

SQL 쿼리에 악의적인 SQL 문을 삽입하여 데이터베이스 정보를 조회·변조·삭제하는 공격

---

## XSS

**Cross Site Scripting**

웹페이지에 악성 스크립트를 삽입하여 다른 사용자의 브라우저에서 실행되도록 하는 공격

---

## Brute Force Attack

**무차별 대입 공격**

가능한 비밀번호나 암호 조합을 반복적으로 대입하여 인증 정보를 알아내는 공격

---

## Spear Phishing

특정 개인이나 조직을 대상으로 맞춤형 메시지를 보내 정보를 탈취하는 공격

---

## APT

**Advanced Persistent Threat**

특정 조직을 대상으로 장기간에 걸쳐 지속적이고 은밀하게 수행되는 지능형 공격

---

## Zero-Day Attack

보안 취약점이 발견되었지만 아직 보안 패치가 제공되지 않은 상태에서 해당 취약점을 이용하는 공격

---

## Back Door

정상적인 인증 과정을 우회하여 시스템에 접근할 수 있도록 만들어 놓은 비정상적인 접근 통로

---

## Rainbow Table Attack

미리 계산해 둔 해시값과 평문 목록을 이용하여 암호화된 비밀번호의 원문을 찾아내는 공격

---

## CSRF

**Cross Site Request Forgery**

로그인된 사용자의 권한을 이용하여 사용자가 의도하지 않은 요청을 서버에 수행하게 만드는 공격

---

## TOCTOU

**Time Of Check To Time Of Use**

자원이나 파일의 상태를 확인한 시점과 실제 사용 시점 사이의 시간차를 이용하는 공격

---

# 11. HRN 스케줄링

## HRN

**Highest Response Ratio Next**

# 3. SOAP

## 문제

(      )은 웹 서비스에서 기본적인 메시지를 전달하는 기반이 되는데, (   )에는 몇 가지 형태의 메시지 패턴이 있지만, 보통의 경우 원격 프로시저 호출(RPC)패턴으로, 네트워크 노드(클라이언트)에서 다른 쪽 노드(서버)로 메시지를 요청 하고, 서버는 메시지를 즉시 응답하게 되는 형식입니다.

즉 (   )는 XML을 이용해서 분산처리 환경에서 정보교환을 쉽게 할 수 있도록 도와준다.

## 정답

**SOAP**

## SOAP

**Simple Object Access Protocol**

XML 기반 메시지를 이용하여 분산 환경에서 정보를 교환하는 프로토콜이다.

### 특징

* XML 기반
* HTTP / HTTPS / SMTP 사용 가능
* 웹 서비스 메시지 교환
* 플랫폼 독립적

```text
XML
HTTP
RPC
웹 서비스
→ SOAP
```

## SOAP / WSDL / UDDI

### SOAP

실제 메시지를 주고받는 통신 규약

```text
SOAP = 통신
```

### WSDL

**Web Services Description Language**

웹 서비스의 기능, 호출 방법, 입력값, 출력값 등을 XML로 설명한다.

```text
WSDL = 웹 서비스 설명서
```

### UDDI

**Universal Description, Discovery and Integration**

웹 서비스를 등록하고 검색하기 위한 레지스트리이다.


# 8. SQL IN 연산자

## 문제

아래 보기의 `<학생>` 테이블을 대상으로 `<요구사항>`을 적용하여 출력하는 SQL문을 작성하시오.

### 요구사항

1. 3학년이거나 4학년 학생의 학번과 이름을 검색하시오.
2. 단, 조건절 작성 시 `IN` 예약어를 사용하여 작성하시오.

### 학생 테이블

| 학번     | 이름  | 학년 |
| ------ | --- | -: |
| 181101 | KKK |  1 |
| 171201 | HHH |  2 |
| 161107 | YYY |  3 |
| 151403 | OOO |  4 |

## 정답

```sql
SELECT 학번, 이름
FROM 학생
WHERE 학년 IN (3, 4);
```

## 풀이

```text
학번과 이름 검색
→ SELECT 학번, 이름

학생 테이블
→ FROM 학생

3학년 또는 4학년
→ WHERE 학년 IN (3, 4)
```

## IN 연산자

여러 값 중 하나와 일치하는지 검사한다.

```sql
WHERE 컬럼명 IN (값1, 값2, 값3);
```

이번 문제:

```sql
WHERE 학년 IN (3, 4);
```

의미:

```sql
WHERE 학년 = 3
   OR 학년 = 4;
```

즉:

```text
IN (3, 4)
=
3 또는 4
```

## NOT IN

지정한 값을 제외한다.

```sql
WHERE 학년 NOT IN (3, 4);
```

```text
IN = 포함
NOT IN = 제외
```

# 14. Linux chmod

## 문제

리눅스 또는 유닉스에서 `a.txt` 파일에 대해 다음 조건을 만족하는 권한을 부여하고자 한다.

### 조건

사용자에게는 읽기, 쓰기, 실행의 세 개 권한을 모두 부여한다.

그룹에게는 읽기, 실행 두 개의 권한을 부여한다.

그룹 외 사용자에게는 실행 권한을 부여한다.

한 줄로 명령문이 작성되어야 하며, 8진수로 권한을 부여한다.

## 정답

```bash
chmod 751 a.txt
```

## 권한 값

```text
r = 4
w = 2
x = 1
```

사용자:

```text
rwx
4 + 2 + 1 = 7
```

그룹:

```text
r-x
4 + 1 = 5
```

기타:

```text
--x
1
```

따라서:

```text
751
```

## 권한표

| 숫자 | 권한  |
| -: | --- |
|  0 | --- |
|  1 | --x |
|  2 | -w- |
|  3 | -wx |
|  4 | r-- |
|  5 | r-x |
|  6 | rw- |
|  7 | rwx |

## 파일 권한 구조

```text
-rwxr-x--x
```

```text
-    rwx    r-x    --x
│     │      │      │
│     │      │      └ 기타 사용자
│     │      └ 그룹
│     └ 소유자
└ 파일 종류
```

파일 종류:

```text
- = 일반 파일
d = 디렉터리
l = 심볼릭 링크
```

# 15. RTO

## 문제

다음은 IP 인프라 서비스 관리 실무와 관련된 `<실무 사례>`에 대한 설명이다. 가장 적합한 용어를 한글 또는 영문으로 쓰시오.

A는 한국아이티 보안관제실에서 정보시스템의 정보관리를 위해 모니터링을 담당하며 근무하고 있다. 시스템 운영 중 자연재해나 시스템 장애 등의 이유로 대고객 서비스가 불가능한 경우가 종종 발생한다. A는 이런 장애 발생시 서비스를 정상적으로 수행하기 위해 구축 시스템을 관리하는 역할을 한다.

이 용어는 이런 비상 상황이 발생했을 때 **"서비스 중단 시점과 서비스 복원 시점 간에 허용되는 최대 지연 시간"**을 가리킨다.

**목표 복구 시간**

## RTO

```text
장애 발생
↓
[ RTO ]
↓
서비스 복구
```

## RPO

**Recovery Point Objective**

장애 발생 시 어느 시점의 데이터까지 복구해야 하는지를 나타낸다.

```text
RTO = 복구 시간
RPO = 복구 시점
```

암기:

```text
T = Time
P = Point
```

```text
Subject
```

# 2. EAI 구축 유형 🔥 빈출

## 문제

다음은 EAI 구축 유형에 대한 설명이다. 1, 2에 해당하는 유형을 쓰시오.

### (1)

* 중간에 미들웨어를 두지 않고 각 애플리케이션 간 직접 연결
* 솔루션 구매 없이 통합하여 상대적으로 저렴하게 통합 가능
* 변경 및 재사용 어려움

### (2)

* 단일 접점인 허브 시스템을 통해 데이터를 전송하는 중앙 집중적 방식
* 모든 데이터 전송 보장
* 확장 및 유지보수 용이
* 허브 장애 시 전체 시스템에 영향

## 정답

(1) **Point-to-Point**

(2) **Hub & Spoke**

---

# EAI

**Enterprise Application Integration**

기업 내부의 서로 다른 애플리케이션을 연결하여 데이터와 업무 프로세스를 통합하는 방식이다.

---

## ① Point-to-Point

애플리케이션끼리 직접 연결하는 방식이다.

```text
A ───── B
│       │
│       │
C ───── D
```

### 특징

* 직접 연결
* 미들웨어 없음
* 초기 구축 비용이 비교적 낮음
* 시스템 수가 증가하면 연결이 복잡해짐
* 변경 및 재사용이 어려움

```text
직접 연결
미들웨어 X
→ Point-to-Point
```

---

## ② Hub & Spoke

중앙의 Hub를 통해 모든 애플리케이션을 연결하는 방식이다.

```text
      A
      │
B ── HUB ── C
      │
      D
```

### 특징

* 중앙 집중 방식
* 유지보수 용이
* 확장 용이
* 허브 장애 시 전체 시스템에 영향

```text
중앙 허브
→ Hub & Spoke
```

---

## ③ Message Bus

애플리케이션 사이에 미들웨어를 두고 버스를 이용하여 연결하는 방식이다.

```text
A ─┐
B ─┼── Message Bus
C ─┘
```

### 특징

* 미들웨어를 통한 통합
* 뛰어난 확장성
* 대용량 처리 가능

※ ESB와 관련이 깊지만 EAI의 Message Bus와 ESB를 완전히 같은 용어라고 외우지는 않는다.

---

## ④ Hybrid

Hub & Spoke와 Message Bus 방식 등의 장점을 결합한 방식이다.

### 특징

* 유연한 통합
* 데이터 병목 최소화
* 다양한 통합 환경에 대응

## 초압축

```text
직접 연결
→ Point-to-Point

중앙 허브
→ Hub & Spoke

미들웨어 버스
→ Message Bus

여러 방식 결합
→ Hybrid
```

# 4. 코드 커버리지(Code Coverage) 🔥🔥 매우 중요

※ 제공한 필기에는 4번 문제 본문은 없고 코드 커버리지 관련 내용이 정리되어 있음.

## 코드 커버리지

테스트를 수행했을 때 프로그램의 코드가 얼마나 실행되었는지를 측정하는 기준이다.

---

## ① 구문 커버리지

**Statement Coverage**

코드 내 모든 구문을 한 번 이상 실행하도록 하는 테스트 커버리지이다.

```text
모든 구문
→ 한 번 이상 실행
```

---

## ② 조건 커버리지

**Condition Coverage**

결정문 내부의 모든 개별 조건식이 각각 한 번 이상 True와 False가 되도록 한다.

예:

```java
if (A && B)
```

A가

```text
True / False
```

B도

```text
True / False
```

를 각각 한 번 이상 가져야 한다.

---

## ③ 결정 커버리지

**Decision Coverage / Branch Coverage**

결정문의 전체 결과가 각각 한 번 이상 True와 False가 되도록 한다.

예:

```java
if (A && B)
```

전체 조건의 결과가

```text
True
False
```

각각 한 번 이상 나오면 된다.

---

## ④ 조건/결정 커버리지

**Condition / Decision Coverage**

조건 커버리지와 결정 커버리지를 모두 만족한다.

```text
개별 조건식
→ T / F

전체 결정 결과
→ T / F
```

---

## ⑤ 변경 조건/결정 커버리지

**MC/DC**

각 개별 조건이 다른 조건의 영향을 받지 않고 **독립적으로 전체 결정 결과에 영향을 주는지** 확인하는 커버리지이다.

### 핵심

```text
각 조건이 독립적으로
전체 결과를 변경시켜야 함
```

단순히 각각의 조건이 True/False가 되는 것만으로는 부족하다.

---

## ⑥ 다중 조건 커버리지

**Multiple Condition Coverage**

결정문 안의 모든 개별 조건식의 가능한 조합을 전부 테스트한다.

예:

```text
A B
T T
T F
F T
F F
```

```text
가능한 모든 조건 조합
→ 다중 조건 커버리지
```

# 5. 블랙박스 테스트 🔥🔥 매우 빈출

## 문제

소프트웨어 테스트 기법 중 소프트웨어 기능이 완전히 작동하는 것을 입증하는 테스트로, 동치분할/경계값 분석을 이용하여 테스트 하는 기법을 쓰시오.

## 정답

**블랙박스 테스트(Black Box Test)**

## 개념

프로그램 내부 구조는 보지 않고 입력값과 출력값을 이용하여 요구사항대로 기능이 동작하는지 검사하는 테스트이다.

```text
내부 코드 X
입력 / 출력 O
→ 블랙박스
```

---

# 블랙박스 테스트 기법

## ① 동등 분할 / 동치 분할

**Equivalence Partitioning**

입력 데이터를 동일한 결과를 낼 것으로 예상되는 그룹으로 나누어 대표값을 테스트하는 기법이다.

---

## ② 경계값 분석

**Boundary Value Analysis**

입력 조건의 경계값에서 오류가 발생할 가능성이 높다는 점을 이용하여 경계 근처의 값을 테스트한다.

예:

```text
정상 범위 1 ~ 100

0
1
2
99
100
101
```

---

## ③ 원인-효과 그래프 검사

입력 조건과 출력 결과 사이의 관계를 분석하여 효율적인 테스트 케이스를 선정한다.

---

## ④ 오류 예측 검사

과거의 경험이나 테스터의 직관을 이용하여 오류가 발생할 가능성이 높은 부분을 테스트한다.

---

## ⑤ 비교 검사

여러 버전의 프로그램에 동일한 테스트 데이터를 입력하여 결과가 동일하게 나오는지 비교한다.

---

# 화이트박스 vs 블랙박스

```text
화이트박스
→ 내부 구조
→ 코드
→ 분기
→ 경로

블랙박스
→ 입력
→ 출력
→ 기능
```

# 7. GROUP BY / HAVING 🔥🔥 매우 중요

## 정답

```sql
SELECT 과목이름,
       MIN(점수) AS 최소점수,
       MAX(점수) AS 최대점수
FROM 성적
GROUP BY 과목이름
HAVING AVG(점수) >= 90;
```

---

## 해석

### SELECT

```sql
SELECT 과목이름,
       MIN(점수),
       MAX(점수)
```

과목별 최소점수와 최대점수를 출력한다.

---

## GROUP BY

```sql
GROUP BY 과목이름
```

같은 과목끼리 그룹으로 묶는다.

---

## HAVING

```sql
HAVING AVG(점수) >= 90
```

과목별 평균 점수가 90점 이상인 그룹만 출력한다.

---

# WHERE vs HAVING 🔥

## WHERE

그룹화하기 전에 각각의 행에 조건을 적용한다.

```sql
WHERE 점수 >= 90
```

→ 점수가 90점 이상인 학생만 선택

## HAVING

GROUP BY를 수행한 후 그룹에 조건을 적용한다.

```sql
HAVING AVG(점수) >= 90
```

→ 평균 점수가 90점 이상인 과목만 선택

### 암기

```text
WHERE
→ 행 조건

HAVING
→ 그룹 조건
```

---

# 집계 함수

```text
COUNT = 개수
SUM   = 합계
AVG   = 평균
MAX   = 최댓값
MIN   = 최솟값
```

# 8. DELETE 🔥 빈출

## 문제

`<학생>` 테이블에서 이름이 `'민수'`인 학생 튜플을 삭제하는 SQL문을 작성하시오.

단 다음의 요구사항을 참고하여 작성하시오.

### 요구사항

1. 이름 속성의 데이터는 문자형이다. 문자형 데이터는 작은 따옴표(`' '`)로 표시하시오.
2. SQL 명령문은 대/소문자를 구분하지 않는다.
3. SQL 명령문의 종결 문자인 세미콜론은 생략 가능하다.

## 정답

```sql
DELETE FROM 학생
WHERE 이름 = '민수';
```

# 11. OSPF 🔥🔥 매우 빈출

## 문제

다음 설명에 해당하는 라우팅 프로토콜을 쓰시오.

* 최단 경로 탐색에 다익스트라 알고리즘 기반 방식 사용
* 최적 경로 선택을 위해 비용을 사용하며 대역폭 등을 반영
* 링크 상태 변화 시 라우팅 정보 전송

## 정답

**OSPF**

## OSPF

**Open Shortest Path First**

## 핵심 키워드

```text

Link State
Cost
→ OSPF
```

# 라우팅 영역에 따른 분류

## IGP

**Interior Gateway Protocol**

하나의 AS 내부에서 사용하는 라우팅 프로토콜이다.

대표:

* RIP
* OSPF
* IGRP

---

## RIP

```text
Distance Vector
Hop Count
```

거리 벡터 방식이며 홉 수를 기준으로 최적 경로를 선택한다.

---

## OSPF

```text
Link State
Dijkstra
Cost
```

링크 상태 방식이며 다익스트라 알고리즘을 이용한다.

---

## EGP

**Exterior Gateway Protocol**

AS와 AS 사이에서 사용하는 라우팅 프로토콜이다.

대표적으로:

```text
BGP
```

### 비교

```text

→ Hop Count

→ Cost
```

디자인 패턴은 객체 지향 프로그래밍 설계를 할 때 자주 발생하는 문제들에 대해 재사용할 수 있도록 만들어놓은 패턴들의 모음이다.

에리히 감마, 리차드 헬름, 랄프 존슨, 존 블리시디스에 의해 개발 영역에서 디자인 패턴을 구체화하고 체계화시켰다.

GoF의 디자인 패턴은 생성, 구조, (   )의 3가지로 분류한다.

## 정답

**행위(Behavioral)**

---

# GoF 디자인 패턴

**Gang of Four**가 정리한 대표적인 객체지향 디자인 패턴이다.

GoF 디자인 패턴은 크게 세 가지로 나뉜다.

```text
생성 패턴
구조 패턴
행위 패턴
```

## ① 생성 패턴(Creational)

객체를 **어떻게 생성할 것인가**에 관련된 패턴이다.

대표:

```text
Singleton
Factory Method
Abstract Factory
Builder
Prototype
```

---

## ② 구조 패턴(Structural)

클래스와 객체를 **어떻게 조합하여 더 큰 구조를 만들 것인가**에 관련된다.

대표:

```text
Adapter
Bridge
Composite
Decorator
Facade
Flyweight
Proxy
```

지난번에 공부한:

```text
Facade Pattern
```

도 구조 패턴이다.

---

## ③ 행위 패턴(Behavioral)

객체들이 서로 **어떻게 책임을 나누고 상호작용할 것인지**와 관련된다.

대표:

```text
Observer
Strategy
State
Command
Iterator
Template Method
Mediator
Memento
Visitor
Chain of Responsibility
Interpreter
```

지난번 공부한:

```text
Observer Pattern
```

은 행위 패턴이다.

## 시험 암기

```text
생성
→ 객체 생성

구조
→ 객체 조합

행위
→ 객체 간 상호작용
```

# 2. 패키지 다이어그램 🔥 빈출

## 문제

UML을 이용한 다이어그램 중 아래 그림에 해당하는 다이어그램을 쓰시오.

## 정답

**패키지 다이어그램(Package Diagram)**

---

# 패키지 다이어그램

클래스, 유스케이스 등의 여러 모델 요소를 **패키지 단위로 그룹화하고 패키지 사이의 관계를 표현하는 UML 구조 다이어그램**이다.

```text
여러 요소
↓
패키지로 그룹화
↓
패키지 간 관계 표시
```

---

# UML 다이어그램 분류 🔥

UML 다이어그램은 크게:

```text
구조 다이어그램
행위 다이어그램
```

으로 나눈다.

---

# 구조 다이어그램(Structure Diagram)

시스템의 **정적인 구조**를 표현한다.

## ① 클래스 다이어그램

클래스의 속성, 연산 및 클래스 사이의 관계를 표현한다.

```text
클래스 구조 / 관계
→ 클래스 다이어그램
```

---

## ② 패키지 다이어그램

여러 모델 요소를 패키지로 그룹화하고 패키지 간 의존관계를 표현한다.

```text
그룹화
패키지 간 관계
→ Package Diagram
```

---

## ③ 복합체 구조 다이어그램

**Composite Structure Diagram**

클래스나 컴포넌트 내부의 복합적인 구조를 표현한다.

---

## ④ 객체 다이어그램

**Object Diagram**

특정 시점에 존재하는 객체와 객체 사이의 관계를 표현한다.

```text
클래스
→ 설계도

객체
→ 실제 인스턴스 상태
```

---

## ⑤ 컴포넌트 다이어그램

**Component Diagram**

소프트웨어 컴포넌트와 컴포넌트 사이의 관계를 표현한다.

---

## ⑥ 배치 다이어그램

**Deployment Diagram**

소프트웨어가 어떤 하드웨어/노드에 배치되는지를 표현한다.

```text
서버
하드웨어
네트워크
배치
→ Deployment
```

---

# 행위 다이어그램(Behavior Diagram)

시스템의 **동적인 동작과 상호작용**을 표현한다.

## ① 유스케이스 다이어그램

사용자 관점에서 시스템의 기능을 표현한다.

```text
Actor + 시스템 기능
```

---

## ② 활동 다이어그램

**Activity Diagram**

업무 처리 절차나 작업 흐름을 표현한다.

```text
업무 흐름
→ Activity
```

---

## ③ 시퀀스 다이어그램

**Sequence Diagram**

객체 사이에서 시간 순서에 따라 주고받는 메시지를 표현한다.

```text
객체
메시지
시간 순서
→ Sequence
```

---

## ④ 커뮤니케이션 다이어그램

**Communication Diagram**

객체 간 상호작용을 표현하되 **객체 간 구조적인 관계**를 중심으로 나타낸다.

> 예전 명칭으로 `Collaboration Diagram`이라고도 한다.

---

## ⑤ 상태 머신 다이어그램

**State Machine Diagram**

객체의 상태 변화와 생명주기를 표현한다.

```text
상태 변화
→ State Machine
```

---

# UML 초압축

```text
클래스
→ 클래스 구조

패키지
→ 요소 그룹화

배치
→ 하드웨어/서버 배치

유스케이스
→ 사용자와 기능

활동
→ 업무 흐름

시퀀스
→ 메시지 시간순서

상태
→ 객체 상태 변화
```

# 3. 샘플링 오라클 🔥 빈출

## 문제

일반, 업무용, 게임, 오락 등의 일반적인 업무에 사용하는 테스트 오라클로 특정한 몇 개의 입력 값에 대해서만 기대하는 결과를 제공해 주는 오라클을 쓰시오.

## 정답

**샘플링 오라클(Sampling Oracle)**

---

# 테스트 오라클(Test Oracle)

테스트 결과가 올바른지 판단하기 위해 **예상되는 결과를 제공하는 방법이나 기준**이다.

---

## ① 참 오라클(True Oracle)

모든 입력값에 대해 정확한 예상 결과를 제공한다.

```text
모든 입력
→ 정확한 결과
```

---

## ② 샘플링 오라클(Sampling Oracle)

일부 입력값에 대해서만 정확한 예상 결과를 제공한다.

```text
특정 몇 개 입력
→ 정확한 결과

나머지
→ 제공 X
```

---

## ③ 휴리스틱 오라클(Heuristic Oracle)

일부 입력에 대해서는 정확한 결과를 제공하고 나머지는 **휴리스틱 또는 추정값**을 사용한다.

```text
일부 정확
+
나머지 추정
```

---

## ④ 일관성 검사 오라클

**Consistent Oracle**

프로그램 변경 전과 변경 후의 결과가 서로 일관되는지 확인한다.

---

## 시험 구별

```text
모든 입력 정확
→ 참 오라클

일부 입력만 정확
→ 샘플링 오라클

일부 정확 + 나머지 추정
→ 휴리스틱 오라클

변경 전후 비교
→ 일관성 검사 오라클
```

---

# 4. 동등 분할 테스트 🔥🔥 매우 빈출

## 문제

테스트 기법 중 다음과 같이 입력값을 넣고, 출력값을 비교하는 테스트 기법을 쓰시오.

## 정답

**동등 분할 테스트(Equivalence Partitioning)**

또는

**동치 분할 테스트**

---

# 동등 분할

입력 데이터를 동일한 결과를 낼 것으로 예상되는 **유효 영역과 무효 영역으로 분할한 후 각 영역의 대표값을 테스트**하는 블랙박스 테스트 기법이다.

예:

```text
나이 입력 범위
1 ~ 100
```

분할:

```text
X < 1
→ 무효

1 ≤ X ≤ 100
→ 유효

X > 100
→ 무효
```

각 영역에서 대표값을 골라 테스트한다.

---

# 블랙박스 테스트 기법 🔥

## ① 동등 분할

```text
유효/무효 영역 분할
→ 대표값 테스트
```

## ② 경계값 분석

```text
경계 근처 값 테스트
```

예:

```text
0 ~ 10

-1
0
1
9
10
11
```

## ③ 원인-효과 그래프

입력 조건과 출력 결과 사이의 관계를 분석한다.

## ④ 오류 예측

테스터의 경험과 직관으로 오류가 예상되는 부분을 검사한다.

## ⑤ 비교 검사

여러 버전의 프로그램에 같은 값을 입력하여 결과를 비교한다.

### 암기

```text
유효/무효 그룹
→ 동등 분할

경계 근처
→ 경계값 분석
```

# 5. GROUP BY / COUNT 🔥🔥 매우 중요

## 문제

`<학생>` 테이블을 대상으로 요구사항을 적용하여 결과와 같이 출력하는 SQL문을 작성하시오.

### 요구사항

1. WHERE 구문은 사용하지 않고 SQL문을 작성하시오.
2. GROUP BY 구문과 집계함수를 반드시 사용하여 SQL문을 작성하시오.
3. 인용 문구를 사용 시 작은따옴표(`' '`) 사용 가능합니다.
4. AS 구문은 반드시 사용하여 작성하시오.

## 정답

```sql
SELECT 학과,
       COUNT(*) AS 학과별튜플수
FROM 학생
GROUP BY 학과;
```

---

# 실행 과정

## SELECT

```sql
SELECT 학과,
       COUNT(*) AS 학과별튜플수
```

학과 이름과 해당 학과에 속하는 튜플의 개수를 출력한다.

---

## COUNT(*)

```sql
COUNT(*)
```

행의 개수를 계산하는 집계 함수이다.

---

## AS

```sql
AS 학과별튜플수
```

출력되는 컬럼에 별칭(Alias)을 지정한다.

---

## GROUP BY

```sql
GROUP BY 학과
```

같은 학과의 데이터를 하나의 그룹으로 묶는다.

---

# 집계 함수 🔥

```text
COUNT
→ 개수

SUM
→ 합계

AVG
→ 평균

MAX
→ 최댓값

MIN
→ 최솟값
```

---

# WHERE / GROUP BY / HAVING

```text
WHERE
→ 그룹화 전 행 조건

GROUP BY
→ 같은 값끼리 그룹

HAVING
→ 그룹화 후 그룹 조건
```

---

# 7. 가용성(Availability) 🔥🔥 매우 빈출

## 문제

정보보안의 3요소 중 가용성에 대하여 서술하시오.

## 정답

**인가된 사용자가 정보를 요구할 때 적시에 제공되어야 하는 원칙**

---

# 정보보안의 3요소 - CIA 🔥🔥

## ① 기밀성(Confidentiality)

인가된 사용자만 정보에 접근할 수 있어야 한다.

```text
허가된 사람만 볼 수 있음
```

---

## ② 무결성(Integrity)

정보가 허가되지 않은 방법으로 변경되거나 훼손되어서는 안 된다.

```text
데이터가 정확하게 유지
```

---

## ③ 가용성(Availability)

인가된 사용자가 필요할 때 언제든 정보나 서비스를 사용할 수 있어야 한다.

```text
필요할 때 사용 가능
```

---

## CIA 암기

```text
C = Confidentiality
    기밀성

I = Integrity
    무결성

A = Availability
    가용성
```

### 공격과 연결

```text
정보 유출
→ 기밀성 침해

정보 변조
→ 무결성 침해

DoS / DDoS
→ 가용성 침해
```

---

# 8. 데이터베이스 이상(Anomaly) 🔥🔥 매우 빈출

## 문제

데이터베이스의 이상(Anomaly)의 종류 3가지를 쓰시오.

## 정답

```text
삽입 이상
갱신 이상
삭제 이상
```

---

# 이상 현상

정규화가 제대로 이루어지지 않은 테이블에서 데이터 중복 때문에 발생하는 문제이다.

---

## ① 삽입 이상(Insertion Anomaly)

필요 없는 데이터까지 입력해야만 원하는 데이터를 삽입할 수 있는 현상이다.

예:

학생이 없는 학과 정보를 저장하고 싶은데 학생 정보까지 반드시 입력해야 하는 경우.

---

## ② 갱신 이상(Update Anomaly)

중복된 데이터 중 일부만 수정되어 데이터가 서로 불일치하게 되는 현상이다.

```text
같은 학과 이름이 여러 행
↓
한 행만 수정
↓
서로 다른 값 발생
```

---

## ③ 삭제 이상(Deletion Anomaly)

특정 데이터를 삭제할 때 필요한 다른 정보까지 함께 삭제되는 현상이다.

---

## 핵심

```text
삽입
→ 넣을 때 문제

갱신
→ 수정할 때 문제

삭제
→ 지울 때 문제
```

### 해결

```text
이상 현상 감소
→ 정규화
```

---

# 9. 즉시 갱신 회복 기법 🔥🔥 매우 중요

## 문제

데이터베이스 회복 기법에 관련된 설명에서 괄호에 들어갈 가장 알맞은 용어를 쓰시오.

다양한 데이터 회복 기법 중 (   ) 회복 기법은 로그를 이용한 회복 기법으로 데이터베이스에 대한 갱신 로그를 저장함으로써 회복에 대비한다.

(   ) 회복 기법은 트랜잭션이 실행 상태에서 변경되는 내용을 그때그때 바로 데이터베이스에 적용하는 기법이다.

(   ) 회복 기법은 장애가 발생하면 로그 파일에 기록된 내용을 참조하여 장애 발생 시점에 따라 Redo나 Undo를 실행하여 데이터베이스를 복구한다.

## 정답

**즉시 갱신(Immediate Update)**

---

# 즉시 갱신

트랜잭션이 완료되기 전이라도 변경 내용을 **즉시 데이터베이스에 반영**하고 그 내용을 로그에 기록한다.

장애가 발생하면:

```text
Undo
+
Redo
```

를 사용할 수 있다.

### 핵심

```text
즉시 DB 반영
+
로그 사용
+
Undo / Redo
→ 즉시 갱신
```

---

# 지연 갱신(Deferred Update) 🔥

트랜잭션이 완료되기 전에는 실제 데이터베이스에 변경 내용을 반영하지 않고 로그에만 기록한다.

트랜잭션이 완료된 후 반영한다.

### 회복

```text
Redo O
Undo X
```

왜?

완료 전에 DB 자체를 수정하지 않았기 때문이다.

---

# 즉시 갱신 vs 지연 갱신

```text
즉시 갱신
→ 완료 전 DB 반영
→ Undo + Redo

지연 갱신
→ 완료 후 DB 반영
→ Redo만
```

---

# 검사점 회복(Checkpoint Recovery)

트랜잭션 처리 중 특정 시점에 검사점을 설정하고, 장애 발생 시 검사점 이후의 로그를 중심으로 회복한다.

```text
Checkpoint
→ 복구해야 할 로그 범위 감소
```

---

# 그림자 페이징(Shadow Paging)

로그를 사용하지 않고 페이지의 복사본인 **그림자 페이지**를 유지한다.

```text
원본 페이지
+
Shadow Page
```

장애 발생 시 그림자 페이지를 이용하여 복구한다.

### 핵심

```text
로그 X
그림자 페이지 O
→ Shadow Paging
```

```text
전송
```

IPv4 주소와 IPv6 주소를 서로 변환하여 두 네트워크를 연결한다.

# 15. NAT 🔥🔥 매우 빈출

## 문제

* 내부에서 사용하는 사설 IP주소와 외부로 보여지는 공인 IP주소 간의 IP Address 변환 방식을 말한다.
* 한정된 공인 IP를 여러 개의 내부 사설 IP에 사용할 수 있도록 하는 기술

## 정답

**NAT(Network Address Translation)**

---

# NAT

사설 IP 주소와 공인 IP 주소를 서로 변환하는 기술이다.

```text
내부 네트워크
192.168.0.10
192.168.0.11
192.168.0.12
      ↓
     NAT
      ↓
공인 IP
```

## 목적

* 공인 IPv4 주소 부족 문제 완화
* 내부 사설망과 외부망 연결
* 내부 IP 주소를 직접 외부에 노출하지 않음

---

# 사설 IP 주소 범위 ⭐ 같이 외우기

```text

~
10.255.255.255
```



시험에서는 특히:

정도로 기억해두면 좋다.

---

# NAT / PAT

## NAT

IP 주소를 변환한다.

## PAT

**Port Address Translation**

IP 주소뿐 아니라 포트 번호까지 이용하여 **하나의 공인 IP를 여러 내부 호스트가 공유**할 수 있게 한다.

```text
192.168.0.10:5000 ─┐
192.168.0.11:5001 ─┼→ 하나의 공인 IP
192.168.0.12:5002 ─┘
```

실제 가정용 공유기 환경에서 흔히 사용하는 방식이다.


# 접근 통제 방식 같이 알아두기 🔥

## DAC

```text

```

## MAC

**Mandatory Access Control**

사용자가 임의로 권한을 바꿀 수 없고 **보안 등급과 정책**에 따라 시스템이 접근을 통제한다.

```text
보안 등급
보안 정책
→ MAC
```

---

## RBAC

**Role Based Access Control**

사용자의 역할(Role)에 따라 권한을 부여한다.

```text
관리자
회원
게스트
```

```text
역할
→ 권한
→ RBAC
```

---

# Bell-LaPadula 모델 🔥 중요

**기밀성(Confidentiality)을 보호하기 위한 접근 통제 모델**이다.

군사 보안 등급처럼 보안 레벨이 있는 환경에서 사용한다.

## 핵심 규칙

### No Read Up

**상위 등급의 정보를 읽을 수 없다.**

```text
낮은 등급 사용자
↓
높은 등급 정보 읽기 X
```

쉽게:

```text
위는 읽지 마
```

---

### No Write Down

**하위 등급으로 정보를 기록할 수 없다.**

```text
높은 등급 사용자
↓
낮은 등급 영역에 쓰기 X
```

왜?

높은 보안 정보가 낮은 등급으로 유출될 수 있기 때문이다.

쉽게:

```text
아래로 쓰지 마
```

---

## Bell-LaPadula 초암기

```text
기밀성 모델

No Read Up
→ 위 읽기 금지

No Write Down
→ 아래 쓰기 금지
```

---

# Biba 모델도 같이 알아두기 ⭐

Bell-LaPadula가 **기밀성**이라면 Biba는 **무결성(Integrity)**을 보호한다.

### Biba

```text
No Read Down
No Write Up
```

### 비교

```text
Bell-LaPadula
→ 기밀성
→ 위 읽기 X
→ 아래 쓰기 X

Biba
→ 무결성
→ 아래 읽기 X
→ 위 쓰기 X
```

이 둘은 반대로 외우면 편하다.

# 13. 단위 테스트 / 통합 테스트 🔥🔥 매우 중요

## 문제

`<보기>`에 해당하는 용어를 쓰시오.

(1) 개발자가 원시 코드를 대상으로 다른 부분과 연계되는 부분은 고려하지 않고, 각각의 단위 자체에만 집중하여 테스트한다.

(2) 인터페이스 간 시스템이 정상적으로 실행되는지 확인하는 테스트이다.

## 정답

(1) **단위 테스트(Unit Test)**

(2) **통합 테스트(Integration Test)**

---

# 테스트 단계

```text
단위 테스트
→ 통합 테스트
→ 시스템 테스트
→ 인수 테스트
```

---

# ① 단위 테스트

프로그램의 가장 작은 단위인 모듈, 클래스, 함수 등을 독립적으로 테스트한다.

```text
하나의 모듈 자체
→ 단위 테스트
```

> 정적 테스트와 동적 테스트는 `단위 테스트의 하위 분류`라기보다는 **프로그램 실행 여부에 따른 테스트 분류**이므로 별도로 구분해 기억하는 것이 더 정확하다.

---

# ② 통합 테스트

단위 테스트가 끝난 여러 모듈을 결합하여 **인터페이스와 상호작용이 정상적인지** 테스트한다.

## 통합 테스트 방법

### 하향식(Top-Down)

상위 모듈부터 아래로 내려가며 통합한다.

부족한 하위 모듈 대신:

**Stub** 사용

```text
Top-Down
→ Stub
```

---

### 상향식(Bottom-Up)

하위 모듈부터 위로 올라가며 통합한다.

상위 모듈 역할 대신:

**Driver** 사용

```text
Bottom-Up
→ Driver
```

---

### Big Bang

모든 모듈을 한 번에 통합하여 테스트한다.

### 샌드위치 / 혼합식

상향식과 하향식을 결합한다.

> 네 필기의 `백도어 테스트`는 통합 테스트의 표준 분류로 보기 어렵고, 보통 시험에서는 **하향식 / 상향식 / 빅뱅 / 샌드위치**를 중심으로 공부하는 게 안전하다.

---

# ③ 시스템 테스트

완성된 시스템 전체가 요구사항을 만족하는지 테스트한다.

### 종류

* 기능 테스트
* 비기능 테스트

---

# ④ 인수 테스트

사용자나 고객 관점에서 실제 사용이 가능한지 최종적으로 테스트한다.

### 종류

#### 알파 테스트

개발자 환경에서 사용자와 개발자가 함께 수행

#### 베타 테스트

실제 사용자 환경에서 사용자가 수행

```text
Alpha
→ 개발자 환경

Beta
→ 실제 사용
자 환경
```

# 15. IPC 🔥 빈출

## 문제

실행 프로세스 간에 통신을 가능하게 하는 기술로, 종류에는 파이프, 메시지 큐, 공유메모리, 세마포어, 소켓 등이 있다.

## 정답

**IPC(Inter-Process Communication)**

## 개념

서로 독립적으로 실행되는 프로세스들이 데이터를 주고받거나 동기화하기 위한 통신 기법이다.

## IPC 종류

```text
Pipe
Message Queue
Shared Memory
Semaphore
Socket
```

---

# ① Pipe

프로세스 사이에서 데이터를 한 방향 또는 양방향으로 전달한다.

# ② Message Queue

메시지를 큐에 저장하여 프로세스끼리 전달한다.

# ③ Shared Memory

여러 프로세스가 동일한 메모리 공간을 공유한다.

### 특징

```text
매우 빠름
```

하지만 동시 접근 문제 때문에 동기화가 필요하다.

# ④ Semaphore

공유 자원에 접근할 수 있는 프로세스 수를 제어한다.

# ⑤ Socket

네트워크 또는 로컬 환경에서 프로세스 간 통신에 사용한다.

---

# IPC 초압축

```text

→ IPC

Pipe
Message Queue
Shared Memory
Semaphore
Socket
```

# 1. Ad-hoc Network 🔥 빈출

## 문제

## 핵심

```text

→ Ad-hoc Network
```

# 5. 트랜잭션 원자성 🔥🔥 매우 빈출

## 문제

트랜잭션의 특성 중 원자성에 대해 설명하시오.

## 정답

**연산의 결과는 모두 반영되거나 모두 반영되지 않아야 한다.**

## 시험용 답안

> 트랜잭션의 모든 연산은 전부 수행되거나 전부 수행되지 않아야 한다.

---

# ACID

```text
A = Atomicity
C = Consistency
I = Isolation
D = Durability
```

## Atomicity - 원자성

```text
All or Nothing
```

전부 수행 또는 전부 취소

## Consistency - 일관성

트랜잭션 수행 전후 데이터베이스가 일관된 상태를 유지해야 한다.

## Isolation - 격리성 / 독립성

트랜잭션들이 서로 영향을 주지 않고 독립적으로 수행되어야 한다.

## Durability - 영속성

완료된 트랜잭션의 결과는 영구적으로 저장되어야 한다.

## 암기

```text
A 원자성
→ 전부 또는 전무

C 일관성
→ 일관된 상태 유지

I 격리성
→ 서로 간섭 X

D 영속성
→ 결과 영구 저장
```

# 정규화

## 제1정규형(1NF)

속성값이 원자값을 가져야 한다.

```text
반복 속성 제거
→ 1NF
```

## 제2정규형(2NF)

부분 함수 종속을 제거한다.

```text
부분 함수 종속 제거
→ 2NF
```

## 제3정규형(3NF)

이행 함수 종속을 제거한다.

```text
이행 함수 종속 제거
→ 3NF
```

## BCNF

모든 결정자가 후보키가 되도록 한다.

```text
결정자
→ 후보키
```

# 키(Key) 🔥🔥

## 슈퍼키

튜플을 유일하게 식별할 수 있는 속성 집합

```text
유일성 O
최소성 X
```

## 후보키

튜플을 유일하게 식별하면서 최소성도 만족

```text
유일성 O
최소성 O
```

## 기본키

후보키 중 대표로 선택된 키

```text
유일성 O
최소성 O
NULL X
```

## 대체키

후보키 중 기본키로 선택되지 않은 키

## 외래키

다른 테이블의 기본키 또는 후보키를 참조하는 키

### 중요 수정

네 필기의

```text
외래키 유일성 최소성 모두 만족
```

은 틀린 내용이다.

외래키는

```text
유일성 필수 X
최소성 필수 X
```

이다.

## 초압축

```text
슈퍼키
→ 유일성

후보키
→ 유일성 + 최소성

기본키
→ 후보키 중 대표

외래키
→ 다른 테이블의 키 참조
```

# 11. 로킹(Locking) 🔥🔥 매우 빈출

## 문제

하나의 트랜잭션이 데이터를 액세스하는 동안 다른 트랜잭션이 그 데이터 항목을 액세스할 수 없도록 하는 병행 제어 기법은?

## 정답

**로킹(Locking)**

## 개념

한 트랜잭션이 특정 데이터를 사용하는 동안 다른 트랜잭션의 접근을 제한하여 데이터의 일관성을 유지하는 병행 제어 기법이다.

```text
트랜잭션 A
↓
데이터 Lock
↓
트랜잭션 B 접근 제한
```

## Shared Lock

읽기를 위한 잠금

```text
읽기 가능
쓰기 제한
```

## Exclusive Lock

쓰기 등을 위해 다른 트랜잭션의 접근을 강하게 제한하는 잠금

## 로킹 단위

```text
로킹 단위 작음
→ 동시성 ↑
→ 관리 부담 ↑

로킹 단위 큼
→ 동시성 ↓
→ 관리 부담 ↓
```

(2) 동일한 입력과 출력을 사용하는 소작업들이 모인 경우

(3) 모듈 내부의 모든 기능 요소들이 한 문제와 연관되어 수행되는 경우

## 정답

(1) **절차적 응집도**

(2) **통신적(교환적) 응집도**

(3) **기능적 응집도**

---

# 응집도 순서

응집도는 **높을수록 좋다.**

좋음 → 나쁨

```text
기능적
→ 순차적
→ 통신적
→ 절차적
→ 시간적
→ 논리적
→ 우연적
```

암기:

```text
기순통절시논우
```

---

## 기능적 응집도

모듈 내부의 모든 기능이 하나의 기능에 집중

→ 가장 좋음

## 순차적 응집도

한 작업의 출력이 다음 작업의 입력이 됨

```text
A 출력
↓
B 입력
```

## 통신적 응집도

동일한 입력 또는 출력을 사용하는 작업들이 모임

## 절차적 응집도

기능들이 정해진 순서에 따라 실행

## 시간적 응집도

특정 시점에 함께 수행

예:

```text
초기화
종료 처리
```

## 논리적 응집도

유사한 성격의 작업들을 하나로 묶음

## 우연적 응집도

관련 없는 기능이 하나의 모듈에 모임

→ 가장 나쁨

---

## 문제

다음은 파일 구조에 대한 설명이다. 빈 칸에 알맞은 답을 작성하시오.

* 파일의 구조는 파일을 구성하는 레코드들이 보조기억장치에 편성되는 방식을 의미하는 것으로, 편성 방법에 따라 순차, (   ), 랜덤, 해싱 등이 있다.
* (   )은 순차 처리와 랜덤 처리가 모두 가능하도록 레코드들을 키 값 순으로 정렬하여 기록하여 데이터에 접근한다. 자기 디스크에서 주로 사용된다.

**색인**

## 관련 개념

색인을 이용하면서 레코드를 키 값 순서로 저장하여 순차 접근과 직접 접근을 모두 지원하는 방식이다.

### 순차 파일

레코드를 논리적인 순서대로 연속 저장한다.

```text
A → B → C → D
```

### 직접 파일

키를 이용해 레코드가 저장된 위치에 직접 접근한다.

### 색인 순차 파일

순차 파일과 직접 파일의 장점을 결합한다.

```text
순차 처리 가능
+
직접 접근 가능
+
Index 사용
→ 색인 순차 파일
```

### 시험에서는

```text
빈칸 정답
→ 색인

전체 파일 구조 명칭
→ 색인 순차 파일
```

로 구분해서 기억한다.

# 1. RAID 0 🔥

## 문제

다음 설명에 맞는 RAID 단계를 쓰시오.

- 두 개 이상의 하드디스크를 병렬로 연결해 하나의 하드디스크처럼 이용하는 기술이다.
- 스트라이프 방식으로 구현한다.
- 데이터가 분산되어 저장되기 때문에 하나의 하드디스크에 문제가 생기면 전체 데이터 사용에 문제가 발생할 수 있다.

## 정답

**RAID 0**

## 개념

여러 디스크에 데이터를 나누어 동시에 저장하는 **스트라이핑(Striping)** 방식이다.
```text
Disk 1 : A1  A3  A5
Disk 2 : A2  A4  A6
```

### 장점

- 읽기/쓰기 속도 향상
- 디스크 용량을 모두 활용

### 단점

- 장애 복구 기능 없음
- 디스크 하나가 고장 나도 전체 데이터 손실 가능
```text
RAID 0
→ Striping
→ 성능 ↑
→ 복구 기능 X
```

---

# RAID 단계 비교

## RAID 0
```text
Striping
성능 향상
복구 기능 X
```

## RAID 1

두 개 이상의 디스크에 같은 데이터를 복제한다.
```text
Mirroring
→ 동일 데이터 복사
```

장애 안정성이 높지만 실제 사용 가능한 용량이 줄어든다.

---

## RAID 2

오류 검출 및 정정을 위해 \*\*해밍 코드(Hamming Code)\*\*를 사용한다.

---

## RAID 3

데이터를 여러 디스크에 분산하고 **별도의 한 디스크를 패리티 전용**으로 사용한다.

일반적으로 바이트 단위 스트라이핑 개념과 연결된다.

---

## RAID 4

RAID 3과 유사하지만 **블록 단위**로 데이터를 분산 저장하며 별도의 패리티 디스크를 둔다.

---

## RAID 5

3개 이상의 디스크를 사용하며 **패리티 정보를 여러 디스크에 분산 저장**한다.
```text
RAID 5
→ 분산 패리티 1개
```

디스크 하나의 장애까지 복구 가능하다.

---

## RAID 6

RAID 5와 비슷하지만 **서로 다른 두 개의 패리티 정보를 분산 저장**한다.
```text
RAID 6
→ 이중 분산 패리티
→ 디스크 2개 장애까지 견딜 수 있음
```

### 주의

`패리티 하나를 두 디스크에 복사한다`기보다는:
```text
서로 다른 2개의 패리티 정보를 분산 저장
```

한다고 이해하는 것이 정확하다.

---

```text
→ Striping / 복구 X

RAID 1
→ Mirroring

RAID 2
→ Hamming Code

RAID 3
```

# 2. REDO / UNDO 🔥🔥

## 문제

로그 기반 회복 기법에서 사용되는 명령이다.

(1) 트랜잭션 로그를 이용하여 오류가 발생한 트랜잭션을 재실행하여 복구한다.

(2) 트랜잭션 로그를 이용하여 오류와 관련된 내용을 취소하여 복구한다.

## 정답

(1) **REDO**

(2) **UNDO**

---

# REDO

이미 완료된 작업을 로그를 이용하여 다시 수행한다.
```text
REDO
→ 다시 실행
```

---

# UNDO

정상 완료되지 않은 트랜잭션의 변경 내용을 이전 상태로 되돌린다.
```text
UNDO
→ 취소 / 이전 상태 복원
```

---

# 즉시 갱신 / 지연 갱신

## 즉시 갱신

트랜잭션이 완료되기 전에도 DB에 변경 내용이 반영될 수 있다.
```text
Immediate Update
→ UNDO + REDO
```

## 지연 갱신

트랜잭션이 완료되기 전에는 DB에 실제 변경 내용을 반영하지 않는다.
```text
Deferred Update
→ REDO
→ UNDO 불필요
```

---

# 트랜잭션 ACID
```text
A = Atomicity
C = Consistency
I = Isolation
D = Durability
```

## 원자성

모두 수행되거나 모두 수행되지 않아야 한다.
```text
All or Nothing
```

COMMIT / ROLLBACK과 관련이 깊다.

## 일관성

트랜잭션 전후 데이터베이스가 일관된 상태를 유지해야 한다.

## 격리성

여러 트랜잭션이 서로 영향을 주지 않고 독립적으로 수행되어야 한다.

## 영속성

완료된 트랜잭션의 결과는 영구적으로 저장되어야 한다.

```text
Car 객체
```

Car는:
```java
implements Runnable
```

이므로 `Runnable` 타입으로 Thread 생성자에 전달할 수 있다.
```java
new Thread(new Car());
```

---

# 원래 정상적인 Runnable 구현은
```java
class Car implements Runnable {

    @Override
    public void run() {
        System.out.println("func call");
    }
}
```

처럼 `run()`을 구현해야 한다.

그리고:
```java
Thread t1 = new Thread(new Car());
t1.start();
```

를 호출하면 내부적으로:
```text
start()
↓
새로운 스레드 생성
↓
run()
```

이 실행된다.

---

# 중요 주의 ⚠️

네가 적어준 코드에는:
```java
public void fun()
```

만 있고
```java
public void run()
```

이 없다.

`Runnable` 인터페이스는:
```java
void run();
```

을 구현해야 한다.

따라서 **문제의 빈칸 답은&#x20;****`Car`****가 맞지만**, 네가 적은 코드가 문제 원문 그대로라면 `Car` 클래스는 `run()`을 구현하지 않아 컴파일 오류가 발생한다.

시험 문제 원본에서는 `fun()`이 아니라 `run()`이었거나 다른 코드가 생략되었을 가능성이 있다.

# Thread 상속 방식과 비교

## Thread 상속
```java
class MyThread extends Thread {

    @Override
    public void run() {
    }
}

MyThread t = new MyThread();
t.start();
```

## Runnable 구현
```java
class Car implements Runnable {

    @Override
    public void run() {
    }
}

Runnable r = new Car();
Thread t = new Thread(r);
t.start();
```

또는:
```java
Thread t = new Thread(new Car());
t.start();
```

```text
extends Thread
→ 내가 Thread 객체

implements Runnable
→ 실행할 작업을 정의
→ Thread 객체에 전달
```

# 17. Java 객체 참조와 메서드 호출 🔥🔥

## 문제 코드
```java
class A {
    int a;
    int b;
}

public class Main {

    static void func1(A a) {
        a.a *= 10;
    }

    static void func2(A a) {
        a.a += a.b;
    }

    public static void main(String[] args) {

        A a = new A();
        a.a = 100;

        func1(m);

        a.b = a.a;

        func2(a);

        System.out.println(a.a);
    }
}
```

## 중요 확인

이미지에는:
```java
func1(m);
```

이라고 되어 있다.

현재 보이는 코드에는 `m`의 선언이 없다.

따라서 현재 보이는 코드가 전부라면:
```text
m 선언 없음
→ 컴파일 오류
```

이다.

---

# 만약 `m`이 `a`와 같은 객체를 참조한다면

예:
```java
A m = a;
```

라고 앞에서 선언되어 있었다면:
```text
a ───┐
     ↓
   A 객체
     ↑
m ───┘
```

둘 다 같은 객체를 가리킨다.

초기:
```text
a 필드 = 100
b 필드 = 0
```

---

## func1(m)
```java
static void func1(A a) {
    a.a *= 10;
}
```
```text
100 × 10
= 1000
```

객체:
```text
a = 1000
b = 0
```

---

## a.b = a.a
```text
a = 1000
b = 1000
```

---

## func2(a)
```java
static void func2(A a) {
    a.a += a.b;
}
```

즉:
```text
1000 + 1000
= 2000
```

따라서 `m`과 `a`가 같은 객체라면:
```text
출력 = 2000
```

---

# 핵심
```text
객체를 메서드로 전달
→ 참조값이 복사됨
→ 같은 객체를 가리킬 수 있음
→ 객체 필드 변경 내용이 공유됨
```

# 18. C 재귀함수 / 팩토리얼 🔥🔥

## 문제

입력값은 5이다.
```c
#include <stdio.h>

int func(int i) {

    if(i <= 1)
        return 1;

    return i * func(i - 1);
}

int main() {

    int in;

    scanf("%d", &in);

    printf("%d", func(in));
}
```

## 정답
```text
120
```

---

# 실행
```text
func(5)
= 5 × func(4)

func(4)
= 4 × func(3)

func(3)
= 3 × func(2)

func(2)
= 2 × func(1)

func(1)
= 1
```

다시 올라오면:
```text
func(2)
= 2

func(3)
= 6

func(4)
= 24

func(5)
= 120
```

즉:
```text
5!
= 5 × 4 × 3 × 2 × 1
= 120
```

---

# 핵심
```text
자기 자신 호출
→ 재귀함수
```

종료 조건:
```c
if(i <= 1)
    return 1;
```

# 20. C 소수 판별 + 최대 소수 약수 🔥🔥

## 문제
```c
int isPrime(int number) {

    int i;

    for(i = 2; i < number; i++) {

        if(number % i == 0)
            return 0;
    }

    return 1;
}

int main(void) {

    int number = 13195;
    int max_div = 0;
    int i;

    for(i = 2; i < number; i++)

        if(isPrime(i) == 1 && number % i == 0)

            max_div = i;

    printf("%d", max_div);

    return 0;
}
```

## 정답
```text
29
```

---

# isPrime()

소수를 판별하는 함수이다.
```text
return 1
→ 소수

return 0
→ 소수 아님
```

예:
```text
5 % 2 != 0
5 % 3 != 0
5 % 4 != 0

→ isPrime(5) = 1
```

반면:
```text
6 % 2 = 0

→ isPrime(6) = 0
```

---

# 핵심 조건
```c
if(isPrime(i) == 1 && number % i == 0)
```

첫 번째:
```text
isPrime(i) == 1
→ i가 소수인가?
```

두 번째:
```text
number % i == 0
→ i가 13195의 약수인가?
```

따라서:
```text
소수이면서
13195의 약수
```

를 찾는다.

---

# 13195 소인수분해
```text
13195 = 5 × 7 × 13 × 29
```

따라서 소수 약수는:
```text
5
7
13
29
```

이다.

for문이 작은 값부터 증가하면서 조건을 만족할 때마다:
```c
max_div = i;
```

로 덮어쓴다.
```text
5
→ max_div = 5

7
→ max_div = 7

13
→ max_div = 13

29
→ max_div = 29
```

29보다 큰 소수는 존재하지만:
```text
31
37
41
43
...
```

이들은 13195를 나누어떨어지게 하지 않는다.

따라서 최종값:
```text
29
```
