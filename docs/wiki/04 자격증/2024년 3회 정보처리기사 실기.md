# 1. Java String 객체 / `equals()` 🔥🔥

## 문제

다음 Java 프로그램의 실행 결과를 쓰시오.

```java
public class Gisafirst {

    static String[] x = new String[3];

    static void func(String[] x, int y) {

        for (int i = 1; i < y; i++) {

            if (x[i-1].equals(x[i])) {
                System.out.print("O");
            }
            else {
                System.out.print("N");
            }
        }

        for (String z : x) {
            System.out.print(z);
        }
    }

    public static void main(String[] args) {

        x[0] = "A";
        x[1] = "A";
        x[2] = new String("A");

        func(x, 3);
    }
}
```

## 정답

```text
OOAAA
```

## 실행 과정

```text
x[0] = "A"
x[1] = "A"
x[2] = new String("A")
```

`x[0]`, `x[1]`은 문자열 리터럴 `"A"`를 사용한다.

반면:

```java
x[2] = new String("A");
```

는 새로운 String 객체를 생성한다.

하지만 비교 연산자는 `==`가 아니라:

```java
equals()
```

이다.

`equals()`는 문자열의 **내용**을 비교한다.

```java
x[0].equals(x[1])
```

→ `"A"`와 `"A"`이므로 `true`

```text
O
```

다음:

```java
x[1].equals(x[2])
```

객체는 다르지만 문자열 내용은 둘 다 `"A"`이므로:

```text
O
```

현재 출력:

```text
OO
```

다음 향상된 for문:

```java
for (String z : x) {
    System.out.print(z);
}
```

배열의 문자열은:

```text
A
A
A
```

따라서:

```text
AAA
```

최종:

```text
OOAAA
```

## `==`와 `equals()` 차이

```text
==
→ 참조값 비교
→ 같은 객체인지 비교

equals()
→ 문자열 내용 비교
→ 같은 문자열인지 비교
```

예:

```java
String a = "A";
String b = new String("A");

System.out.println(a == b);       // false
System.out.println(a.equals(b));  // true
```

# 2. Python 리스트 역순 / 슬라이싱 🔥🔥

## 문제

```python
def func(lst):

    for i in range(len(lst) // 2):

        lst[i], lst[-i-1] = lst[-i-1], lst[i]


lst = [1, 2, 3, 4, 5, 6]

func(lst)

print(sum(lst[::2]) - sum(lst[1::2]))
```

## 정답

```text
3
```

## 리스트 뒤집기

처음:

```text
[1, 2, 3, 4, 5, 6]
```

길이는 6이므로:

```python
range(len(lst) // 2)
```

는:

```text
range(3)
```

즉:

```text
i = 0, 1, 2
```

### i = 0

```python
lst[0], lst[-1] = lst[-1], lst[0]
```

```text
1 ↔ 6
```

결과:

```text
[6, 2, 3, 4, 5, 1]
```

### i = 1

```text
2 ↔ 5
```

결과:

```text
[6, 5, 3, 4, 2, 1]
```

### i = 2

```text
3 ↔ 4
```

결과:

```text
[6, 5, 4, 3, 2, 1]
```

## 슬라이싱

```python
lst[::2]
```

인덱스:

```text
0, 2, 4
```

값:

```text
6, 4, 2
```

합:

```text
12
```

다음:

```python
lst[1::2]
```

인덱스:

```text
1, 3, 5
```

값:

```text
5, 3, 1
```

합:

```text
9
```

따라서:

```text
12 - 9 = 3
```

## 슬라이싱 형식

```text
list[start:end:step]
```

예:

```python
a[::2]
```

→ 0, 2, 4 ... 인덱스

```python
a[1::2]
```

→ 1, 3, 5 ... 인덱스

```python
a[::-1]
```

→ 역순

# 3. SQL JOIN + 중첩 서브쿼리 🔥🔥

## 문제

### employee

| no | first_name | last_name | project_id |
|---:|---|---|---:|
| 1 | John | Doe | 10 |
| 2 | Jim | Carry | 20 |
| 3 | Rachel | Redmond | 10 |

### project

| project_id | name |
|---:|---|
| 10 | Alpha |
| 20 | Beta |
| 10 | Gamma |

```sql
SELECT COUNT(*)
FROM employee AS e
JOIN project AS p
    ON e.project_id = p.project_id
WHERE p.name IN (
    SELECT name
    FROM project p
    WHERE p.project_id IN (
        SELECT project_id
        FROM employee
        GROUP BY project_id
        HAVING COUNT(*) < 2
    )
);
```

## 정답

```text
1
```

## 실행 과정

가장 안쪽 서브쿼리부터 실행한다.

```sql
SELECT project_id
FROM employee
GROUP BY project_id
HAVING COUNT(*) < 2;
```

employee 테이블에서:

```text
project_id = 10
→ John, Rachel
→ 2명

project_id = 20
→ Jim
→ 1명
```

따라서:

```text
project_id = 20
```

다음:

```sql
SELECT name
FROM project
WHERE project_id IN (20);
```

결과:

```text
Beta
```

메인 쿼리에서:

```sql
WHERE p.name IN ('Beta')
```

Beta와 연결되는 직원은 Jim 1명이다.

따라서:

```text
COUNT(*) = 1
```

## 핵심 개념

```text
중첩 서브쿼리
→ 가장 안쪽부터 실행

GROUP BY
→ 그룹화

HAVING
→ 그룹 조건

JOIN
→ 관련 행 연결
```

# 4. LRU 페이지 교체 알고리즘 🔥🔥

## 문제

3개의 페이지를 수용할 수 있는 주기억장치가 있으며 처음에는 모두 비어 있다.

페이지 참조 순서:

```text
7 0 1 2 0 3 0 4 2 3 0 3 2 1 2 0 1 7 0 1
```

LRU 페이지 교체 알고리즘을 사용할 경우 페이지 부재(Page Fault)의 횟수를 구하시오.

## 정답

```text
12회
```

## LRU

**Least Recently Used**

최근에 가장 오랫동안 사용하지 않은 페이지를 교체한다.

```text
기준
→ 마지막으로 사용된 시간
```

진행 결과 Page Fault는 총:

```text
12회
```

## 페이지 교체 알고리즘 비교

```text
FIFO
→ 가장 먼저 들어온 페이지 교체

LRU
→ 가장 오래 사용하지 않은 페이지 교체

LFU
→ 사용 빈도가 가장 낮은 페이지 교체

OPT
→ 앞으로 가장 늦게 사용할 페이지 교체
```

# 5. Smurf Attack 🔥🔥

## 문제

- IP나 ICMP의 특성을 악용한다.
- 송신 주소를 공격 대상의 IP 주소로 위조한다.
- 브로드캐스트 주소로 ICMP 패킷을 전송한다.
- 네트워크의 여러 컴퓨터가 공격 대상에게 응답하게 하여 네트워크를 마비시킨다.

## 정답

**Smurf Attack(스머프 공격)**

## 공격 구조

```text
공격자
↓
출발지 IP를 피해자의 IP로 위조
↓
ICMP Echo Request
↓
Broadcast 주소
↓
여러 컴퓨터가 Echo Reply
↓
피해자에게 응답 집중
↓
서비스 거부
```

## 핵심 키워드

```text
ICMP
IP Spoofing
Broadcast
응답 증폭
```

## 비슷한 공격

### Ping of Death

허용 범위를 넘어서는 큰 IP 패킷을 전송하여 시스템 장애를 유발한다.

### ICMP Flooding

대량의 ICMP 패킷을 직접 전송하여 자원을 고갈시킨다.

# 6. C static 지역 변수 🔥🔥

## 문제

```c
#include <stdio.h>

int func() {

    static int x = 0;

    x += 2;

    return x;
}

int main() {

    int x = 0;
    int sum = 0;

    for (int i = 0; i < 4; i++) {

        x++;

        sum += func();
    }

    printf("%d", sum);

    return 0;
}
```

## 정답

```text
20
```

## 실행 과정

`func()` 안의:

```c
static int x = 0;
```

는 함수가 종료되어도 값이 유지된다.

호출 순서:

```text
1회
0 → 2

2회
2 → 4

3회
4 → 6

4회
6 → 8
```

따라서:

```text
sum
= 2 + 4 + 6 + 8
= 20
```

main의 `x`와 func의 `x`는 서로 다른 변수이다.

```text
일반 지역 변수
→ 함수 종료 시 사라짐

static 지역 변수
→ 값 유지
```


# 10. C 연결 리스트 / 구조체 포인터 🔥🔥

## 문제

```c
#include <stdio.h>

struct Node {
    int value;
    struct Node* next;
};

void func(struct Node* node) {

    while (node != NULL &&
           node->next != NULL) {

        int t = node->value;

        node->value =
            node->next->value;

        node->next->value = t;

        node = node->next->next;
    }
}

int main() {

    struct Node n1 = {1, NULL};
    struct Node n2 = {2, NULL};
    struct Node n3 = {3, NULL};

    n1.next = &n3;
    n3.next = &n2;

    func(&n1);

    struct Node* current = &n1;

    while (current != NULL) {

        printf("%d", current->value);

        current = current->next;
    }

    return 0;
}
```

## 정답

```text
312
```

## 연결 구조

처음:

```text
n1 → n3 → n2

1 → 3 → 2
```

`func(&n1)`에서 첫 번째 노드와 다음 노드의 값을 교환한다.

```text
n1 값
1 → 3

n3 값
3 → 1
```

결과:

```text
3 → 1 → 2
```

따라서 출력:

```text
312
```

# 11. URL 구조 🔥🔥

## 문제

다음 URL을 보고 구성 요소를 구분하시오.

```text
foo://example.com:8042/over/there?name=ferret#nose
```

## 정답

```text
1 → scheme
2 → authority
3 → path
4 → query
5 → fragment
```

<보기> 순서가:

```text
query
path
scheme
authority
fragment
```

이라면 답은:

```text
4, 3, 1, 2, 5
```

## URL 구조

```text
scheme://authority/path?query#fragment
```

### Scheme

접근 방법 또는 프로토콜.

```text
http
https
ftp
```

### Authority

호스트명, 포트 번호, 사용자 정보 등을 포함한다.

### Path

서버 내부 특정 자원 경로.

### Query

`?` 뒤에 붙는 추가 데이터.

### Fragment

`#` 뒤에 붙는 문서 내부 위치.

# 12. Python `type()` / 자료형 판별 🔥🔥

## 문제

```python
def func(value):

    if type(value) == type(100):
        return 100

    elif type(value) == type(""):
        return len(value)

    else:
        return 20


a = "100.0"
b = 100.0
c = (100, 200)

print(func(a) + func(b) + func(c))
```

## 정답

```text
45
```

## 실행 과정

### a

```python
a = "100.0"
```

문자열이다.

```text
len("100.0") = 5
```

따라서:

```text
func(a) = 5
```

### b

```python
b = 100.0
```

자료형은 `float`.

`int`도 아니고 `str`도 아니므로:

```text
func(b) = 20
```

### c

```python
c = (100, 200)
```

자료형은 `tuple`.

따라서:

```text
func(c) = 20
```

최종:

```text
5 + 20 + 20
= 45
```

## Python 주요 자료형

```text
int
→ 정수

float
→ 실수

str
→ 문자열

bool
→ 논리값

list
→ 리스트

tuple
→ 튜플

set
→ 집합

dict
→ 딕셔너리
```

# 13. UML 관계 🔥🔥

## 문제

UML 모델에서 각 관계를 쓰시오.

### ①

차와 타이어, 바퀴, 엔진이 실선으로 연결되어 있음.

### ②

버스, 택시, 승용차가 차를 상위 개념으로 가지며 빈 삼각형 화살표로 연결되어 있음.

### ③

텔레비전에서 리모콘으로 점선 화살표가 향함.

## 정답

```text
① 연관 관계
   Association

② 일반화 관계
   Generalization

③ 의존 관계
   Dependency
```

## 연관 관계

둘 이상의 사물이 서로 관련되어 있는 관계.

```text
실선
```

## 일반화 관계

상위 클래스와 하위 클래스의 관계.

```text
IS-A
```

예:

```text
버스 is a 차
```

표현:

```text
빈 삼각형 화살표

```

## 의존 관계

한 사물이 다른 사물을 일시적으로 사용하는 관계.

```text
점선 화살표
```

## 집약 관계(Aggregation)

전체-부분 관계이지만 서로 독립적으로 존재 가능.

```text
빈 마름모
```

예:

```text
컴퓨터 ◇──── 프린터
```

## 포함/합성 관계(Composition)

집약보다 강한 전체-부분 관계.

전체가 없어지면 부분 객체도 함께 생명주기가 종료된다.

```text
채워진 마름모
```

## 실체화 관계(Realization)

인터페이스와 구현 클래스의 관계.

```text
점선 + 빈 삼각형
```

Java의:

```java
implements
```

와 연결해서 보면 된다.

# 14. Java 상속 / 오버라이딩 / 필드 숨김 🔥🔥

## 문제

```java
public class Main {

    public static void main(String[] args) {

        B a = new D();
        D b = new D();

        System.out.print(
            a.getX() + a.x +
            b.getX() + b.x
        );
    }
}

class B {

    int x = 3;

    int getX() {
        return x * 2;
    }
}

class D extends B {

    int x = 7;

    int getX() {
        return x * 3;
    }
}
```

## 정답

```text
52
```

## 핵심 원리

```text
메서드
→ 실제 객체 기준
→ 오버라이딩 적용

필드
→ 참조변수 타입 기준
```

### `B a = new D();`

참조 타입:

```text
B
```

실제 객체:

```text
D
```

`a.getX()`는 실제 객체 D의 메서드가 호출된다.

```text
7 × 3
= 21
```

`a.x`는 참조 타입 B 기준이다.

```text
B.x = 3
```

### `D b = new D();`

```text
b.getX()
= 7 × 3
= 21
```

```text
b.x
= 7
```

최종:

```text
21 + 3 + 21 + 7
= 52
```

# 16. 개체 무결성(Entity Integrity) 🔥🔥

## 문제

다음 무결성 제약 조건에 대한 설명에서 괄호에 들어갈 알맞은 용어를 쓰시오.

> `(    )` 무결성은 기본 테이블의 기본키를 구성하는 어떠한 속성도 `NULL` 값이나 중복값을 가질 수 없다는 규정이다.

## 정답

**개체 무결성(Entity Integrity)**

## 개념

개체 무결성은 **기본키(Primary Key)**와 관련된 제약 조건이다.

기본키는:

```text
NULL X
중복 X
```

이어야 한다.

## 주요 무결성 제약 조건

### 개체 무결성

```text
기본키
→ NULL X
→ 중복 X
```

### 참조 무결성

외래키는 참조 대상 테이블에 존재하는 기본키 값 또는 허용된 경우 `NULL`이어야 한다.

### 도메인 무결성

속성값은 정의된 자료형, 범위, 형식을 만족해야 한다.

### 사용자 정의 무결성

업무 규칙에 따라 사용자가 직접 정의한 제약 조건.

# 17. Java 예외처리 / `try-catch-finally` 🔥🔥

## 문제

```java
public class Main {

    public static void main(String[] args) {

        int sum = 0;

        try {
            func();
        }
        catch (NullPointerException e) {
            sum = sum + 1;
        }
        catch (Exception e) {
            sum = sum + 10;
        }
        finally {
            sum = sum + 100;
        }

        System.out.print(sum);
    }

    static void func() throws Exception {

        throw new NullPointerException();
    }
}
```

## 정답

```text
101
```

## 실행 과정

초기값:

```text
sum = 0
```

`func()`에서:

```java
throw new NullPointerException();
```

이 실행된다.

따라서:

```java
catch (NullPointerException e)
```

가 실행된다.

```text
sum
0 → 1
```

그 뒤:

```java
finally
```

가 실행된다.

```text
1 + 100
= 101
```

따라서:

```text
101
```

## catch 순서

`NullPointerException`은 `Exception`의 하위 클래스이다.

따라서:

```text
구체적인 예외
→ 넓은 예외
```

순서로 작성해야 한다.

# 18. Java 제네릭 / 메서드 오버로딩 🔥🔥

## 문제

```java
class Printer {

    void print(Integer a) {
        System.out.print("A" + a);
    }

    void print(Object a) {
        System.out.print("B" + a);
    }

    void print(Number a) {
        System.out.print("C" + a);
    }
}

public class Main {

    public static void main(String[] args) {

        new Collection<>(0).print();
    }

    public static class Collection<T> {

        T value;

        public Collection(T t) {
            value = t;
        }

        public void print() {
            new Printer().print(value);
        }
    }
}
```

## 정답

```text
B0
```

## 이유

`Collection<T>` 내부의:

```java
T value;
```

에서 `T`의 상한을 따로 지정하지 않았으므로 컴파일 시 기본 상한은:

```text
Object
```

이다.

따라서:

```java
new Printer().print(value);
```

에서 오버로딩을 결정할 때:

```java
print(Object a)
```

가 선택된다.

내용:

```java
System.out.print("B" + a);
```

따라서:

```text
B0
```

## 타입 관계

```text
Object
  ↑
Number
  ↑
Integer
```

## 오버로딩

```java
print(Integer)
print(Number)
print(Object)
```

처럼 메서드 이름은 같지만 매개변수 타입이 다른 형태이다.

# 19. C 이중 포인터 / 배열 값 변경 🔥🔥

## 문제

```c
#include <stdio.h>

void func(int** arr, int size) {

    for (int i = 0; i < size; i++) {

        *(*arr + i) =
            (*(*arr + i) + i) % size;
    }
}

int main() {

    int arr[] = {3, 1, 4, 1, 5};

    int* p = arr;

    int** pp = &p;

    int num = 6;

    func(pp, 5);

    num = arr[2];

    printf("%d", num);

    return 0;
}
```

## 정답

```text
1
```

## 포인터 구조

```c
int* p = arr;
```

`p`는 배열의 첫 번째 요소를 가리킨다.

```c
int** pp = &p;
```

`pp`는 `p`의 주소를 저장한다.

```text
pp
↓
p
↓
arr
```

따라서:

```text
*pp
→ p

**pp
→ arr[0]
```

## 식 해석

```c
*(*arr + i)
```

는 결국:

```text
원래 배열의 arr[i]
```

와 같은 위치를 의미한다.

공식:

```text
새 값
= (기존 값 + i) % 5
```

처음 배열:

```text
3 1 4 1 5
```

### i = 0

```text
(3 + 0) % 5
= 3
```

### i = 1

```text
(1 + 1) % 5
= 2
```

### i = 2

```text
(4 + 2) % 5
= 1
```

### i = 3

```text
(1 + 3) % 5
= 4
```

### i = 4

```text
(5 + 4) % 5
= 4
```

최종 배열:

```text
3 2 1 4 4
```

다음:

```c
num = arr[2];
```

따라서:

```text
1
```

# 20. Ad-hoc Network / 네트워크 신기술 🔥🔥

## 문제

다음 설명에 해당하는 용어를 쓰시오.

- 재난 및 군사 현장처럼 고정된 유선망을 구축할 수 없는 장소에서 모바일 호스트만을 이용하여 구성
- 단기간 사용되는 경우나 유선망 구성이 어려운 경우 적합
- 멀티 홉 라우팅 지원

## 정답

**Ad-hoc Network(애드혹 네트워크)**

## 개념

기지국이나 Access Point 같은 고정 인프라 없이 이동 단말들이 직접 네트워크를 구성한다.

```text
Mobile Host
↕
Mobile Host
↕
Mobile Host
```

각 노드는 다른 노드의 데이터를 중계하는 라우터 역할도 수행할 수 있다.

## Multi-Hop Routing

직접 통신할 수 없는 경우 중간 노드를 거친다.

```text
A → B → C → D
```

## 활용

```text
재난 현장
군사 네트워크
긴급 구조
임시 네트워크
```

# 네트워크 관련 신기술 추가 정리

```text
자원 공유
+
네트워크
```

```text
Cloud A
↕
Cloud B
↕
Cloud C
```

```text

장애 대응
넓은 범위
```

주변 상황에 맞추어 스스로 망을 구성하고 최적화하는 네트워크.

```text
Organizing
Network
```

하나의 물리적 네트워크를 여러 개의 독립된 가상 네트워크로 나누는 기술.
