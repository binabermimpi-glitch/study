# 1. 동등 분할 테스트(Equivalence Partitioning) 🔥🔥

## 문제

다음 설명에 해당하는 테스트 기법을 작성하시오.

> 입력 데이터의 영역을 유사한 도메인별로 **유효값과 무효값으로 그룹화**하여 대표값을 테스트 케이스로 도출하는 테스트 기법은 무엇인가?

## 정답

**동등 분할 테스트(Equivalence Partitioning Testing)**

## 개념

입력값을 비슷한 특성을 가지는 영역으로 나눈 뒤, 각 영역에서 대표값을 하나씩 골라 테스트하는 **블랙박스 테스트 기법**이다.

예를 들어 시험 점수가 다음 조건이라고 하자.

```text
정상 입력 범위 : 0 ~ 100
```

동등 분할을 하면 다음과 같이 나눌 수 있다.

```text
무효 영역 : 0 미만
유효 영역 : 0 ~ 100
무효 영역 : 100 초과
```

각 영역을 전부 테스트할 필요 없이 대표값을 선택할 수 있다.

```text
-10
50
110
```

### 핵심

```text
입력값을 여러 그룹으로 나눈다.
→ 각 그룹에서 대표값을 선택한다.
```

## 관련 블랙박스 테스트

### 동등 분할

```text
유효값 / 무효값 등의 그룹을 나누어 대표값 검사
```

### 경계값 분석

```text
입력 범위의 시작과 끝 주변을 검사
```

예:

```text
범위 1 ~ 100

0, 1, 2
99, 100, 101
```

### 원인-효과 그래프

입력 조건과 출력 결과 사이의 관계를 그래프로 표현하여 테스트한다.

### 오류 예측

과거 경험이나 테스터의 직관을 이용해 오류가 발생할 만한 부분을 검사한다.

# 2. 디자인 패턴 - Bridge / Observer 🔥🔥

## 문제

다음 설명에 해당하는 디자인 패턴을 작성하시오.

### (1)

구현부에서 추상층을 분리하여 서로 독립적으로 확장할 수 있도록 구성한 패턴이다.

기능과 구현을 두 개의 별도 클래스로 구현하며, 기능 클래스는 구현 클래스를 참조한다.

### (2)

한 객체의 상태가 변하면 그 객체에 의존하는 다른 객체들에게 변경된 상태를 전달하는 패턴이다.

일대다의 의존성을 정의하며 Publish / Subscribe 구조에서 많이 사용된다.

## 정답

```text
(1) Bridge Pattern
(2) Observer Pattern
```

---

## Bridge Pattern

**브리지 패턴**

추상화 부분과 구현 부분을 분리하여 각각 독립적으로 변경할 수 있도록 하는 **구조 패턴**이다.

```text
추상부 ───── 구현부
 기능        실제 구현
```

핵심:

```text
기능과 구현을 분리
→ 서로 독립적으로 확장
```

---

## Observer Pattern

**옵저버 패턴**

한 객체의 상태가 변경되면 이를 관찰하고 있는 다른 객체들에게 자동으로 알리는 **행위 패턴**이다.

```text
Subject
   ↓ 상태 변경
Observer A
Observer B
Observer C
```

키워드:

```text
상태 변화
알림
일대다 관계
Publish / Subscribe
```

---

## GoF 디자인 패턴 분류

### 생성 패턴

```text
Abstract Factory
Builder
Factory Method
Prototype
Singleton
```

### 구조 패턴

```text
Adapter
Bridge
Composite
Decorator
Facade
Flyweight
Proxy
```

### 행위 패턴

```text
Observer
Strategy
Iterator
Command
Visitor
Mediator
Template Method
State
...
```

# 5. ISMS 🔥🔥

## 문제

정보 보호에 대한 다음 설명에 해당하는 용어를 영문 약어로 쓰시오.

> 정보 자산을 안전하게 보호하기 위한 보호 절차와 대책으로, 정보보호 관리 체계라고 한다.
>
> 조직에 맞는 정보보호 정책을 수립하고 위험에 상시 대응하는 여러 보안 대책을 통합 관리한다.
>
> 공공 부문과 민간 기업 부문에서 이를 평가하고 인증하는 사업을 한국인터넷진흥원(KISA)에서 운영 중이다.

## 정답

**ISMS**

```text
Information Security Management System
정보보호 관리체계
```

## 개념

기업이나 기관이 정보 자산을 보호하기 위해 구축한:

```text
보안 정책
보안 절차
위험 관리
보안 대책
```

등이 적절하게 운영되고 있는지를 관리하는 체계이다.

---

## 같이 알아두기

```text
정보보호 관리체계
```

```text
정보보호 및 개인정보보호 관리체계
```

ISMS에 개인정보보호 영역까지 포함한 개념이다.

# 6. HDLC 🔥🔥

## 문제

HDLC의 프레임 종류와 동작 모드에 대한 설명이다.

빈칸에 들어갈 용어를 작성하시오.

제어부의 첫 번째, 두 번째 비트를 이용하여 프레임을 구분한다.

```text
(1) 프레임
(2) 프레임
(3) 프레임
```

(1)은 사용자 데이터를 전달하거나 Piggybacking을 통한 확인 응답에 사용한다.

(2)는 오류 제어와 흐름 제어에 사용한다.

(3)는 링크 설정 및 관리에 사용한다.

(3) 프레임에서 설정할 수 있는 동작 모드는

```text
NRM
(4)
(5)
```

이다.

## 정답

```text
(1) 정보 프레임(I-Frame)
(2) 감독 프레임(S-Frame)
(3) 비번호 프레임(U-Frame)
(4) 비동기 균형 모드(ABM)
(5) 비동기 응답 모드(ARM)
```

---

## HDLC

```text
High-level Data Link Control
```

OSI **데이터링크 계층**에서 사용되는 비트 중심 프로토콜이다.

---

## 프레임 종류

### I-Frame

```text
Information Frame
정보 프레임
```

사용자의 실제 데이터를 전달한다.

Piggybacking을 통한 ACK 전송에도 사용된다.

---

### S-Frame

```text
Supervisory Frame
감독 프레임
```

주로:

```text
오류 제어
흐름 제어
확인 응답
```

등에 사용한다.

---

### U-Frame

```text
Unnumbered Frame
비번호 프레임
```

링크의:

```text
설정
관리
해제
```

등에 사용한다.

---

## HDLC 전송 모드

### NRM

```text
Normal Response Mode
정규 응답 모드
```

보조국은 주국의 허가가 있어야 데이터를 전송할 수 있다.

---

### ARM

```text
Asynchronous Response Mode
비동기 응답 모드
```

보조국이 주국의 허가 없이 데이터를 전송할 수 있다.

단, 링크 관리 권한은 주국에 있다.

---

### ABM

```text
Asynchronous Balanced Mode
비동기 균형 모드
```

가장 널리 사용되는 방식이다.

두 장치가 대등한 관계에서 서로 명령과 응답을 주고받는다.

# 7. Java - 오버라이딩과 오버로딩 🔥🔥

## 문제

다음 Java 프로그램의 실행 결과를 쓰시오.

```java
class A {

    String f(Object x) {
        return "1";
    }

    String g() {
        return f("a");
    }
}

class B extends A {

    String f(Object x) {
        return "2";
    }

    String f(String x) {
        return "3";
    }
}

public class Test {

    public static void main(String[] args) {

        A a = new B();

        System.out.println(a.g());
    }
}
```

## 정답

```text
2
```

---

## 가장 중요한 부분

```java
A a = new B();
```

참조 변수 타입:

```text
A
```

실제 객체:

```text
B
```

---

## `a.g()`

B는 `g()`를 오버라이딩하지 않았다.

따라서 A의:

```java
String g() {
    return f("a");
}
```

가 실행된다.

여기서 중요한 점은 **오버로딩 선택은 컴파일 시점**에 이루어진다는 것이다.

A 클래스에서 존재하는 `f()`는:

```java
f(Object x)
```

뿐이다.

따라서 `f(Object)`가 선택된다.

---

## 그런데 실제 객체는 B

B는 다음 메서드를 오버라이딩했다.

```java
String f(Object x) {
    return "2";
}
```

오버라이딩된 메서드는 실행 시 실제 객체를 기준으로 선택한다.

```text
실제 객체 = B
```

따라서:

```java
B.f(Object)
```

가 실행된다.

결과:

```text
2
```

---

## 핵심

```text
오버로딩
→ 컴파일 시점
→ 참조 타입 중심

오버라이딩
→ 실행 시점
→ 실제 객체 중심
```

# 8. C언어 - 함수 포인터 🔥🔥

## 문제

다음 C 프로그램의 실행 결과를 쓰시오.

```c
#include <stdio.h>

struct week {
    int *(*fn)(int *);
};

int *dum(int *d) {
    return d + 1;
}

int main() {

    int n[] = {16, 32};

    struct week mine;

    mine.fn = dum;

    printf("%x", *mine.fn(n));

    return 0;
}
```

## 정답

```text
20
```

주의:

```text
20은 10진수 20이 아니라
16진수 출력 결과 20
```

이다.

실제 값은 10진수:

```text
32
```

---

## 함수 포인터 해석

```c
int *(*fn)(int *);
```

바깥쪽부터 보면:

```text
fn
→ 함수 포인터

(int *)
→ int*를 매개변수로 받음

int *
→ int*를 반환
```

즉:

```text
int*를 받아서 int*를 반환하는 함수의 주소
```

를 저장한다.

---

## 배열

```c
int n[] = {16, 32};
```

메모리 개념:

```text
n
↓
+------+------+
|  16  |  32  |
+------+------+
  n     n+1
```

---

## `mine.fn = dum`

`fn`에 `dum()` 함수의 주소를 저장한다.

따라서:

```c
mine.fn(n)
```

은 사실상:

```c
dum(n)
```

과 같다.

---

## dum 함수

```c
int *dum(int *d) {
    return d + 1;
}
```

`d`는 `n[0]`의 주소.

```text
d
→ n[0]

d + 1
→ n[1]
```

따라서 반환 주소는 `n[1]`.

```text
*n[1] 주소
→ 32
```

정확히는:

```c
*mine.fn(n)
```

결과:

```text
32
```

---

## `%x`

```c
printf("%x", 32);
```

`%x`는 정수를 **16진수**로 출력한다.

```text
32(10진수)
=
```

>
> 이후 감염된 PC를 기반으로 조직의 중요 시스템에 접근하거나 봇넷으로 만드는 등의 영향력을 행사하는 웹 기반 공격이다.

```text
감염
```


### Drive-by Download

```text
감염된 웹 사이트 접속
→ 사용자 동의 없이 악성 코드 다운로드/실행
```

# 19. 심볼릭 링크(Symbolic Link) 🔥

## 문제

다음 설명에 해당하는 용어를 쓰시오.

> 다른 파일이나 디렉터리의 실제 위치를 나타내는 경로명을 저장하여 해당 대상 파일을 간접적으로 참조하는 기능이다.
>
> 데이터 내용을 가지지 않고 원본 파일의 경로 정보를 기반으로 접근한다.
>
> 파일 시스템에서 사용되는 특수한 파일로 실제 데이터를 저장하지 않고 다른 파일이나 디렉터리의 경로명을 저장하여 해당 대상을 간접적으로 참조한다.
>
> 원본 파일이 삭제되거나 이동될 경우 더 이상 유효한 경로를 참조할 수 없어 접근이 불가능할 수 있다.

## 정답

**심볼릭 링크(Symbolic Link)**

또는:

```text
Symbolic Link
Soft Link
```

---

## 개념

심볼릭 링크는 원본 파일 자체를 가리키는 것이 아니라 **원본 파일의 경로를 저장**한다.

예:

```text
link.txt
    ↓
/home/user/original.txt
```

---

## Linux 생성 명령

```bash
ln -s original.txt link.txt
```

여기서:

```text
-s
→ symbolic link
```

---

## 심볼릭 링크와 하드 링크

### 심볼릭 링크

```text
원본 파일의 경로를 저장

원본 삭제
→ 링크 깨질 수 있음

다른 파일 시스템 가능

디렉터리 링크 가능
```

### 하드 링크

```text
원본과 같은 inode를 가리킴

원본 파일 이름을 삭제해도
다른 하드 링크가 있으면 데이터 유지

일반적으로 다른 파일 시스템을 넘을 수 없음

디렉터리 하드 링크는 일반 사용자에게 제한
```

---

## Linux `ls -l`에서

심볼릭 링크의 파일 종류 표시는:

```text
l
```

예:

```text
lrwxrwxrwx
```

첫 번째:

```text
l
```

이 심볼릭 링크를 의미한다.

# 20. 응집도(Cohesion) 🔥🔥

## 문제

모듈에 대한 다음 설명에서 각 지문 ①~③에 해당하는 응집도를 보기에서 찾아 쓰시오.

### ①

내부의 요소들이 기능적으로 연관성은 없으나, **순차적으로 실행될 때**의 응집도

### ②

서로 다른 기능을 수행하지만 **동일한 입력과 출력을 사용할 때**의 응집도

### ③

하나의 기능에 밀접하게 관련되어 있거나 연관이 있을 때의 응집도

### 보기

```text
기능적 응집도
순차적 응집도
교환적 응집도
절차적 응집도
시간적 응집도
논리적 응집도
우연적 응집도
```

## 정답

```text
① 절차적 응집도
② 교환적 응집도(통신적 응집도)
③ 기능적 응집도
```

---

## ① 절차적 응집도

모듈 내부 기능들이 기능적으로 강하게 관련된 것은 아니지만 **정해진 순서대로 수행**되어야 하는 경우이다.

키워드:

```text
순서대로 실행
```

주의:

**순차적 응집도와 다르다.**

---

## 절차적 vs 순차적 🔥🔥

### 절차적 응집도

단순히:

```text
A 실행
↓
B 실행
↓
C 실행
```

처럼 수행 순서가 관계의 핵심이다.

### 순차적 응집도

앞 기능의 **출력 결과가 다음 기능의 입력으로 사용**된다.

```text
A 출력
   ↓
B 입력

B 출력
   ↓
C 입력
```

따라서:

```text
순서만 관련
→ 절차적

출력 → 다음 입력
→ 순차적
```

---

## ② 교환적 응집도

**통신적 응집도(Communicational Cohesion)**라고도 한다.

서로 다른 기능들이:

```text
동일한 입력 데이터
또는
동일한 출력 데이터
```

를 사용할 때이다.

키워드:

```text
같은 데이터
같은 입출력
```

---

## ③ 기능적 응집도

모듈 내부의 모든 요소가 **하나의 목적을 수행하기 위해 서로 밀접하게 관련**되어 있는 경우이다.

가장 좋은 응집도이다.

---

## 응집도 약한 순 → 강한 순 🔥🔥

```text
우연적
↓
논리적
↓
시간적
↓
절차적
↓
교환적(통신적)
↓
순차적
↓
기능적
```

암기:

```text
우논시절교순기
```

### 우연적 응집도

관련 없는 기능들이 우연히 하나의 모듈에 모여 있음.

### 논리적 응집도

비슷한 성격의 기능들을 하나의 모듈에 모음.

### 시간적 응집도

같은 시간에 수행되는 기능들을 모음.

예:

```text
프로그램 초기화
프로그램 종료 처리
```

### 절차적 응집도

정해진 순서에 따라 실행.

### 교환적 응집도

동일한 데이터를 사용.

### 순차적 응집도

앞 기능의 출력이 다음 기능의 입력.

### 기능적 응집도

하나의 기능만을 위해 모든 요소가 수행.

---

## 결합도와 응집도 관계

좋은 모듈 설계는:

```text
결합도는 낮게
응집도는 높게
```

만드는 것이다.

```text
결합도
→ 모듈과 모듈 사이의 의존 정도

응집도
→ 하나의 모듈 내부 요소들이 얼마나 관련되어 있는지
```

결합도 강 → 약:

```text
내용
공통
외부
제어
스탬프
자료
```

암기:

```text
내공외제스자
```

응집도 약 → 강:

```text
우연
논리
시간
절차
교환
순차
기능
```

암기:

```text
우논시절교순기
```
