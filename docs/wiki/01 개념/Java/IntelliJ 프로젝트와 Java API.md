# IntelliJ 프로젝트와 Java API

## 2026-08-23 자바 실행 구조와 기초 문법

### 인텔리J 프로젝트 구조

> 인텔리J의 자바 프로젝트는 SDK, 모듈, 소스 루트, 출력 경로가 모두 연결되어야 소스 인식과 컴파일 결과 생성이 정상적으로 이루어집니다.

인텔리J에서 프로젝트 이름은 작업 단위를 식별하는 최상위 설정입니다. 프로젝트 SDK는 어떤 JDK를 사용하여 컴파일하고 실행할지를 지정하며, Language Level은 사용할 자바 문법 수준을 결정합니다.

모듈은 프로젝트 내부의 실제 컴파일 단위입니다. 프로젝트에 SDK를 지정했더라도 모듈에 SDK와 언어 수준이 연결되지 않으면 라이브러리 인식, 컴파일, 실행 구성이 불완전할 수 있습니다.

- `src` 디렉터리는 소스 루트로 지정하여 자바 소스 파일 위치로 인식해야 합니다.
- `out` 디렉터리는 컴파일된 `.class` 파일이 생성되는 출력 경로로 지정할 수 있습니다.
- 외부 라이브러리 목록에는 연결된 JDK의 표준 모듈과 클래스가 표시됩니다.
- 프로젝트와 모듈의 SDK 설정은 서로 일치하는지 함께 확인해야 합니다.

워크스페이스와 프로젝트 경로는 영문 및 공백 없는 이름을 권장합니다. 경로에 공백이나 비ASCII 문자가 포함되면 명령행 도구, 빌드 도구, 라이브러리 경로 처리 과정에서 예상하지 못한 오류가 발생할 수 있습니다.

인텔리J는 `.idea` 디렉터리와 `.iml` 파일 등에 프로젝트 설정을 XML 형식으로 저장합니다. 이러한 설정 파일에는 모듈 경로, SDK 연결 정보, 출력 디렉터리 등 IDE가 프로젝트를 인식하기 위한 메타데이터가 포함됩니다.

### Java API 문서 탐색

> Java API 문서는 패키지, 클래스, 필드, 생성자, 메소드 및 상속 계층을 확인하는 공식 기술 문서입니다.

Java API는 자바에서 제공하는 표준 클래스와 기능을 확인하는 핵심 자료입니다. 개발자는 모든 기능을 직접 구현하기보다 API에서 필요한 클래스를 찾고, 제공되는 필드와 메소드를 조합하여 프로그램을 구현합니다.

Java 8 API는 모듈 구조가 없으므로 패키지와 클래스의 관계를 처음 익히기에 비교적 단순합니다. Java 9 이상에서는 모듈 아래에 패키지와 클래스가 배치되므로 구조가 한 단계 더 깊어집니다.

- 패키지는 관련 클래스들을 폴더 구조처럼 묶는 논리적 단위입니다.
- 모듈은 관련 패키지들을 다시 묶어 관리하는 상위 단위입니다.
- 클래스 문서의 Summary 영역에서는 필드, 생성자, 메소드 목록을 확인할 수 있습니다.
- 상속 계층에서는 부모 클래스와 자식 클래스의 관계를 확인할 수 있습니다.

`java.lang.System` 클래스는 표준 입출력과 오류 출력에 관련된 멤버를 제공합니다. `System.out`은 표준 출력 스트림을 가리키는 필드이며, 반환되는 `PrintStream` 객체가 `println()`, `print()`, `printf()`, `write()` 등의 출력 메소드를 제공합니다.

| 대상 | 역할 | 대표 사용 예시 |
|---|---|---|
| `System.in` | 표준 입력 장치를 나타냅니다. | 키보드 입력 처리와 연결됩니다. |
| `System.out` | 표준 출력 장치를 나타냅니다. | 콘솔 출력에 사용됩니다. |
| `System.err` | 표준 오류 출력 장치를 나타냅니다. | 오류 메시지 출력에 사용됩니다. |
| `PrintStream` | 출력 관련 메소드를 제공합니다. | `println()`, `print()`, `printf()`를 제공합니다. |

API 문서를 읽을 때는 클래스의 전체 이름, 소속 패키지, 상속 관계, 필드의 타입, 메소드의 반환 타입, `static` 여부를 순서대로 확인하면 구조를 빠르게 파악할 수 있습니다.


## 2026-09-22 Java 컬렉션 다형성 Comparator 정리

### 4. Java 문서 영어 표현

```text
All Known Implementing Classes
→ 이 인터페이스를 구현하는 것으로 알려진 모든 클래스
→ NavigableSet 문서에서 TreeSet 등을 보여준다.

All Implemented Interfaces
→ 이 클래스가 구현한 모든 인터페이스
→ TreeSet 문서에서 NavigableSet, SortedSet, Set 등을 보여준다.

Implementing Classes
→ 구현하는 클래스들

Implemented Interfaces
→ 구현된 인터페이스들
```

- Implemented는 여기서 “구현했다”가 아니라 “구현된”이라는 뜻이다.
- 뒤의 Interfaces를 꾸며준다.
- 직접 구현뿐 아니라 간접적인 구현 관계도 포함된다.
