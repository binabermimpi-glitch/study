# 상속 오버라이딩 다형성

## 2026-09-03 자바 배열과 객체지향 핵심

### 자바 배열과 객체지향 핵심


### 상속과 다형성

> 상속은 공통 기능을 부모 클래스에 정의하고 자식 클래스가 이를 재사용, 확장하는 구조이며, 다형성은 부모 타입 참조로 여러 자식 객체를 다루는 방식입니다.

자바의 모든 클래스는 명시하지 않아도 기본적으로 `Object` 클래스를 상속합니다. 사용자 정의 클래스 역시 `Object`의 자식이며, 필요에 따라 다른 클래스를 상속해 공통 속성과 기능을 재사용할 수 있습니다.

```java
public class Person {
    private String name;
    private int age;
}

public class Student extends Person {
    private String school;
}
```

자식 객체를 생성하면 부모 객체 영역이 먼저 초기화된 뒤 자식 객체 영역이 초기화됩니다. 자식 생성자에서 부모 생성자를 명시하지 않으면 컴파일러는 기본적으로 `super()`를 삽입합니다.

| 키워드 | 의미 | 주요 사용 위치 |
|---|---|---|
| `this` | 현재 객체 자신을 가리킵니다. | 현재 필드 및 생성자 호출에 사용합니다. |
| `super` | 부모 객체 또는 부모 멤버를 가리킵니다. | 부모 메서드와 필드 접근에 사용합니다. |
| `super()` | 부모 생성자를 호출합니다. | 자식 생성자의 첫 실행 문장에 사용합니다. |
| `extends` | 특정 클래스를 상속함을 선언합니다. | 클래스 선언부에 사용합니다. |

부모 클래스의 `private` 필드는 자식 클래스가 직접 접근할 수 없습니다. 이는 캡슐화와 정보 은닉을 위한 제약이며, 자식 클래스는 부모가 제공하는 `public` 또는 `protected` 메서드를 통해 필요한 값에 접근해야 합니다.

메서드 오버라이딩은 부모에게서 상속받은 메서드를 자식 클래스의 목적에 맞게 재정의하는 기능입니다. 메서드 이름과 매개변수 형태는 유지하지만 실행 내용은 자식 클래스에서 변경합니다.

```java
@Override
public String personInfo() {
    return super.personInfo() + "\t학교: " + school;
}
```

부모 타입 변수에는 자식 객체를 대입할 수 있습니다. 이를 업캐스팅이라고 하며, 부모 타입으로 선언된 참조 변수는 부모에 선언된 멤버만 직접 접근할 수 있습니다.

```java
Person person = new Student();
person.personInfo();
```

컴파일 시점에는 변수의 선언 타입을 기준으로 접근 가능 여부를 확인합니다. 반면 오버라이딩된 메서드 호출은 실행 시점의 실제 객체 타입을 기준으로 결정되며, 이를 동적 바인딩이라고 합니다.

형제 관계의 클래스끼리는 직접 형변환할 수 없습니다. 공통 부모를 가졌더라도 실제 객체가 해당 자식 타입이 아니라면 런타임에 `ClassCastException`이 발생합니다.

### 자바 상속과 다형성 핵심 정리


### 2. 상속과 this, super

- `this.field`: 현재 객체의 필드
- `this()`: 같은 클래스의 다른 생성자 호출
- `super.field`: 부모 영역의 필드
- `super()`: 부모 생성자 호출
- `super.method()`: 부모 메서드 호출

자식 객체를 생성할 때 부모 생성자가 먼저 실행된 후 자식 생성자가 실행된다.


### 3. 오버라이딩과 동적 바인딩

```java
class Parent {
    void show() {
        System.out.println("부모");
    }
}

class Child extends Parent {
    @Override
    void show() {
        System.out.println("자식");
    }
}

Parent p = new Child();
p.show();
```

오버라이딩된 메서드는 실제 객체인 Child를 기준으로 실행된다. 이를 동적 바인딩이라고 한다. `@Override`는 올바른 재정의인지 컴파일러가 검사하도록 한다.


### 4. 다형성과 업캐스팅

```java
interface Payment {
    void pay(int amount);
}

class KakaoPay implements Payment {
    @Override
    public void pay(int amount) {
        System.out.println("카카오페이 결제");
    }
}

class NaverPay implements Payment {
    @Override
    public void pay(int amount) {
        System.out.println("네이버페이 결제");
    }
}

Payment[] payments = {
    new KakaoPay(),
    new NaverPay()
};

for (Payment payment : payments) {
    payment.pay(10000);
}
```

하나의 상위 타입으로 여러 하위 객체를 관리하고 같은 메서드 호출로 객체마다 다른 동작을 실행할 수 있다.


## 2026-08-31 Java 배열 반복문 패턴 매칭 복습

### 11. 중요한 점: 변수 타입과 실제 객체 타입은 다를 수 있다

```java
Object obj = "monkey";
```

여기서:

```text
변수의 타입 → Object
실제 객체   → String
```

이다.

따라서:

```java
obj instanceof String
```

→ `true`

`instanceof`는 **변수 선언 타입만 보는 것이 아니라 실제로 가리키는 객체의 타입을 확인한다.**
