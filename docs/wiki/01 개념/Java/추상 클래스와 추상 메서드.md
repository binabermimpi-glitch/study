# 추상 클래스와 추상 메서드

## 자바 배열과 객체지향 핵심

### 추상화와 캡슐화

> 추상 클래스는 공통 구조와 기본 기능을 제공하며, 추상 메서드는 자식 클래스가 구체적인 동작을 구현하도록 강제합니다.

추상화는 여러 객체에 공통으로 존재하는 특성을 상위 개념으로 묶는 과정입니다. 예를 들어 자동차의 공통 기능을 `Car`에 정의하고, SUV, 트럭, 버스 같은 구체 클래스가 이를 상속받아 확장할 수 있습니다.

`abstract` 클래스를 사용하면 객체를 직접 생성할 수 없으며, 공통 기능을 제공하는 상위 설계 역할을 수행합니다. 추상 클래스는 일반 메서드와 추상 메서드를 함께 가질 수 있습니다.

```java
public abstract class Animal {
    public abstract void bark();

    public void eat(String feed) {
        System.out.println(feed + "을 먹습니다.");
    }
}
```

추상 메서드는 메서드 본문이 없는 선언이며, 이를 상속받는 구체 클래스는 반드시 메서드를 오버라이딩해야 합니다. 구현하지 않으려면 자식 클래스도 다시 추상 클래스로 선언해야 합니다.

```java
public class Cat extends Animal {
    @Override
    public void bark() {
        System.out.println("야옹");
    }
}
```

캡슐화는 객체의 내부 상태를 직접 노출하지 않고, 제한된 메서드를 통해 접근하도록 설계하는 방식입니다. 일반적으로 필드는 `private`으로 선언하고, 필요한 경우 게터와 세터를 제공합니다.

```java
private int age;

public void setAge(int age) {
    this.age = age >= 0 ? age : 0;
}
```

세터 메서드는 외부에서 전달된 값을 검증하고 필터링할 수 있습니다. 따라서 잘못된 값이 객체 내부 상태에 저장되는 것을 방지하며, 데이터 무결성과 일관성을 유지하는 데 도움이 됩니다.

객체지향 프로그래밍의 주요 특징은 추상화, 상속, 다형성, 캡슐화로 정리할 수 있습니다. 이 특징들은 공통 구조의 재사용, 기능 확장, 유연한 객체 처리, 안전한 상태 관리를 지원합니다.


## 자바 상속과 객체 설계

### 인터페이스와 추상 클래스

> 인터페이스는 구현해야 할 공통 규약을 정의하는 데 적합하고, 추상 클래스는 공통 상태와 구현을 제공하면서 일부 기능을 하위 클래스에 구현하도록 강제할 수 있습니다.

자바 클래스는 하나의 클래스만 직접 상속할 수 있습니다.

```java
class Child extends Parent {
}
```

반면 하나의 클래스는 여러 인터페이스를 구현할 수 있습니다.

```java
class Griffin extends Lion implements Eagle, Fantasy {
}
```

예를 들어:

```java
interface Eagle {
    void fly();
}

interface Fantasy {
    void born();
}

class Griffin extends Lion implements Eagle, Fantasy {

    @Override
    public void fly() {
        System.out.println("그리핀이 날아갑니다.");
    }

    @Override
    public void born() {
        System.out.println("그리핀이 태어났습니다.");
    }
}
```

인터페이스의 필드는 기본적으로 `public static final`입니다.

```java
interface Animal {
    String COUNTRY = "주토피아";
}
```

이는 다음과 같은 의미입니다.

```java
public static final String COUNTRY = "주토피아";
```

본문 없이 선언한 인터페이스 메서드는 기본적으로 `public abstract`입니다.

```java
interface Animal {
    void bark();
}
```

다음과 같은 의미로 볼 수 있습니다.

```java
public abstract void bark();
```

또한 인터페이스에는 `default`, `static`, `private` 메서드도 선언할 수 있습니다.

```java
interface Animal {

    void bark();

    default void sleep() {
        System.out.println("자고 있습니다.");
    }

    static void eat() {
        System.out.println("냠냠");
    }
}
```

추상 클래스는 일반 클래스와 마찬가지로 생성자, 인스턴스 필드, 일반 메서드, 정적 메서드를 가질 수 있고 추가로 추상 메서드도 선언할 수 있습니다.

```java
abstract class Score {

    public abstract int getTotal();

    public void printInfo() {
        System.out.println("점수 정보");
    }
}
```

추상 클래스 자체는 직접 객체를 생성할 수 없습니다.

```java
// Score score = new Score(); // 오류
```

추상 메서드를 포함한 클래스를 상속받은 하위 클래스는 해당 메서드를 구현해야 합니다.

```java
class MidtermScore extends Score {

    @Override
    public int getTotal() {
        return 300;
    }
}
```

하위 클래스가 추상 메서드를 구현하지 않는다면 해당 클래스 역시 `abstract`로 선언해야 합니다.

| 구분       | 인터페이스                             | 추상 클래스           |
| -------- | --------------------------------- | ---------------- |
| 선언       | `interface`                       | `abstract class` |
| 직접 객체 생성 | 불가능                               | 불가능              |
| 관계       | `implements`                      | `extends`        |
| 다중 관계    | 여러 인터페이스 구현 가능                    | 클래스 상속은 하나만 가능   |
| 상태       | 주로 상수                             | 인스턴스 필드 보유 가능    |
| 생성자      | 없음                                | 있음               |
| 일반 메서드   | `default`, `static`, `private` 가능 | 자유롭게 선언 가능       |
| 추상 메서드   | 선언 가능                             | 선언 가능            |

추상 메서드를 공통 규약으로 만들면 서로 다른 하위 클래스라도 동일한 방식으로 호출할 수 있습니다.

```java
abstract class Score {
    public abstract int getTotal();
}
```

```java
class MidtermScore extends Score {
    @Override
    public int getTotal() {
        return 300;
    }
}
```

```java
class FinalScore extends Score {
    @Override
    public int getTotal() {
        return 400;
    }
}
```

이렇게 하면 `Score` 타입을 기준으로 서로 다른 객체를 동일한 방식으로 다룰 수 있으며, 이것이 다형성과 연결됩니다.
