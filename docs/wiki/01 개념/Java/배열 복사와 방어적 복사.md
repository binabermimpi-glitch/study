# 배열 복사와 방어적 복사

## 한 문장 설명

배열 복사는 새 배열 컨테이너를 만들 수 있지만, 객체 배열의 요소가 가리키는 객체까지 자동으로 복제하지는 않는다.

## 기본형 배열 복사

```java
int[] source = {1, 2, 3};
int[] target = new int[source.length];

System.arraycopy(source, 0, target, 0, source.length);
```

`System.arraycopy(원본, 원본 시작, 대상, 대상 시작, 길이)` 순서다. 시작 위치와 복사 길이가 배열 범위를 벗어나면 예외가 발생한다. `Arrays.copyOf()`도 새 배열을 만드는 간단한 방법이다.

## 객체 배열의 얕은 복사

```java
Person[] original = {new Person("홍길동", 20)};
Person[] copy = original.clone();

System.out.println(original == copy);       // false
System.out.println(original[0] == copy[0]); // true
```

배열 객체는 새로 만들어지지만, 요소의 참조값이 복사되어 내부 `Person` 객체는 공유된다. 이것이 얕은 복사다.

## 깊은 복사

```java
Person[] copy = new Person[original.length];

for (int i = 0; i < original.length; i++) {
    Person person = original[i];
    copy[i] = new Person(person.getName(), person.getAge());
}
```

깊은 복사는 각 요소 객체도 새로 만든다. 객체가 내부에 또 다른 가변 객체를 갖는다면 그 구조까지 어디까지 복제할지 명확히 정해야 한다.

## 방어적 복사

방어적 복사는 복사의 깊이를 나타내는 말이 아니라 외부 코드가 내부 상태를 직접 바꾸지 못하게 복사본을 저장하거나 반환하는 설계 전략이다.

```java
class Scores {
    private final int[] values;

    Scores(int[] values) {
        this.values = values.clone();
    }

    int[] getValues() {
        return values.clone();
    }
}
```

## 흔한 실수

- `clone()`이 객체 요소까지 깊게 복사한다고 생각한다.
- 방어적 복사를 했지만 내부 요소가 가변 객체라서 상태가 계속 공유된다.
- 복사 범위와 `null`을 확인하지 않고 `System.arraycopy()`를 호출한다.

## 실무에서는 어떻게 쓰이나

DTO나 도메인 객체가 배열·가변 컬렉션을 보유할 때 외부 변경을 차단하는 데 사용한다. 가능하면 불변 객체와 수정 불가능한 뷰 등도 함께 고려한다.
