# JVM 메모리와 가비지 컬렉션

## 한 문장 설명

JVM은 실행 중 필요한 메모리 영역을 관리하고, 가비지 컬렉터는 더 이상 도달할 수 없는 객체의 메모리를 자동으로 회수한다.

## 입문용 그림

| 영역 | 주로 이해할 대상 |
|---|---|
| 스택 | 메소드 호출 프레임과 지역 변수의 실행 범위 |
| 힙 | 생성된 객체와 배열 |
| 메소드 영역에 대응하는 영역 | 클래스 메타데이터와 클래스 수준 정보 |

이 표는 학습을 위한 단순화다. JVM 명세의 런타임 데이터 영역, 실제 JVM 구현과 최적화 결과가 항상 이 그림과 정확히 일치한다고 가정하면 안 된다.

JVM도 운영체제의 프로세스로 실행되며 운영체제가 제공하는 가상 주소 공간 위에서 메모리를 사용한다. 따라서 시스템의 RAM, 가상 메모리와 프로세스 제한은 JVM 실행 환경과 연결된다.

일반적인 `java MainClass` 실행은 새 JVM 프로세스를 시작하지만, 한 JVM은 많은 클래스를 로딩하고 여러 스레드와 작업을 실행할 수 있다. `클래스 하나당 JVM 하나`로 대응시키지 않는다.

## 가비지 컬렉션

```java
Object value = new Object();
value = null; // 기존 객체에 도달할 경로가 없다면 GC 회수 후보가 될 수 있다.
```

- 참조가 없어진 객체는 즉시 삭제되는 것이 아니라 회수 후보가 된다.
- GC 실행 시점은 JVM이 결정하며 코드가 일반적으로 직접 정하지 않는다.
- 세대별 GC에서는 새 객체와 오래 살아남은 객체를 구분해 관리할 수 있다.
- Eden, Old 같은 구체적인 구획은 GC 구현과 설정에 따라 다르게 이해해야 한다.

## 실무에서는 어떻게 쓰이나

장시간 실행되는 서버에서 메모리 누수, 과도한 객체 생성, 긴 GC 정지 시간을 진단할 때 중요하다. 입문 단계에서는 먼저 객체가 언제 참조 가능하고 언제 범위를 벗어나는지 이해한다.

## 흔한 실수

- `null`을 대입하면 그 자리에서 객체가 삭제된다고 생각한다.
- Java에는 자동 GC가 있으므로 메모리 누수가 없다고 생각한다.
- JVM 구현에 따라 달라지는 세부 구조를 Java 언어의 절대 규칙으로 외운다.
