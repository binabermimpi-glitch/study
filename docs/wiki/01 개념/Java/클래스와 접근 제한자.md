# 클래스와 접근 제한자

## 자바 참조와 자료형 기초

### 클래스와 접근 제한자

> 클래스는 사용자 정의 자료형을 만드는 키워드이며, 필드와 메소드로 속성과 기능을 표현하고 접근 제한자로 공개 범위를 제어합니다.

자바의 클래스는 개발자가 새로운 자료형을 정의할 수 있게 하는 사용자 정의 자료형입니다. 클래스 블록 내부에는 값과 상태를 나타내는 필드, 동작을 나타내는 메소드, 객체 생성을 담당하는 생성자 등이 멤버로 포함됩니다.

```java
public class Test {
    public static final double PI = 3.141592;

    public void printValue() {
        System.out.println(PI);
    }
}
```

클래스는 일반적으로 속성과 기능의 집합으로 설명됩니다. 속성은 필드로 표현되며, 기능은 메소드로 표현됩니다. 생성자는 객체가 만들어질 때 초기 상태를 설정하는 특별한 멤버입니다.

| 접근 제한자 | 접근 범위 | 특징 |
|---|---|---|
| `public` | 모든 위치에서 접근할 수 있습니다. | 가장 넓은 공개 범위를 가집니다. |
| `protected` | 같은 패키지와 상속 관계에서 접근할 수 있습니다. | 상속 구조에서 주로 활용됩니다. |
| 기본 접근 수준 | 같은 패키지에서 접근할 수 있습니다. | 별도 키워드를 작성하지 않습니다. |
| `private` | 선언된 클래스 내부에서만 접근할 수 있습니다. | 내부 구현을 은닉하는 데 사용됩니다. |

기본 접근 수준은 `default`라는 키워드를 작성하는 방식이 아닙니다. 접근 제한자를 생략했을 때 같은 패키지에 공개되는 상태를 기본 접근 수준이라고 부릅니다.

`final`은 확장을 제한하거나 변경을 막는 성질과 연결됩니다. 클래스에 적용하면 상속을 제한하고, 필드에 적용하면 값을 변경할 수 없는 상수로 만들 수 있습니다. 반대로 `abstract`는 하위 클래스에서 구현을 확장하는 추상화 구조와 관련됩니다.


## 자바 메서드와 연산자 기초

### 접근 제어와 클래스 다이어그램
접근 제어자는 클래스와 멤버의 사용 범위를 제한하며, 클래스 다이어그램은 필드·생성자·메서드의 구조와 정적 여부를 시각적으로 표현합니다.

접근 제어자는 클래스, 필드, 메서드의 접근 가능 범위를 지정합니다. 외부에 공개할 기능과 내부 구현으로 감출 기능을 분리하면 캡슐화를 강화하고 코드의 변경 영향을 줄일 수 있습니다.

접근 제어자	같은 클래스	같은 패키지	상속 관계	다른 패키지
public	가능합니다.	가능합니다.	가능합니다.	가능합니다.
protected	가능합니다.	가능합니다.	가능합니다.	제한적으로 가능합니다.
기본 접근 제어	가능합니다.	가능합니다.	제한됩니다.	불가능합니다.
private	가능합니다.	불가능합니다.	불가능합니다.	불가능합니다.
정적 메서드는 클래스에 소속되므로 클래스명.메서드명()으로 호출할 수 있습니다. 반면 정적 키워드가 없는 메서드는 인스턴스 메서드이므로 객체 생성 후 참조변수.메서드명() 방식으로 호출해야 합니다.

public class Calculator {
    public void multiply(double x, double y) {
        System.out.println(x * y);
    }
}

Calculator calculator = new Calculator();
calculator.multiply(3.2, 4.5);
클래스 다이어그램은 클래스 구조를 상자 형태로 표현합니다. 일반적으로 클래스명, 필드, 생성자, 메서드를 구분해 표시하며, 정적 멤버 여부와 접근 수준도 함께 확인할 수 있습니다.

클래스 다이어그램을 먼저 보고 메서드의 이름, 반환형, 매개변수 구조를 파악한 뒤 코드를 작성하면 객체지향 구조를 더 명확하게 설계할 수 있습니다. 코드만 순서대로 읽기보다 결과와 구조를 먼저 설계하는 방식이 유지보수에 유리합니다.

클래스 다이어그램은 여러 클래스 간의 관계와 역할을 빠르게 확인하는 데 활용됩니다.
메서드 목록은 클래스가 제공하는 기능의 인터페이스 역할을 합니다.
정적 메서드는 다이어그램에서 별도 기호 또는 밑줄 등의 규칙으로 표현될 수 있습니다.
API 문서와 클래스 다이어그램을 함께 보면 호출 가능한 메서드를 더 빠르게 찾을 수 있습니다.
