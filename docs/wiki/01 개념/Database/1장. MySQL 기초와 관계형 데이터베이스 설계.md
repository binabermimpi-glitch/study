# 1장. MySQL 기초와 관계형 데이터베이스 설계

## 1. 데이터의 종류와 구조

데이터는 구조의 고정 여부에 따라 정형 데이터, 반정형 데이터, 비정형 데이터로 구분한다.

### 1-1. 정형 데이터

정형 데이터는 미리 정의된 구조에 맞춰 저장하는 데이터다.

대표적으로 행(Row)과 열(Column)로 구성된 관계형 데이터베이스 테이블이 있다.

예시:

| id | name | age |
|---|---|---|
| 1 | 홍길동 | 25 |
| 2 | 김개발 | 30 |

특징:
- 데이터의 구조가 명확하다.
- 각 열에 데이터 타입을 지정할 수 있다.
- SQL을 사용해 데이터를 조회하고 관리한다.
- 회원, 주문, 결제, 재고 등의 관리에 적합하다.

CSV와 TSV도 일정한 열 구조를 갖는 정형 데이터의 대표적인 파일 형식이다.

### 1-2. 반정형 데이터

반정형 데이터는 고정된 테이블 형태는 아니지만 데이터 내부에 구조를 표현하는 정보가 존재한다.

대표적인 형식:
- JSON
- XML
- YAML
- JSONL

JSON 예시:

```json
{
    "id": 1,
    "name": "홍길동",
    "skills": ["Java", "MySQL"]
}
```

JSON은 키(Key)와 값(Value)을 이용하여 데이터를 표현한다.

JSONL은 한 줄에 하나의 JSON 값을 기록하는 형식으로, 여러 데이터를 줄 단위로 처리하는 데 사용한다.

반정형 데이터는 데이터마다 속성이 달라질 수 있다는 특징이 있다.

### 1-3. 비정형 데이터

비정형 데이터는 미리 정해진 테이블 구조로 표현하기 어려운 데이터다.

예시:
- 이미지
- 동영상
- 음성
- 일반 텍스트

이미지나 동영상은 파일 저장소에 저장하고, MySQL에는 파일의 위치와 관련 정보를 저장하는 방법을 사용할 수 있다.

예시:

| file_id | file_name | file_url |
|---|---|---|
| 1 | profile.jpg | /images/profile.jpg |
| 2 | video.mp4 | /videos/video.mp4 |

이 경우 MySQL에는 실제 이미지나 영상이 아닌 파일을 식별하고 접근하기 위한 정보가 저장된다.

물론 MySQL의 BLOB 타입을 이용하여 바이너리 데이터를 직접 저장할 수도 있다.

## 2. 데이터베이스와 DBMS

### 2-1. 데이터베이스란?

데이터베이스(Database)는 여러 데이터를 체계적으로 저장하고 관리하기 위한 데이터의 집합이다.

예를 들어 쇼핑몰을 개발한다면 다음 정보들이 필요하다.

- 회원 정보
- 상품 정보
- 주문 정보
- 결제 정보
- 배송 정보

이러한 데이터들을 데이터베이스에 저장하고 서로 연결하여 관리할 수 있다.

### 2-2. DBMS란?

DBMS(Database Management System)는 데이터베이스를 생성하고 관리하는 소프트웨어다.

DBMS의 주요 기능:
1. 데이터 저장
2. 데이터 조회
3. 데이터 수정 및 삭제
4. 접근 권한 관리
5. 동시성 제어
6. 트랜잭션 처리
7. 백업 및 복구

파일 시스템만으로 데이터를 관리하면 동일한 정보가 여러 파일에 중복 저장될 수 있다.

또한 여러 사용자가 동시에 데이터를 수정할 때 충돌이 발생할 수 있다.

DBMS는 이러한 데이터를 통합적으로 관리하고 데이터의 일관성을 유지할 수 있도록 지원한다.

### 2-3. 데이터베이스의 유형

| 종류 | 대표 제품 | 특징 |
|---|---|---|
| 관계형 DB | MySQL, PostgreSQL, Oracle | 테이블과 SQL을 사용 |
| 키-값 DB | Redis | 키를 이용하여 값에 접근 |
| 문서형 DB | MongoDB | JSON과 유사한 문서 구조 사용 |
| 와이드 컬럼 DB | Cassandra, HBase | 대규모 분산 데이터 처리 |
| 그래프 DB | Neo4j | 노드와 관계 중심의 데이터 처리 |
| 벡터 DB | Milvus, Pinecone | 벡터 유사도 검색 |

Redis는 캐시, 세션, 카운터 등에 사용된다.

MongoDB는 문서형 데이터베이스로, 유연한 문서 구조를 저장할 수 있다.

그래프 DB는 사람 사이의 연결이나 추천 관계처럼 관계 자체가 중요한 데이터를 처리하는 데 사용된다.

벡터 DB는 임베딩 벡터를 이용하여 의미가 유사한 데이터를 검색하는 데 사용된다.

## 3. RDBMS와 관계형 데이터베이스

### 3-1. RDBMS란?

RDBMS는 Relational Database Management System의 약자다.

데이터를 행과 열로 구성된 테이블에 저장하고, 테이블 사이의 관계를 이용하여 데이터를 관리하는 시스템이다.

대표적인 RDBMS:
- MySQL
- PostgreSQL
- Oracle Database
- Microsoft SQL Server

이러한 제품들은 SQL을 사용하지만, 함수와 데이터 타입 및 일부 문법은 서로 다를 수 있다.

공통적인 SQL 표준 문법을 ANSI SQL이라고 부른다.

### 3-2. 관계형 데이터베이스의 구성

MySQL의 논리적인 구조는 다음과 같다.

```text
MySQL Server
    └── Database(Schema)
            ├── Table
            │     ├── Column
            │     └── Row
            ├── View
            ├── Index
            └── Stored Program
```

MySQL에서 DATABASE와 SCHEMA는 일반적으로 같은 의미로 사용된다.

테이블은 실제 데이터를 행과 열 형태로 저장한다.

### 3-3. 관계형 모델의 용어

| 용어 | 의미 |
|---|---|
| 엔터티(Entity) | 관리 대상이 되는 개념적 객체 |
| 테이블(Table) | 데이터를 행과 열로 저장하는 구조 |
| 튜플(Tuple) | 테이블의 하나의 행 |
| 속성(Attribute) | 테이블의 열 |
| 도메인(Domain) | 속성에 허용되는 값의 집합 |
| 차수(Degree) | 테이블의 속성 개수 |
| 카디널리티(Cardinality) | 관계에 포함된 튜플의 개수 |

예시:

| student_id | name | age |
|---|---|---|
| 1 | 홍길동 | 25 |
| 2 | 김개발 | 30 |

위 테이블의 차수는 3이다.

튜플이 2개이므로 카디널리티는 2이다.

단, SQL 테이블은 중복 행과 NULL을 허용할 수 있으므로 순수한 관계형 이론의 릴레이션과 완전히 동일하지는 않다.

## 4. MySQL 제품과 저장 구조

### 4-1. MySQL 제품

MySQL은 데이터베이스 서버뿐 아니라 다양한 관리 도구를 제공한다.

- MySQL Community Server
- MySQL Enterprise Edition
- MySQL Workbench
- MySQL Shell
- MySQL Router
- MySQL Cluster
- MySQL HeatWave

MySQL Community Server는 일반적인 학습과 개발에서 사용할 수 있는 서버 제품이다.

MySQL Workbench는 데이터베이스를 시각적으로 관리하는 도구다.

MySQL Shell은 MySQL 서버에 접속하여 관리 작업과 스크립트를 실행하는 도구다.

MySQL Router는 MySQL 서버 구성에서 클라이언트 연결을 적절한 서버로 전달하는 역할을 한다.

### 4-2. MySQL 버전

MySQL 릴리스는 크게 다음과 같이 구분된다.

LTS:
- Long-Term Support
- 장기간 유지보수와 안정성을 중시하는 릴리스

Innovation:
- 새로운 기능과 변경사항을 빠르게 제공하는 릴리스

MySQL의 기능은 버전에 따라 달라질 수 있으므로, 사용하는 서버 버전을 확인해야 한다.

```sql
SELECT VERSION();
```

MySQL 공식 문서:
https://dev.mysql.com/doc/

### 4-3. 스토리지 엔진

스토리지 엔진은 데이터가 실제로 저장되고 관리되는 방식을 담당한다.

| 엔진 | 특징 |
|---|---|
| InnoDB | 트랜잭션, 외래키, 행 잠금 지원 |
| MyISAM | 트랜잭션 및 외래키 미지원 |
| MEMORY | 주로 메모리에 데이터 저장 |
| CSV | CSV 형식으로 테이블 데이터 저장 |

MySQL에서 일반적으로 사용하는 스토리지 엔진은 InnoDB이다.

InnoDB는 기본키를 중심으로 데이터를 저장하고 인덱스, 잠금, 트랜잭션, 복구 기능을 지원한다.

### 4-4. MySQL의 저장 경로

MySQL에서 데이터가 저장되는 디렉터리를 확인할 수 있다.

```sql
SHOW VARIABLES LIKE 'datadir';
```

MySQL 프로그램의 기본 설치 디렉터리 관련 설정은 다음과 같이 확인한다.

```sql
SHOW VARIABLES LIKE 'basedir';
```

InnoDB는 데이터와 인덱스를 테이블스페이스에 저장한다.

설정에 따라 테이블별 `.ibd` 파일을 사용할 수 있지만, 모든 데이터가 반드시 각각의 `.ibd` 파일로만 저장되는 것은 아니다.

## 5. MySQL 서버 접속

MySQL 서버는 다양한 클라이언트 도구로 접속할 수 있다.

대표적인 도구:
- MySQL Command Line Client
- MySQL Workbench
- IntelliJ IDEA Database 도구

일반적인 접속 정보:

```text
Host: localhost
Port: 3306
User: root
Password: 본인이 설정한 비밀번호
```

localhost는 현재 사용 중인 컴퓨터를 의미한다.

127.0.0.1은 IPv4의 루프백 주소다.

MySQL의 기본 포트는 3306이다.

### 5-1. 명령 프롬프트 접속

```bash
mysql -u root -p
```

명령어 설명:

mysql
→ MySQL 명령행 클라이언트를 실행한다.

-u root
→ root 계정으로 접속한다.

-p
→ 비밀번호를 입력받는다.

접속한 뒤에는 SQL 문을 실행할 수 있다.

### 5-2. 데이터베이스 목록 조회

```sql
SHOW DATABASES;
```

### 5-3. 데이터베이스 선택

```sql
USE mysql;
```

USE 명령어는 현재 작업할 데이터베이스를 선택한다.

### 5-4. 테이블 목록 조회

```sql
SHOW TABLES;
```

### 5-5. 현재 선택된 데이터베이스 확인

```sql
SELECT DATABASE();
```

## 6. MySQL 시스템 스키마

MySQL은 사용자가 생성한 데이터베이스 외에도 시스템 관리를 위한 스키마를 제공한다.

### 6-1. information_schema

테이블, 컬럼, 제약 조건, 인덱스 등 데이터베이스의 구조 정보를 제공한다.

```sql
SELECT *
FROM information_schema.tables;
```

### 6-2. mysql

사용자 계정, 권한 및 서버 관리와 관련된 정보를 저장한다.

```sql
USE mysql;

SHOW TABLES;
```

사용자 관련 정보를 조회하는 예시:

```sql
SELECT user, host
FROM mysql.user;
```

### 6-3. performance_schema

MySQL 서버의 실행 상태와 성능 관련 정보를 수집한다.

### 6-4. sys

performance_schema 등의 데이터를 이해하기 쉬운 뷰 형태로 제공한다.

## 7. SQL의 종류

SQL은 Structured Query Language의 약자다.

데이터베이스의 구조를 정의하고 데이터를 조회하거나 변경하는 데 사용한다.

### 7-1. SQL 분류

| 분류 | 의미 | 대표 명령어 |
|---|---|---|
| DDL | 데이터 정의어 | CREATE, ALTER, DROP, TRUNCATE |
| DML | 데이터 조작어 | INSERT, UPDATE, DELETE |
| DQL | 데이터 질의어 | SELECT |
| DCL | 데이터 제어어 | GRANT, REVOKE |
| TCL | 트랜잭션 제어어 | COMMIT, ROLLBACK, SAVEPOINT |

SELECT는 자료에 따라 DML에 포함하기도 하고 DQL로 별도 분류하기도 한다.

### 7-2. DDL

데이터베이스와 테이블 등 객체의 구조를 정의한다.

```sql
CREATE DATABASE test;
```

```sql
ALTER TABLE student
ADD email VARCHAR(100);
```

```sql
DROP TABLE student;
```

### 7-3. DML과 DQL

데이터를 삽입, 조회, 수정, 삭제한다.

```sql
INSERT INTO student (id, name)
VALUES (1, '홍길동');
```

```sql
SELECT *
FROM student;
```

```sql
UPDATE student
SET name = '김개발'
WHERE id = 1;
```

```sql
DELETE FROM student
WHERE id = 1;
```

### 7-4. DCL

사용자의 접근 권한을 관리한다.

```sql
GRANT SELECT ON test.*
TO 'student'@'localhost';
```

```sql
REVOKE SELECT ON test.*
FROM 'student'@'localhost';
```

### 7-5. TCL

트랜잭션을 제어한다.

```sql
COMMIT;
```

```sql
ROLLBACK;
```

## 8. 데이터베이스와 테이블 생성

### 8-1. 데이터베이스 생성

```sql
CREATE DATABASE test;
```

### 8-2. 데이터베이스 선택

```sql
USE test;
```

### 8-3. 테이블 목록 조회

```sql
SHOW TABLES;
```

### 8-4. 테이블 생성

```sql
CREATE TABLE student (
    id INT,
    name VARCHAR(100),
    phone VARCHAR(30),
    address VARCHAR(100)
);
```

각 컬럼의 역할:

id
→ 학생 번호

name
→ 학생 이름

phone
→ 전화번호

address
→ 주소

INT는 정수를 저장하는 데이터 타입이다.

VARCHAR(n)은 가변 길이 문자열을 저장하는 데이터 타입이다.

VARCHAR(100)은 최대 100문자까지 저장할 수 있다는 의미이며, 실제 저장 가능한 바이트 수는 문자 집합의 영향을 받는다.

### 8-5. 테이블 구조 조회

```sql
DESC student;
```

또는

```sql
DESCRIBE student;
```

확인할 수 있는 정보:
- 컬럼명
- 데이터 타입
- NULL 허용 여부
- 키 정보
- 기본값
- 추가 속성

### 8-6. 컬럼 추가

```sql
ALTER TABLE student
ADD subject VARCHAR(100);
```

기존 student 테이블에 subject 컬럼을 추가한다.

기존 행에 새 컬럼의 값이 없다면 일반적으로 NULL이 들어간다. 단, 기본값과 제약 조건에 따라 달라질 수 있다.

## 9. INSERT, SELECT, UPDATE, DELETE

### 9-1. INSERT

행을 삽입한다.

```sql
INSERT INTO student
VALUES (
    1,
    '홍길동',
    '010-1111-1111',
    '서울',
    '백엔드'
);
```

VALUES에 값을 입력할 때는 테이블의 컬럼 순서와 개수를 맞춰야 한다.

컬럼명을 명시하는 방식도 있다.

```sql
INSERT INTO student (
    id, name, phone, address, subject
)
VALUES (
    2, '김개발', '010-2222-2222',
    '서울', '백엔드'
);
```

컬럼명을 직접 지정하면 입력하는 값이 어떤 컬럼에 저장되는지 명확하게 알 수 있다.

### 9-2. 여러 행 INSERT

```sql
INSERT INTO student
VALUES
    (3, '이순신', '010-3333-3333', '서울', '백엔드'),
    (4, '강개발', '010-4444-4444', '부산', '프론트엔드');
```

VALUES 뒤에 괄호를 여러 개 작성하면 여러 행을 한 번에 삽입한다.

### 9-3. SELECT

```sql
SELECT *
FROM student;
```

`*`는 모든 컬럼을 조회한다.

특정 컬럼만 조회할 수도 있다.

```sql
SELECT name, phone, address
FROM student;
```

### 9-4. UPDATE

```sql
UPDATE student
SET subject = '프론트엔드'
WHERE id = 1;
```

id가 1인 학생의 subject를 수정한다.

WHERE를 생략하면 조건 없이 모든 행이 변경된다.

### 9-5. DELETE

```sql
DELETE FROM student
WHERE id = 1;
```

id가 1인 행을 삭제한다.

WHERE가 없으면 테이블의 모든 행이 삭제 대상이 된다.

### 9-6. DROP TABLE

```sql
DROP TABLE student;
```

테이블 구조와 데이터가 함께 삭제된다.

### 9-7. DROP DATABASE

```sql
DROP DATABASE test;
```

데이터베이스와 내부 객체를 삭제한다.

## 10. 키(Key)의 종류

키는 테이블의 행을 구별하거나 테이블 사이의 관계를 연결하는 데 사용한다.

### 10-1. 슈퍼키(Super Key)

행을 유일하게 식별할 수 있는 컬럼 또는 컬럼 집합이다.

예를 들어 student_id가 모든 학생을 유일하게 식별한다면 다음 항목들은 슈퍼키가 될 수 있다.

- student_id
- student_id + name
- student_id + phone

슈퍼키는 유일성을 만족하지만 반드시 최소성을 만족할 필요는 없다.

### 10-2. 후보키(Candidate Key)

유일성과 최소성을 모두 만족하는 키다.

유일성:
각 행을 구별할 수 있어야 한다.

최소성:
불필요한 컬럼이 포함되어서는 안 된다.

### 10-3. 기본키(Primary Key)

후보키 중 테이블의 대표 식별자로 선택한 키다.

조건:
- 중복 불가
- NULL 불가
- 하나의 테이블에 기본키 제약 조건은 하나만 지정 가능
- 여러 컬럼으로 구성한 복합 기본키도 가능

예시:

```sql
CREATE TABLE student (
    id INT PRIMARY KEY,
    name VARCHAR(100)
);
```

### 10-4. 대체키(Alternate Key)

후보키 중 기본키로 선택되지 않은 키다.

SQL에서는 UNIQUE 제약 조건 등을 통해 유일성을 관리할 수 있다.

### 10-5. 외래키(Foreign Key)

다른 테이블의 키를 참조하는 컬럼 또는 컬럼 집합이다.

예시:

```sql
CREATE TABLE departments (
    dept_id INT PRIMARY KEY,
    dept_name VARCHAR(100)
);
```

```sql
CREATE TABLE employees (
    emp_id INT PRIMARY KEY,
    emp_name VARCHAR(100),
    dept_id INT,
    FOREIGN KEY (dept_id)
        REFERENCES departments(dept_id)
);
```

employees.dept_id는 departments.dept_id를 참조한다.

즉, 직원이 어느 부서에 소속되는지 연결하는 역할을 한다.

외래키는 기본키뿐 아니라 참조 가능한 적절한 인덱스가 있는 키를 대상으로 정의할 수도 있다.

### 10-6. 자연키와 대리키

자연키:
업무적으로 의미를 가지는 식별자

예시:
- 사원번호
- 학번
- 이메일

대리키:
시스템에서 별도로 생성한 식별자

예시:

```sql
id INT AUTO_INCREMENT PRIMARY KEY
```

AUTO_INCREMENT는 새로운 행이 삽입될 때 자동으로 증가하는 정수 값을 생성한다.

## 11. 무결성과 제약 조건

무결성은 데이터가 올바르고 일관된 상태를 유지하도록 하는 특성이다.

### 11-1. 개체 무결성

기본키는 중복될 수 없으며 NULL이 될 수 없다.

### 11-2. 참조 무결성

외래키는 참조 대상과 올바른 관계를 유지해야 한다.

외래키 값은 참조 가능한 부모 키 값과 일치하거나, NULL이 허용되는 경우 NULL일 수 있다.

### 11-3. 도메인 무결성

컬럼에 허용된 타입과 범위의 데이터가 입력되어야 한다.

### 11-4. 주요 제약 조건

| 제약 조건 | 역할 |
|---|---|
| PRIMARY KEY | 기본키 지정 |
| FOREIGN KEY | 외래키 지정 |
| UNIQUE | 중복 값 제한 |
| NOT NULL | NULL 입력 제한 |
| DEFAULT | 기본값 지정 |
| CHECK | 입력 값에 조건 적용 |

### 11-5. UNIQUE

```sql
CREATE TABLE student_unique (
    id INT,
    name VARCHAR(100),
    address VARCHAR(100),

    CONSTRAINT address_uk UNIQUE (address),
    CONSTRAINT id_name_uk UNIQUE (id, name)
);
```

address_uk는 address 컬럼의 중복을 제한한다.

id_name_uk는 id와 name을 하나의 조합으로 검사한다.

예를 들어 다음 값은 조합이 다르기 때문에 허용될 수 있다.

```text
(1, '홍길동')
(1, '김개발')
(2, '홍길동')
```

MySQL UNIQUE 제약 조건에서는 일반적으로 NULL을 여러 개 허용할 수 있다.

### 11-6. DEFAULT

```sql
CREATE TABLE member (
    id INT PRIMARY KEY,
    name VARCHAR(100),
    status VARCHAR(20) DEFAULT 'ACTIVE'
);
```

status에 값을 지정하지 않으면 기본값인 ACTIVE가 사용된다.

### 11-7. CHECK

```sql
CREATE TABLE student_score (
    id INT PRIMARY KEY,
    score INT CHECK (score BETWEEN 0 AND 100)
);
```

score는 0부터 100까지의 값만 허용하도록 제한한다.

MySQL 8.0.16 이상에서는 CHECK 제약 조건을 실제로 검사한다.

## 12. 외래키의 참조 동작

외래키는 부모 테이블의 데이터가 수정되거나 삭제될 때 자식 테이블을 어떻게 처리할지 정할 수 있다.

### 12-1. CASCADE

부모 데이터가 삭제되면 연결된 자식 데이터도 함께 삭제한다.

```sql
FOREIGN KEY (dept_id)
REFERENCES departments(dept_id)
ON DELETE CASCADE
```

### 12-2. SET NULL

부모 데이터가 삭제되면 자식의 외래키 값을 NULL로 변경한다.

```sql
FOREIGN KEY (dept_id)
REFERENCES departments(dept_id)
ON DELETE SET NULL
```

이 옵션을 사용하려면 외래키 컬럼이 NULL을 허용해야 한다.

### 12-3. RESTRICT / NO ACTION

참조 중인 자식 데이터가 있으면 부모 데이터의 삭제 또는 변경을 제한한다.

MySQL InnoDB에서는 NO ACTION을 RESTRICT처럼 즉시 검사한다.

## 13. 트랜잭션과 ACID

트랜잭션(Transaction)은 하나의 논리적인 작업 단위다.

예를 들어 계좌 이체는 다음 두 작업으로 구성된다.

1. A 계좌에서 10,000원 출금
2. B 계좌에 10,000원 입금

두 작업은 모두 성공하거나 모두 취소되어야 한다.

### 13-1. ACID

| 항목 | 의미 |
|---|---|
| Atomicity | 원자성 |
| Consistency | 일관성 |
| Isolation | 격리성 |
| Durability | 지속성 |

원자성:
작업 전체가 성공하거나 실패해야 한다.

일관성:
트랜잭션 전후에 데이터베이스의 제약과 규칙이 유지되어야 한다.

격리성:
동시에 수행되는 트랜잭션들이 서로의 처리에 부적절하게 간섭하지 않도록 한다.

지속성:
COMMIT된 결과는 장애가 발생해도 유지되어야 한다.

### 13-2. autocommit

```sql
SELECT @@autocommit;
```

또는

```sql
SHOW VARIABLES LIKE 'autocommit';
```

autocommit이 1이면 기본적으로 각 SQL 문을 자동 커밋한다.

### 13-3. 트랜잭션 시작

```sql
START TRANSACTION;
```

### 13-4. COMMIT

```sql
COMMIT;
```

변경 사항을 확정한다.

### 13-5. ROLLBACK

```sql
ROLLBACK;
```

아직 커밋하지 않은 트랜잭션의 변경 사항을 취소한다.

예시:

```sql
START TRANSACTION;

UPDATE account
SET balance = balance - 10000
WHERE account_id = 1;

UPDATE account
SET balance = balance + 10000
WHERE account_id = 2;

COMMIT;
```

### 13-6. SAVEPOINT

트랜잭션 내부에서 중간 복구 지점을 지정한다.

```sql
START TRANSACTION;

UPDATE student
SET name = '김개발'
WHERE id = 1;

SAVEPOINT sp1;

UPDATE student
SET name = '이순신'
WHERE id = 2;

ROLLBACK TO SAVEPOINT sp1;

COMMIT;
```

두 번째 UPDATE는 취소되고, 첫 번째 UPDATE는 COMMIT된다.

MySQL에서는 CREATE TABLE, DROP TABLE 등의 많은 DDL 명령이 암묵적 COMMIT을 발생시키므로 일반적인 DML과 롤백 동작이 다를 수 있다.

## 14. MySQL 사용자와 권한

MySQL 계정은 사용자명과 접속 호스트를 함께 사용한다.

형식:

```text
'사용자명'@'호스트'
```

예시:

```text
'student'@'localhost'
```

### 14-1. 사용자 생성

```sql
CREATE USER 'student'@'localhost'
IDENTIFIED BY 'password';
```

### 14-2. 권한 부여

```sql
GRANT ALL PRIVILEGES ON test_db.*
TO 'student'@'localhost';
```

test_db 데이터베이스에 대한 여러 권한을 부여한다.

### 14-3. 권한 회수

```sql
REVOKE DELETE ON test_db.*
FROM 'student'@'localhost';
```

DELETE 권한을 회수한다.

단, 실제 회수 결과는 해당 사용자가 가진 권한의 부여 범위에 따라 달라진다.

### 14-4. 권한 확인

```sql
SHOW GRANTS FOR 'student'@'localhost';
```

CREATE USER, GRANT, REVOKE로 정상 변경한 권한은 일반적으로 즉시 반영된다.

FLUSH PRIVILEGES는 권한 관련 시스템 테이블을 직접 변경한 경우 등에 필요할 수 있는 명령이다.

## 15. ERD와 데이터 모델링

ERD는 Entity Relationship Diagram의 약자다.

테이블과 테이블 사이의 관계를 도식화하여 표현한다.

데이터베이스를 설계할 때는 먼저 어떤 데이터가 필요하고, 서로 어떤 관계를 가지는지 파악해야 한다.

### 15-1. 데이터 모델링 과정

1. 요구사항 분석
2. 개념적 데이터 모델링
3. 논리적 데이터 모델링
4. 물리적 데이터 모델링

개념 모델링:
업무에 필요한 엔터티와 관계를 파악한다.

논리 모델링:
속성, 기본키, 외래키, 관계, 정규화를 설계한다.

물리 모델링:
실제 MySQL 테이블명, 컬럼명, 데이터 타입, 인덱스, 제약 조건 등을 정의한다.

### 15-2. 1:1 관계

한 행이 다른 테이블의 최대 한 행과 연결된다.

예시:
사용자와 사용자 상세 프로필

### 15-3. 1:N 관계

하나의 부모 행이 여러 자식 행과 연결된다.

예시:

```text
departments (1)
    │
    └── employees (N)
```

하나의 부서에 여러 직원이 소속될 수 있다.

### 15-4. N:M 관계

양쪽 테이블의 여러 행이 서로 연결된다.

예시:
학생과 수강 과목

한 학생이 여러 과목을 수강할 수 있다.

한 과목에도 여러 학생이 참여할 수 있다.

이를 구현할 때는 교차 테이블을 사용한다.

```text
students
    │
    └── enrollments
            │
            └── courses
```

교차 테이블에는 양쪽 테이블의 식별자와 관계 자체의 속성을 저장할 수 있다.

---

## 16. 식별 관계와 비식별 관계

### 16-1. 식별 관계

부모 테이블의 기본키가 자식 테이블의 기본키를 구성하는 관계다.

예시:

orders
- order_id (PK)

order_items
- order_id (PK, FK)
- product_id (PK, FK)
- quantity

order_items의 기본키가 부모 키를 포함한다.

### 16-2. 비식별 관계

부모 테이블의 기본키를 외래키로 참조하지만, 자식 테이블은 별도의 기본키를 가지는 관계다.

예시:

departments
- dept_id (PK)

employees
- emp_id (PK)
- dept_id (FK)

employees의 기본키는 emp_id다.

dept_id는 외래키이지만 기본키에 포함되지 않는다.

주의할 점은 식별 관계와 비식별 관계가 자식 데이터의 독립적인 존재 가능 여부만으로 결정되는 것은 아니라는 것이다.

핵심 구분 기준은 부모 키가 자식의 기본키에 포함되는지 여부다.

## 17. 정규화

정규화(Normalization)는 데이터 중복을 줄이고 이상 현상을 방지하기 위해 테이블을 구조화하는 과정이다.

### 17-1. 이상 현상

삽입 이상:
불필요한 다른 정보가 없으면 새로운 데이터를 삽입할 수 없는 문제

갱신 이상:
중복된 데이터 일부만 수정되어 서로 다른 값이 남는 문제

삭제 이상:
하나의 데이터를 삭제하면서 필요한 다른 정보까지 사라지는 문제

### 17-2. 제1정규형(1NF)

각 컬럼이 관계형 모델에서 원자적인 값을 갖도록 구성한다.

잘못된 구조 예시:

| student_id | phones |
|---|---|
| 1 | 010-1111, 010-2222 |

전화번호를 여러 개 관리해야 한다면 별도의 테이블로 분리할 수 있다.

student_phones

| student_id | phone |
|---|---|
| 1 | 010-1111 |
| 1 | 010-2222 |

### 17-3. 제2정규형(2NF)

제1정규형을 만족하고, 후보키의 일부에만 종속되는 비주요 속성이 없어야 한다.

예를 들어 복합키가 (order_id, product_id)일 때 상품 이름이 product_id에만 종속된다면 별도 상품 테이블로 분리한다.

### 17-4. 제3정규형(3NF)

제2정규형을 만족하고, 비주요 속성이 다른 비주요 속성에 이행적으로 종속되는 문제를 제거한다.

예시:

employees
- emp_id
- emp_name
- dept_id
- dept_name

dept_name이 dept_id에 의해 결정된다면 departments 테이블로 분리할 수 있다.

employees
- emp_id
- emp_name
- dept_id

departments
- dept_id
- dept_name

### 17-5. BCNF

모든 비자명한 함수 종속 X → Y에서 X가 슈퍼키가 되도록 하는 정규형이다.

제3정규형보다 엄격한 정규화 조건이다.

### 17-6. 반정규화

반정규화는 데이터 조회 성능이나 처리 편의성을 위해 정규화된 구조에 일부 중복을 허용하는 방법이다.

예시:
- 집계 결과 저장
- 자주 사용하는 값을 별도 컬럼으로 저장
- 반복되는 조인 결과를 별도 테이블로 구성

반정규화로 중복 저장된 데이터는 변경 시 일관성을 유지하도록 관리해야 한다.

## 18. MySQL 샘플 데이터베이스

MySQL 샘플 데이터베이스는 SQL과 테이블 관계를 연습하는 데 사용한다.

대표적으로 employees 데이터베이스가 있다.

주요 테이블:

employees
→ 직원 정보

departments
→ 부서 정보

dept_emp
→ 직원의 부서 배정 이력

dept_manager
→ 부서 관리자 이력

salaries
→ 급여 이력

titles
→ 직함 이력

### 18-1. 테이블 관계

```text
employees.emp_no
    │
    ├── salaries.emp_no
    ├── titles.emp_no
    ├── dept_emp.emp_no
    └── dept_manager.emp_no

departments.dept_no
    │
    ├── dept_emp.dept_no
    └── dept_manager.dept_no
```

직원과 부서의 관계는 dept_emp를 통해 연결한다.

직원과 직함의 관계는 titles를 통해 연결한다.

### 18-2. 샘플 DB 확인

```sql
SHOW DATABASES;
```

```sql
USE employees;
```

```sql
SHOW TABLES;
```

```sql
DESC employees;
```

### 18-3. ERD

ERD를 통해 어떤 테이블이 서로 연결되는지 확인할 수 있다.

특히 여러 테이블을 JOIN하기 전에 기본키와 외래키 관계를 확인하는 데 도움이 된다.

### 18-4. Collation

Collation은 문자열의 비교와 정렬 규칙을 의미한다.

설정에 따라 다음 값이 같다고 판단될 수도 있고 서로 다르다고 판단될 수도 있다.

```text
'ABC'
'abc'
```

따라서 문자열 비교 결과는 컬럼과 데이터베이스에 설정된 Collation의 영향을 받는다.
