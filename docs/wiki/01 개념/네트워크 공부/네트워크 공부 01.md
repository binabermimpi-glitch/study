# 네트워크 공부 01

> 컴퓨터 네트워크의 구성 요소, 교환 방식, 주소별 전송 방식, 참조 모델과 성능 지표를 공부한 기록입니다.

01-1 컴퓨터 네트워크를 알아야 하는 이유

1. 컴퓨터 네트워크

컴퓨터 네트워크란 여러 개의 장치가 그물처럼 서로 연결되어 정보를 주고받을 수 있는 통신망이다.

오늘날 대부분의 프로그램과 스마트폰 애플리케이션은 네트워크를 이용한다.

개발자는 프로그램을 만드는 것뿐만 아니라 프로그램에서 발생하는 문제를 해결하고 서비스를 유지·보수해야 한다. 따라서 404 Not Found와 같은 오류가 무엇을 의미하는지 이해하려면 네트워크 지식이 필요하다.

404 Not Found는 서버에 요청이 전달되었지만, 서버에서 요청한 자원을 찾지 못했다는 HTTP 상태 코드이다.


2. 네트워크의 구조

네트워크의 구조는 그래프와 비슷하다.

그래프는 노드(node)와 노드를 연결하는 간선(edge) 또는 링크(link)로 이루어진 자료구조이다.

네트워크에서 노드는 네트워크에 연결된 장치를 의미한다.


3. 호스트

호스트는 네트워크의 가장자리에서 데이터를 보내거나 받는 장치이다.

호스트는 역할에 따라 클라이언트와 서버로 구분할 수 있다.

(1) 클라이언트
서버에 요청을 보내는 호스트이다.

(2) 서버
클라이언트의 요청을 받고 그에 대한 응답을 보내는 호스트이다.

클라이언트와 서버는 장치의 종류가 아니라 역할에 따라 구분한 개념이다.

따라서 하나의 호스트가 상황에 따라 클라이언트 역할과 서버 역할을 모두 수행할 수도 있다.


4. 네트워크 장비

네트워크 장비는 호스트 사이에서 주고받는 정보가 거쳐 가는 중간 노드이다.

대표적인 네트워크 장비에는 다음과 같은 것들이 있다.

- 이더넷 허브
- 스위치
- 라우터
- 공유기

네트워크 장비는 호스트가 보낸 정보가 수신지까지 올바르게 전달될 수 있도록 중간에서 데이터를 전달하거나 경로를 결정한다.

호스트와 네트워크 장비도 완전히 배타적인 개념은 아니다. 하나의 노드가 상황에 따라 여러 역할을 수행할 수도 있다.


5. 범위에 따른 네트워크 분류

(1) LAN

LAN은 Local Area Network의 약자이다.

가정, 학교, 회사처럼 가까운 지역의 장치들을 연결한 근거리 통신망이다.

예시
- 가정 내부 네트워크
- 학교 컴퓨터실
- 회사 사무실 네트워크


(2) WAN

WAN은 Wide Area Network의 약자이다.

서로 멀리 떨어진 지역이나 여러 LAN을 연결하는 광역 통신망이다.

다른 LAN에 속한 호스트와 메시지를 주고받으려면 WAN이 필요하다.

인터넷은 대표적인 WAN으로 볼 수 있다.


(3) ISP

ISP는 Internet Service Provider의 약자이다.

사용자에게 인터넷과 같은 WAN에 연결할 수 있는 회선과 관련 서비스를 제공하는 업체이다.

국내의 대표적인 ISP는 다음과 같다.

- KT
- LG유플러스
- SK브로드밴드


6. 메시지 교환 방식에 따른 네트워크 분류

네트워크는 메시지를 교환하는 방식에 따라 다음과 같이 구분할 수 있다.

- 회선 교환 네트워크
- 패킷 교환 네트워크


7. 회선 교환 방식

회선 교환 방식은 메시지를 주고받기 전에 두 호스트 사이의 회선, 즉 전송로를 먼저 설정한 다음 해당 회선을 이용하여 메시지를 주고받는 방식이다.

다음 표현은 비슷한 의미이다.

- 회선을 설정한다.
- 두 호스트가 연결되었다.
- 두 호스트 사이의 전송로를 예약했다.
- 전송로를 확보했다.


회선 스위치

회선 스위치는 호스트 사이에 일대일 전송로를 확보하는 네트워크 장비이다.


회선 교환 방식의 장점

두 호스트 사이의 연결을 먼저 확보한 후 메시지를 주고받기 때문에 일정 시간 동안 전송되는 정보량이 비교적 일정하다.

안정적인 통신 품질을 기대할 수 있다.


회선 교환 방식의 단점

메시지를 주고받지 않는 동안에도 회선을 계속 점유한다.

사용하지 않는 회선이 생기면 전체 회선의 이용 효율이 낮아질 수 있다.


8. 패킷 교환 방식

패킷 교환 방식은 전송하려는 메시지를 패킷이라는 작은 단위로 나누어 전송하는 방식이다.

각 패킷은 서로 다른 전송 경로를 통해 전달될 수 있다.

따라서 패킷이 수신지에 도착하는 순서가 달라질 수도 있다.

수신지에서는 전달받은 패킷들을 원래 메시지의 형태로 다시 조립한다.

인터넷은 기본적으로 패킷 교환 방식을 사용한다.


9. 패킷 스위치

패킷 스위치는 다음과 같은 역할을 수행한다.

- 패킷의 송신지와 수신지 식별
- 패킷이 이동할 경로 결정
- 다음 네트워크 장비로 패킷 전달

대표적인 패킷 스위치에는 라우터와 스위치가 있다.


10. 패킷의 구성

패킷은 일반적으로 페이로드, 헤더, 트레일러로 구성된다.


(1) 페이로드

페이로드(payload)는 실제로 전송하려는 데이터이다.

택배에 비유하면 택배 상자 안에 들어 있는 물품이다.


(2) 헤더

헤더(header)는 패킷의 앞부분에 붙는 부가 정보 또는 제어 정보이다.

헤더에는 다음과 같은 정보가 포함될 수 있다.

- 송신지 주소
- 수신지 주소
- 데이터의 순서
- 사용한 프로토콜
- 데이터의 길이

택배에 비유하면 보내는 사람과 받는 사람의 정보가 적힌 택배 송장이다.


(3) 트레일러

트레일러(trailer)는 데이터의 뒷부분에 붙는 부가 정보 또는 제어 정보이다.

주로 데이터 전송 과정에서 오류가 발생했는지 검사하는 데 사용된다.

헤더는 일반적으로 포함되지만 트레일러는 사용하는 프로토콜에 따라 포함되지 않을 수도 있다.



01-2 주소와 송수신지 유형에 따른 전송 방식

1. 주소

주소(address)는 송신지와 수신지를 특정하기 위한 정보이다.

대표적인 네트워크 주소에는 다음과 같은 것들이 있다.

- IP 주소
- MAC 주소

주소를 이용하면 메시지를 누구에게 전달할 것인지 지정할 수 있다.

예를 들어 다음과 같이 수신지를 지정할 수 있다.

- 특정 장치 하나
- 같은 네트워크의 모든 장치
- 특정 그룹에 속한 장치
- 특정 그룹 중 가장 가까운 장치


2. 송수신지 유형에 따른 전송 방식

(1) 유니캐스트

유니캐스트(unicast)는 하나의 송신지가 하나의 수신지에 메시지를 전달하는 일대일 전송 방식이다.

A → B


(2) 브로드캐스트

브로드캐스트(broadcast)는 같은 네트워크에 속한 모든 호스트에게 메시지를 전달하는 방식이다.

A → 같은 네트워크의 모든 호스트

브로드캐스트 도메인이란 브로드캐스트 메시지가 전달되는 범위를 말한다.


(3) 멀티캐스트

멀티캐스트(multicast)는 네트워크에서 특정 그룹에 속한 호스트들에게만 메시지를 전달하는 방식이다.

A → 특정 그룹의 여러 호스트


(4) 애니캐스트

애니캐스트(anycast)는 동일한 그룹에 속한 여러 호스트 중에서 네트워크상 가장 가까운 하나의 호스트에게 메시지를 전달하는 방식이다.

A → 동일 그룹 중 가장 가까운 호스트 한 대



01-3 네트워크를 미시적으로 살펴보기

1. 프로토콜

프로토콜(protocol)은 노드 사이에서 정보를 올바르게 주고받기 위해 합의된 규칙이나 방법이다.

사람들이 서로 대화하려면 같은 언어와 규칙이 필요한 것처럼 네트워크 장치도 서로 이해할 수 있는 통신 규칙이 필요하다.

네트워크 통신에는 일반적으로 하나의 프로토콜만 사용하는 것이 아니라 여러 프로토콜을 함께 사용한다.

여러 프로토콜이 계층적으로 쌓여 있는 구조를 프로토콜 스택(protocol stack)이라고 한다.


2. 프로토콜을 공부할 때 중요한 부분

모든 프로토콜에는 고유한 목적과 특징이 있다.

프로토콜을 공부할 때는 다음 두 가지를 중심으로 이해해야 한다.

- 이 프로토콜은 무엇을 위해 사용하는가?
- 이 프로토콜은 어떤 특징을 가지고 있는가?

프로토콜의 목적과 특징에 따라 헤더에 포함되는 정보도 달라질 수 있다.


3. 네트워크 참조 모델

네트워크를 통해 데이터를 송수신하는 과정은 여러 단계로 이루어진다.

이러한 통신 과정을 계층으로 나누어 표현한 것이 네트워크 참조 모델이다.


통신 과정을 계층적으로 나눈 이유

(1) 네트워크를 구성하고 설계하기 쉽다.

(2) 문제가 발생했을 때 문제가 발생한 계층을 찾아 진단하고 해결하기 쉽다.


대표적인 네트워크 참조 모델

- OSI 7계층 모델
- TCP/IP 4계층 모델


4. OSI 7계층

OSI 모델은 국제표준화기구인 ISO에서 만든 네트워크 참조 모델이다.


1계층 물리 계층

0과 1로 표현되는 비트 신호를 통신 매체를 통해 주고받는 계층이다.

PDU는 비트(bit)이다.


2계층 데이터 링크 계층

같은 네트워크에 있는 주변 장치 사이에서 정보를 올바르게 주고받기 위한 계층이다.

PDU는 프레임(frame)이다.


3계층 네트워크 계층

다른 네트워크를 거쳐 메시지를 최종 수신지까지 전달하는 계층이다.

PDU는 패킷(packet)이다.


4계층 전송 계층

종단 간에 신뢰성 있고 안정적인 데이터 전송을 지원하는 계층이다.

PDU는 세그먼트(segment) 또는 데이터그램(datagram)이다.


5계층 세션 계층

통신을 주고받는 응용 프로그램 사이의 연결 상태인 세션을 관리하는 계층이다.

PDU는 데이터(data)이다.


6계층 표현 계층

문자를 컴퓨터가 이해할 수 있는 형식으로 변환하고 데이터를 압축하거나 암호화하는 계층이다.

PDU는 데이터(data)이다.


7계층 응용 계층

사용자와 사용자가 이용하는 응용 프로그램에 다양한 네트워크 서비스를 제공하는 계층이다.

PDU는 데이터(data)이다.


OSI 7계층 순서

응용 → 표현 → 세션 → 전송 → 네트워크 → 데이터 링크 → 물리


5. TCP/IP 4계층

TCP/IP 모델은 현재 인터넷 통신을 설명할 때 주로 사용하는 네트워크 참조 모델이다.

TCP/IP 모델은 인터넷 프로토콜 스위트 또는 프로토콜 스택이라고도 한다.


(1) 네트워크 액세스 계층

같은 네트워크에 있는 장치 사이에서 데이터를 전송한다.

링크 계층 또는 네트워크 인터페이스 계층이라고도 한다.

OSI 모델의 데이터 링크 계층 및 물리 계층과 유사하다.


(2) 인터넷 계층

다른 네트워크를 거쳐 수신지까지 패킷을 전달한다.

OSI 모델의 네트워크 계층과 유사하다.


(3) 전송 계층

프로세스 사이에서 데이터를 안정적으로 전송한다.

OSI 모델의 전송 계층과 유사하다.


(4) 응용 계층

사용자와 응용 프로그램에 네트워크 서비스를 제공한다.

OSI 모델의 세션 계층, 표현 계층, 응용 계층과 유사하다.


OSI 모델과 TCP/IP 모델의 대응 관계

OSI 응용·표현·세션 계층
→ TCP/IP 응용 계층

OSI 전송 계층
→ TCP/IP 전송 계층

OSI 네트워크 계층
→ TCP/IP 인터넷 계층

OSI 데이터 링크·물리 계층
→ TCP/IP 네트워크 액세스 계층


6. 캡슐화와 역캡슐화

송신 과정에서는 캡슐화가 이루어진다.

수신 과정에서는 역캡슐화가 이루어진다.


캡슐화

송신자가 데이터를 보내기 위해 상위 계층에서 하위 계층으로 내려가면서 각 계층의 프로토콜 헤더를 추가하는 과정이다.

필요한 경우 트레일러도 추가된다.

데이터
→ 전송 계층 헤더 + 데이터
→ 네트워크 계층 헤더 + 전송 계층 데이터
→ 데이터 링크 계층 헤더 + 데이터 + 트레일러
→ 비트 신호

캡슐화는 택배 물품을 여러 단계에 걸쳐 포장하고 송장을 붙이는 과정과 비슷하다.


역캡슐화

수신자가 받은 정보를 하위 계층에서 상위 계층으로 올리면서 각 계층의 헤더와 트레일러를 확인하고 제거하는 과정이다.

비트
→ 프레임
→ 패킷
→ 세그먼트 또는 데이터그램
→ 데이터


캡슐화와 역캡슐화 핵심

송신자
상위 계층 → 하위 계층
캡슐화
헤더 추가

수신자
하위 계층 → 상위 계층
역캡슐화
헤더 확인 및 제거


7. PDU

PDU는 Protocol Data Unit의 약자이다.

PDU는 각 계층에서 송수신되는 메시지의 단위이다.

현재 계층의 PDU는 상위 계층에서 전달받은 데이터에 현재 계층의 프로토콜 헤더와 필요한 경우 트레일러를 추가한 것이다.

현재 계층의 PDU
= 상위 계층에서 전달받은 데이터
+ 현재 계층의 프로토콜 헤더
+ 필요한 경우 트레일러


계층별 PDU 이름

응용·표현·세션 계층
→ 데이터(data)

전송 계층
→ 세그먼트(segment) 또는 데이터그램(datagram)

네트워크 계층
→ 패킷(packet)

데이터 링크 계층
→ 프레임(frame)

물리 계층
→ 비트(bit)


8. 네트워크 참조 모델을 바라보는 방법

OSI 7계층과 TCP/IP 4계층이 직접 데이터를 전송하는 것은 아니다.

네트워크 참조 모델은 복잡한 네트워크 통신 과정을 이해하기 쉽게 계층으로 나눈 밑그림이다.

실제로 네트워크를 작동시키는 주체는 각 계층에서 사용되는 프로토콜과 네트워크 장비이다.

모든 프로토콜과 네트워크 장비가 특정 계층에 완벽하게 대응하는 것은 아니다.

새로운 프로토콜과 장비가 계속 만들어지고 있기 때문이다.

따라서 다음과 같이 이해하는 것이 좋다.

- 시험과 면접을 위해 계층별 역할과 대표적인 프로토콜은 알아야 한다.
- 실무에서는 모든 네트워크 기술을 특정 계층에 억지로 대응시킬 필요는 없다.
- 실제 학습의 중심은 프로토콜과 장비의 목적, 특징, 동작 방식이다.

참조 모델은 네트워크를 직접 작동시키는 주체가 아니라 네트워크를 이해하기 위한 밑그림이다.



01-3 추가 트래픽과 네트워크 성능 지표

1. 트래픽

트래픽(traffic)은 네트워크에서 주고받는 정보량이다.

일반적으로 특정 시점에 특정 노드를 통과하는 정보량을 의미한다.

트래픽이 지나치게 많아지면 네트워크 장비에 과부하가 발생한다.

그 결과 네트워크 지연이나 성능 저하가 발생할 수 있다.


2. 처리율

처리율(throughput)은 단위 시간 동안 네트워크를 통해 실제로 전송된 정보량이다.

처리율은 실제 전송 결과를 나타낸다.


처리율의 표현 단위

- bps(bits per second): 초당 전송된 비트 수
- Mbps(megabits per second): 초당 전송된 메가비트 수
- Gbps(gigabits per second): 초당 전송된 기가비트 수
- pps(packets per second): 초당 전송된 패킷 수


3. 대역폭

대역폭(bandwidth)은 단위 시간 동안 통신 매체를 통해 송수신할 수 있는 최대 정보량이다.

쉽게 말하면 데이터를 주고받을 수 있는 통로의 최대 폭이다.


대역폭의 표현 단위

- bps
- Mbps
- Gbps


4. 대역폭과 처리율의 차이

대역폭은 이론적으로 전송할 수 있는 최대 정보량이다.

처리율은 네트워크를 통해 실제로 전송된 정보량이다.

예를 들어 최대 대역폭이 100Mbps인 회선을 사용하더라도 네트워크 혼잡, 장비 성능, 패킷 손실 등의 영향으로 실제 처리율은 80Mbps가 될 수 있다.

대역폭
= 도로의 최대 차선 수

처리율
= 일정 시간 동안 실제로 도로를 통과한 자동차 수

일반적으로 실제 처리율은 대역폭보다 작거나 같다.


5. 패킷 손실

패킷 손실(packet loss)은 송신자가 보낸 패킷이 전송 과정에서 사라져 수신지에 도착하지 못한 상태이다.

패킷 손실은 다음과 같이 표현할 수 있다.

- 손실된 패킷 수
- 전체 패킷 중 손실된 패킷의 비율


패킷 손실률 계산

패킷 손실률
= 손실된 패킷 수 ÷ 전체 전송 패킷 수 × 100

예를 들어 패킷 100개 중 5개가 손실되었다면 패킷 손실률은 5%이다.



전체 흐름

호스트가 데이터를 생성한다.
↓
프로토콜의 규칙에 따라 헤더를 추가한다.
↓
데이터를 패킷으로 나누어 전송한다.
↓
스위치와 라우터 등의 네트워크 장비를 거친다.

↓

↓
