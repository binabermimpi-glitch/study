## 04-1 전송 계층 개요: IP의 한계와 포트

## 1. 전송 계층의 역할

전송 계층(Transport Layer)은 **네트워크 계층과 응용 계층 사이**에 위치한다.

전송 계층의 핵심 역할은 다음과 같다.

1. IP의 한계를 보완한다.
2. 신뢰할 수 있는 통신을 제공한다.
3. 연결형 통신을 제공할 수 있다.
4. 포트 번호를 이용하여 응용 계층의 프로세스를 식별한다.

| 계층 | 주요 식별 정보 | 식별 대상 |
|---|---|---|
| 네트워크 계층 | IP 주소 | 네트워크에 연결된 호스트 |
| 전송 계층 | 포트 번호 | 호스트에서 실행 중인 애플리케이션 프로세스 |

즉, IP 주소가 컴퓨터를 찾는 정보라면 포트 번호는 해당 컴퓨터 안에서 실행 중인 프로그램을 찾는 정보이다.

---

## 2. IP의 한계

IP는 다음과 같은 특성을 가진다.

- 신뢰할 수 없는 프로토콜
- 비연결형 프로토콜

따라서 IP 패킷의 전달은 기본적으로 다음과 같다.

> 신뢰할 수 없는 통신 + 비연결형 통신

### 신뢰할 수 없는 통신

IP는 패킷이 수신지까지 제대로 전달되었다는 것을 보장하지 않는다.

- 패킷의 도착을 보장하지 않는다.
- 패킷이 손실되어도 스스로 재전송하지 않는다.
- 패킷의 순서가 바뀔 수 있다.
- 중복된 패킷이 도착할 수 있다.
- 패킷이 잘못 전송되어도 이를 완전히 복구하지 않는다.

여기서 신뢰할 수 없다는 말은 IP가 항상 잘못 동작한다는 뜻이 아니다.

> IP 자체에서 패킷의 도착, 순서, 재전송을 보장하지 않는다는 뜻이다.

### 비연결형 통신

IP는 송신 호스트와 수신 호스트 사이에 미리 연결을 설정하지 않는다.

- 사전 연결 수립 과정이 없다.
- 상대방의 준비 상태를 먼저 확인하지 않는다.
- 수신지를 향해 패킷을 전송한다.
- 각각의 패킷이 독립적으로 처리될 수 있다.

---

## 3. IP가 신뢰할 수 없는 비연결형 통신을 사용하는 이유

가장 큰 이유는 **성능과 효율성**이다.

신뢰성과 연결을 제공하려면 다음과 같은 추가 작업이 필요하다.

- 연결 수립
- 수신 여부 확인
- 순서 확인
- 오류 발생 시 재전송
- 흐름 제어
- 혼잡 제어

이러한 작업은 통신의 신뢰성을 높이지만 처리 시간과 부하도 증가시킨다.

또한 모든 통신에서 완벽한 신뢰성이 필요한 것은 아니다.

예를 들어 실시간 음성이나 영상 통신에서는 손실된 일부 데이터를 다시 전송하는 것보다 지연 없이 다음 데이터를 전달하는 것이 더 중요할 수 있다.

---

## 4. TCP와 UDP

전송 계층의 대표적인 프로토콜은 TCP와 UDP이다.

| 구분 | TCP | UDP |
|---|---|---|
| 전체 이름 | Transmission Control Protocol | User Datagram Protocol |
| 연결 방식 | 연결형 | 비연결형 |
| 신뢰성 | 신뢰성 있는 통신 제공 | 신뢰성을 보장하지 않음 |
| 데이터 전달 순서 | 순서 보장 | 순서 보장 안 함 |
| 손실 시 재전송 | 지원 | 기본적으로 지원하지 않음 |
| 흐름 제어 | 지원 | 지원하지 않음 |
| 혼잡 제어 | 지원 | 지원하지 않음 |
| 전송 속도 | 상대적으로 느림 | 상대적으로 빠름 |
| 대표적인 사용 | 웹, 파일 전송, 이메일, 원격 접속 | 실시간 영상, 음성, DNS 질의 |

### TCP

TCP는 연결형 통신과 신뢰성 있는 통신을 제공한다.

- 통신 전에 연결을 수립한다.
- 통신하는 동안 연결을 유지한다.
- 통신이 끝나면 연결을 종료한다.
- 데이터의 도착 여부를 확인한다.
- 손실된 데이터를 재전송한다.
- 데이터의 순서를 보장한다.
- 흐름 제어를 제공한다.
- 혼잡 제어를 제공한다.

### UDP

UDP는 비연결형 통신을 제공하며 신뢰성을 기본적으로 보장하지 않는다.

- 연결 수립 과정이 없다.
- 데이터 도착 여부를 확인하지 않는다.
- 손실된 데이터를 기본적으로 재전송하지 않는다.
- 패킷의 순서를 보장하지 않는다.
- TCP보다 구조가 단순하다.
- TCP보다 비교적 빠른 전송이 가능하다.

> UDP를 사용한다고 해서 애플리케이션이 반드시 신뢰성 없는 것은 아니다. 필요한 경우 응용 프로그램이 직접 재전송이나 오류 제어 기능을 구현할 수 있다.

## 5. 포트

포트(Port)는 네트워크상에서 **애플리케이션 프로세스를 식별하는 번호**이다.

한 컴퓨터에서는 웹 브라우저, 데이터베이스, 메신저 등 여러 프로그램이 동시에 네트워크를 사용할 수 있다.

따라서 다음 두 정보가 함께 필요하다.

- IP 주소: 호스트 식별
- 포트 번호: 호스트 안의 애플리케이션 프로세스 식별

### IP 주소와 포트 번호

`192.168.0.15:8000`

| 정보 | 값 | 역할 |
|---|---|---|
| IP 주소 | `192.168.0.15` | 호스트 식별 |
| 포트 번호 | `8000` | 애플리케이션 프로세스 식별 |

IP 주소와 포트 번호의 조합을 **소켓 주소(Socket Address)**라고 부르기도 한다.

---

## 6. TCP·UDP 헤더의 포트 번호

TCP와 UDP 헤더에는 송신지 포트와 수신지 포트가 포함된다.

### TCP 헤더의 주요 구조

| 비트 범위 | 필드 |
|---|---|
| 0~15비트 | 송신지 포트 |
| 16~31비트 | 수신지 포트 |
| 다음 필드 | 순서 번호 |
| 다음 필드 | 확인 응답 번호 |
| 다음 필드 | 제어 비트, 윈도우, 체크섬 등 |

### UDP 헤더의 구조

| 비트 범위 | 필드 |
|---|---|
| 0~15비트 | 송신지 포트 |
| 16~31비트 | 수신지 포트 |
| 다음 16비트 | 길이 |
| 다음 16비트 | 체크섬 |

송신지 포트와 수신지 포트는 각각 16비트이다.

따라서 표현할 수 있는 포트 번호의 개수는 다음과 같다.

`2¹⁶ = 65,536개`

포트 번호의 범위:

`0번~65,535번`

> 포트 번호의 최댓값은 65,535번이다. 65,635번이 아니다.

---

## 7. 송신지 포트와 수신지 포트

### 송신지 포트

패킷을 보낸 애플리케이션 프로세스를 식별한다.

응답 패킷을 어느 프로그램으로 돌려보낼지 판단할 때 사용한다.

### 수신지 포트

패킷을 받을 애플리케이션 프로세스를 식별한다.

서버에서 어떤 프로그램이 패킷을 처리해야 하는지 판단할 때 사용한다.

### HTTP 통신 예시

클라이언트의 웹 브라우저가 HTTP 서버에 접속한다고 가정한다.

#### 클라이언트 → HTTP 서버

| 구분 | 포트 번호 |
|---|---:|
| 송신지 포트 | 55717 |
| 수신지 포트 | 80 |

- `55717`: 클라이언트가 임시로 사용한 동적 포트
- `80`: HTTP 서버의 잘 알려진 포트

#### HTTP 서버 → 클라이언트

| 구분 | 포트 번호 |
|---|---:|
| 송신지 포트 | 80 |
| 수신지 포트 | 55717 |

서버가 응답할 때는 요청 패킷의 송신지 포트였던 `55717`을 수신지 포트로 사용한다.

---

## 8. 포트 번호의 분류

포트 번호는 다음과 같이 세 종류로 분류할 수 있다.

| 포트 종류 | 포트 번호 범위 | 주요 용도 |
|---|---:|---|
| 잘 알려진 포트 | 0~1023 | 범용적인 서버 프로그램 |
| 등록된 포트 | 1024~49151 | 특정 애플리케이션과 서비스 |
| 동적·사설·임시 포트 | 49152~65535 | 클라이언트가 임시로 사용 |

### 포트 번호 구조

| 전체 포트 번호 범위 |
|---|
| `0 ── 잘 알려진 포트 ── 1023 ── 등록된 포트 ── 49151 ── 동적 포트 ── 65535` |

포트 번호의 분류와 등록은 인터넷 할당 번호 관리 기관인 **IANA(Internet Assigned Numbers Authority)**에서 관리한다.

다만 포트 번호 배정은 일반적으로 지켜야 하는 표준과 권고이며, 기술적으로 다른 포트를 사용하도록 설정할 수도 있다.

---

## 9. 잘 알려진 포트

잘 알려진 포트(Well-Known Port)는 `0~1023번` 범위이다.

- 시스템 포트라고도 한다.
- 범용적으로 사용되는 애플리케이션 프로토콜에 할당된다.
- 주로 서버 애플리케이션이 사용한다.

| 포트 번호 | 프로토콜·서비스 | 설명 |
|---:|---|---|
| 20 | FTP 데이터 | FTP 데이터 전송 |
| 21 | FTP 제어 | FTP 연결 및 명령 전달 |
| 22 | SSH | 보안 원격 접속 |
| 23 | Telnet | 암호화되지 않은 원격 접속 |
| 25 | SMTP | 이메일 전송 |
| 53 | DNS | 도메인 이름과 IP 주소 변환 |
| 67 | DHCP 서버 | DHCP 서버가 사용 |
| 68 | DHCP 클라이언트 | DHCP 클라이언트가 사용 |
| 80 | HTTP | 암호화되지 않은 웹 통신 |
| 110 | POP3 | 이메일 수신 |
| 143 | IMAP | 서버 기반 이메일 관리 |
| 443 | HTTPS | 암호화된 웹 통신 |

### 시험 주의

FTP는 두 개의 대표 포트를 사용한다.

- 20번: 데이터 전송
- 21번: 제어 및 명령 전달

DHCP도 서버와 클라이언트가 서로 다른 포트를 사용한다.

- 67번: DHCP 서버
- 68번: DHCP 클라이언트

## 10. 등록된 포트

등록된 포트(Registered Port)는 `1024~49151번` 범위이다.

- 잘 알려진 포트보다 범용성은 낮다.
- 흔히 사용되는 특정 애플리케이션이나 서비스에 등록된다.
- 서버 프로그램에서 자주 사용된다.

| 포트 번호 | 애플리케이션·서비스 |
|---:|---|
| 1194 | OpenVPN |
| 1433 | Microsoft SQL Server |
| 1521 | Oracle Database |
| 3306 | MySQL |
| 5432 | PostgreSQL |
| 6379 | Redis |
| 8080 | HTTP 대체 포트 |

> `8080`은 개발용 웹 서버나 프록시 서버 등에서 HTTP의 대체 포트로 자주 사용된다.

---

## 11. 동적 포트

동적 포트(Dynamic Port)는 `49152~65535번` 범위이다.

다음과 같은 이름으로도 불린다.

- 동적 포트
- 사설 포트
- 임시 포트
- 에페멀 포트(Ephemeral Port)

### 동적 포트의 특징

- 특정 서비스에 고정적으로 할당되지 않는다.
- 비교적 자유롭게 사용할 수 있다.
- 클라이언트가 서버에 접속할 때 임시로 할당받는 경우가 많다.
- 통신이 종료되면 해당 포트를 반환하여 다시 사용할 수 있다.

### 서버와 클라이언트의 포트 사용

| 구분 | 주로 사용하는 포트 |
|---|---|
| 서버 | 잘 알려진 포트 또는 등록된 포트 |
| 클라이언트 | 동적 포트 |

### 동적 포트 통신 예시

클라이언트가 HTTP 서버에 접속하는 상황:

| 통신 방향 | 송신지 포트 | 수신지 포트 |
|---|---:|---:|
| 클라이언트 → 서버 | 55717 | 80 |
| 서버 → 클라이언트 | 80 | 55717 |

동작 과정:

1. HTTP 서버는 80번 포트에서 요청을 기다린다.
2. 클라이언트 운영체제가 55717번과 같은 임시 포트를 할당한다.
3. 클라이언트는 수신지 포트를 80번으로 설정하여 요청한다.
4. 서버는 송신지 포트를 80번으로 설정한다.
5. 서버는 클라이언트의 임시 포트인 55717번으로 응답한다.
6. 클라이언트는 55717번 포트를 사용하는 프로세스에 응답을 전달한다.

> 운영체제가 사용하는 실제 동적 포트 범위는 운영체제 설정에 따라 달라질 수 있지만, IANA 기준 동적 포트 범위는 `49152~65535`이다.

## 12. 포트 번호를 이용한 통신 식별

실제 통신은 IP 주소와 포트 번호뿐만 아니라 전송 계층 프로토콜까지 함께 고려하여 식별한다.

대표적으로 다음 정보를 이용한다.

| 정보 | 역할 |
|---|---|
| 송신지 IP 주소 | 패킷을 보낸 호스트 |
| 송신지 포트 번호 | 패킷을 보낸 프로세스 |
| 수신지 IP 주소 | 패킷을 받을 호스트 |
| 수신지 포트 번호 | 패킷을 받을 프로세스 |
| 전송 계층 프로토콜 | TCP 또는 UDP 구분 |

이러한 정보를 조합하면 동시에 여러 네트워크 통신을 구분할 수 있다.

---

## 13. NAT의 한계

NAT(Network Address Translation)는 일반적으로 사설 IP 주소와 공인 IP 주소를 변환하는 기술이다.

단순한 NAT에서는 NAT 변환 테이블에 변환 대상이 되는 IP 주소 쌍을 기록한다.

| 사설 IP 주소 | 공인 IP 주소 |
|---|---|
| 192.168.0.5 | 1.2.3.4 |
| 192.168.0.6 | 1.2.3.5 |

이 방식에서는 사설 IP 주소 하나당 공인 IP 주소 하나가 필요할 수 있다.

### 단순 NAT의 문제점

- 많은 사설 IP 주소를 변환하려면 많은 공인 IP 주소가 필요하다.
- 사설 IP 주소 수만큼 공인 IP 주소가 필요할 수 있다.
- 한정된 공인 IPv4 주소가 낭비될 수 있다.

이러한 문제를 개선하기 위해 포트 번호까지 함께 변환하는 NAPT가 사용된다.

---

## 14. NAPT와 PAT

NAPT는 **Network Address Port Translation**의 약자이다.

PAT는 **Port Address Translation**의 약자이다.

두 용어는 여러 사설 IP 주소가 하나의 공인 IP 주소를 공유하도록 IP 주소와 포트 번호를 함께 변환하는 기술을 의미한다.

가정용 공유기에서 흔히 사용하는 NAT 방식이다.

### NAPT의 특징

- NAT 테이블에 IP 주소와 포트 번호를 함께 기록한다.
- 여러 사설 IP 주소가 하나의 공인 IP 주소를 공유할 수 있다.
- 각 통신은 서로 다른 포트 번호로 구분한다.
- 사설 IP 주소와 공인 IP 주소를 `N:1` 형태로 변환할 수 있다.
- 공인 IPv4 주소 부족 문제를 완화한다.

### NAPT 변환 테이블 예시

| 네트워크 내부 | 네트워크 외부 |
|---|---|
| `192.168.0.5:1025` | `1.2.3.4:6200` |
| `192.168.0.6:1026` | `1.2.3.4:6201` |

두 내부 호스트는 같은 공인 IP 주소 `1.2.3.4`를 사용한다.

하지만 외부 포트 번호가 각각 `6200`, `6201`로 다르기 때문에 공유기는 응답 패킷을 어느 내부 호스트에 전달해야 하는지 구분할 수 있다.

### NAPT 동작 과정

1. 내부 호스트가 외부 서버로 패킷을 전송한다.
2. 공유기가 사설 IP 주소와 포트 번호를 확인한다.
3. 공유기가 공인 IP 주소와 새로운 포트 번호로 변환한다.
4. 변환 관계를 NAPT 테이블에 저장한다.
5. 외부 서버가 공인 IP 주소와 변환된 포트 번호로 응답한다.
6. 공유기가 NAPT 테이블을 확인한다.
7. 원래의 사설 IP 주소와 포트 번호로 되돌려 내부 호스트에 전달한다.

---

# 04-1 추가: 포트 포워딩

## 15. 외부에서 내부 네트워크로 접속할 때의 문제

NAPT를 사용하면 여러 내부 호스트가 하나의 공인 IP 주소를 공유할 수 있다.

하지만 외부 호스트가 먼저 내부 네트워크로 접속하려는 경우 문제가 발생한다.

예를 들어 내부에 다음과 같은 서버가 있다고 가정한다.

`192.168.0.10:8080`

외부 사용자는 공유기의 공인 IP 주소만 알고 있으며, 공유기는 들어온 패킷을 어느 내부 호스트로 전달해야 하는지 알 수 없다.

이를 해결하기 위해 포트 포워딩을 사용한다.

---

## 16. 포트 포워딩

포트 포워딩(Port Forwarding)은 공유기의 특정 외부 포트로 들어온 패킷을 미리 지정한 내부 IP 주소와 포트 번호로 전달하는 기능이다.

### 포트 포워딩 설정 예시

| 외부 접속 정보 | 내부 전달 대상 |
|---|---|
| `1.2.3.4:9000` | `192.168.0.10:8080` |

외부 사용자가 다음 주소로 접속한다.

`1.2.3.4:9000`

공유기는 해당 패킷을 다음 내부 서버로 전달한다.

`192.168.0.10:8080`

### 동작 과정

1. 내부 서버에 고정된 사설 IP 주소를 설정한다.
2. 공유기에 외부 포트와 내부 주소의 연결 규칙을 설정한다.
3. 외부 사용자는 공인 IP 주소와 외부 포트로 접속한다.
4. 공유기는 설정된 내부 IP 주소와 포트로 패킷을 전달한다.

### 포트 포워딩의 활용

- 외부에서 내부 웹 서버 접속
- 게임 서버 운영
- 원격 데스크톱 접속
- NAS 접속
- CCTV 접속
- SSH 원격 접속

### 주의 사항

포트 포워딩은 내부 서비스를 인터넷에 노출하므로 다음 사항을 확인해야 한다.

- 필요한 포트만 개방한다.
- 강력한 비밀번호를 사용한다.
- 사용하지 않는 서비스는 종료한다.
- 서버와 프로그램을 최신 상태로 유지한다.
- 방화벽 규칙을 함께 확인한다.

# 04-1 추가: ICMP

## 17. ICMP란?

ICMP는 **Internet Control Message Protocol**의 약자이다.

IP 패킷의 전송 과정에서 발생한 상황을 송신자에게 알려주는 보조 프로토콜이다.

ICMP가 제공하는 메시지는 크게 두 가지로 나눌 수 있다.

1. 전송 과정에서 발생한 문제에 대한 오류 보고
2. 네트워크 상태 확인을 위한 진단 정보

| ICMP 역할 | 설명 |
|---|---|
| 오류 보고 | 패킷 전달 실패나 TTL 만료 등의 문제 전달 |
| 네트워크 진단 | 대상 호스트의 응답 여부와 경로 등을 확인 |

---

## 18. ICMP 메시지 구조

ICMP 메시지는 대표적으로 **타입(Type)**과 **코드(Code)**를 포함한다.

| 필드 | 의미 |
|---|---|
| 타입 | ICMP 메시지의 큰 종류를 나타내는 번호 |
| 코드 | 해당 타입 안의 구체적인 원인을 나타내는 번호 |

같은 타입의 ICMP 메시지라도 코드 번호에 따라 구체적인 의미가 달라질 수 있다.

예를 들어 타입 3은 모두 목적지 도달 불가를 의미하지만, 코드에 따라 네트워크 문제인지 포트 문제인지 구분한다.

---

## 19. ICMP 오류 보고 메시지

### 목적지 도달 불가

ICMP 타입 3은 **목적지 도달 불가(Destination Unreachable)**를 의미한다.

특정 패킷을 수신지까지 전달할 수 없을 때 사용한다.

| 타입 | 코드 | 의미 |
|---:|---:|---|
| 3 | 0 | 네트워크 도달 불가 |
| 3 | 1 | 호스트 도달 불가 |
| 3 | 2 | 프로토콜 도달 불가 |
| 3 | 3 | 포트 도달 불가 |
| 3 | 4 | 단편화가 필요하지만 DF 비트가 1이어서 단편화할 수 없음 |

### 코드별 의미

#### 타입 3, 코드 0

목적지 네트워크까지 도달할 수 없다는 의미이다.

#### 타입 3, 코드 1

목적지 네트워크에는 도달했지만 특정 호스트까지 도달할 수 없다는 의미이다.

#### 타입 3, 코드 2

수신지에서 해당 전송 계층 프로토콜을 사용할 수 없다는 의미이다.

#### 타입 3, 코드 3

수신지 호스트에는 도달했지만 해당 포트를 사용하는 프로세스가 없다는 의미이다.

#### 타입 3, 코드 4

패킷을 전달하려면 단편화가 필요하지만 IPv4 헤더의 DF 비트가 설정되어 있어 단편화할 수 없다는 의미이다.

이 메시지는 경로 MTU를 확인하는 과정에서도 사용될 수 있다.

---

## 20. 시간 초과 메시지

ICMP 타입 11은 **시간 초과(Time Exceeded)**를 의미한다.

| 타입 | 코드 | 의미 |
|---:|---:|---|
| 11 | 0 | 패킷 전송 중 TTL 만료 |

IP 패킷이 라우터를 하나 거칠 때마다 TTL 값이 1씩 감소한다.

TTL이 0이 되면 라우터는 패킷을 폐기하고 일반적으로 송신자에게 ICMP 시간 초과 메시지를 전달한다.

### TTL의 목적

- 패킷이 네트워크를 무한히 순환하는 것을 방지한다.
- 잘못된 라우팅으로 인한 네트워크 자원 낭비를 줄인다.

---

## 21. ICMP 네트워크 진단 메시지

| 타입 | 코드 | 메시지 | 설명 |
|---:|---:|---|---|
| 8 | 0 | 에코 요청 | 대상 호스트에 응답 요청 |
| 0 | 0 | 에코 응답 | 에코 요청에 대한 응답 |
| 9 | 0 | 라우터 광고 | 라우터가 호스트에게 자신의 존재를 알림 |

### 에코 요청과 에코 응답

에코 요청과 에코 응답은 대상 호스트와 통신할 수 있는지 확인할 때 사용한다.

동작 과정:

1. 호스트 A가 호스트 B에게 ICMP 에코 요청을 전송한다.
2. 호스트 B가 요청을 정상적으로 받는다.
3. 호스트 B가 호스트 A에게 ICMP 에코 응답을 전송한다.
4. 호스트 A는 응답 시간 등을 확인한다.

## 22. ping과 ICMP

`ping` 명령어는 일반적으로 ICMP 에코 요청과 에코 응답을 사용하여 대상 호스트와의 통신 가능 여부를 확인한다.

### ping으로 확인할 수 있는 것

- 대상 호스트의 응답 여부
- 패킷 왕복 시간
- 패킷 손실 여부
- 기본적인 네트워크 연결 상태

### 사용 예시

Windows, macOS, Linux:

`ping 8.8.8.8`

도메인 이름으로 확인:

`ping example.com`

### 주의

ping 응답이 없다고 해서 대상 서버가 반드시 꺼져 있는 것은 아니다.

다음과 같은 이유로 응답이 없을 수 있다.

- 방화벽이 ICMP 메시지를 차단
- 서버가 ping 응답을 하지 않도록 설정
- 중간 네트워크 장비에서 ICMP 차단
- 실제 네트워크 연결 문제

---

## 23. traceroute와 ICMP

`traceroute` 또는 `tracert` 명령어는 목적지까지 패킷이 거치는 라우터 경로를 확인할 때 사용한다.

- Windows: `tracert`
- macOS·Linux: `traceroute`

### 기본 원리

1. TTL을 1로 설정한 패킷을 전송한다.
2. 첫 번째 라우터에서 TTL이 0이 된다.
3. 첫 번째 라우터가 ICMP 시간 초과 메시지를 보낸다.
4. TTL을 2로 설정하여 다시 전송한다.
5. 두 번째 라우터가 ICMP 시간 초과 메시지를 보낸다.
6. TTL 값을 증가시키면서 목적지까지의 경로를 확인한다.

> traceroute의 구체적인 패킷 종류는 운영체제와 구현 방식에 따라 UDP, ICMP 또는 TCP를 사용할 수 있다.

---

## 24. ICMP의 한계

ICMP는 IP의 전송 특성을 보조하지만 IP를 완전히 신뢰성 있는 프로토콜로 만드는 것은 아니다.

ICMP가 제공하는 것:

- 일부 패킷 전달 실패 정보
- TTL 만료 정보
- 네트워크 진단 정보
- 목적지 도달 불가 정보

ICMP가 완전히 보장하지 않는 것:

- 모든 패킷의 정상 도착
- 손실된 모든 패킷의 재전송
- 패킷의 순서
- 중복 패킷 제거
- 데이터 흐름 제어
- 네트워크 혼잡 제어

따라서 다음과 같이 구분해야 한다.

> ICMP는 IP의 보조 프로토콜일 뿐, 신뢰성을 완전히 보장하지 않는다.

신뢰성 있는 통신이 필요하면 일반적으로 TCP와 같은 전송 계층 프로토콜을 사용한다.

# 정보처리기사 핵심 정리

1. 전송 계층은 네트워크 계층과 응용 계층 사이에 위치한다.
2. IP는 신뢰할 수 없는 비연결형 프로토콜이다.
3. TCP는 연결형이며 신뢰성 있는 통신을 제공한다.
4. UDP는 비연결형이며 TCP보다 구조가 단순하고 빠르다.
5. IP 주소는 호스트를 식별하고 포트 번호는 애플리케이션 프로세스를 식별한다.
6. 포트 번호는 16비트이며 범위는 `0~65535`이다.
7. 잘 알려진 포트의 범위는 `0~1023`이다.
8. 등록된 포트의 범위는 `1024~49151`이다.
9. 동적 포트의 범위는 `49152~65535`이다.
10. 서버는 주로 잘 알려진 포트나 등록된 포트를 사용한다.
11. 클라이언트는 주로 동적 포트를 임시로 사용한다.
12. FTP는 데이터 20번, 제어 21번 포트를 사용한다.
13. SSH는 22번, Telnet은 23번 포트를 사용한다.
14. DNS는 53번 포트를 사용한다.
15. DHCP 서버는 67번, DHCP 클라이언트는 68번 포트를 사용한다.
16. HTTP는 80번, HTTPS는 443번 포트를 사용한다.
17. MySQL은 3306번, PostgreSQL은 5432번 포트를 사용한다.
18. NAPT 또는 PAT는 IP 주소와 포트 번호를 함께 변환한다.
19. NAPT를 이용하면 여러 사설 IP 주소가 하나의 공인 IP 주소를 공유할 수 있다.
20. 포트 포워딩은 외부 포트로 들어온 패킷을 지정된 내부 호스트와 포트로 전달한다.
21. ICMP는 IP 패킷 전송 과정의 오류 보고와 네트워크 진단 정보를 제공한다.
22. ICMP 메시지는 타입과 코드로 구체적인 내용을 구분한다.
23. ICMP 타입 3은 목적지 도달 불가이다.
24. ICMP 타입 11은 시간 초과이다.
25. ICMP 타입 8은 에코 요청, 타입 0은 에코 응답이다.
26. ping은 일반적으로 ICMP 에코 요청과 에코 응답을 사용한다.
27. ICMP는 IP의 보조 프로토콜이며 신뢰성을 완전히 보장하지 않는다.

# 핵심 암기 문장

> IP 주소는 호스트를 찾고, 포트 번호는 호스트 안의 애플리케이션 프로세스를 찾는다.

> 포트 번호는 16비트이며 0번부터 65,535번까지 사용할 수 있다.

> 잘 알려진 포트는 0~1023, 등록된 포트는 1024~49151, 동적 포트는 49152~65535이다.

> TCP는 연결·신뢰성·재전송·순서 보장, UDP는 비연결·빠른 전송이다.

> NAPT는 IP 주소와 포트 번호를 함께 변환하여 여러 사설 IP 주소가 하나의 공인 IP 주소를 공유하게 한다.

> ICMP는 오류 보고와 네트워크 진단을 제공하지만 IP 통신의 신뢰성을 완전히 보장하지는 않는다.
