# 자바 메소드와 객체 생성 — 출처 노트

## 세 줄 요약

1. JVM 프로세스와 가상 메모리, static·인스턴스 상태의 차이를 복습했다.
2. 메소드 오버로딩, 인수 전달, 반환형과 `return`, 객체 생성과 생성자를 연결했다.
3. `Object`의 공통 메소드와 데이터 전달 객체인 DTO·`record`를 학습했다.

## 국비수업 연결

- 이전 [객체 생성자 캡슐화 학습 지도](</wiki/02%20%EC%A3%BC%EC%A0%9C/Java/%EA%B0%9D%EC%B2%B4%20%EC%83%9D%EC%84%B1%EC%9E%90%20%EC%BA%A1%EC%8A%90%ED%99%94%20%ED%95%99%EC%8A%B5%20%EC%A7%80%EB%8F%84>)의 생성자·this·캡슐화 내용을 확장한다.
- Spring MVC에서 요청·응답 DTO를 배울 때 [DTO와 record](</wiki/01%20%EA%B0%9C%EB%85%90/Java/DTO%EC%99%80%20record>)를 다시 연결한다.
- 상속과 오버라이딩 수업에서 [Object 클래스](</wiki/01%20%EA%B0%9C%EB%85%90/Java/Object%20%ED%81%B4%EB%9E%98%EC%8A%A4>)의 `equals`, `hashCode`, `toString`을 확장한다.

## 바로잡거나 주의할 내용

- JVM은 운영체제의 가상 주소 공간을 사용하지만, 그 안에서 힙과 GC 등 런타임 메모리를 JVM이 관리한다. `JVM은 물리 메모리를 전혀 관리하지 않는다`는 표현은 역할 구분을 위한 단순화다.
- `클래스 하나를 실행하면 JVM 프로세스 하나`로 고정해 외우지 않는다. 일반적인 `java MainClass` 실행은 새 JVM 프로세스를 시작하지만 하나의 JVM 안에서 많은 클래스를 로딩하고 여러 작업을 수행할 수 있다.
- 참조 변수는 Java 언어 관점의 참조값을 보관한다. 실제 물리 주소가 그대로 노출된다고 단정하지 않는다.
- 모든 클래스의 직접 부모가 항상 `Object`인 것은 아니다. 명시적 부모가 없으면 `Object`가 직접 부모가 되고, 다른 클래스를 상속하면 계층의 최상위가 `Object`다.
- `clone()`은 단순히 모든 객체가 자유롭게 복제할 수 있는 공개 API가 아니다. 접근 수준과 `Cloneable` 계약에 주의한다.
- record의 컴포넌트 재대입은 막히지만, 컴포넌트가 가변 객체를 참조하면 그 내부 상태까지 자동으로 깊은 불변이 되는 것은 아니다.
- DTO가 반드시 setter를 가져야 하는 것은 아니다. 생성자, 정적 팩토리, record 등 여러 방식으로 구성할 수 있다.
