# 정보처리기사 데이터 모델링과 정규화 — 출처 노트

## 세 줄 요약

1. 개념·논리·물리 데이터 모델링과 ER 모델, 관계 데이터 모델의 기본 용어를 학습했다.
2. 관계대수·관계해석, 키와 무결성 제약조건을 기출문제와 연결했다.
3. 이상 현상과 정규형, 반정규화, 인덱스와 뷰까지 데이터베이스 설계 흐름을 폭넓게 공부했다.

## 국비수업 및 다른 자격증 연결

- 앞으로 진행할 국비 데이터베이스·SQL 수업의 선행지식이다.
- SQLD의 데이터 모델링, 정규화, 키, 무결성 영역과 직접 겹친다.
- Spring/JPA에서 엔터티 관계, 기본키와 외래키를 배울 때 다시 연결한다.

## 바로잡거나 주의할 내용

- 네트워크 데이터 모델은 그래프 구조로 다대다 관계도 표현할 수 있다. `1:N만 허용`으로 외우지 않는다.
- 대체키는 기본키로 선택되지 않은 **후보키**다. 고객 이름이나 주소가 유일성과 최소성을 보장하지 않으면 후보키나 대체키가 아니다.
- 일반 집합 연산자는 합집합·교집합·차집합·카티션 프로덕트이고, 순수 관계 연산자는 셀렉트·프로젝트·조인·디비전이다.
- 프로젝트는 속성, 셀렉트는 조건에 맞는 튜플을 선택한다.
- 반정규화는 `성능에 중점을 두어 정규화`하는 것이 아니라 정규화 원칙을 의도적으로 일부 완화하는 설계다.
- 인덱스가 효과적인 결과 비율을 `10~15%`처럼 절대 기준으로 외우지 않는다. DBMS, 데이터 분포와 실행 계획에 따라 달라진다.
- `FORCE`, `NOFORCE` 등 뷰 옵션은 DBMS에 종속적이며 특히 Oracle 문맥인지 확인한다.
- 마지막 예상 문제는 문맥에 따라 클러스터링 또는 클러스터드 인덱스를 묻는 문제일 수 있어 원문 문제와 선택지 확인이 필요하다.
