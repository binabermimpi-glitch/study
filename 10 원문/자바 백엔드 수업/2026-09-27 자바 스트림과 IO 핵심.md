# 자바 스트림과 IO 핵심

## 금일 학습 요약

자바 정렬 알고리즘의 비교, 분할 방식과 데이터 교환 원리를 정리하고, 버블, 선택, 삽입, 셸, 퀵, 병합, 힙, 기수 정렬의 핵심 동작을 비교했습니다. 특히 최솟값과 최댓값을 찾는 순차 비교 방식이 `min`, `max`, `reduce` 연산의 내부 원리와 연결됨을 확인했습니다.

스트림 API에서는 기본형 스트림, 중간 연산과 최종 연산, `map`-`reduce` 파이프라인, 병렬 리듀스의 항등값, 누적 함수, 컴바이너를 다루었습니다. 이어서 `Collectors` 기반 수집과 자바 IO의 바이트, 문자, 객체 단위 처리, 버퍼, `try-with-resources`, 파일 입출력 구조를 살펴보았습니다.

## 1. 정렬 알고리즘과 값 교환

> 정렬은 데이터의 비교, 이동, 분할 방식을 선택하는 과정이며, 데이터 크기와 처리 특성에 따라 적합한 알고리즘이 달라집니다.

비교 정렬은 원소 간의 대소를 비교하여 위치를 변경하는 방식입니다. 최댓값, 최솟값, 중앙값과 같은 집계성 값을 구할 때도 비교 로직이 핵심이 되며, 배열 기반 정렬은 일반적으로 바깥 반복문과 안쪽 반복문을 조합하여 구현합니다.

정렬 방식은 데이터가 한 번에 모여 있는지, 지속적으로 유입되는지, 데이터 양이 작은지 큰지에 따라 달라집니다. 소량 데이터에서는 단순 비교 정렬이 구현하기 편리하고, 대량 데이터에서는 분할 후 병합하는 전략이 효율적일 수 있습니다.

| 알고리즘 | 핵심 방식 | 특징 |
|---|---|---|
| 버블 정렬 | 인접한 두 원소를 비교하여 큰 값을 뒤로 보냅니다. | 한 회전마다 가장 큰 값이 끝 위치에 확정됩니다. |
| 선택 정렬 | 남은 영역의 최솟값을 찾아 현재 위치와 교환합니다. | 최솟값의 위치를 인덱스로 관리합니다. |
| 삽입 정렬 | 기준값을 앞쪽의 정렬된 영역에 삽입합니다. | 큰 앞쪽 원소를 오른쪽으로 밀어 공간을 만듭니다. |
| 셸 정렬 | 큰 간격으로 먼저 정렬하고 간격을 줄입니다. | 삽입 정렬을 간격 단위로 확장한 방식입니다. |
| 퀵 정렬 | 피벗 기준으로 작은 값과 큰 값을 분할합니다. | 부분 배열에 같은 작업을 재귀적으로 적용합니다. |
| 병합 정렬 | 배열을 분할한 뒤 정렬된 부분 배열을 병합합니다. | 분할과 병합 단계를 반복합니다. |
| 힙 정렬 | 최대 힙의 루트값을 끝으로 이동합니다. | 이진 트리 기반 힙 구조를 활용합니다. |
| 기수 정렬 | 자릿수별 버킷에 분배한 뒤 수집합니다. | 원소끼리 직접 비교하지 않는 방식입니다. |

### 버블 정렬

버블 정렬은 인접 원소를 비교하여 큰 값을 오른쪽으로 이동시킵니다.

예를 들어 다음 데이터가 있다고 가정합니다.

```text
7, 3, 9, 1, 5
```

`7`과 `3`을 비교하여 교환하면 다음과 같이 됩니다.

```text
3, 7, 9, 1, 5
```

이러한 비교를 계속 반복하면서 큰 값을 오른쪽으로 이동시키고, 한 회전이 끝나면 가장 큰 값이 마지막 위치에 확정됩니다.

### 값 교환

값을 교환할 때는 기존 값을 보존할 임시 변수 `temp`가 필요합니다.

```java
int temp = arr[j];
arr[j] = arr[j + 1];
arr[j + 1] = temp;
```

예를 들어 다음 두 값이 있다고 가정합니다.

```text
arr[j]     = 7
arr[j + 1] = 3
```

먼저 `7`을 `temp`에 보관합니다.

```text
temp = 7
```

그다음 `arr[j]`에 `3`을 저장하고 마지막으로 `temp`에 보관했던 `7`을 `arr[j + 1]`에 저장합니다.

결과는 다음과 같습니다.

```text
3, 7
```

임시 변수 없이 바로 값을 덮어쓰면 기존 값 하나가 사라질 수 있기 때문에 `temp`를 사용합니다.

### 선택 정렬

선택 정렬은 현재 위치부터 마지막까지 탐색하여 **가장 작은 값의 위치**를 찾습니다.

최솟값 자체보다는 최솟값이 있는 **인덱스**를 기억해 두었다가 현재 위치의 값과 교환하는 방식입니다.

```text
현재 위치 결정
↓
남은 영역 탐색
↓
최솟값의 인덱스 발견
↓
현재 위치와 교환
```

### 삽입 정렬

삽입 정렬은 두 번째 원소부터 기준값으로 잡고 앞쪽의 정렬된 영역과 비교합니다.

앞쪽에 기준값보다 큰 값이 있다면 오른쪽으로 한 칸씩 이동시킵니다.

```text
정렬된 영역 | 기준값
            ↓
큰 값들을 오른쪽으로 이동
            ↓
빈 공간에 기준값 삽입
```

선택 정렬이 **최솟값을 찾아 교환하는 방식**이라면, 삽입 정렬은 **값들을 밀어낸 후 기준값을 적절한 위치에 삽입하는 방식**입니다.

### 퀵 정렬

퀵 정렬은 하나의 값을 `pivot`으로 선택하고 피벗을 기준으로 데이터를 나눕니다.

```text
pivot보다 작은 값 | pivot | pivot보다 큰 값
```

이렇게 나뉜 부분 배열에 다시 같은 작업을 적용하여 정렬합니다.

즉,

```text
분할 → 부분 배열 정렬 → 다시 분할
```

과정을 재귀적으로 반복합니다.

### 병합 정렬

병합 정렬은 배열을 절반씩 나눈 다음 다시 합치는 방식입니다.

```text
큰 배열
↓
절반으로 분할
↓
다시 절반으로 분할
↓
작은 단위까지 분할
↓
정렬하면서 병합
```

퀵 정렬이 **피벗을 기준으로 분할**한다면, 병합 정렬은 **배열을 절반씩 분할한 후 정렬하면서 다시 합치는 방식**입니다.

### 힙 정렬

힙 정렬은 이진 트리 기반의 힙 구조를 사용합니다.

최대 힙에서는 가장 큰 값이 루트에 위치합니다.

```text
        최댓값
       /      \
    작은 값   작은 값
```

루트의 최댓값을 배열 끝으로 이동한 후 남은 데이터로 다시 힙을 구성합니다.

이 과정을 반복하면 큰 값부터 배열 뒤쪽에 차례대로 위치하게 됩니다.

## 2. 기본형 스트림과 리듀스

> 기본형 스트림은 수치 데이터 처리에 특화된 스트림이며, 순차적으로 전달되는 요소를 변환, 비교, 누적하여 최종 결과를 생성합니다.

`IntStream`, `LongStream`, `DoubleStream`은 각각 `int`, `long`, `double` 데이터 처리에 특화된 스트림입니다.

객체 스트림을 사용할 때 발생할 수 있는 불필요한 박싱과 언박싱을 줄일 수 있으며, 합계, 평균, 최솟값, 최댓값 같은 수치 연산을 간결하게 제공합니다.

### 스트림 종류

일반 객체와 기타 타입은 다음과 같이 처리합니다.

```java
Stream<T>
```

정수형 데이터는 다음과 같이 처리합니다.

```java
IntStream
```

긴 정수형 데이터는 다음과 같이 처리합니다.

```java
LongStream
```

실수형 데이터는 다음과 같이 처리합니다.

```java
DoubleStream
```

스트림은 컬렉션 데이터를 연산하기 위한 파이프라인으로 생각할 수 있습니다.

```text
데이터
↓
스트림 생성
↓
중간 연산
↓
중간 연산
↓
최종 연산
↓
결과
```

중간 연산은 요소를 변환하거나 걸러낸 뒤 다음 단계로 전달합니다.

대표적으로 다음과 같은 연산이 있습니다.

```java
filter()
map()
sorted()
distinct()
flatMap()
```

최종 연산은 스트림 파이프라인을 실제로 실행하고 결과를 생성합니다.

대표적으로 다음과 같은 연산이 있습니다.

```java
forEach()
count()
min()
max()
reduce()
collect()
```

### min()과 max()

`min()`과 `max()`는 모든 요소를 한 번에 비교하는 것이 아닙니다.

현재까지 선택된 값과 다음 값을 계속 비교합니다.

예를 들어 다음 데이터에서 최솟값을 찾는다고 가정합니다.

```text
7, 3, 9, 1, 5
```

처리 과정은 다음과 같이 생각할 수 있습니다.

```text
7과 3 비교 → 3 유지
3과 9 비교 → 3 유지
3과 1 비교 → 1 유지
1과 5 비교 → 1 유지

최솟값 = 1
```

`max()`는 반대로 더 큰 값을 계속 유지합니다.

```java
int min = IntStream.of(7, 3, 9, 1, 5)
    .min()
    .orElseThrow();

int max = IntStream.of(7, 3, 9, 1, 5)
    .max()
    .orElseThrow();
```

`min()`과 `max()`는 스트림에 값이 하나도 없을 가능성이 있기 때문에 `OptionalInt`를 반환합니다.

```java
OptionalInt
```

`orElseThrow()`는 값이 존재하면 내부 값을 꺼내 반환하고, 값이 없으면 예외를 발생시킵니다.

### reduce()

`reduce()`는 여러 개의 요소를 **하나의 결과로 줄이는 최종 연산**입니다.

예를 들어 다음 숫자가 있다고 가정합니다.

```text
1, 2, 3, 4
```

합계를 구하면 다음과 같은 누적 과정이 발생합니다.

```text
0 + 1 = 1
1 + 2 = 3
3 + 3 = 6
6 + 4 = 10
```

즉 이전 계산 결과가 다음 계산의 입력으로 다시 사용됩니다.

```java
int result = IntStream.of(7, 3, 9, 1, 5)
    .map(n -> n * 2)
    .reduce(0, Integer::sum);
```

먼저 `map()`이 실행되면 다음과 같이 변환됩니다.

```text
7 → 14
3 → 6
9 → 18
1 → 2
5 → 10
```

따라서 스트림은 다음과 같습니다.

```text
14, 6, 18, 2, 10
```

이후 `reduce()`가 누적합니다.

```text
0 + 14 = 14
14 + 6 = 20
20 + 18 = 38
38 + 2 = 40
40 + 10 = 50
```

최종 결과는 다음과 같습니다.

```text
50
```

## 3. 병렬 리듀스와 collect()

> 병렬 리듀스는 분할된 부분 결과를 누적 함수와 컴바이너로 결합하며, `collect()`는 가변 컨테이너에 데이터를 목적별로 수집합니다.

`reduce()`를 이해할 때 중요한 구성 요소는 다음 세 가지입니다.

| 구성 요소 | 역할 | 합계 예시 |
|---|---|---|
| 항등값 | 연산 시작값과 빈 스트림의 기본 결과를 제공합니다. | `0` |
| 누적 함수 | 현재 누적값과 다음 요소를 결합합니다. | `Integer::sum` |
| 컴바이너 | 병렬 처리된 부분 결과를 최종 결합합니다. | `Integer::sum` |

### 항등값

항등값은 연산 결과를 바꾸지 않는 값입니다.

덧셈에서는 다음과 같습니다.

```text
10 + 0 = 10
```

따라서 덧셈의 항등값은 `0`입니다.

곱셈에서는 다음과 같습니다.

```text
10 × 1 = 10
```

따라서 곱셈의 항등값은 `1`입니다.

### 누적 함수

누적 함수는 현재까지 계산한 결과와 다음 요소를 결합합니다.

```text
현재 누적값 + 다음 값 → 새로운 누적값
```

예를 들어 다음과 같습니다.

```text
0 + 1 = 1
1 + 2 = 3
3 + 3 = 6
6 + 4 = 10
```

### 컴바이너

컴바이너는 병렬 처리에서 만들어진 **부분 결과끼리 결합**합니다.

```java
int sum = Stream.of(1, 2, 3, 4)
    .parallel()
    .reduce(0, Integer::sum, Integer::sum);
```

개념적으로는 다음과 같이 생각할 수 있습니다.

```text
1, 2, 3, 4

↓ 분할

[1, 2]    [3, 4]

↓ 각각 누적

3          7

↓ 컴바이너

3 + 7

↓

10
```

실제로 데이터가 정확히 두 덩어리로 나뉜다는 의미는 아닙니다. 병렬 스트림의 실제 분할 방식은 데이터 구조와 실행 환경 등에 따라 달라질 수 있습니다.

따라서 중요한 것은 다음 흐름입니다.

```text
데이터 분할
→ 각 부분에서 누적
→ 부분 결과 생성
→ 컴바이너가 부분 결과 결합
→ 최종 결과
```

작은 데이터나 단순한 연산에서는 병렬 처리 준비와 결과 결합 비용이 실제 계산 비용보다 더 커질 수 있으므로 무조건 병렬 스트림이 빠른 것은 아닙니다.

## 4. collect()와 Collectors

`collect()`는 스트림 요소를 하나의 자료구조나 결과 컨테이너에 모으는 최종 연산입니다.

`reduce()`와 `collect()`의 차이를 간단하게 생각하면 다음과 같습니다.

```text
reduce()
여러 값 → 하나의 값

collect()
여러 값 → List, Set, Map 등의 결과
```

예를 들어 학생 객체에서 이름만 추출하여 리스트로 만들 수 있습니다.

```java
List<String> names = students.stream()
    .map(Student::name)
    .collect(Collectors.toList());
```

처리 과정은 다음과 같습니다.

```text
Student 객체들
↓
map(Student::name)
↓
학생 이름들
↓
Collectors.toList()
↓
List<String>
```

중복 없는 부서 목록을 만들고 싶다면 `Set`으로 수집할 수 있습니다.

```java
Set<String> departments = students.stream()
    .map(Student::department)
    .collect(Collectors.toSet());
```

`List`는 순서와 중복을 유지할 수 있고, `Set`은 중복 값을 허용하지 않습니다.

### 주요 Collector

| Collector | 수집 결과 | 활용 목적 |
|---|---|---|
| `joining()` | 문자열 | 여러 문자열을 하나로 연결합니다. |
| `toMap()` | `Map` | 키와 값 형태의 데이터를 만듭니다. |
| `groupingBy()` | 그룹별 `Map` | 특정 기준으로 객체를 묶습니다. |
| `partitioningBy()` | `Map<Boolean, ...>` | 조건에 따라 `true`, `false` 두 그룹으로 나눕니다. |

### groupingBy()

`groupingBy()`는 특정 기준에 따라 데이터를 그룹으로 묶습니다.

예를 들어 학생들을 도시별로 묶는다면 다음과 같은 형태가 됩니다.

```text
서울 → 학생A, 학생B
부산 → 학생C
인천 → 학생D, 학생E
```

다운스트림 컬렉터를 함께 사용하면 그룹별 평균이나 합계도 계산할 수 있습니다.

```java
Map<String, Double> averageByCity = students.stream()
    .collect(Collectors.groupingBy(
        Student::city,
        Collectors.averagingInt(Student::score)
    ));
```

처리 흐름은 다음과 같습니다.

```text
학생 객체
↓
도시 기준으로 그룹화
↓
같은 도시의 학생 점수 수집
↓
평균 계산
↓
Map<String, Double>
```

### partitioningBy()

`partitioningBy()`는 `Predicate`의 결과에 따라 데이터를 두 그룹으로 나눕니다.

예를 들어 점수가 80점 이상인지 확인하면 다음과 같이 나뉠 수 있습니다.

```text
true  → 80점 이상 학생
false → 80점 미만 학생
```

따라서 `groupingBy()`가 여러 종류의 그룹으로 나눌 수 있는 것과 달리 `partitioningBy()`는 항상 `true`, `false`를 기준으로 두 그룹으로 나눕니다.

### flatMap()

`flatMap()`은 중첩된 구조를 하나의 스트림으로 평탄화합니다.

예를 들어 다음과 같은 구조가 있다고 가정합니다.

```text
[[1, 2], [3, 4], [5, 6]]
```

`flatMap()`을 사용하면 다음과 같이 만들 수 있습니다.

```text
1, 2, 3, 4, 5, 6
```

즉,

```text
여러 개의 내부 스트림
→ 하나의 스트림
```

으로 만드는 역할을 합니다.

### mapMulti()

`mapMulti()`는 하나의 요소를 처리하면서 조건에 따라 0개, 1개 또는 여러 개의 결과를 다음 단계로 전달할 수 있습니다.

따라서 조건부 변환과 필터링을 함께 처리할 때 활용할 수 있습니다.

### anyMatch(), allMatch(), noneMatch()

이 메서드들은 조건을 검사하고 `boolean` 결과를 반환하는 최종 연산입니다.

```text
anyMatch()
→ 하나라도 조건을 만족하는가?

allMatch()
→ 모든 요소가 조건을 만족하는가?

noneMatch()
→ 조건을 만족하는 요소가 하나도 없는가?
```

이들은 결과가 확정되는 순간 나머지 요소를 검사하지 않을 수 있습니다.

예를 들어 `anyMatch()`에서 첫 번째 요소가 이미 조건을 만족한다면 뒤의 모든 요소를 확인할 필요가 없습니다.

## 5. 자바 IO와 파일 처리

> 자바 IO는 바이트, 문자, 객체 단위로 데이터를 읽고 쓰며, 처리 대상과 데이터 특성에 따라 스트림, 버퍼, 파일 시스템 API를 선택합니다.

자바 입출력은 크게 바이트 단위, 문자 단위, 객체 단위 처리로 구분할 수 있습니다.

파일, 네트워크, 채팅, 이미지, 동영상 등 데이터를 전달하는 작업은 입출력 처리와 연결됩니다.

| 처리 단위 | 대표 클래스 | 적합한 데이터 |
|---|---|---|
| 바이트 단위 | `InputStream`, `OutputStream` | 이미지, 음성, 영상, 바이너리 파일 |
| 문자 단위 | `Reader`, `Writer` | 텍스트 파일과 문자열 데이터 |
| 객체 단위 | `ObjectInputStream`, `ObjectOutputStream` | 직렬화 가능한 객체 데이터 |

### 바이트 스트림

바이트 스트림은 바이너리 데이터를 처리하는 기본 스트림입니다.

대표적인 클래스는 다음과 같습니다.

```text
InputStream
OutputStream
```

파일을 대상으로 사용할 때는 다음 클래스를 사용할 수 있습니다.

```text
FileInputStream
FileOutputStream
```

`FileInputStream`은 파일의 데이터를 바이트 단위로 읽습니다.

`FileOutputStream`은 파일에 바이트 데이터를 씁니다.

이미지, 음성, 영상처럼 원본 바이트가 중요한 데이터 처리에 사용할 수 있습니다.

### FileOutputStream

```java
try (FileOutputStream out = new FileOutputStream("a.txt")) {
    out.write(100);
    out.write(97);
    out.write(98);
}
```

`write(int)`는 정수 전체를 파일에 저장하는 것이 아니라 하위 1바이트를 출력합니다.

기본적으로 기존 파일이 존재하면 내용을 덮어씁니다.

기존 파일 뒤에 내용을 추가하고 싶다면 두 번째 인수에 `true`를 전달합니다.

```java
try (FileOutputStream out = new FileOutputStream("a.txt", true)) {
    out.write(100);
}
```

```text
false 또는 생략 → 기존 내용 덮어쓰기
true            → 기존 내용 뒤에 추가
```

### FileInputStream

바이트 스트림의 `read()`는 읽은 데이터를 `int`로 반환합니다.

```java
int data = in.read();
```

여기서 반환형이 `int`인 중요한 이유 중 하나는 실제 바이트 값뿐만 아니라 **파일의 끝을 나타내는 `-1`도 표현해야 하기 때문**입니다.

따라서 파일을 끝까지 읽을 때 다음 패턴을 많이 사용합니다.

```java
try (FileInputStream in = new FileInputStream("a.txt")) {

    int data;

    while ((data = in.read()) != -1) {
        System.out.print((char) data);
    }
}
```

처리 흐름은 다음과 같습니다.

```text
read()
↓
데이터 존재
↓
int 값 반환
↓
처리
↓
다시 read()

...

데이터 없음
↓
-1 반환
↓
반복 종료
```

## 6. 문자 스트림

문자 스트림은 텍스트 데이터를 처리할 때 사용합니다.

대표적인 클래스는 다음과 같습니다.

```text
Reader
Writer
```

파일을 문자 단위로 처리할 때는 `FileReader`, `FileWriter` 등을 사용할 수 있습니다.

텍스트 처리에서는 문자 인코딩도 중요합니다.

운영체제나 실행 환경에 따라 기본 인코딩이 달라질 수 있으므로 필요한 경우 UTF-8 등의 인코딩을 명시하는 것이 안전합니다.

문자 스트림에서는 다음과 같은 클래스도 자주 사용됩니다.

```text
BufferedReader
BufferedWriter
```

`BufferedReader`는 문자 데이터를 버퍼에 모아 효율적으로 읽을 수 있게 해줍니다.

특히 다음 메서드를 이용하여 한 줄씩 읽을 수 있습니다.

```java
readLine()
```

`BufferedWriter`에서는 플랫폼에 맞는 줄바꿈을 위해 다음 메서드를 사용할 수 있습니다.

```java
newLine()
```

## 7. 버퍼

버퍼는 데이터를 바로바로 처리하지 않고 **임시 메모리 공간에 일정량 모아두었다가 처리하는 구조**입니다.

예를 들어 데이터가 하나씩 들어올 때마다 매번 외부 장치와 입출력을 수행하면 많은 입출력 작업이 발생할 수 있습니다.

```text
데이터 → 바로 출력
데이터 → 바로 출력
데이터 → 바로 출력
데이터 → 바로 출력
```

버퍼를 사용하면 다음과 같이 처리할 수 있습니다.

```text
데이터
데이터
데이터
데이터
↓
버퍼에 저장
↓
한꺼번에 처리
```

이를 통해 입출력 횟수를 줄여 성능을 향상시킬 수 있습니다.

### flush()

`flush()`는 출력 버퍼에 남아 있는 데이터를 실제 출력 대상으로 밀어내는 역할을 합니다.

```text
프로그램
↓
버퍼
↓ flush()
파일 / 네트워크 등의 출력 대상
```

`close()`가 호출될 때 일반적으로 남아 있는 출력 데이터도 처리되지만, 스트림을 닫기 전에 즉시 데이터를 전달해야 하는 상황에서는 `flush()`가 중요할 수 있습니다.

## 8. IO, NIO, NIO.2

자바의 파일 및 데이터 입출력 방식은 크게 다음과 같이 구분해서 볼 수 있습니다.

| 구분 | 중심 개념 | 주요 용도 |
|---|---|---|
| IO | 스트림 | 순차적인 데이터 입출력 |
| NIO | 버퍼와 채널 | 버퍼 중심의 효율적인 데이터 처리 |
| NIO.2 | `Path`, `Files` | 파일 및 파일 시스템 관리 |

### IO

IO는 스트림 중심으로 데이터를 처리합니다.

```text
입력 → InputStream / Reader
출력 → OutputStream / Writer
```

데이터가 순차적으로 흘러가는 구조로 이해하면 됩니다.

### NIO

NIO는 `Channel`과 `Buffer`를 중심으로 데이터를 처리합니다.

```text
파일
↕
Channel
↕
Buffer
↕
프로그램
```

스트림 기반 IO와 달리 버퍼를 중심으로 데이터를 읽고 쓰는 구조를 사용합니다.

### NIO.2

NIO.2에서는 파일과 경로 작업을 위한 `Path`, `Files` API가 중요합니다.

```java
Path
Files
```

이를 이용하여 다음과 같은 작업을 수행할 수 있습니다.

```text
파일 생성
파일 복사
파일 이동
파일 삭제
디렉터리 탐색
파일 존재 여부 확인
파일 정보 확인
```

## 9. try-with-resources

파일이나 스트림 같은 자원은 사용이 끝난 후 반드시 닫아야 합니다.

기존에는 다음과 같이 직접 `close()`를 호출해야 했습니다.

```java
FileInputStream in = null;

try {
    in = new FileInputStream("a.txt");

} finally {

    if (in != null) {
        in.close();
    }
}
```

이 방식은 코드가 길어지고 자원을 닫는 코드를 직접 관리해야 합니다.

`try-with-resources`를 사용하면 다음처럼 작성할 수 있습니다.

```java
try (FileInputStream in = new FileInputStream("a.txt")) {

    // 파일 읽기

}
```

`try` 블록이 끝나면 자원이 자동으로 닫힙니다.

이 기능을 사용할 수 있는 객체는 기본적으로 `AutoCloseable`을 구현해야 합니다.

개념적으로 다음과 같이 이해할 수 있습니다.

```text
자원 생성
↓
try 블록에서 사용
↓
try 블록 종료
↓
자동 close()
```

따라서 파일이나 스트림을 다룰 때는 `try-with-resources`를 적극적으로 사용하는 것이 좋습니다.

## 10. 파일 입출력과 예외

파일을 읽거나 쓰는 작업에서는 여러 문제가 발생할 수 있습니다.

예를 들어 다음과 같은 상황입니다.

```text
파일이 존재하지 않음
파일을 읽을 권한이 없음
파일을 쓰지 못함
입출력 도중 오류 발생
```

대표적인 예외는 다음과 같습니다.

```java
FileNotFoundException
IOException
```

이들은 검사 예외이므로 컴파일 단계에서 예외 처리가 요구됩니다.

방법은 크게 두 가지입니다.

### 직접 처리

```java
try {

    // 파일 작업

} catch (IOException e) {

    // 예외 처리

}
```

### 호출한 곳으로 위임

```java
public static void readFile() throws IOException {

    // 파일 작업

}
```

따라서 IO 코드를 볼 때는 다음 흐름을 함께 생각하는 것이 중요합니다.

```text
파일/네트워크 등의 외부 데이터
        ↓
입력 또는 출력 스트림
        ↓
필요하면 버퍼 사용
        ↓
데이터 읽기/쓰기
        ↓
예외 처리
        ↓
자원 close
```

`try-with-resources`를 사용하면 마지막 자원 해제 과정은 자동으로 처리할 수 있습니다.
