# 자바 배열과 객체지향 핵심

## 금일 학습 요약

배열의 선언, 생성, 초기화 과정과 참조 변수의 `null` 상태를 메모리 관점에서 정리했습니다. 인덱스와 `length`의 관계, 일반 `for`문과 향상된 `for-each`문의 목적 차이, `Arrays.toString()` 및 `System.arraycopy()`를 활용한 배열 처리도 함께 다루었습니다.

또한 배열이 객체라는 특성을 바탕으로 `Object` 타입으로 다양한 배열을 전달하고, `getClass()`와 `instanceof`로 타입을 판별하는 방법을 확인했습니다. 이어서 객체 배열의 얕은 복사와 깊은 복사, 상속, 오버라이딩, 다형성, 추상화, 캡슐화 등 객체지향 프로그래밍의 핵심 원리를 연결했습니다.

## 배열 선언과 초기화

> 배열은 동일한 자료형의 여러 값을 하나의 이름으로 관리하는 객체이며, 요소는 0부터 시작하는 인덱스로 접근합니다.

배열 변수는 배열 객체 자체가 아니라 배열의 시작 주소를 보관하는 참조 변수입니다. 따라서 배열을 선언만 한 상태와 `new` 연산자로 배열 객체를 생성한 상태는 구분해야 합니다.

참조 타입 변수는 객체 주소를 대입받기 전 `null` 상태를 가집니다. `null`은 참조 대상이 없다는 의미이며, 아직 특정 객체나 배열을 참조하지 않는 상태를 나타냅니다.

```java
int[] ar;           // 참조 변수 선언
ar = new int[5];    // 길이가 5인 배열 객체 생성 및 주소 대입
```

`new int[5]`처럼 크기만 지정해 생성한 정수 배열은 각 요소가 기본값인 `0`으로 초기화됩니다. 반면, 배열 리터럴을 사용하면 배열 생성과 값 초기화를 한 번에 수행할 수 있습니다.

| 선언 방식 | 의미 | 초기 요소값 |
|---|---|---|
| `int[] ar;` | 배열 참조 변수만 선언합니다. | 참조 대상이 없습니다. |
| `ar = new int[5];` | 길이가 5인 정수 배열을 생성합니다. | 모든 요소가 `0`입니다. |
| `int[] ar = {10, 20, 30};` | 배열 생성과 초기화를 동시에 수행합니다. | 지정한 값으로 초기화됩니다. |
| `ar = new int[]{10, 20, 30};` | 기존 참조 변수에 새 배열 주소를 재대입합니다. | 지정한 값으로 초기화됩니다. |

배열 리터럴인 `{10, 20, 30}`은 선언과 동시에 초기화할 때 사용하는 문법입니다. 이미 선언된 배열 변수에 단독으로 배열 리터럴을 대입할 수는 없으며, 이 경우에는 반드시 `new 자료형[]{...}` 형태를 사용해야 합니다.

```java
int[] ar = {10, 20, 30};

// ar = {40, 50, 60};       // 컴파일 오류입니다.
ar = new int[]{40, 50, 60}; // 새 배열을 생성하여 주소를 재대입합니다.
```

배열의 각 요소는 인덱스로 접근하며, 배열의 유효 인덱스 범위는 `0`부터 `length - 1`까지입니다. 배열의 요소 개수와 마지막 인덱스는 항상 1 차이가 납니다.

### 핵심 키워드
`배열` `참조 변수` `null` `new` `length`

## 배열 순회와 유틸리티

> 일반 `for`문은 인덱스 제어가 필요한 순회에 적합하고, 향상된 `for-each`문은 모든 요소를 순서대로 읽는 작업에 적합합니다.

배열의 요소를 직접 출력할 때는 각 인덱스를 명시할 수 있지만, 데이터 수가 많아지면 반복문을 이용하는 편이 효율적입니다. 특히 외부 입력처럼 배열 크기가 가변적인 경우에는 고정 숫자 대신 `length`를 기준으로 반복해야 합니다.

```java
int[] score = {90, 80, 100, 70, 85};

for (int i = 0; i < score.length; i++) {
    System.out.println(score[i]);
}
```

일반 `for`문은 인덱스를 직접 제어할 수 있으므로 역순 출력, 홀수, 짝수 인덱스 선택, 특정 구간 순회와 같은 작업에 적합합니다. 반복 변수 `i`는 `for` 블록 내부에서만 유효한 지역 변수입니다.

향상된 `for-each`문은 배열의 처음부터 끝까지 모든 요소를 순차적으로 읽을 때 사용할 수 있습니다. 요소 자체를 변수로 전달받으므로 인덱스 연산이 필요하지 않은 단순 출력에 간결합니다.

```java
for (int value : score) {
    System.out.println(value);
}
```

`for-each`문의 반복 변수는 매 반복마다 현재 요소의 값을 받는 지역 변수입니다. 따라서 요소의 위치를 기준으로 조건을 적용하거나 특정 인덱스의 값을 변경해야 한다면 일반 `for`문을 선택해야 합니다.

`java.util.Arrays` 클래스는 배열을 문자열로 변환하거나 비교, 복사, 정렬하는 정적 메서드를 제공합니다. `Arrays.toString()`은 1차원 배열 전체를 사람이 읽기 쉬운 문자열 형태로 반환합니다.

```java
import java.util.Arrays;

int[] score = {90, 80, 100, 70, 85};

System.out.println(Arrays.toString(score));
score[1] = 95;
System.out.println(Arrays.toString(score));
```

배열의 내용을 다른 배열로 복사할 때는 `System.arraycopy()`를 사용할 수 있습니다. 이 메서드는 원본 배열, 원본 시작 인덱스, 대상 배열, 대상 시작 인덱스, 복사 길이를 인자로 받습니다.

```java
int[] src = {1, 2, 3, 4, 5};
int[] dst = new int[5];

System.arraycopy(src, 0, dst, 0, src.length);
```

배열 복사 시 원본과 대상 배열의 범위가 유효해야 하며, 참조값이 `null`이면 `NullPointerException`이 발생할 수 있습니다. API 문서에서는 매개변수와 반환 타입뿐 아니라 예외 조건도 함께 확인해야 합니다.

### 핵심 키워드
`for` `for-each` `인덱스` `Arrays.toString` `System.arraycopy`

## 배열 객체와 타입 판별

> 배열은 객체이므로 `Object` 타입으로 전달할 수 있으며, 실제 배열 타입은 `instanceof` 또는 `getClass()`로 확인할 수 있습니다.

자바의 배열은 기본형 요소를 저장하더라도 배열 자체는 객체입니다. 따라서 `int[]`, `double[]`, `String[]` 같은 서로 다른 배열 객체를 `Object` 타입의 매개변수로 전달할 수 있습니다.

```java
static void myPrint(Object obj) {
    if (obj instanceof int[] ar) {
        for (int value : ar) {
            System.out.println(value);
        }
    }
}
```

`instanceof`는 특정 객체가 지정한 타입으로 활용 가능한지 판별하며, 결과는 `boolean`입니다. 상속 관계까지 고려하므로 다형성 기반의 타입 검사에 적합합니다.

`getClass()`는 실행 시점의 실제 객체 타입을 `Class` 객체로 반환합니다. `getName()`은 패키지를 포함한 전체 클래스 이름을, `getSimpleName()`은 클래스의 단순 이름을 반환합니다.

| 기능 | 목적 | 반환 특성 |
|---|---|---|
| `obj instanceof String` | 객체가 특정 타입과 호환되는지 확인합니다. | `boolean`을 반환합니다. |
| `obj.getClass()` | 실제 생성된 객체의 클래스 정보를 확인합니다. | `Class` 객체를 반환합니다. |
| `getClass().getName()` | 패키지명을 포함한 타입명을 확인합니다. | 전체 타입명을 반환합니다. |
| `getClass().getSimpleName()` | 간단한 클래스 이름을 확인합니다. | 클래스명만 반환합니다. |

`getClass()`는 실제 타입을 정확히 확인하는 데 사용되며, `instanceof`는 해당 객체가 특정 상위 타입 또는 인터페이스로 취급 가능한지를 확인하는 데 사용됩니다. 두 기능은 모두 타입과 관련 있지만 판별 목적이 다릅니다.

```java
Object value = Arrays.toString(new int[]{10, 20, 30});

System.out.println(value.getClass().getName());
System.out.println(value instanceof String);
```

`Arrays.toString()`의 반환 타입은 `String`입니다. 배열을 문자열로 변환하면 로그 출력, 파일 저장, 데이터베이스 전송, 구분자 기반 데이터 분리 등 문자열 중심의 데이터 처리 흐름에 활용할 수 있습니다.

패턴 매칭 `switch`를 사용하면 여러 배열 타입을 분기할 수도 있습니다. 객체 참조는 `null`일 수 있으므로 `case null`을 명시적으로 처리하는 것이 안전합니다.

```java
switch (obj) {
    case int[] ar -> System.out.println(Arrays.toString(ar));
    case double[] ar -> System.out.println(Arrays.toString(ar));
    case String[] ar -> System.out.println(Arrays.toString(ar));
    case null -> System.out.println("참조 대상이 없습니다.");
    default -> System.out.println("지원하지 않는 타입입니다.");
}
```

### 핵심 키워드
`Object` `instanceof` `getClass` `패턴 매칭` `업캐스팅`

## 객체 배열의 복사 방식

> 객체 배열을 `clone()`으로 복사하면 배열 컨테이너는 새로 생성되지만, 내부 객체 참조는 공유될 수 있으므로 얕은 복사가 발생할 수 있습니다.

배열 자체를 복사하면 원본 배열과 복사 배열은 서로 다른 배열 객체가 됩니다. 그러나 배열의 요소가 `Person`처럼 객체 참조라면, 단순 복사는 내부 객체까지 새로 생성하지 않을 수 있습니다.

```java
Person[] original = {
    new Person("홍길동", 10),
    new Person("김선달", 24)
};

Person[] copy = original.clone();
```

위 코드에서 `original`과 `copy`는 서로 다른 배열 객체입니다. 하지만 `original[0]`과 `copy[0]`은 동일한 `Person` 객체를 참조할 수 있으므로, 한 배열을 통해 객체 상태를 변경하면 다른 배열에서도 변경 결과가 보입니다.

| 구분 | 배열 객체 | 배열 내부 객체 |
|---|---|---|
| 얕은 복사 | 새로운 배열 객체를 생성합니다. | 기존 객체의 주소를 공유합니다. |
| 깊은 복사 | 새로운 배열 객체를 생성합니다. | 각 요소 객체도 새로 생성합니다. |
| 방어적 복사 | 외부 변경을 막기 위한 복사본을 사용합니다. | 객체 상태 보호가 목적입니다. |

깊은 복사는 배열을 새로 만든 뒤, 각 인덱스의 객체도 생성자를 통해 다시 만드는 방식으로 구현할 수 있습니다. 이때 원본 객체의 필드값을 사용해 새 객체를 구성하므로, 원본과 복사본의 내부 객체가 분리됩니다.

```java
Person[] copy = new Person[original.length];

for (int i = 0; i < original.length; i++) {
    copy[i] = new Person(
        original[i].getName(),
        original[i].getAge()
    );
}
```

방어적 복사는 얕은 복사와 깊은 복사처럼 단순한 복사 결과의 분류가 아니라 객체 설계 전략입니다. 외부 코드가 내부 배열이나 가변 객체를 직접 변경하지 못하도록 복사본을 저장하거나 반환하여 객체의 상태를 보호합니다.

### 핵심 키워드
`얕은 복사` `깊은 복사` `clone` `객체 배열` `방어적 복사`

## 상속과 다형성

> 상속은 공통 기능을 부모 클래스에 정의하고 자식 클래스가 이를 재사용, 확장하는 구조이며, 다형성은 부모 타입 참조로 여러 자식 객체를 다루는 방식입니다.

자바의 모든 클래스는 명시하지 않아도 기본적으로 `Object` 클래스를 상속합니다. 사용자 정의 클래스 역시 `Object`의 자식이며, 필요에 따라 다른 클래스를 상속해 공통 속성과 기능을 재사용할 수 있습니다.

```java
public class Person {
    private String name;
    private int age;
}

public class Student extends Person {
    private String school;
}
```

자식 객체를 생성하면 부모 객체 영역이 먼저 초기화된 뒤 자식 객체 영역이 초기화됩니다. 자식 생성자에서 부모 생성자를 명시하지 않으면 컴파일러는 기본적으로 `super()`를 삽입합니다.

| 키워드 | 의미 | 주요 사용 위치 |
|---|---|---|
| `this` | 현재 객체 자신을 가리킵니다. | 현재 필드 및 생성자 호출에 사용합니다. |
| `super` | 부모 객체 또는 부모 멤버를 가리킵니다. | 부모 메서드와 필드 접근에 사용합니다. |
| `super()` | 부모 생성자를 호출합니다. | 자식 생성자의 첫 실행 문장에 사용합니다. |
| `extends` | 특정 클래스를 상속함을 선언합니다. | 클래스 선언부에 사용합니다. |

부모 클래스의 `private` 필드는 자식 클래스가 직접 접근할 수 없습니다. 이는 캡슐화와 정보 은닉을 위한 제약이며, 자식 클래스는 부모가 제공하는 `public` 또는 `protected` 메서드를 통해 필요한 값에 접근해야 합니다.

메서드 오버라이딩은 부모에게서 상속받은 메서드를 자식 클래스의 목적에 맞게 재정의하는 기능입니다. 메서드 이름과 매개변수 형태는 유지하지만 실행 내용은 자식 클래스에서 변경합니다.

```java
@Override
public String personInfo() {
    return super.personInfo() + "\t학교: " + school;
}
```

부모 타입 변수에는 자식 객체를 대입할 수 있습니다. 이를 업캐스팅이라고 하며, 부모 타입으로 선언된 참조 변수는 부모에 선언된 멤버만 직접 접근할 수 있습니다.

```java
Person person = new Student();
person.personInfo();
```

컴파일 시점에는 변수의 선언 타입을 기준으로 접근 가능 여부를 확인합니다. 반면 오버라이딩된 메서드 호출은 실행 시점의 실제 객체 타입을 기준으로 결정되며, 이를 동적 바인딩이라고 합니다.

형제 관계의 클래스끼리는 직접 형변환할 수 없습니다. 공통 부모를 가졌더라도 실제 객체가 해당 자식 타입이 아니라면 런타임에 `ClassCastException`이 발생합니다.

### 핵심 키워드
`상속` `오버라이딩` `업캐스팅` `동적 바인딩` `ClassCastException`

## 추상화와 캡슐화

> 추상 클래스는 공통 구조와 기본 기능을 제공하며, 추상 메서드는 자식 클래스가 구체적인 동작을 구현하도록 강제합니다.

추상화는 여러 객체에 공통으로 존재하는 특성을 상위 개념으로 묶는 과정입니다. 예를 들어 자동차의 공통 기능을 `Car`에 정의하고, SUV, 트럭, 버스 같은 구체 클래스가 이를 상속받아 확장할 수 있습니다.

`abstract` 클래스를 사용하면 객체를 직접 생성할 수 없으며, 공통 기능을 제공하는 상위 설계 역할을 수행합니다. 추상 클래스는 일반 메서드와 추상 메서드를 함께 가질 수 있습니다.

```java
public abstract class Animal {
    public abstract void bark();

    public void eat(String feed) {
        System.out.println(feed + "을 먹습니다.");
    }
}
```

추상 메서드는 메서드 본문이 없는 선언이며, 이를 상속받는 구체 클래스는 반드시 메서드를 오버라이딩해야 합니다. 구현하지 않으려면 자식 클래스도 다시 추상 클래스로 선언해야 합니다.

```java
public class Cat extends Animal {
    @Override
    public void bark() {
        System.out.println("야옹");
    }
}
```

캡슐화는 객체의 내부 상태를 직접 노출하지 않고, 제한된 메서드를 통해 접근하도록 설계하는 방식입니다. 일반적으로 필드는 `private`으로 선언하고, 필요한 경우 게터와 세터를 제공합니다.

```java
private int age;

public void setAge(int age) {
    this.age = age >= 0 ? age : 0;
}
```

세터 메서드는 외부에서 전달된 값을 검증하고 필터링할 수 있습니다. 따라서 잘못된 값이 객체 내부 상태에 저장되는 것을 방지하며, 데이터 무결성과 일관성을 유지하는 데 도움이 됩니다.

객체지향 프로그래밍의 주요 특징은 추상화, 상속, 다형성, 캡슐화로 정리할 수 있습니다. 이 특징들은 공통 구조의 재사용, 기능 확장, 유연한 객체 처리, 안전한 상태 관리를 지원합니다.
