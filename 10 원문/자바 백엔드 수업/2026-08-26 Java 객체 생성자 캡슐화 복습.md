# Java 객체·생성자·캡슐화 복습 정리

지금까지 이해한 것, 헷갈린 것과 놓치기 쉬운 핵심을 정리했다.

## 1. 현재까지 이해가 잘 잡힌 부분

- `Person`은 객체가 아니라 클래스(설계도)다.
- `Person p1 = new Person();`에서 `new Person()`이 실제 Person 객체를 만들고 `p1`은 객체를 가리키는 참조 변수다.
- `new`는 객체를 생성하는 연산자이며 객체 생성 시 생성자가 호출된다.
- 생성자를 직접 만들지 않으면 조건에 따라 기본 생성자 `Person()`이 자동 제공된다.
- 생성자는 상속되지 않지만 자식 객체를 만들 때 부모 생성자가 먼저 호출된다.
- `static` 요소는 클래스 소속이고 객체 없이 접근할 수 있으며 non-static 요소는 객체 소속이다.
- Mutable 객체는 같은 객체를 계속 참조하면서 내부 필드 값을 바꿀 수 있다.

## 2. 헷갈렸던 부분과 정리

### 2-1. 클래스와 객체 구분

```java
class Person {
    public int age;
}

Person p1 = new Person();
```

`Person` 클래스는 설계도이고 `new Person()`을 실행할 때 그 설계도를 이용한 새로운 객체가 힙에 생성된다. `p1`은 클래스 자체가 아니라 생성된 Person 타입 객체를 가리킨다.

```text
Person 클래스(설계도)
       ↓ new
p1 ─────→ Person 객체(실제 데이터)
             age = 0
```

### 2-2. this는 생성자에서 만드는 것이 아니다

```java
class Person {
    String name;

    Person(String name) {
        this.name = name;
    }

    void printName() {
        System.out.println(this.name);
    }
}
```

- `this`는 현재 실행 중인 객체 자기 자신을 가리키는 참조다.
- 생성자와 non-static 메서드 안에서 사용할 수 있다.
- `this.name`은 현재 객체의 필드이고 오른쪽 `name`은 매개변수다.
- `static` 메서드는 특정 객체 하나에 속하지 않으므로 `this`를 사용할 수 없다.

### 2-3. 객체 생성과 초기화 순서

```java
Person p1 = new Person("철수", 20);
```

1. `new`가 객체 공간을 마련한다.
2. 인스턴스 필드가 기본값으로 초기화된다. 예: `String → null`, `int → 0`, `boolean → false`.
3. 필드에 직접 적은 초기값과 인스턴스 초기화가 적용된다.
4. 생성자 본문이 실행되어 원하는 값으로 초기화한다.
5. 생성이 정상 완료되면 참조 변수 `p1`에 참조값이 대입된다.

## 3. 생성자와 생성자 오버로딩

```java
class Person {
    Person() { }
    Person(String name) { }
    Person(String name, int age) { }
}
```

- 생성자는 클래스 이름과 같고 반환형을 적지 않는다.
- 객체 생성 과정에서 호출된다.
- 같은 클래스 안에 생성자를 여러 개 선언할 수 있다.
- 생성자 오버로딩은 매개변수의 개수·타입·순서가 달라야 한다.
- 호출할 때 전달한 인자에 맞는 생성자를 Java가 선택한다.

```java
new Person();
new Person("철수");
new Person("철수", 20);
```

## 4. 캡슐화, private, Getter와 Setter

```java
class Person {
    private int age;

    public int getAge() {
        return age;
    }

    public void setAge(int age) {
        if (age >= 0) {
            this.age = age;
        }
    }
}
```

- `private` 필드는 외부 클래스의 직접 접근을 막는다.
- Getter는 값을 읽는 통로이고 Setter는 값을 변경하는 통로다.
- Setter에 조건 검사를 넣어 잘못된 값을 막을 수 있다.
- 객체 내부 데이터를 숨기고 정해진 방법으로 접근시키는 것이 캡슐화의 핵심이다.

## 5. instanceof

`instanceof`는 참조 변수가 가리키는 실제 객체가 특정 타입으로 취급될 수 있는지 확인하며 결과는 `boolean`이다.

```java
Person p1 = new Person();
System.out.println(p1 instanceof Person); // true
```

```java
class Animal { }
class Dog extends Animal { }

Dog d = new Dog();
System.out.println(d instanceof Dog);    // true
System.out.println(d instanceof Animal); // true
```

## 6. Mutable과 String(Immutable)의 차이

### Mutable 객체

```java
Human hong = new Human("hong-gd", 100);
hong.setName("홍길동");
```

새 Human 객체를 만든 것이 아니라 기존 Human 객체 내부의 `name` 값을 변경한 것이다.

### String은 참조형이지만 Immutable

```java
String original = "hello";
original = "bye";
```

- `String`은 클래스이므로 참조형이다.
- 문자열 리터럴을 이용해 `new` 없이 간편하게 사용할 수 있다.
- `String` 객체의 내용 자체는 수정되지 않는다.
- 대입은 기존 문자열 내용을 바꾸는 것이 아니라 다른 String 객체를 가리키도록 참조를 바꾼다.
- 문자열 리터럴은 String Pool의 영향을 받으므로 참조를 놓았다고 즉시 GC에 수거된다고 단정할 수 없다.

## 7. identityHashCode와 객체 주소

```java
System.out.println(System.identityHashCode(hong));
```

- `System.identityHashCode(hong)`은 객체의 identity 기반 해시 코드를 `int` 값으로 반환한다.
- 이 값은 실제 메모리 주소가 아니다.
- Java 일반 코드에서는 JVM이 관리하는 객체의 실제 메모리 주소를 직접 확인하지 않는다.
- 두 참조가 같은 객체를 가리키는지 확인할 때는 `==`를 사용할 수 있다.

```java
Human h1 = new Human("hong", 100);
Human h2 = h1;
System.out.println(h1 == h2); // true
```

## 8. 놓치기 쉬운 핵심

| 번호 | 헷갈리기 쉬운 표현 | 정확한 개념 |
|---:|---|---|
| 1 | 클래스 ≠ 객체 | 클래스는 설계도, 객체는 생성된 인스턴스다. |
| 2 | 참조 변수 ≠ 객체 | `p1`은 객체를 가리키는 변수다. |
| 3 | this ≠ 생성자 전용 | `this`는 현재 객체를 가리키며 non-static 메서드에서도 사용한다. |
| 4 | identityHashCode ≠ 메모리 주소 | 객체 identity 기반의 해시값이다. |
| 5 | String 재대입 ≠ 객체 내부 수정 | String은 immutable이고 참조가 다른 String으로 바뀐다. |
| 6 | GC 대상 ≠ 즉시 삭제 | 실제 수거 시점은 JVM이 결정한다. |
| 7 | 생성자는 상속되지 않음 | 자식 객체 생성 과정에서 부모 생성자는 호출된다. |
