# 자바 참조와 자료형 기초

## 금일 학습 요약

자바 프로그램에서 대상을 찾아 호출하는 참조 개념을 중심으로 점 연산자, 변수, 함수, 메소드의 형태, `static`과 인스턴스 멤버의 호출 차이를 다루었습니다. 또한 Java API 문서에서 패키지, 클래스, 필드, 메소드, 상속 계층을 탐색하는 방법과 클래스의 구성 요소 및 접근 제한자를 정리했습니다.

이어서 비트, 바이트, 스트림, 리터럴, 기본 자료형을 연결하여 데이터가 메모리에 저장되고 처리되는 원리를 살펴보았습니다. 실습에서는 IntelliJ IDEA에서 패키지와 클래스를 생성하고, 정수, 실수, 문자, 논리형 및 문자열 타입의 동작과 범위를 직접 확인했습니다.

## 참조와 점 연산자

> 자바의 점 연산자는 소속된 영역을 따라 대상의 주소를 참조하며, `System.out.println()`은 시스템의 표준 출력 장치에 속한 메소드를 호출하는 표현식입니다. 
> 참조 변수는 객체를 가리키는 참조값을 가지고 있으며, 점 연산자를 통해 해당 객체의 필드나 메소드에 접근할 수 있습니다.

객체지향 프로그램은 사람의 주소 표기처럼 상위 영역에서 하위 영역으로 대상을 찾아갑니다. `System.out.println()`에서는 `System`이 가장 상위 영역이며, `out`은 표준 출력 장치이고, `println()`은 실제 출력 기능을 수행하는 최종 메소드입니다.

점 연산자가 많아질수록 참조 경로의 깊이가 깊어집니다. 따라서 표현식을 읽을 때는 가장 왼쪽의 소속 영역부터 시작해 점을 따라 최종 대상까지 내려가는 방식으로 해석하는 것이 중요합니다.

| 표현 형태 | 의미 | 예시 |
|---|---|---|
| 이름만 존재하는 형태 | 값을 보관하거나 반환하는 변수 또는 필드입니다. | `out` |
| 괄호가 붙은 이름 | 메소드를 호출하는 형태입니다. | `test()` |
| 점 뒤에 괄호가 붙은 형태 | 클래스나 객체에 귀속된 메소드 호출 형태입니다. | `System.out.println()` |

참조 관계는 대상의 주소를 이용해 연결한 뒤 데이터를 조회, 생성, 수정, 삭제하는 관계로 이해할 수 있습니다. 웹 환경에서는 URL을 통해 서버에 연결하고, 연결된 자원에 CRUD 작업을 수행하는 구조가 대표적인 예입니다.

- 참조 관계는 대상의 위치 또는 주소를 통해 연결을 형성하는 구조입니다.
- 연결된 대상은 조회, 생성, 수정, 삭제와 같은 관리 작업의 대상이 됩니다.
- 연결이 가능하다면 연결 종료 또는 해제도 가능한 구조로 설계됩니다.
- 자바에서는 주로 점 연산자로 클래스와 객체의 멤버를 참조합니다.

### 핵심 키워드
`참조` `점 연산자` `메소드 호출` `System.out.println` `CRUD`

## static과 인스턴스 호출

> `static` 멤버는 클래스 이름으로 직접 호출할 수 있지만, 인스턴스 멤버는 객체를 생성하여 주소를 확보한 뒤 호출해야 합니다.

자바에서 클래스는 실행과 구성의 기본 단위이며, 클래스 안에는 필드, 생성자, 메소드 등의 멤버가 선언됩니다. 메소드를 호출할 때 가장 먼저 확인할 요소는 해당 메소드가 `static`인지 여부입니다.

`static` 멤버는 선언 시점에 클래스 차원에서 관리되므로 클래스 이름을 통해 바로 접근할 수 있습니다. 반면 인스턴스 멤버는 객체마다 별도의 상태와 주소를 가질 수 있으므로 객체 생성 이후에 접근해야 합니다.

```java
class Test {
    static void staticMethod() {
    }

    void instanceMethod() {
    }
}

Test.staticMethod();      // static 메소드는 클래스명으로 호출합니다.
// Test.instanceMethod(); // 인스턴스 메소드는 직접 호출할 수 없습니다.

Test test = new Test();
test.instanceMethod();    // 객체 생성 후 호출합니다.
```

| 구분 | 귀속 대상 | 기본 호출 방식 | 예시 |
|---|---|---|---|
| `static` 멤버 | 클래스에 귀속 | `클래스명.멤버` 형식으로 호출합니다. | `Math.PI` |
| 인스턴스 멤버 | 객체에 귀 | `객체참조.멤버` 형식으로 호출합니다. | `file.exists()` |

인스턴스 메소드를 호출하기 위해 객체를 생성하는 과정은 생성자와 연결됩니다. 이후 학습에서는 `new` 연산자, 생성자, 객체 주소, 인스턴스 필드와 인스턴스 메소드의 관계를 함께 다루게 됩니다.

### 핵심 키워드
`static` `인스턴스` `객체 생성` `생성자` `클래스 멤버`

## Java API 문서 탐색

> Java API 문서는 패키지, 클래스, 필드, 생성자, 메소드 및 상속 계층을 확인하는 공식 기술 문서입니다.

Java API는 자바에서 제공하는 표준 클래스와 기능을 확인하는 핵심 자료입니다. 개발자는 모든 기능을 직접 구현하기보다 API에서 필요한 클래스를 찾고, 제공되는 필드와 메소드를 조합하여 프로그램을 구현합니다.

Java 8 API는 모듈 구조가 없으므로 패키지와 클래스의 관계를 처음 익히기에 비교적 단순합니다. Java 9 이상에서는 모듈 아래에 패키지와 클래스가 배치되므로 구조가 한 단계 더 깊어집니다.

- 패키지는 관련 클래스들을 폴더 구조처럼 묶는 논리적 단위입니다.
- 모듈은 관련 패키지들을 다시 묶어 관리하는 상위 단위입니다.
- 클래스 문서의 Summary 영역에서는 필드, 생성자, 메소드 목록을 확인할 수 있습니다.
- 상속 계층에서는 부모 클래스와 자식 클래스의 관계를 확인할 수 있습니다.

`java.lang.System` 클래스는 표준 입출력과 오류 출력에 관련된 멤버를 제공합니다. `System.out`은 표준 출력 스트림을 가리키는 필드이며, 반환되는 `PrintStream` 객체가 `println()`, `print()`, `printf()`, `write()` 등의 출력 메소드를 제공합니다.

| 대상 | 역할 | 대표 사용 예시 |
|---|---|---|
| `System.in` | 표준 입력 장치를 나타냅니다. | 키보드 입력 처리와 연결됩니다. |
| `System.out` | 표준 출력 장치를 나타냅니다. | 콘솔 출력에 사용됩니다. |
| `System.err` | 표준 오류 출력 장치를 나타냅니다. | 오류 메시지 출력에 사용됩니다. |
| `PrintStream` | 출력 관련 메소드를 제공합니다. | `println()`, `print()`, `printf()`를 제공합니다. |

API 문서를 읽을 때는 클래스의 전체 이름, 소속 패키지, 상속 관계, 필드의 타입, 메소드의 반환 타입, `static` 여부를 순서대로 확인하면 구조를 빠르게 파악할 수 있습니다.

### 핵심 키워드
`Java API` `패키지` `모듈` `System` `PrintStream`

## 클래스와 접근 제한자

> 클래스는 사용자 정의 자료형을 만드는 키워드이며, 필드와 메소드로 속성과 기능을 표현하고 접근 제한자로 공개 범위를 제어합니다.

자바의 클래스는 개발자가 새로운 자료형을 정의할 수 있게 하는 사용자 정의 자료형입니다. 클래스 블록 내부에는 값과 상태를 나타내는 필드, 동작을 나타내는 메소드, 객체 생성을 담당하는 생성자 등이 멤버로 포함됩니다.

```java
public class Test {
    public static final double PI = 3.141592;

    public void printValue() {
        System.out.println(PI);
    }
}
```

클래스는 일반적으로 속성과 기능의 집합으로 설명됩니다. 속성은 필드로 표현되며, 기능은 메소드로 표현됩니다. 생성자는 객체가 만들어질 때 초기 상태를 설정하는 특별한 멤버입니다.

| 접근 제한자 | 접근 범위 | 특징 |
|---|---|---|
| `public` | 모든 위치에서 접근할 수 있습니다. | 가장 넓은 공개 범위를 가집니다. |
| `protected` | 같은 패키지와 상속 관계에서 접근할 수 있습니다. | 상속 구조에서 주로 활용됩니다. |
| 기본 접근 수준 | 같은 패키지에서 접근할 수 있습니다. | 별도 키워드를 작성하지 않습니다. |
| `private` | 선언된 클래스 내부에서만 접근할 수 있습니다. | 내부 구현을 은닉하는 데 사용됩니다. |

기본 접근 수준은 `default`라는 키워드를 작성하는 방식이 아닙니다. 접근 제한자를 생략했을 때 같은 패키지에 공개되는 상태를 기본 접근 수준이라고 부릅니다.

`final`은 확장을 제한하거나 변경을 막는 성질과 연결됩니다. 클래스에 적용하면 상속을 제한하고, 필드에 적용하면 값을 변경할 수 없는 상수로 만들 수 있습니다. 반대로 `abstract`는 하위 클래스에서 구현을 확장하는 추상화 구조와 관련됩니다.

### 핵심 키워드
`클래스` `접근 제한자` `public` `private` `final`

## 상수와 필드

> `static final` 필드는 클래스에 귀속된 변경 불가능한 값이며, 일반적으로 `클래스명.필드명` 형태로 참조합니다.

필드는 클래스 내부에 선언되는 값 저장 공간입니다. 특히 `static final`이 함께 선언된 필드는 클래스가 공유하는 고정값, 즉 상수로 사용됩니다. 대표적인 예가 `Math.PI`입니다.

```java
public class Score {
    public static final double DEFAULT_SCORE = 50.0;
    public static double currentScore = 50.0;
}
```

상수는 선언과 동시에 초기값이 고정되며 이후 재대입할 수 없습니다. 반면 `static`만 선언된 필드는 클래스 차원에서 공유되지만 값 변경은 가능합니다.

| 선언 형태 | 값 변경 가능 여부 | 호출 방식 | 의미 |
|---|---|---|---|
| `static final` 필드 | 값을 변경할 수 없습니다. | `클래스명.필드명`으로 호출합니다. | 클래스 상수입니다. |
| `static` 필드 | 값을 변경할 수 있습니다. | `클래스명.필드명`으로 호출합니다. | 클래스 변수입니다. |
| 인스턴스 필드 | 객체별로 값을 변경할 수 있습니다. | `객체참조.필드명`으로 호출합니다. | 객체 상태 값입니다. |

상수 이름은 관례적으로 대문자와 밑줄을 사용하여 작성합니다. 이는 API 문서에서 상수와 일반 변수 또는 메소드를 빠르게 구분할 수 있게 해주는 중요한 명명 규칙입니다.

### 핵심 키워드
`필드` `상수` `static final` `Math.PI` `클래스 변수`

## 바이트와 스트림

> 컴퓨터는 데이터를 비트와 바이트 단위로 저장하며, 스트림은 바이트 단위 데이터가 입출력 장치 사이를 이동하는 통로입니다.

컴퓨터 내부의 모든 데이터는 결국 `0`과 `1`의 비트 형태로 처리됩니다. 비트 8개는 1바이트이며, 바이트는 데이터를 저장하고 전달하는 기본 단위입니다. 메모리에서는 일반적으로 바이트 단위의 저장 공간과 주소가 연결됩니다.

| 단위 | 구성 | 의미 |
|---|---|---|
| 비트 | `0` 또는 `1` 하나로 구성됩니다. | 가장 작은 정보 단위입니다. |
| 바이트 | 비트 8개로 구성됩니다. | 기본 저장 및 전송 단위입니다. |
| ASCII 코드 | 기본 문자와 숫자를 코드값으로 표현합니다. | 1바이트 기반 문자 표현과 연결됩니다. |
| 유니코드 | 다국어 문자를 표현하는 확장 문자 체계입니다. | 자바의 `char` 처리와 연결됩니다. |

키보드로 입력한 문자나 숫자는 내부적으로 바이트 형태로 변환됩니다. 입력된 데이터는 버퍼와 같은 임시 기억 공간을 거쳐 화면, 파일, 네트워크 등의 대상에 전달됩니다.

- 버퍼는 데이터를 일시적으로 보관하여 입출력 속도 차이를 조절하는 임시 기억 공간입니다.
- 스트림은 바이트 단위 데이터를 입력 장치와 출력 장치 사이에서 전달하는 흐름입니다.
- `InputStream`과 `OutputStream` 계열은 바이트 기반 입출력 구조를 나타냅니다.
- 문자 기반 스트림은 내부적으로 문자와 바이트 간 변환 과정을 포함할 수 있습니다.

`java.io` 패키지에서 이름에 `InputStream` 또는 `OutputStream`이 포함된 클래스는 바이트 단위 입출력과 직접적으로 관련됩니다. 파일, 콘솔, 네트워크 통신 등 다양한 입출력 작업은 이러한 스트림 구조를 기반으로 구현됩니다.

### 핵심 키워드
`비트` `바이트` `버퍼` `스트림` `InputStream`

## 리터럴과 기본 자료형

> 리터럴은 코드에 직접 작성한 실제 값이며, 자바의 기본 자료형은 값의 종류와 메모리 크기에 따라 데이터를 처리합니다.

리터럴은 변수나 상수에 저장되는 순수한 값 자체를 의미합니다. `100`, `100.0`, `'A'`, `"Hello"`, `true`와 같은 값이 리터럴입니다. 자바는 리터럴의 형태에 따라 기본 타입을 판단하고 필요한 저장 공간을 확보합니다.

| 리터럴 예시 | 기본 타입 | 설명 |
|---|---|---:|---|
| `true`, `false` | `boolean` | 논리 값을 나타냅니다. |
| `'A'` | `char` | 유니코드 기반 문자 하나를 나타냅니다. |
| `100` | `int` | 정수 리터럴의 기본 타입입니다. |
| `100.0` | `double` | 실수 리터럴의 기본 타입입니다. |
| `"Hello"` | `String` | 문자열 객체를 참조합니다. |

정수형에는 `byte`, `short`, `int`, `long`이 있으며, 일반적인 정수 리터럴은 기본적으로 `int`로 처리됩니다. 실수형에는 `float`, `double`이 있으며, 일반적인 실수 리터럴은 기본적으로 `double`로 처리됩니다.

```java
int count = 100;
double rate = 100.0;
char grade = 'A';
boolean enabled = true;
String message = "Hello";
```

변수는 값을 저장한 뒤 재대입할 수 있는 공간입니다. 상수는 `final`로 선언되어 초기화 이후 값을 변경할 수 없습니다. 따라서 값의 변경 가능 여부는 변수와 상수를 구분하는 핵심 기준입니다.

### 핵심 키워드
`리터럴` `기본 자료형` `int` `double` `String`

## 형변환과 연산 프로모션

> 작은 타입은 큰 타입으로 자동 변환될 수 있지만, 큰 타입을 작은 타입으로 변환할 때는 데이터 손실 가능성을 고려한 명시적 캐스팅이 필요합니다.

자료형 변환은 값이 저장되는 메모리 크기와 표현 범위를 바꾸는 과정입니다. 작은 범위의 값을 큰 범위로 옮기는 프로모션은 일반적으로 안전하게 수행되지만, 큰 범위의 값을 작은 범위로 옮기는 과정에서는 값 손실이 발생할 수 있습니다.

```java
int number = 10;
double promoted = number;

double decimal = 123.45;
int casted = (int) decimal;
```

| 구분 | 변환 방향 | 특징 | 예시 |
|---|---|---|---|
| 프로모션 | 작은 타입에서 큰 타입으로 변환됩니다. | 대체로 자동 변환됩니다. | `int`에서 `double`로 변환됩니다. |
| 캐스팅 | 특정 타입으로 명시적으로 변환합니다. | 개발자가 타입을 지정합니다. | `(int) decimal` 형태입니다. |
| 디모션 | 큰 타입에서 작은 타입으로 변환됩니다. | 데이터 손실 가능성이 있습니다. | `double`에서 `int`로 변환됩니다. |

연산 과정에서도 프로모션이 발생할 수 있습니다. 예를 들어 `byte` 또는 `short` 값끼리 덧셈이나 뺄셈을 수행하면, 자바는 안전한 연산을 위해 결과를 `int`로 처리합니다. 따라서 결과를 다시 작은 타입에 저장하려면 명시적 캐스팅이 필요할 수 있습니다.

### 핵심 키워드
`프로모션` `캐스팅` `디모션` `연산 프로모션` `형변환`

## 패키지와 식별자 규칙

> 패키지는 관련 클래스의 묶음이며, 식별자는 변수, 클래스, 메소드 등을 구별하기 위해 규칙에 따라 작성하는 이름입니다.

패키지는 관련 있는 클래스들을 논리적으로 묶는 단위이며 파일 시스템의 폴더 구조와 대응됩니다. 예를 들어 `type01.primitive`는 `type01` 아래에 `primitive`가 속하는 계층 구조를 나타냅니다.

자바에서는 패키지명, 클래스명, 필드명, 메소드명에 서로 다른 관례를 적용합니다. 이러한 규칙은 코드의 역할을 이름만으로 빠르게 파악할 수 있게 해줍니다.

| 대상 | 일반적인 명명 관례 | 예시 |
|---|---|---|
| 패키지 | 소문자와 점으로 계층을 표현합니다. | `type01.primitive` |
| 클래스 | 대문자로 시작하는 파스칼 표기법을 사용합니다. | `Type01Byte` |
| 변수, 메소드 | 소문자로 시작하는 카멜 표기법을 사용합니다. | `totalScore` |
| 상수 | 대문자와 밑줄을 사용합니다. | `DEFAULT_SCORE` |

식별자는 숫자로 시작할 수 없고, 공백이나 일반 특수문자를 포함할 수 없습니다. 또한 자바 키워드는 이미 언어 기능을 위해 예약되어 있으므로 식별자로 사용할 수 없습니다.

- 식별자는 대소문자를 구분하므로 `count`와 `Count`는 서로 다른 이름입니다.
- 식별자는 문자, 밑줄, 달러 기호로 시작할 수 있습니다.
- `class`, `public`, `static`, `void`와 같은 키워드는 이름으로 사용할 수 없습니다.
- 최신 자바 버전의 키워드는 공식 언어 명세 문서에서 확인해야 합니다.

### 핵심 키워드
`패키지` `식별자` `키워드` `명명 규칙` `Java Language Specification`

## JVM과 클래스 실행 단위

> 자바 소스 파일은 컴파일되어 바이트코드 클래스 파일이 되고, JVM은 클래스 파일을 로딩하여 프로그램을 실행합니다.

자바 프로그램은 일반적으로 `.java` 소스 파일을 작성한 뒤 컴파일 과정을 거쳐 `.class` 파일을 생성합니다. `.class` 파일에는 JVM이 실행할 수 있는 바이트코드가 저장됩니다.

```text
소스 코드(.java)
    ↓ javac 컴파일
바이트코드(.class)
    ↓ JVM 클래스 로딩
프로그램 실행
```

JVM은 Java Virtual Machine의 약자이며, 바이트코드를 로딩하고 실행하는 가상 실행 환경입니다. 자바가 운영체제에 직접 종속되지 않고 다양한 환경에서 실행될 수 있는 이유는 JVM이 운영체제와 자바 바이트코드 사이의 중간 실행 계층 역할을 하기 때문입니다.

- 클래스는 자바 프로그램의 기본 구성 단위이자 JVM의 주요 로딩 단위입니다.
- `main` 메소드는 프로그램 실행이 시작되는 진입점입니다.
- `.java` 파일 하나에는 여러 클래스를 선언할 수 있지만 공개 클래스에는 파일명 관련 규칙이 적용됩니다.
- 중첩 클래스는 바깥 클래스와 내부 클래스의 구조로 선언할 수 있습니다.

클래스 파일 생성 과정과 JVM 로딩 구조를 이해하면 컴파일 오류, 실행 오류, 클래스 경로 문제를 구분하는 기반이 됩니다. 또한 자바의 플랫폼 독립성과 바이트코드 기반 실행 모델을 이해하는 핵심이 됩니다.

### 핵심 키워드
`JVM` `바이트코드` `javac` `class 파일` `main 메소드`

## 기본 자료형 실습

> 기본 자료형 실습은 타입별 저장 범위, 정수 리터럴의 기본 타입, 오버플로우 및 연산 결과 타입을 확인하는 과정입니다.

IntelliJ IDEA에서 `type01.primitive` 패키지를 생성하고 자료형별 클래스를 분리하여 작성했습니다. 각 클래스는 `main` 메소드에서 값을 선언하고 출력하여 타입의 동작을 확인하는 구조입니다.

`byte`는 1바이트 정수형으로 `-128`부터 `127`까지 저장할 수 있습니다. 범위를 넘는 값을 강제로 저장하면 값이 순환하는 오버플로우 현상이 발생할 수 있습니다.

```java
byte b01 = 127;
byte b02 = (byte) 128;

System.out.println(b01);
System.out.println(b02); // -128
```

`byte`와 `short` 연산은 결과가 기본 정수 타입인 `int`로 승격됩니다. 따라서 연산 결과를 다시 `byte` 또는 `short` 변수에 넣으려면 명시적 캐스팅이 필요합니다.

```java
byte b01 = 127;
byte sum = (byte) (b01 - 1);

short s01 = 32767;
short sumShort = (short) (s01 + 1);
```

| 타입 | 크기 | 대표 범위 또는 특성 | 실습 확인 내용 |
|---|---:|---|---|
| `byte` | 1바이트 | `-128`부터 `127`까지 표현합니다. | 범위 초과 시 오버플로우를 확인합니다. |
| `short` | 2바이트 | `-32768`부터 `32767`까지 표현합니다. | 연산 결과가 `int`가 되는 것을 확인합니다. |
| `int` | 4바이트 | 정수 리터럴의 기본 타입입니다. | 일반적인 정수 연산을 확인합니다. |
| `long` | 8바이트 | 큰 정수를 저장합니다. | 큰 리터럴 뒤에 `L`을 사용합니다. |

정수 리터럴은 접두사를 통해 진법을 표현할 수 있습니다. `0b`는 2진수, `0`은 8진수, `0x`는 16진수를 의미하며, 출력 시에는 해당 값이 10진수로 변환되어 표시됩니다.

```java
System.out.println(0b10); // 2
System.out.println(010);  // 8
System.out.println(0x10); // 16
```

### 핵심 키워드
`byte` `short` `int` `long` `오버플로우`

## 문자, 실수, 논리 타입 실습

> `char`는 문자 코드값과 연결되며, `float`와 `double`은 실수 리터럴의 접미사 및 기본 타입 규칙으로 구분되고, `boolean`은 참과 거짓을 표현합니다.

`char`는 하나의 문자를 저장하는 2바이트 기본 타입입니다. 문자 리터럴은 작은따옴표로 작성하며, `char` 값을 `int`로 변환하면 해당 문자의 코드값을 확인할 수 있습니다.

```java
char c01 = 'A';

System.out.println(c01);
System.out.println((int) c01);
```

ASCII는 영문자, 숫자, 제어 문자를 숫자 코드와 연결하는 문자 인코딩 체계입니다. 예를 들어 대문자 `A`와 소문자 `a`는 서로 다른 코드값을 가지며, 자바는 문자 처리에서 유니코드 체계를 사용합니다.

실수 리터럴은 기본적으로 `double`로 처리됩니다. `float`에 실수 리터럴을 저장하려면 값 뒤에 `F` 또는 `f`를 붙여 해당 값이 `float`임을 명시해야 합니다.

```java
float f01 = 0.1F;
double d01 = 100.04;

System.out.println(f01);
System.out.println(d01);
```

`boolean`은 `true`와 `false`만 저장할 수 있는 논리형입니다. 조건문, 반복문, 비교 연산의 결과와 같이 참 또는 거짓이 필요한 프로그램 흐름 제어에 사용됩니다.

```java
boolean enabled = true;
boolean completed = false;

System.out.println(enabled);
System.out.println(completed);
```

### 핵심 키워드
`char` `ASCII` `float` `double` `boolean`

## 문자열과 참조 자료형

> String은 참조 타입이지만 문자열 리터럴을 사용하여 간편하게 객체를 생성하고 사용할 수 있습니다.

문자열은 문자 하나 이상이 연결된 데이터이며, 자바에서는 `String` 클래스로 처리합니다. `String`은 객체의 주소를 참조하는 자료형이지만 문자열 리터럴을 사용하여 기본 타입처럼 선언하고 사용할 수 있습니다.

```java
String first = "Java";
String second = " Programming";
String message = first.concat(second);

System.out.println(message);
```

문자열 연결에는 `concat()` 메소드를 사용할 수 있으며, 이후에는 `+` 연산자와 문자열 빌더 계열 도구의 차이도 함께 다룰 수 있습니다. 문자열은 불변 객체이므로 연결, 치환, 분할 등의 작업에서 새 객체 생성 여부를 고려해야 합니다.

여러 줄 텍스트는 텍스트 블록 문법을 사용할 수 있습니다. 텍스트 블록은 큰따옴표 세 개로 시작하고 끝나며, 여러 줄의 문자열을 비교적 읽기 쉬운 형태로 작성할 수 있습니다.

```java
String text = """
        AAA
        BBB
        CCC
        """;

System.out.println(text);
```

기본 자료형은 값 자체를 직접 저장하지만, 참조 자료형은 객체가 위치한 주소를 통해 대상에 접근합니다. `String`, 배열, 클래스 타입은 대표적인 참조 자료형이며, 점 연산자를 통해 객체가 제공하는 기능을 호출합니다.

### 핵심 키워드
`String` `참조 자료형` `concat` `텍스트 블록` `문자열 리터럴`
