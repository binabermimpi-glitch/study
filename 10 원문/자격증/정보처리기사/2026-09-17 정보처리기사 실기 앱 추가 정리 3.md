# 1. 애자일(Agile) 🔥🔥

## 문제

개발과 함께 피드백을 받으며 유동적이고 변화에 유연한 개발 모델

## 정답

**애자일(Agile)**

## 개념

짧은 개발 주기를 반복하면서 지속적으로 고객의 피드백을 받아 요구사항 변화에 유연하게 대응하는 개발 방법론이다.
```text
짧은 개발 주기
+
지속적인 피드백
+
변화에 유연
→ Agile
```

## 대표 애자일 방법론
```text
XP
Scrum
Kanban
```

# 2. SDN 🔥🔥

## 문제

네트워크를 제어부(Control Plane), 데이터 전달부(Data Plane)로 분리하여 효율적으로 네트워크를 관리하는 것, 소프트웨어로 안정성, 속도, 보안 등을 관리하기 위해 개발되었다.

## 정답

**SDN(Software Defined Networking)**

## 개념

네트워크의 제어 기능과 실제 데이터 전달 기능을 분리하여 소프트웨어를 통해 중앙에서 네트워크를 제어하고 관리하는 기술이다.
```text
Control Plane
→ 네트워크 제어

Data Plane
→ 실제 패킷 전달
```
```text
제어부와 전달부 분리
→ SDN
```

# 3. TP Monitor 🔥

## 문제

항공기나 철도 예약 업무 등과 같은 온라인 트랜잭션을 처리 및 감시하는 미들웨어로, 사용자 수가 증가하더라도 빠른 응답속도를 유지해야 할 경우 주로 사용된다.

## 정답

**TP Monitor(Transaction Processing Monitor)**

## 개념

많은 사용자가 동시에 발생시키는 트랜잭션을 효율적으로 처리하고 감시하는 미들웨어이다.

### 사용 예
```text
항공 예약
철도 예약
은행 업무
온라인 결제
```

## 핵심
```text
대량 트랜잭션
+
동시 사용자
+
처리 / 감시
→ TP Monitor
```

# 12. 세그멘테이션(Segmentation) 🔥🔥

## 문제

가상메모리의 프로세스를 논리적인 단위로 나누어 배치한다. 논리적인 단위는 서로 다른 크기를 가질 수 있으며 내부 단편화가 발생하지 않는다.

## 정답

**세그멘테이션(Segmentation)**

## 개념

프로그램을 코드, 데이터, 스택 등 **논리적인 가변 크기 단위**로 나누는 메모리 관리 기법이다.
```text
가변 크기
논리적 단위
→ Segmentation
```

## 페이징과 비교
```text
Paging
→ 고정 크기
→ 내부 단편화 발생 가능

Segmentation
→ 가변 크기
→ 외부 단편화 발생 가능
```

### 중요
```text
세그멘테이션
→ 내부 단편화 X
→ 외부 단편화 O
```

# 24. 변경 조건/결정 커버리지(MC/DC) 🔥🔥

## 문제

개별 조건식이 다른 개별 조건식에 영향을 받지 않고 전체 조건식의 결과에 독립적으로 영향을 주도록 하는 커버리지

## 정답

**변경 조건/결정 커버리지(MC/DC, Modified Condition/Decision Coverage)**

### 중요 수정 ⚠️

네 필기의:
```text
Condition / Decision Coverage
```

와 **MC/DC는 다르다.**

### 조건/결정 커버리지
```text
각 개별 조건 T/F
+
전체 결정 T/F
```

### MC/DC
```text
각 개별 조건이
독립적으로
전체 결과를 변화시켜야 함
```

## 초압축
```text
개별 조건 T/F
→ 조건

전체 결과 T/F
→ 결정

둘 다
→ 조건/결정

각 조건이 독립적으로 전체 결과 변경
→ MC/DC
```

# 44. 데이터 범주화(Data Generalization) 🔥

## 문제

데이터 비식별화 처리기법 중 단일 식별 정보를 그룹의 대표값으로 변환하거나 구간 값으로 변환하여 고유 정보 추적을 방지하는 기법

## 정답

**데이터 범주화 / 총계처리 / 일반화(Generalization)**

### 중요 수정 ⚠️

네 필기의:
```text

```

은 **삭제/억제**에 더 가까운 개념이다.

```text

→ 20대

서울시 강남구
→ 서울시
```

처럼 범위나 상위 범주로 바꾸는 것은 \*\*Generalization(범주화)\*\*로 이해하는 것이 정확하다.

### 비교
```text
Masking
→ 홍길동 → 홍**

Suppression
→ 값을 삭제하거나 숨김

Generalization
→ 구체적 값을 범위/상위 범주로 변경
```

# 50. 응집도 🔥🔥

## 문제

응집도가 약한 것부터 순서대로 나열

## 정답

약함 → 강함
```text
우연적
→ 논리적
→ 시간적
→ 절차적
→ 통신적
→ 순차적
→ 기능적
```

## 각각의 의미

### 우연적

모듈 내부 구성요소 사이에 연관이 거의 없다.

### 논리적

유사한 성격의 작업을 하나의 모듈에 묶는다.

### 시간적

특정 시점에 함께 수행되는 기능을 묶는다.

### 절차적

기능들이 정해진 순서에 따라 실행된다.

### 통신적

동일한 입력 또는 출력을 사용하는 기능들을 묶는다.

### 순차적

앞 기능의 출력이 다음 기능의 입력이 된다.

### 기능적

모듈의 모든 기능이 하나의 목적을 수행한다.

→ 가장 좋음

## 암기

강함 → 약함:
```text
기순통절시논우
```

### 핵심
```text
응집도
→ 높을수록 좋음

결합도
→ 낮을수록 좋음
```

### POP3와 비교
```text
POP3
→ 다운로드 중심
→ 110

IMAP
→ 서버 동기화
→ 143
```

# 54. AJAX 🔥

## 문제

필요한 데이터만 웹 서버에 요청해서 받은 후 브라우저 전체 페이지를 새로고침하지 않고 일부 영역만 갱신하는 웹 개발 기법

## 정답

**AJAX(Asynchronous JavaScript and XML)**

## 개념

JavaScript를 이용하여 서버와 비동기적으로 데이터를 주고받고 페이지 전체를 다시 불러오지 않고 일부만 변경한다.
```text
비동기 요청
+
부분 화면 갱신
→ AJAX
```

### 중요

AJAX가 반드시 SOAP나 XML만 사용하는 것은 아니다.

현재는 JSON도 매우 많이 사용한다.
```text
AJAX
→ 비동기 통신 방식

JSON / XML
→ 주고받는 데이터 형식
```
