# 1. Java static 변수 / 지역변수 🔥🔥

## 문제

다음 Java 프로그램의 실행 결과를 쓰시오.

```java
class Static {
    public int a = 20;
    static int b = 0;
}

public class Gisafirst {
    public static void main(String[] args) {
        int a;

        a = 10;
        Static.b = a;

        Static st = new Static();

        System.out.println(Static.b++);
        System.out.println(st.b);
        System.out.println(a);
        System.out.println(st.a);
    }
}
```

## 정답

```text
10
11
10
20
```

---

# 실행 과정

## ① 지역변수 a

```java
int a;
a = 10;
```

main()의 지역변수:

```text
a = 10
```

---

## ② static 변수 b

```java
Static.b = a;
```

현재 `a = 10`이므로:

```text
Static.b = 10
```

---

## ③ 객체 생성

```java
Static st = new Static();
```

`Static` 객체의 인스턴스 변수:

```text
st.a = 20
```

`b`는 static이므로 객체마다 따로 생성되는 것이 아니라 클래스가 공유한다.

---

## ④ 후위 증가

```java
System.out.println(Static.b++);
```

현재:

```text
b = 10
```

`b++`는 **출력한 후 증가**한다.

따라서:

```text
출력 → 10
그 후 b → 11
```

---

## ⑤ st.b

```java
System.out.println(st.b);
```

`b`는 static 변수이므로:

```text
Static.b
st.b
```

모두 같은 변수를 가리킨다.

따라서:

```text
11
```

---

## ⑥ 지역변수 a

```java
System.out.println(a);
```

main의 지역변수:

```text
10
```

---

## ⑦ 인스턴스 변수 st.a

```java
System.out.println(st.a);
```

객체의 `a`:

```text
20
```

---

# 핵심

```text
지역변수 a
→ main() 내부
→ 10

st.a
→ 객체마다 존재
→ 20

Static.b
→ 클래스가 공유
→ static 변수
```

```text
b++
→ 먼저 사용
→ 나중에 +1

++b
→ 먼저 +1
→ 나중에 사용
```

# 2. C 문자열 포인터 🔥🔥

## 문제

```c
#include <stdio.h>

int main() {

    char a[] = "Art";
    char *p = NULL;

    p = a;

    printf("%s\n", a);
    printf("%c\n", *p);
    printf("%c\n", *a);
    printf("%s\n", p);

    for(int i = 0; a[i] != '\0'; i++) {
        printf("%c", a[i]);
    }
}
```

## 정답

```text
Art
A
A
Art
Art
```

---

# 핵심

배열:

```text
a = ['A', 'r', 't', '\0']
```

```c
p = a;
```

배열 이름 `a`는 첫 번째 문자 주소를 가리킨다.

따라서:

```text
p
→ &a[0]
```

---

## `%s`

```c
printf("%s", a);
```

문자열 끝 `\0`까지 출력한다.

```text
Art
```

---

## `*p`

```c
printf("%c", *p);
```

`p`는 첫 문자 `A`를 가리키므로:

```text
A
```

---

## `*a`

배열 이름 `a`는 첫 번째 요소의 주소이므로:

```text
*a
= a[0]
= 'A'
```

---

## `%s`, p

```c
printf("%s", p);
```

`p` 역시 문자열 첫 주소를 가지고 있으므로:

```text
Art
```

---

## 반복문

```c
for(int i = 0; a[i] != '\0'; i++)
```

```text
A
r
t
```

를 차례대로 출력한다.

---

# 핵심 암기

```text
a
→ 배열 첫 번째 요소의 주소

*a
→ 첫 번째 요소

p = a
→ p가 배열 첫 요소를 가리킴

*p
→ p가 가리키는 값
```

# 3. C 두 문자열에서 같은 문자 찾기 🔥

## 문제

```c
#include <stdio.h>

int main() {

    char *a = "qwer";
    char *b = "qwtety";

    for(int i = 0; a[i] != '\0'; i++) {

        for(int j = 0; b[j] != '\0'; j++) {

            if(a[i] == b[j])
                printf("%c", a[i]);
        }
    }
}
```

## 정답

```text
qwe
```

---

# 실행

문자열:

```text
a = q w e r
b = q w t e t y
```

## q

```text
q == q
```

따라서:

```text
q 출력
```

## w

```text
w == w
```

따라서:

```text
w 출력
```

## e

`b` 안에 `e`가 있다.

```text
e 출력
```

## r

`b`에는 `r`이 없다.

출력 없음.

따라서:

```text
qwe
```


```text

→ 비동기 통신 방식

```

# 6. L2TP 🔥

## 문제

Cisco의 L2F와 PPTP를 결합하여 만든 VPN 터널링 프로토콜이다.

자체적인 강력한 암호화 기능이 없어 IPsec 등과 함께 사용되는 경우가 많다.

## 정답

**L2TP(Layer 2 Tunneling Protocol)**

## 개념

데이터링크 계층 수준에서 터널링을 제공한다.

```text
L2F
+
PPTP
→ L2TP
```

---

# 터널링

두 네트워크 또는 두 노드 사이에 가상의 통신 경로를 만드는 기술

```text
공용 인터넷
↓
가상 터널
↓
사설 네트워크처럼 통신
```

---

# 중요 수정 ⚠️

네 필기에:

```text
L2TP가 UDP 500 사용
```

이라고 되어 있는데 정확히 구별해야 한다.

```text
L2TP 자체
→ UDP 1701
```

L2TP/IPsec에서:

```text
UDP 500
→ IKE의 키 교환 등에 사용
```

따라서 시험에서는:

```text
L2TP = UDP 1701
IPsec/IKE = UDP 500
```

로 구분해두는 것이 좋다.

# 8. Worm / Trojan Horse / Virus 🔥🔥

## 문제

ㄷ. 다른 실행 파일이나 프로그램에 자신을 복제하여 감염시키며 스스로 전파되지는 않는다.


# 9. ICMP 🔥🔥

## 문제

인터넷 환경에서 오류 처리와 상태 정보 전달에 사용되는 프로토콜이다.

Echo Request / Echo Reply는 ping에서 사용된다.

## 정답

**ICMP(Internet Control Message Protocol)**

## 개념

IP 통신 과정에서 발생한 오류나 네트워크 상태 정보를 전달한다.

```text
IP 오류 보고
네트워크 상태 진단
→ ICMP
```

대표:

```text
ping
→ ICMP Echo Request
→ ICMP Echo Reply
```

---

# Ping of Death

허용 범위를 초과하거나 비정상적으로 큰 IP 패킷을 이용하여 시스템에 장애를 발생시키는 공격

```text
비정상적인 큰 패킷
→ Ping of Death
```

---

# Smurf Attack ⚠️

네 필기의 설명은 일반적인 DDoS 설명과 섞여 있다.

Smurf 공격의 핵심은:

```text
피해자 IP로 출발지 IP 위조
↓
ICMP Echo Request를
브로드캐스트 주소로 전송
↓
다수의 호스트가 피해자에게 Echo Reply
↓
피해자 트래픽 폭주
```

즉:

```text
IP Spoofing
+
ICMP
+
Broadcast
→ Smurf Attack
```

# 10. C 2진수 → 10진수 변환 🔥🔥

## 문제

```c
#include <stdio.h>

int main() {

    int input = 101110;
    int di = 1;
    int sum = 0;

    while(1) {

        if(input == 0)
            break;

        else {

            sum = sum + (input (①) (②)) * di;

            di = di * 2;

            input = input / 10;
        }
    }

    printf("%d", sum);
}
```

## 정답

```text
① %
② 10
```

완성:

```c
sum = sum + (input % 10) * di;
```

---

# 왜 `% 10`인가?

```text
101110 % 10
= 0
```

가장 오른쪽 자릿수를 꺼낸다.

```text
% 10
→ 마지막 자리 추출
```

---

# `/ 10`

```text
101110 / 10
= 10111
```

마지막 자리를 제거한다.

```text
/ 10
→ 마지막 자리 제거
```

---

# di

처음:

```text
di = 1
```

반복할 때마다:

```c
di = di * 2;
```

따라서:

```text
1
2
4
8
16
32
...
```

즉 2진수의 자리값이다.

---

# 실행 개념

```text
101110₂
```

오른쪽부터:

```text
0 × 1
1 × 2
1 × 4
1 × 8
0 × 16
1 × 32
```

따라서:

```text
0 + 2 + 4 + 8 + 0 + 32
= 46
```

즉:

```text
101110₂
= 46₁₀
```

---

# 핵심

```text
input % 10
→ 현재 이진수 한 자리 추출

di *= 2
→ 자리값 증가

input /= 10
→ 처리한 자리 제거
```

# 11. Proxy Pattern 🔥🔥

## 문제

특정 객체에 대한 접근을 제어하거나 기능을 추가할 수 있는 디자인 패턴이다.

객체를 직접 참조하지 않고 대리자 객체를 통해 대상 객체에 접근한다.

## 정답

**Proxy Pattern**

## 분류

**구조 패턴**

## 핵심

```text
사용자
↓
Proxy
↓
실제 객체
```

Proxy가 실제 객체 대신 접근을 제어한다.

### 활용

- 접근 제어
- 지연 생성
- 원격 객체 접근
- 로깅

---

# 관련 패턴

## Builder

객체 생성 단계를 분리하고 복잡한 객체를 단계적으로 생성

## Bridge

추상부와 구현부를 분리하여 각각 독립적으로 확장

## Observer

한 객체의 상태가 변경되면 관련 객체에게 자동 통지

## 문제

```python
asia = {'한국', '중국', '일본'}

asia.add('베트남')

asia.remove('일본')
```



Python의 `set`은 **순서가 보장되지 않는다.**

따라서 실제 출력 순서는 달라질 수 있다.

---

```text
중괄호 {}
순서 없음
중복 불가
```

---

## add()

요소 하나 추가

```python
asia.add('베트남')
```

---

## 중복 추가

```python
asia.add('중국')
```

이미 `중국`이 있으므로 변화 없음.

```text
Set
→ 중복 허용 X
```

---

## remove()

```python

```

# 16. C 버블 정렬 🔥🔥

## 문제

```c
#include <stdio.h>

void swap(int a[], int idx1, int idx2) {

    int t = a[idx1];

    a[idx1] = a[idx2];

    a[(①)] = t;
}

void sort(int a[], int len) {

    for(int i = 0; i < len-1; i++) {

        for(int j = 1; j < len-i-1; j++) {

            if(a[j] > a[j+1])
                swap(a, j, j+1);
        }
    }
}

int main() {

    int nx = 5;

    int a[] = {5, 15, 7, 20, 11};

    sort(a, (②));

    for(int i = 0; i < nx; i++) {
        printf("%d ", a[i]);
    }
}
```

## 정답

```text
① idx2
② nx
```

---

# swap()

처음:

```c
int t = a[idx1];
```

첫 번째 값을 임시 저장

```c
a[idx1] = a[idx2];
```

두 번째 값을 첫 번째 위치에 저장

마지막에는:

```c
a[idx2] = t;
```

해야 두 값이 교환된다.

따라서:

```text
① idx2
```

---

# sort()

```c
sort(a, nx);
```

배열의 길이는:

```text
nx = 5
```

이므로:

```text
② nx
```

---

# 버블 정렬 개념

인접한 두 값을 비교해서 큰 값을 뒤로 보낸다.

예:

```text
5 15 7 20 11
```

비교:

```text
15 > 7
```

이면 교환

```text
5 7 15 20 11
```

이 과정을 반복하면:

```text
5 7 11 15 20
```

과 같이 정렬된다.

# 18. Java 추상 클래스 / 오버로딩 🔥🔥

## 문제

```java
abstract class Vehicle {

    String name;

    abstract public String getName(String val);

    public String getName() {
        return "Vehicle name:" + name;
    }
}

class Car extends Vehicle {

    String name;

    public Car(String val) {
        name = super.name = val;
    }

    public String getName(String val) {
        return "Car name:" + val;
    }

    public String getName(byte val[]) {
        return "Car name:" + val;
    }
}

public class Gisafirst {

    public static void main(String[] args) {

        Vehicle obj = new Car("Spark");

        System.out.print(obj.getName());
    }
}
```

## 정답

```text
Vehicle name:Spark
```

---

# 가장 중요한 부분

호출:

```java
obj.getName();
```

괄호 안에 인자가 없다.

Vehicle에는:

```java
public String getName()
```

이 있다.

Car에는:

```java
getName(String val)
getName(byte[] val)
```

만 있다.

즉 `Car`는 **매개변수 없는 getName()을 오버라이딩하지 않았다.**

따라서 상속받은:

```java
Vehicle.getName()
```

이 실행된다.

---

# 생성자

```java
name = super.name = val;
```

`val`은:

```text
Spark
```

이다.

따라서:

```text
Car의 name
→ Spark

Vehicle의 name
→ Spark
```

둘 다 설정된다.

---

# 호출

```java
obj.getName();
```

실행되는 메서드:

```java
Vehicle.getName()
```

그 안에서:

```java
return "Vehicle name:" + name;
```

Vehicle의 `name`은:

```text
Spark
```

따라서:

```text
Vehicle name:Spark
```

---

# 오버로딩

Car 안에서:

```java
getName(String)
getName(byte[])
```

처럼 메서드 이름은 같지만 매개변수가 다르다.

```text
같은 메서드 이름
+
매개변수 다름
→ Overloading
```

---

# 오버라이딩

부모의 동일한 메서드를 자식에서 다시 정의

```text

→ Overriding
```

이 문제에서는:

```text

```

을 Car가 오버라이딩하지 않았다.

# 19. Java 상속 / 생성자 / 필드 숨김 🔥🔥

## 문제

```java
class Parent {

    int x = 100;

    Parent() {
        this(500);
    }

    Parent(int x) {
        this.x = x;
    }

    int getX() {
        return this.x;
    }
}

class Child extends Parent {

    int x = 1000;

    Child() {
        this(5000);
    }

    Child(int x) {
        this.x = x;
    }
}

public class Gisafirst {

    public static void main(String[] args) {

        Child obj = new Child();

        System.out.println(obj.getX());
    }
}
```

## 정답

```text
500
```

---

# 이 문제 핵심

Child에는:

```text
Child.x
```

Parent에는:

```text
Parent.x
```

가 각각 따로 존재한다.

즉 같은 이름이지만 서로 다른 필드다.

---

# 1. Child()

```java
new Child();
```

실행하면:

```java
Child() {
    this(5000);
}
```

따라서:

```text
Child(int 5000)
```

을 호출한다.

---

# 2. Child(int x)

```java
Child(int x) {
    this.x = x;
}
```

그런데 Java 생성자에서는 명시적인 `this()`나 `super()`가 없으면 자동으로:

```java
super();
```

가 가장 먼저 호출된다.

즉 Parent의 기본 생성자가 먼저 실행된다.

---

# 3. Parent()

```java
Parent() {
    this(500);
}
```

따라서:

```java
Parent(500)
```

호출

---

# 4. Parent(int)

```java
Parent(int x) {
    this.x = x;
}
```

Parent의 `x`에:

```text
500
```

저장

```text
Parent.x = 500
```

---

# 5. 다시 Child(int)

```java
this.x = 5000;
```

여기서 `this.x`는 Child의 x다.

따라서:

```text
Child.x = 5000
```

최종 객체 상태:

```text
Parent.x = 500
Child.x = 5000
```

---

# 6. getX()

```java
obj.getX()
```

Child는 `getX()`를 오버라이딩하지 않았다.

따라서 Parent의:

```java
int getX() {
    return this.x;
}
```

가 실행된다.

여기서 `x`는 **Parent 클래스에 선언된 x**를 사용한다.

따라서:

```text
Parent.x
= 500
```

## 출력

```text
500
```

---

# 매우 중요

메서드는 오버라이딩에 의해 동적으로 선택될 수 있지만 필드는 그렇게 동적으로 오버라이딩되는 것이 아니다.

```text
Parent.x
Child.x
→ 서로 다른 필드
```

# 20. 분기 커버리지 🔥🔥

## 문제

다음 순서도의 **분기(Decision) 커버리지**를 만족하는 수행 순서를 작성하시오.

노드:

```text
1
POINTER = FALSE

2
X > K ?

3
POINTER = TRUE

4
X = X + 1

5
CALL SUB(X, POINTER, RESULT)

6
RESULT > 0 ?

7
PRINT RESULT
```

## 가능한 정답

예:

```text
① 1234561
② 124567
```

또는:

```text
① 1234567
② 124561
```

---

# 왜 두 경로가 필요한가?

분기 커버리지는 각 결정문의 결과가:

```text
TRUE
FALSE
```

를 모두 한 번 이상 수행해야 한다.

이 순서도에는 결정문이 두 개 있다.

```text
2번
X > K ?

6번
RESULT > 0 ?
```

따라서 두 결정문 모두:

```text
YES
NO
```

를 경험해야 한다.

---

# 첫 번째 예

```text
1 → 2 → 3 → 4 → 5 → 6 → 1
```

즉:

```text
1234561
```

이 경로에서는:

```text
2번
→ YES

6번
→ YES
```

를 수행한다.

---

# 두 번째 예

```text
1 → 2 → 4 → 5 → 6 → 7
```

즉:

```text
124567
```

이 경로에서는:

```text
2번
→ NO

6번
→ NO
```

를 수행한다.

따라서 두 경로를 합치면 모든 분기를 한 번 이상 수행한다.

---

# 분기 커버리지

```text
각 Decision의
TRUE / FALSE
모두 실행
→ Decision Coverage
```

## 조건 커버리지와 비교

```text
구문 커버리지
→ 모든 문장 실행

결정/분기 커버리지
→ 전체 조건 결과 T/F

조건 커버리지
→ 개별 조건식 T/F

조건/결정 커버리지
→ 둘 다

MC/DC
→ 각 조건이 독립적으로 전체 결과에 영향
```
