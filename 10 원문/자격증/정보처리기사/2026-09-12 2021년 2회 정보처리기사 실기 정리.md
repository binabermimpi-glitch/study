# 1. Ad-hoc Network 🔥 빈출

## 문제

네트워크의 구성 및 유지를 위해 기지국이나 액세스 포인트와 같은 기반 네트워크 장치를 필요로 하지 않고, 멀티 홉 라우팅 기능에 의해 무선 인터페이스가 가지는 통신 거리상의 제약을 극복하며, 노드들의 이동이 자유롭기 때문에 네트워크 토폴로지가 동적으로 변화되는 특징이 있다.

응용 분야로는 긴급 구조, 긴급회의, 전쟁터에서의 군사 네트워크 등이 있다.

## 정답

**Ad-hoc Network**

## 개념

기지국이나 AP와 같은 고정 인프라 없이 노드들이 서로 직접 통신하여 임시로 구성되는 무선 네트워크이다.

## 핵심

```text
기지국 X
AP X
멀티 홉
노드 이동 자유
토폴로지 동적 변화
→ Ad-hoc Network
```

# 5. 트랜잭션 원자성 🔥🔥 매우 빈출

## 문제

트랜잭션의 특성 중 원자성에 대해 설명하시오.

## 정답

**연산의 결과는 모두 반영되거나 모두 반영되지 않아야 한다.**

## 시험용 답안

> 트랜잭션의 모든 연산은 전부 수행되거나 전부 수행되지 않아야 한다.

---

# ACID

```text
A = Atomicity
C = Consistency
I = Isolation
D = Durability
```

## Atomicity - 원자성

```text
All or Nothing
```

전부 수행 또는 전부 취소

## Consistency - 일관성

트랜잭션 수행 전후 데이터베이스가 일관된 상태를 유지해야 한다.

## Isolation - 격리성 / 독립성

트랜잭션들이 서로 영향을 주지 않고 독립적으로 수행되어야 한다.

## Durability - 영속성

완료된 트랜잭션의 결과는 영구적으로 저장되어야 한다.

## 암기

```text
A 원자성
→ 전부 또는 전무

C 일관성
→ 일관된 상태 유지

I 격리성
→ 서로 간섭 X

D 영속성
→ 결과 영구 저장
```

# 6. 제2정규형(2NF) 🔥🔥 매우 빈출

## 문제

부분 함수적 종속성을 제거하여 완전 함수 종속을 만족하는 정규형이 무엇인지 쓰시오.

## 정답

**제2정규형(2NF)**

## 핵심

```text
부분 함수 종속 제거
→ 2NF
```

---

# 정규화

## 제1정규형(1NF)

속성값이 원자값을 가져야 한다.

```text
반복 속성 제거
→ 1NF
```

## 제2정규형(2NF)

부분 함수 종속을 제거한다.

```text
부분 함수 종속 제거
→ 2NF
```

## 제3정규형(3NF)

이행 함수 종속을 제거한다.

```text
이행 함수 종속 제거
→ 3NF
```

## BCNF

모든 결정자가 후보키가 되도록 한다.

```text
결정자
→ 후보키
```

---

# 키(Key) 🔥🔥

## 슈퍼키

튜플을 유일하게 식별할 수 있는 속성 집합

```text
유일성 O
최소성 X
```

## 후보키

튜플을 유일하게 식별하면서 최소성도 만족

```text
유일성 O
최소성 O
```

## 기본키

후보키 중 대표로 선택된 키

```text
유일성 O
최소성 O
NULL X
```

## 대체키

후보키 중 기본키로 선택되지 않은 키

## 외래키

다른 테이블의 기본키 또는 후보키를 참조하는 키

### 중요 수정

네 필기의

```text
외래키 유일성 최소성 모두 만족
```

은 틀린 내용이다.

외래키는

```text
유일성 필수 X
최소성 필수 X
```

이다.

## 초압축

```text
슈퍼키
→ 유일성

후보키
→ 유일성 + 최소성

기본키
→ 후보키 중 대표

외래키
→ 다른 테이블의 키 참조
```

# 10. LIKE / ORDER BY 🔥🔥 매우 중요

## 문제

다음 테이블에서 이름이 `'이'` 씨로 시작하는 사람을 내림차순 정렬로 출력하는 SQL문을 완성하시오.

## 정답

```sql
SELECT *
FROM 학생
WHERE 이름 LIKE '이%'
ORDER BY 이름 DESC;
```

---

# LIKE

문자열 패턴 검색에 사용한다.

## %

0개 이상의 문자를 의미한다.

```sql
LIKE '이%'
```

→ `이`로 시작

```sql
LIKE '%이'
```

→ `이`로 끝남

```sql
LIKE '%이%'
```

→ `이`가 포함됨

---

# _

한 글자를 의미한다.

```sql
LIKE '이_수'
```

---

# ORDER BY

## ASC

오름차순

```sql
ORDER BY 이름 ASC;
```

## DESC

내림차순

```sql
ORDER BY 이름 DESC;
```

# 11. 로킹(Locking) 🔥🔥 매우 빈출

## 문제

하나의 트랜잭션이 데이터를 액세스하는 동안 다른 트랜잭션이 그 데이터 항목을 액세스할 수 없도록 하는 병행 제어 기법은?

## 정답

**로킹(Locking)**

## 개념

한 트랜잭션이 특정 데이터를 사용하는 동안 다른 트랜잭션의 접근을 제한하여 데이터의 일관성을 유지하는 병행 제어 기법이다.

```text
트랜잭션 A
↓
데이터 Lock
↓
트랜잭션 B 접근 제한
```

## Shared Lock

읽기를 위한 잠금

```text
읽기 가능
쓰기 제한
```

## Exclusive Lock

쓰기 등을 위해 다른 트랜잭션의 접근을 강하게 제한하는 잠금

## 로킹 단위

```text
로킹 단위 작음
→ 동시성 ↑
→ 관리 부담 ↑

로킹 단위 큼
→ 동시성 ↓
→ 관리 부담 ↓
```

# 12. 응집도 🔥🔥 매우 빈출

## 문제

다음 (1), (2), (3)에 설명하는 알맞은 답안을 쓰시오.

(1) 모듈이 다수의 관련 기능을 가질 때 모듈 내부의 기능 요소들이 그 기능을 순차적으로 수행할 경우

(2) 동일한 입력과 출력을 사용하는 소작업들이 모인 경우

(3) 모듈 내부의 모든 기능 요소들이 한 문제와 연관되어 수행되는 경우

## 정답

(1) **절차적 응집도**

(2) **통신적(교환적) 응집도**

(3) **기능적 응집도**

---

# 응집도 순서

응집도는 **높을수록 좋다.**

좋음 → 나쁨

```text
기능적
→ 순차적
→ 통신적
→ 절차적
→ 시간적
→ 논리적
→ 우연적
```

암기:

```text
기순통절시논우
```

---

## 기능적 응집도

모듈 내부의 모든 기능이 하나의 기능에 집중

→ 가장 좋음

## 순차적 응집도

한 작업의 출력이 다음 작업의 입력이 됨

```text
A 출력
↓
B 입력
```

## 통신적 응집도

동일한 입력 또는 출력을 사용하는 작업들이 모임

## 절차적 응집도

기능들이 정해진 순서에 따라 실행

## 시간적 응집도

특정 시점에 함께 수행

예:

```text
초기화
종료 처리
```

## 논리적 응집도

유사한 성격의 작업들을 하나로 묶음

## 우연적 응집도

관련 없는 기능이 하나의 모듈에 모임

→ 가장 나쁨

---

# 응집도와 결합도 같이 외우기 🔥🔥

```text
응집도
→ 높을수록 좋음

결합도
→ 낮을수록 좋음
```

결합도:

```text
강함
내용 → 공통 → 외부 → 제어 → 스탬프 → 자료
약함
```

# 14. 가상회선 / 데이터그램 🔥🔥 중요

## 문제

다음 패킷 교환 방식에 대한 설명으로 (1), (2)에 알맞은 용어를 쓰시오.

(1) 패킷을 전송하기 전에 논리적인 연결을 먼저 수행하여 패킷을 주고받는다.

(2) 각 전송 패킷을 미리 정해진 경로 없이 독립적으로 처리하여 교환하는 방식이다.

## 정답

(1) **가상회선(Virtual Circuit)**

(2) **데이터그램(Datagram)**

---

# 가상회선

패킷 전송 전에 논리적인 경로를 먼저 설정한다.

```text
경로 설정
↓
패킷 전송
```

### 특징

* 연결 설정 필요
* 패킷들이 같은 경로 사용
* 순서대로 도착하기 쉬움

---

# 데이터그램

각 패킷을 독립적으로 처리한다.

```text
패킷 1 → 경로 A
패킷 2 → 경로 B
패킷 3 → 경로 C
```

### 특징

* 사전 연결 없음
* 패킷마다 다른 경로 가능
* 도착 순서가 달라질 수 있음

## 암기

```text
먼저 연결
→ 가상회선

각 패킷 독립
→ 데이터그램
```

# 15. JOIN / ON 🔥🔥 매우 중요

## 문제

학생정보와 학과정보를 조인하여 결과값을 출력하는 SELECT문을 완성하시오.

```sql
SELECT *
FROM 학생정보 T1
JOIN 학과정보 T2
(1) T1.학과 = T2.(2)
```

## 정답

(1) **ON**

(2) **학과**

## 완성

```sql
SELECT *
FROM 학생정보 T1
JOIN 학과정보 T2
ON T1.학과 = T2.학과;
```

---

# JOIN

두 개 이상의 테이블을 관련된 컬럼을 기준으로 결합한다.

## ON

테이블 사이의 연결 조건을 작성한다.

```sql
ON T1.학과 = T2.학과
```

## JOIN 종류

```text
INNER JOIN
→ 양쪽에 모두 존재

LEFT JOIN
→ 왼쪽 전체 + 일치하는 오른쪽

RIGHT JOIN
→ 오른쪽 전체 + 일치하는 왼쪽

FULL OUTER JOIN
→ 양쪽 전체
```

# 18. 화이트박스 테스트 커버리지 🔥🔥 매우 빈출

## 문제

화이트박스 테스트에서 수행하는 구조적 커버리지의 설명으로 알맞은 것을 쓰시오.

(1) 시험 대상의 전체 구문 중 테스트에 의해 실행된 구문을 측정한다.

(2) 시험 대상의 전체 분기 중 테스트에 의해 실행된 것을 측정한다.

(3) 모든 조건식의 True, False 중 테스트에 의해 실행된 것을 측정한다.

## 정답

(1) **구문 커버리지 / 문장 커버리지**

(2) **결정 커버리지 / 분기 커버리지**

(3) **조건 커버리지**

---

# 구문 커버리지

모든 문장을 최소 한 번 이상 실행한다.

```text
모든 구문 실행
→ Statement Coverage
```

---

# 결정 커버리지

결정문의 전체 결과가 각각 True / False가 되도록 한다.

```text
전체 분기
T / F
→ Decision Coverage
```

---

# 조건 커버리지

각 개별 조건식이 각각 True / False가 되도록 한다.

```text
개별 조건
T / F
→ Condition Coverage
```

---

# 추가 커버리지

## 조건/결정 커버리지

```text
개별 조건 T/F
+
전체 결정 T/F
```

## MC/DC

각 개별 조건이 독립적으로 전체 결정 결과를 변화시켜야 한다.

## 다중 조건 커버리지

모든 조건식의 가능한 조합을 테스트한다.

## 경로 커버리지

실행 가능한 모든 경로를 테스트한다.

# 19. 럼바우 객체지향 분석 🔥🔥 매우 빈출

## 문제

럼바우 객체지향 분석 기법의 설명이다. 해당 설명의 유형을 쓰시오.

(1) 자료 흐름도, 프로세스들의 자료 흐름을 중심으로 처리 과정을 표현

(2) 상태 다이어그램, 시간의 흐름에 따라 객체들 사이의 제어 흐름, 동작 순서 등의 동적인 행위를 표현

(3) 객체 다이어그램, 정보 모델링이라고도 하며 시스템에서 요구하는 객체를 찾고 객체들 간의 관계를 정의하며 가장 중요하고 선행되어야 함

## 정답

(1) **기능 모델링(Functional Modeling)**

(2) **동적 모델링(Dynamic Modeling)**

(3) **객체 모델링(Object Modeling)**

---

# 럼바우 분석

## 객체 모델링

객체와 객체 사이의 관계를 표현한다.

```text
객체
속성
관계
→ 객체 모델링
```

가장 먼저 수행하는 모델링이다.

---

# 동적 모델링

시간의 흐름에 따른 객체의 상태 변화와 제어 흐름을 표현한다.

주로:

```text
State Diagram
```

을 사용한다.

```text
시간
상태 변화
제어 흐름
→ 동적 모델링
```

---

# 기능 모델링

데이터의 흐름과 처리 과정을 표현한다.

주로:

```text
DFD
Data Flow Diagram
```

을 사용한다.

```text
자료 흐름
프로세스
DFD
→ 기능 모델링
```

---

# 럼바우 모델링 순서

```text
객체 모델링
→ 동적 모델링
→ 기능 모델링
```

암기:

```text
객동기
```

그리고:

```text
객체
→ Object

동적
→ State

기능
→ DFD
```
