
# Java 헷갈리는 핵심 개념 정리

## 1. return 이후 코드 실행

`return`을 만나면 메서드가 즉시 종료된다.

```java
static int gamja(int n) {
    return n * 2;
    // System.out.println("실행 안 됨");
}
```

- `return` 이후에 도달할 수 없는 실행문을 작성하면 Java에서는 컴파일 오류가 발생한다.
- 단, 조건문 등으로 인해 실행 가능성이 있는 코드는 예외다.
- Python은 일반적으로 실행되지 않는 코드를 허용한다.
- C도 일반적으로 허용하지만 컴파일러에 따라 경고가 발생할 수 있다.

## 2. this() 생성자 호출

`this()`는 같은 클래스의 다른 생성자를 호출한다.

```java
class Student {
    String name;
    String dream;

    Student() {
        this("이름없음", "미정");
    }

    Student(String name, String dream) {
        this.name = name;
        this.dream = dream;
    }
}
```

- `this()` : 같은 클래스의 다른 생성자 호출
- `this.name` : 현재 객체의 필드 접근
- `super()` : 부모 클래스 생성자 호출
- `this()`와 `super()`를 같은 생성자에서 직접 함께 호출할 수 없다.

## 3. static 블록과 생성자 실행 순서

```java
class Parent {
    static { System.out.print("1 "); }
    { System.out.print("2 "); }
    Parent() { System.out.print("3 "); }
}

class Child extends Parent {
    static { System.out.print("4 "); }
    { System.out.print("5 "); }
    Child() { System.out.print("6"); }
}

public class Main {
    public static void main(String[] args) {
        new Child();
        System.out.println();
        new Child();
    }
}
```

### 실행 결과

```text
1 4 2 3 5 6
2 3 5 6
```

### 실행 순서

1. 부모 static 블록 → 1
2. 자식 static 블록 → 4
3. 부모 인스턴스 초기화 블록 → 2
4. 부모 생성자 → 3
5. 자식 인스턴스 초기화 블록 → 5
6. 자식 생성자 → 6

**핵심**

- static 초기화 블록은 클래스 초기화 시 한 번만 실행된다.
- 인스턴스 초기화 블록과 생성자는 객체를 생성할 때마다 실행된다.
- 부모 초기화가 자식 초기화보다 먼저 진행된다.

## 4. super()를 반드시 작성해야 하는 경우

부모 클래스에 매개변수 없는 생성자가 없으면 자식 생성자에서 적절한 부모 생성자를 명시적으로 호출해야 한다.

```java
class Rectangle {
    int width, height;

    Rectangle(int width, int height) {
        this.width = width;
        this.height = height;
    }
}

class Square extends Rectangle {
    Square(int s) {
        super(s, s);
    }
}
```

### super()를 생략할 수 있는 경우

```java
class Rectangle {
    Rectangle() {}
}

class Square extends Rectangle {
    Square() {
        // super() 자동 삽입
    }
}
```

**핵심**

- 부모의 접근 가능한 기본 생성자가 있으면 `super()` 생략 가능
- 부모에 매개변수 생성자만 있으면 `super(인수)` 등을 명시해야 함
- 생성자를 하나라도 직접 선언하면 기본 생성자는 자동 생성되지 않음

## 5. 필드 하이딩 (Field Hiding)

부모와 자식이 같은 이름의 필드를 선언하면 자식 필드가 부모 필드를 가린다.

```java
class Parent {
    String x = "Parent";
}

class Child extends Parent {
    String x = "Child";
}

public class Main {
    public static void main(String[] args) {
        Parent a = new Child();
        Child b = new Child();

        System.out.println(a.x);
        System.out.println(b.x);
    }
}
```

### 실행 결과

```text
Parent
Child
```

**핵심**

- 필드는 참조 변수의 선언 타입을 기준으로 접근한다.
- `Parent a = new Child()`에서 선언 타입은 Parent다.
- 부모 필드가 사라지는 것이 아니라 자식 필드에 가려진다.
- 자식 클래스 내부에서 `super.x`로 부모 필드에 접근할 수 있다.

## 6. 필드 vs 인스턴스 메서드 vs static 메서드

```java
class Parent {
    String name = "Parent";

    int x(int i) {
        return i + 2;
    }

    static String id() {
        return "P";
    }
}

class Child extends Parent {
    String name = "Child";

    @Override
    int x(int i) {
        return i + 3;
    }

    static String id() {
        return "C";
    }
}

public class Main {
    public static void main(String[] args) {
        Parent ref = new Child();

        System.out.println(ref.name);
        System.out.println(ref.x(2));
        System.out.println(ref.id());
    }
}
```

### 실행 결과

```text
Parent
5
P
```

### 호출 기준 비교

| 구분 | 호출 기준 |
|---|---|
| 필드 | 선언 타입 |
| 오버라이딩된 인스턴스 메서드 | 실제 객체 타입 |
| static 메서드 | 선언 타입 |

**핵심**

- `ref.name` → Parent 필드
- `ref.x(2)` → Child 메서드 → 5
- `ref.id()` → Parent static 메서드 → P
- static 메서드는 오버라이딩이 아니라 메서드 하이딩이다.
- static 메서드는 `Parent.id()`처럼 클래스 이름으로 호출하는 것이 권장된다.

※ 인스턴스 메서드는 먼저 선언 타입을 기준으로 호출 가능한 메서드인지 검사하고, 오버라이딩된 구현은 실제 객체 타입을 기준으로 선택한다.

## 7. 섀도잉 (Shadowing)

지역 변수가 필드와 같은 이름이면 가까운 범위의 지역 변수가 우선한다.

```java
class Main {
    static int x = 10;

    static void func() {
        int x = 99;
        System.out.println(x);
    }

    public static void main(String[] args) {
        System.out.println(x);
        func();
        System.out.println(x);
    }
}
```

### 실행 결과

```text
10
99
10
```

**핵심**

- 메서드 내부에서는 지역 변수 `x = 99`가 우선한다.
- 클래스 변수 `x = 10`은 변경되지 않는다.
- 가려진 클래스 변수는 `Main.x`로 접근할 수 있다.

## 8. Java는 항상 Call by Value

Java는 메서드에 인수를 전달할 때 항상 값을 복사한다.

```java
public class Main {
    static void change(int x) {
        x = 100;
    }

    public static void main(String[] args) {
        int a = 10;
        change(a);
        System.out.println(a);
    }
}
```

### 실행 결과

```text
10
```

**핵심**

- `change(a)`는 a의 값 10을 복사하여 전달한다.
- 메서드 내부에서 복사본을 변경해도 원본 a는 변경되지 않는다.

## 9. 배열을 매개변수로 전달하면?

배열은 참조 타입이므로 배열 객체를 가리키는 참조값이 복사된다.

```java
public class Main {
    static void change(String[] data) {
        data[0] = "변경됨";
    }

    public static void main(String[] args) {
        String[] data = {"원본"};
        change(data);
        System.out.println(data[0]);
    }
}
```

### 실행 결과

```text
변경됨
```

**핵심**

- 참조값은 복사되지만 같은 배열 객체를 가리킨다.
- `data[0] = "변경됨"`은 배열 내부 요소를 수정한다.
- 따라서 호출한 쪽에서도 변경된 값이 보인다.

※ Java의 참조값은 객체를 가리키는 값이며, 메모리 주소 자체라고 단정하는 것은 정확하지 않다.

## 10. String 매개변수를 재할당하면?

```java
public class Main {
    static void change(String s) {
        s = "Z";
    }

    public static void main(String[] args) {
        String s = "B";
        change(s);
        System.out.println(s);
    }
}
```

### 실행 결과

```text
B
```

**핵심**

- String도 참조 타입이다.
- `s = "Z"`는 메서드 내부의 지역 변수만 재할당한다.
- 호출한 쪽의 변수는 그대로 "B"를 가리킨다.
- String 객체 자체는 불변(immutable)이다.

### 배열과 String 비교

| 코드 | 원본 영향 |
|---|---|
| `arr[0] = 10` | 배열 요소 변경 |
| `arr = new int[5]` | 원본 변수 변경 없음 |
| `s = "Z"` | 원본 변수 변경 없음 |

## 11. 객체 배열과 참조값 복사

객체 배열에는 객체 자체가 아니라 객체를 가리키는 참조값이 저장된다.

```java
class BO {
    int num;

    BO(int num) {
        this.num = num;
    }
}

public class Main {
    public static void main(String[] args) {
        BO a = new BO(10);
        BO b = new BO(20);

        BO[] arr = {a, b};

        arr[0].num = 99;

        System.out.println(a.num);
    }
}
```

### 실행 결과

```text
99
```

**핵심**

- `arr[0]`과 `a`는 같은 객체를 가리킨다.
- `arr[0].num`을 변경하면 `a.num`에서도 변경된 값이 보인다.
- `arr[0] = new BO(50)`처럼 배열 요소를 재할당하면 a가 가리키는 객체는 그대로 유지된다.

## 12. try-finally와 return

`try`에서 반환값을 정했더라도 `finally`에서 다시 return하면 finally의 반환값이 우선한다.

```java
public class Main {
    static int test() {
        try {
            return 1;
        } finally {
            return 2;
        }
    }

    public static void main(String[] args) {
        System.out.println(test());
    }
}
```

### 실행 결과

```text
2
```

### 실행 순서

1. try에서 반환값 1을 결정
2. 메서드가 종료되기 전 finally 실행
3. finally에서 반환값 2를 결정
4. 최종적으로 2 반환

**핵심**

- finally는 return 직전에도 실행된다.
- finally의 return은 앞서 결정한 반환값을 덮어쓴다.
- 실무에서는 예외를 숨길 수도 있으므로 finally에서 return을 사용하는 것은 피하는 것이 좋다.
