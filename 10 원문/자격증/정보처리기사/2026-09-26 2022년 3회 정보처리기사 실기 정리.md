# 2. Bridge / Observer Pattern 🔥🔥

## 문제

(1) 구현부에서 추상층을 분리하여 각각 독립적으로 변경하고 확장할 수 있도록 하는 디자인 패턴

(2) 한 객체의 상태가 변하면 해당 객체에 의존하는 다른 객체들에게 알리고 자동으로 내용이 갱신되는 디자인 패턴

## 정답

```text
(1) Bridge Pattern
(2) Observer Pattern
```

---

# Bridge Pattern

추상화와 구현을 분리하여 각각 독립적으로 확장할 수 있게 한다.

```text
추상부
↕
Bridge
↕
구현부
```

분류:

```text
구조 패턴
```

핵심:

```text
추상과 구현 분리
→ Bridge
```

---

# Observer Pattern

한 객체의 상태가 변경되면 관련된 다른 객체들에게 자동으로 알린다.

```text
Subject 상태 변경
↓
Observer 1
Observer 2
Observer 3
자동 통지
```

분류:

```text
행위 패턴
```

# 3. UML 구성요소 / 클래스 / 인터페이스 🔥🔥

## 문제

UML은 컴퓨터 애플리케이션을 모델링할 수 있는 통합 언어이다.

구성요소는 사물, (1), 다이어그램으로 이루어져 있다.

구조 다이어그램 중 (2) 다이어그램은 객체들의 타입을 정의하고 객체들 간의 관계를 표현한다.

UML 모델링에서 (3)는 클래스나 컴포넌트가 구현해야 하는 오퍼레이션 집합을 정의한다.

## 정답

```text
(1) 관계
(2) 클래스
(3) 인터페이스
```

## UML 구성 요소

```text
사물(Things)
관계(Relationships)
다이어그램(Diagrams)
```

---

# UML 관계 🔥🔥

## 일반화 관계 Generalization

상위 클래스와 하위 클래스의 관계

```text
IS-A
```

예:

```text
Dog IS-A Animal
```

---

## 연관 관계 Association

두 사물이 서로 구조적으로 관련되어 있는 관계

```text
학생 ─── 강의
```

### 중요 수정

`다른 클래스의 기능을 잠깐 사용한다`는 설명은 연관 관계보다는 **의존 관계**에 가깝다.

---

## 의존 관계 Dependency

한 클래스가 다른 클래스의 기능을 일시적으로 사용하는 관계

```text
짧은 시간 동안 사용
→ Dependency
```

---

## 실체화 관계 Realization

인터페이스와 실제 구현 클래스의 관계

Java에서는:

```java
class Dog implements Animal
```

처럼 `implements`와 연결해서 기억하면 된다.

```text
인터페이스 구현
→ Realization
```

---

## 집약 관계 Aggregation

전체-부분 관계이지만 각각 독립적으로 존재할 수 있다.

```text
약한 has-a
```

예:

```text
Team ◇── Player
```

팀이 없어져도 선수는 존재할 수 있다.

---

## 합성 관계 Composition

전체-부분 관계가 강하게 결합되어 있다.

```text
강한 has-a
```

전체 객체가 사라지면 부분 객체도 함께 사라지는 관계로 본다.

---

# 7. 프로세스 스케줄링 🔥🔥

## 문제

(1) 선점형 스케줄링으로 현재 실행 중인 프로세스보다 남은 실행 시간이 더 짧은 프로세스가 들어오면 CPU를 할당하는 방식

(2) 일정한 시간 단위(Time Quantum)를 정해 프로세스들을 순서대로 실행하는 방식

(3) 비선점형으로 실행 시간이 가장 짧은 프로세스에 CPU를 먼저 할당하는 방식

## 정답

```text
(1) SRT
(2) Round Robin
(3) SJF
```

---

# 선점형 / 비선점형 개념 🔥🔥

## 선점형

CPU를 사용하고 있는 프로세스가 있어도 운영체제가 CPU 사용권을 빼앗을 수 있다.

```text
A 실행 중

더 중요한 B 도착
↓
A 중단
B 실행
```

즉:

```text
실행 도중 CPU 강제로 회수 가능
→ 선점형
```

대표:

```text
SRT
Round Robin
선점형 Priority
MLQ
MLFQ
```

---

# 비선점형

한 프로세스가 CPU를 받으면 스스로 종료하거나 대기 상태로 갈 때까지 CPU를 빼앗지 않는다.

```text
A가 CPU 획득
↓
A가 끝날 때까지 사용
↓
다음 프로세스 실행
```

대표:

```text
FCFS
SJF
HRN
비선점형 Priority
```

---

# SJF

**Shortest Job First**

실행 시간이 가장 짧은 작업부터 실행한다.

```text
비선점형
```

---

# SRT

**Shortest Remaining Time**

SJF의 선점형 버전이다.

현재 실행 중인 프로세스보다 **남은 시간이 더 짧은 프로세스**가 들어오면 교체한다.

```text
SJF
→ 비선점

SRT
→ 선점
```

---

# Round Robin

각 프로세스에 동일한 시간 할당량을 부여한다.

```text
P1 → P2 → P3 → P1 ...
```

Time Quantum이 끝나면 다음 프로세스로 CPU를 넘긴다.

```text
선점형
```

---

# 핵심

```text
선점
→ CPU 뺏기 가능

비선점
→ CPU 뺏기 불가능
```

# 8. FLSM 서브넷 🔥🔥

## 문제

```text
192.168.1.0/24
```

네트워크를 FLSM 방식으로 **3개의 서브넷**으로 나누었을 때 두 번째 네트워크의 브로드캐스트 IP를 쓰시오.

## 정답

```text
192.168.1.127
```

---

# 1단계 - 몇 비트를 빌려야 하는가?

현재:

```text
/24
```

3개의 서브넷이 필요하다.

1비트를 빌리면:

```text
2¹ = 2
```

2개밖에 못 만든다.

2비트를 빌리면:

```text
2² = 4
```

4개의 서브넷 생성 가능.

따라서:

```text
/24 + 2
= /26
```

---

# 2단계 - 서브넷 마스크

`/26`은:

```text
255.255.255.192
```

블록 크기:

```text
256 - 192
= 64
```

---

# 3단계 - 네트워크 나누기

64개 단위로 나눈다.

```text
1번째
192.168.1.0
~
192.168.1.63
```

```text
2번째
192.168.1.64
~
192.168.1.127
```

```text
3번째
192.168.1.128
~
192.168.1.191
```

```text
4번째
192.168.1.192
~
192.168.1.255
```

---

# 두 번째 네트워크

```text
Network
→ 192.168.1.64

사용 가능
→ 192.168.1.65 ~ 126

Broadcast
→ 192.168.1.127
```

따라서 정답:

```text
192.168.1.127
```

---

# FLSM

**Fixed Length Subnet Mask**

모든 서브넷에 같은 크기의 서브넷 마스크를 적용한다.

```text
모든 서브넷 크기 동일
→ FLSM
```

# 14. DISTINCT / COUNT 🔥🔥

## 문제

STUDENT 테이블에:

```text
컴퓨터학과 50명
기계과 100명
건축과 50명
```

총:

```text
200명
```

이 존재한다.

---

## (1)

```sql
SELECT DEPT
FROM STUDENT;
```

## 정답

```text
200개
```

`DISTINCT`가 없으므로 모든 튜플의 학과값이 출력된다.

---

## (2)

```sql
SELECT DISTINCT DEPT
FROM STUDENT;
```

## 정답

```text
3개
```

학과 종류:

```text
컴퓨터학과
기계과
건축과
```

중복 제거 후 3개

---

## (3)

```sql
SELECT COUNT(DISTINCT DEPT)
FROM STUDENT
WHERE DEPT = '건축과';
```

## 정답

```text
1
```

WHERE 처리 후:

```text
건축과 50명
```

이지만:

```text
DISTINCT DEPT
```

를 적용하면 학과명은:

```text
건축과
```

하나뿐이다.

따라서:

```text
COUNT
= 1
```

# 16. C 배열 비교 / 순위 계산 🔥🔥

## 문제

```c
int main() {

    int result[5];

    int ary[] = {77, 32, 10, 99, 50};

    for(int i = 0; i < 5; i++) {

        result[i] = 1;

        for(int j = 0; j < 5; j++)

            if(ary[i] < ary[j])
                result[i]++;
    }

    for(int i = 0; i < 5; i++)
        printf("%d", result[i]);
}
```

## 정답

```text
24513
```

---

# 이 코드가 하는 일

각 숫자보다 **큰 숫자가 몇 개 있는지** 확인한다.

초기 순위는:

```c
result[i] = 1;
```

즉 기본적으로 모두 1등부터 시작한다.

자기보다 큰 값이 발견될 때마다:

```c
result[i]++;
```

한다.
