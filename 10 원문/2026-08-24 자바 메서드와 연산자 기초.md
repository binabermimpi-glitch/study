자바 메서드와 연산자 기초
금일 학습 요약
자바의 플랫폼 독립성과 JVM 실행 환경을 메모리 관점에서 복습하고, 클래스·상속·다형성으로 이어지는 객체지향 프로그래밍의 구조를 확인합니다. 특히 클래스의 속성과 기능 중 메서드는 API를 활용하고 프로그램을 확장하는 핵심 단위이므로, 선언 원형과 호출 방식을 정확히 이해하는 것이 강조됩니다.

정적 메서드의 바인딩, void 메서드와 매개변수 전달, 메서드 오버로딩, 접근 제어자, 클래스 다이어그램 활용을 다룹니다. 또한 연산자의 구성 요소와 우선순위, 증감·논리·비트·시프트 연산의 기본 동작도 함께 정리합니다.

JVM과 정적 영역
JVM은 운영체제가 제공하는 가상 주소 공간에서 자바 실행 환경을 구성하며, 클래스와 static 멤버는 클래스 로딩 시점에 정적 영역과 연관되어 관리됩니다.

자바 프로그램은 운영체제 위에서 JVM을 실행 환경으로 사용합니다. JVM은 물리 메모리를 직접 관리하는 주체가 아니라, 운영체제가 제공하는 가상 메모리와 프로세스 실행 환경을 바탕으로 자바 애플리케이션의 메모리 구조를 구성합니다.

운영체제는 프로세스의 가상 주소 공간, 실제 RAM과 페이지 파일의 매핑, 프로세스별 실행 공간 등을 관리합니다. 따라서 가상 메모리 부족이나 페이지 파일 설정은 JVM만의 문제가 아니라 운영체제 메모리 관리와 관련된 문제입니다.

자바 학습 단계에서는 JVM 메모리를 크게 정적 영역, 스택 영역, 힙 영역으로 구분해 이해할 수 있습니다. 실제 JVM 명세와 구현은 더 복잡하지만, 클래스와 정적 멤버의 공용성 및 객체의 동적 생성 구조를 파악하는 데 이 구분이 유용합니다.

static 멤버는 클래스에 소속되며, 인스턴스를 생성하지 않아도 클래스 이름을 통해 접근할 수 있습니다.
힙 영역은 객체와 배열처럼 실행 중 생성되는 데이터를 저장하는 영역으로 이해할 수 있습니다.
스택 영역은 메서드 호출 흐름과 지역 변수의 생명 주기를 이해하는 데 사용하는 영역입니다.
메서드 실행이 끝난 뒤 더 이상 참조되지 않는 객체는 가비지 컬렉션의 대상이 될 수 있습니다.
static 멤버를 선언과 동시에 주소가 연결된 상태라고 설명할 때 바인드라는 표현을 사용합니다. 이러한 정적 멤버는 클래스 차원에서 공용으로 사용되며, 호출 시 해당 멤버의 주소를 찾아 실행하는 과정을 바인딩으로 이해할 수 있습니다.

메서드 선언과 정적 호출
정적 void 메서드는 값을 반환하지 않고 기능만 수행하며, 일반적으로 클래스명.메서드명() 형태로 호출합니다.

클래스는 속성과 기능으로 구성되며, 자바에서 기능은 메서드로 구현합니다. 객체지향 프로그래밍에서는 직접 모든 코드를 작성하기보다, 클래스와 API가 제공하는 메서드를 목적에 맞게 호출하고 확장하는 방식이 중요합니다.

메서드는 크게 정적 메서드와 인스턴스 메서드로 구분할 수 있습니다. 정적 메서드는 객체 생성 없이 호출할 수 있지만, 인스턴스 메서드는 객체를 생성한 뒤 참조 변수를 통해 호출해야 합니다.

public static void test() {
    System.out.println("실행");
}

public static void main(String[] args) {
    Example.test();
}
정적 메서드의 일반적인 선언 구조는 접근 제어자, static, 반환형, 메서드명, 매개변수, 실행문으로 구성됩니다. 매개변수가 없는 void 메서드는 가장 기본적인 메서드 원형입니다.

접근 제어자는 메서드에 접근할 수 있는 범위를 결정합니다.
static은 메서드가 인스턴스가 아닌 클래스에 소속됨을 나타냅니다.
void는 호출자에게 반환할 값이 없음을 의미합니다.
메서드명 뒤의 괄호는 메서드 호출과 매개변수 선언의 기준이 됩니다.
void는 반환값이 없다는 뜻입니다. 따라서 void 메서드는 실행 결과를 변수에 저장하는 방식으로 사용할 수 없으며, 내부 명령 수행이 끝나면 호출한 위치로 제어가 돌아갑니다.

정적 메서드끼리는 동일한 클래스의 정적 멤버를 직접 활용하기 쉽습니다. 반면 인스턴스에 소속된 멤버는 객체가 생성되어야 접근할 수 있으므로, 정적 메서드에서 인스턴스 멤버를 직접 호출하는 것은 제한됩니다.

매개변수와 오버로딩
매개변수는 호출 시 전달된 값을 메서드 내부에서 사용할 수 있도록 받는 지역 변수이며, 오버로딩은 이름이 같은 메서드를 매개변수 구성으로 구분하는 방식입니다.

매개변수가 있는 메서드는 호출자가 전달한 값을 받아 기능을 수행합니다. 호출 위치에서 전달하는 값을 인수라고 하며, 메서드 선언부에서 이를 받는 변수를 매개변수라고 합니다.

public static void display(int value) {
    System.out.println(value);
}

public static void main(String[] args) {
    Example.display(10);
}
display(10)이 호출되면 value라는 정수형 매개변수가 생성되고, 전달된 10으로 초기화됩니다. 매개변수는 메서드 내부에서만 유효한 지역 변수이므로 메서드 실행이 끝나면 사용할 수 없습니다.

매개변수의 자료형은 호출 시 전달하는 값의 자료형과 호환되어야 합니다.
매개변수는 호출 시 전달된 값으로 초기화되므로 별도의 초기화 값을 작성할 필요가 없습니다.
메서드 내부에서 선언한 변수와 매개변수는 모두 해당 메서드의 지역 변수입니다.
서로 다른 메서드에 같은 이름의 지역 변수가 있어도 각각 별도의 저장 공간을 사용합니다.
오버로딩은 하나의 클래스 안에서 같은 이름의 메서드를 여러 개 선언하는 기능입니다. 메서드명은 같아도 매개변수의 자료형 또는 개수가 다르면 서로 다른 메서드로 인식됩니다.

public static void display(int value) {
    System.out.println(value);
}

public static void display(String value) {
    System.out.println(value);
}

public static void display(String first, String second) {
    System.out.println(first + second);
}
오버로딩의 목적은 메서드 이름이 전달하는 의미를 유지하는 것입니다. 예를 들어 print, sum, format처럼 기능의 목적은 같지만 입력값의 자료형이나 개수가 다른 경우, 여러 메서드명을 만들지 않고 동일한 이름을 일관되게 사용할 수 있습니다.

구분	허용 여부	예시
메서드명만 동일	허용됩니다.	sum(...)
매개변수 자료형이 다름	허용됩니다.	sum(int)과 sum(double)
매개변수 개수가 다름	허용됩니다.	sum(int, int)과 sum(int, int, int)
이름·자료형·개수가 모두 같음	허용되지 않습니다.	동일한 선언의 중복입니다.
자바 API의 System.out.println()과 print()는 대표적인 오버로딩 사례입니다. 정수, 실수, 문자, 문자열, 객체 등 다양한 자료형을 받을 수 있도록 여러 메서드 원형이 제공됩니다.

접근 제어와 클래스 다이어그램
접근 제어자는 클래스와 멤버의 사용 범위를 제한하며, 클래스 다이어그램은 필드·생성자·메서드의 구조와 정적 여부를 시각적으로 표현합니다.

접근 제어자는 클래스, 필드, 메서드의 접근 가능 범위를 지정합니다. 외부에 공개할 기능과 내부 구현으로 감출 기능을 분리하면 캡슐화를 강화하고 코드의 변경 영향을 줄일 수 있습니다.

접근 제어자	같은 클래스	같은 패키지	상속 관계	다른 패키지
public	가능합니다.	가능합니다.	가능합니다.	가능합니다.
protected	가능합니다.	가능합니다.	가능합니다.	제한적으로 가능합니다.
기본 접근 제어	가능합니다.	가능합니다.	제한됩니다.	불가능합니다.
private	가능합니다.	불가능합니다.	불가능합니다.	불가능합니다.
정적 메서드는 클래스에 소속되므로 클래스명.메서드명()으로 호출할 수 있습니다. 반면 정적 키워드가 없는 메서드는 인스턴스 메서드이므로 객체 생성 후 참조변수.메서드명() 방식으로 호출해야 합니다.

public class Calculator {
    public void multiply(double x, double y) {
        System.out.println(x * y);
    }
}

Calculator calculator = new Calculator();
calculator.multiply(3.2, 4.5);
클래스 다이어그램은 클래스 구조를 상자 형태로 표현합니다. 일반적으로 클래스명, 필드, 생성자, 메서드를 구분해 표시하며, 정적 멤버 여부와 접근 수준도 함께 확인할 수 있습니다.

클래스 다이어그램을 먼저 보고 메서드의 이름, 반환형, 매개변수 구조를 파악한 뒤 코드를 작성하면 객체지향 구조를 더 명확하게 설계할 수 있습니다. 코드만 순서대로 읽기보다 결과와 구조를 먼저 설계하는 방식이 유지보수에 유리합니다.

클래스 다이어그램은 여러 클래스 간의 관계와 역할을 빠르게 확인하는 데 활용됩니다.
메서드 목록은 클래스가 제공하는 기능의 인터페이스 역할을 합니다.
정적 메서드는 다이어그램에서 별도 기호 또는 밑줄 등의 규칙으로 표현될 수 있습니다.
API 문서와 클래스 다이어그램을 함께 보면 호출 가능한 메서드를 더 빠르게 찾을 수 있습니다.

연산자와 우선순위
연산자는 피연산자에 대해 계산을 수행하는 기호이며, 자바는 산술·관계·논리·비트·시프트 연산자와 우선순위 규칙을 제공합니다.

연산식은 피연산자와 연산자로 구성됩니다. 피연산자는 연산 대상 데이터이며, 연산자는 데이터를 계산하거나 비교하기 위한 기호입니다. 피연산자 수에 따라 단항, 이항, 삼항 연산자로 분류합니다.

구분	피연산자 수	대표 예시
단항 연산자	1개	++x, --x, !flag
이항 연산자	2개	a + b, a > b, a && b
삼항 연산자	3개	condition ? a : b
증감 연산자는 변수 값을 1씩 증가 또는 감소시킵니다. 전위 연산은 값을 먼저 변경한 뒤 사용하고, 후위 연산은 현재 값을 먼저 사용한 뒤 값을 변경합니다.

int x = 5;
int y = x++;
// y는 5이고, x는 6입니다.
연산식에 여러 연산자가 포함되면 우선순위가 적용됩니다. 일반적으로 괄호를 가장 먼저 계산하고, 이후 단항 연산, 곱셈·나눗셈·나머지 연산, 덧셈·뺄셈 순서로 계산합니다. 복잡한 식은 괄호를 명시해 의도를 분명히 하는 것이 안전합니다.

논리 연산자는 boolean 값의 참과 거짓을 조합합니다. 논리 AND는 양쪽 조건이 모두 참일 때 참이며, 논리 OR는 한쪽 조건만 참이어도 참입니다. 논리 NOT은 참과 거짓을 반전합니다.

비트 연산자는 정수 값을 이진수 비트 단위로 처리합니다. AND, OR, XOR, NOT 연산은 각 비트의 조합에 따라 결과 비트를 만들며, 비트 시프트 연산은 비트를 좌우로 이동시켜 곱셈이나 나눗셈과 유사한 효과를 만들 수 있습니다.

왼쪽 시프트는 비트를 왼쪽으로 이동시키며 일반적으로 2의 거듭제곱 곱셈과 관련됩니다.
오른쪽 시프트는 비트를 오른쪽으로 이동시키며 일반적으로 2의 거듭제곱 나눗셈과 관련됩니다.
시프트 연산은 정수 계열인 byte, short, int, long, char에 적용됩니다.
부동소수점형과 boolean에는 시프트 연산을 적용할 수 없습니다.
