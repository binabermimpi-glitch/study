# 백엔드 개발과 취업 준비

## 금일 학습 요약

백엔드 개발 과정의 전체 기술 로드맵을 기준으로 Java 기초, 객체지향 프로그래밍, 관계형 데이터베이스, 프론트엔드, Spring Boot, DevOps, 프로젝트와 배포 자동화의 연결 구조를 정리했습니다. 특히 AI 코딩 도구는 코드 생성 자체보다 생성 결과를 이해하고 검증, 수정, 책임지는 역량이 핵심임을 강조했습니다.

또한 Java 실행 환경을 직접 설치하고 JDK, JRE, JVM, 컴파일 과정, 공식 문서와 API 문서 활용법을 살펴보았습니다. 취업 준비에서는 학습, 실습, 프로젝트의 과정을 지속적으로 기록하여 이력서와 포트폴리오를 수료 시점에 완성하는 전략을 다루었습니다.

## 백엔드 개발 로드맵

> Java 기반의 기초 역량을 바탕으로 데이터베이스, 웹 애플리케이션, Spring Boot, DevOps, AI 기능과 프로젝트 배포까지 확장하는 풀스택 백엔드 개발 흐름입니다.

백엔드 개발은 단순히 서버 코드를 작성하는 역할에 한정되지 않습니다. 객체지향 설계, 데이터 저장 구조, API 구현, 인증, 배포와 운영 관측까지 연결된 시스템을 다룰 수 있어야 합니다.

과정의 기술 흐름은 기초 문법을 학습한 뒤 실제 서비스 구조를 구축하는 방향으로 구성됩니다. 프론트엔드 학습은 백엔드 서버가 제공하는 데이터를 UI에서 어떻게 소비하는지 이해하기 위한 기반이 됩니다.

| 학습 단계 | 핵심 기술 | 개발 관점 |
|---|---|---|
| 기초 프로그래밍 | Java 문법과 객체지향 프로그래밍 | 프로그램 구조와 코드 재사용 원리를 이해합니다. |
| 데이터 처리 | 관계형 데이터베이스와 SQL | 서비스 데이터를 모델링하고 조회, 저장합니다. |
| 웹 애플리케이션 | HTML, JavaScript, 프론트엔드 | API와 사용자 화면의 연결 방식을 이해합니다. |
| 백엔드 심화 | Spring Boot와 인증 | 서버 애플리케이션과 REST API를 구현합니다. |
| 운영과 배포 | Linux, Docker, CI/CD, 모니터링 | 애플리케이션을 안정적으로 배포하고 운영합니다. |

프로젝트는 개인 또는 팀 단위로 진행되며, 요구사항을 구현 가능한 기능으로 분해하는 과정이 중요합니다. 요구사항 정의서, 데이터 모델, API 설계, 역할 분담, 결과물 문서화가 모두 실제 개발 산출물에 포함됩니다.

최종 배포 흐름에서는 소스 코드를 Git으로 관리하고, CI 도구로 빌드와 테스트를 수행하며, Docker 이미지로 패키징한 애플리케이션을 실행 환경에 배포합니다. 이후 모니터링 도구를 통해 서비스 상태와 지표를 확인합니다.

- Git은 코드 변경 이력을 관리하고 협업 시 충돌을 조정하는 버전 관리 도구입니다.
- Jenkins와 같은 CI 도구는 코드 변경 이후 빌드와 테스트를 자동으로 실행합니다.
- Docker는 애플리케이션과 실행 환경을 이미지로 묶어 배포 일관성을 높입니다.
- 모니터링 도구는 서버 상태와 애플리케이션 지표를 수집하여 장애 대응을 돕습니다.

### 핵심 키워드
`Java` `Spring Boot` `REST API` `Docker` `CI/CD`

## AI 에이전트와 코드 검증

> AI 기반 개발의 핵심은 자연어로 코드를 생성하는 능력이 아니라 생성된 코드의 구조, 정확성, 품질을 검증하고 수정하는 역량입니다.

바이브 코딩은 자연어 프롬프트를 바탕으로 AI가 코드 초안을 생성하도록 하는 개발 방식입니다. 코드 작성 속도를 높일 수 있지만, 요구사항이 모호하거나 개발자가 기본 개념을 이해하지 못하면 부정확한 결과를 그대로 수용하게 될 위험이 있습니다.

AI 에이전트 기반 개발은 요구사항 분석, 데이터베이스 설계, API 구현, 테스트, 결과 검증의 단계를 연결합니다. 개발자는 에이전트가 만든 결과를 조합하는 역할을 넘어, 요구사항에 부합하는지 판단하고 오류를 수정해야 합니다.

| 개발 단계 | AI 활용 가능 영역 | 개발자 책임 |
|---|---|---|
| 요구사항 분석 | 기능 목록과 사용자 시나리오 초안을 생성합니다. | 요구사항의 범위와 우선순위를 확정합니다. |
| 설계 | 데이터 모델과 API 구조의 초안을 제안합니다. | 도메인 규칙과 확장성을 검토합니다. |
| 구현 | 반복 코드와 기능 구현 예시를 생성합니다. | 코드 품질, 보안, 예외 처리를 수정합니다. |
| 테스트 | 테스트 케이스와 오류 원인을 제안합니다. | 재현 여부와 수정 결과를 검증합니다. |

AI가 생성한 코드는 정답이 아니라 검토 대상입니다. 특히 여러 에이전트가 제안한 코드를 병합할 때는 의존성 충돌, 보안 취약점, 성능 저하, 도메인 규칙 누락 여부를 확인해야 합니다.

- AI에게 요청하기 전에는 입력값, 출력값, 예외 상황, 완료 조건을 명확히 정의해야 합니다.
- 생성된 코드에는 로직 오류와 불필요한 의존성이 포함될 수 있으므로 직접 실행해야 합니다.
- 오류가 발생하면 단순 재생성보다 원인 분석과 수정 과정을 기록하는 편이 중요합니다.
- 프로젝트 단계에서는 AI 도구를 설계, 구현, 테스트 보조 수단으로 활용할 수 있습니다.

기초 문법과 객체지향 개념을 익히는 단계에서는 AI 답변을 그대로 복사하는 방식보다 직접 구현하고 오류를 해결하는 과정이 중요합니다. 이후 프로젝트에서는 AI를 활용하되, 코드의 책임 주체가 개발자라는 원칙을 유지해야 합니다.

### 핵심 키워드
`바이브 코딩` `AI 에이전트` `프롬프트` `코드 검증` `문제 해결`

## Java 실행 환경과 공식 문서

> Java 프로그램은 개발 도구인 JDK로 작성, 컴파일되며, JVM이 운영체제 차이를 추상화하여 컴파일된 바이트코드를 실행합니다.

Java는 객체지향 프로그래밍 언어이며, 다양한 운영체제에서 동일한 프로그램을 실행할 수 있도록 설계되었습니다. Java 코드는 운영체제별 실행 파일로 바로 변환되지 않고, JVM이 이해할 수 있는 바이트코드로 컴파일됩니다.

Java 실행 환경은 JDK, JRE, JVM의 포함 관계로 이해할 수 있습니다. 개발자는 JDK를 설치하며, JDK에는 실행 환경인 JRE와 가상 머신인 JVM이 포함됩니다.

| 구성 요소 | 역할 | 포함 관계 |
|---|---|---|
| JVM | Java 바이트코드를 운영체제 위에서 실행합니다. | JRE에 포함됩니다. |
| JRE | JVM과 실행에 필요한 라이브러리를 제공합니다. | JDK에 포함됩니다. |
| JDK | 컴파일러와 개발 도구를 포함한 Java 개발 환경입니다. | 개발자가 설치하는 패키지입니다. |

JDK 배포판에는 Oracle JDK, OpenJDK, Amazon Corretto 등이 있습니다. 배포판마다 제공 주체와 지원 정책은 다를 수 있지만, 표준 Java 기능을 학습하고 일반적인 애플리케이션을 개발하는 데에는 동일한 Java 생태계를 활용합니다.

LTS(Long-Term Support) 버전은 장기간 유지보수와 보안 업데이트가 제공되는 버전입니다. Java 8, 11, 17, 21, 25는 대표적인 LTS 계열이며, 실무에서는 안정적인 운영을 위해 LTS 버전을 중심으로 선택합니다.

Java 프로그램은 `.java` 소스 파일을 작성한 후 `javac` 컴파일러로 `.class` 바이트코드 파일을 생성합니다. 이후 `java` 명령어가 JVM을 통해 클래스 파일을 실행합니다.

```bash
javac Hello.java
java Hello
```

`javac`는 컴파일러이며, 사람이 작성한 Java 소스 코드를 JVM이 실행할 수 있는 바이트코드로 변환합니다. 컴파일러와 인터프리터의 차이, 바이트코드의 의미, JVM의 실행 역할을 함께 이해해야 Java 실행 구조를 정확히 파악할 수 있습니다.

공식 문서는 언어 문법, 표준 라이브러리, API 사용법을 확인하는 가장 신뢰도 높은 자료입니다. 특정 기능을 사용하기 전에는 블로그 예제만 참조하기보다 클래스, 메서드, 매개변수, 반환값, 예외 조건을 API 문서에서 직접 확인하는 습관이 필요합니다.

- Java API 문서는 표준 클래스와 메서드의 사용 조건을 확인하는 기준 문서입니다.
- Java 튜토리얼은 언어의 기본 구조와 핵심 개념을 단계적으로 설명합니다.
- 개발 중 오류가 발생하면 에러 메시지와 공식 문서의 예외 설명을 함께 확인해야 합니다.
- 공식 문서를 탐색하는 능력은 새로운 라이브러리와 회사 내부 API를 빠르게 이해하는 기반이 됩니다.

### 핵심 키워드
`JDK` `JRE` `JVM` `javac` `공식 문서`

## 기록 기반 취업 준비

> 학습, 실습, 프로젝트의 경험을 진행 중에 기록하면 수료 시점에 이력서와 포트폴리오를 빠르게 완성하고 즉시 지원할 수 있습니다.

취업 준비를 수료 이후에 시작하면 프로젝트의 세부 내용, 오류 해결 과정, 기여 역할이 기억에서 사라질 수 있습니다. 학습 과정과 동시에 기록을 남기면 실습 경험을 이력서와 포트폴리오의 근거 자료로 전환할 수 있습니다.

학습 기록은 단순한 수업 요약이 아니라 핵심 개념을 자신의 언어로 설명하고, 구현 결과와 문제 해결 과정을 남기는 활동입니다. 특히 오류를 어떻게 재현하고 어떤 가설을 세워 해결했는지 기록하면 기술 면접에서 설명할 수 있는 사례가 됩니다.

- 학습 기록에는 핵심 개념, 이해가 어려운 부분, 해결 방법을 함께 작성해야 합니다.
- 실습 기록에는 목표, 구현 방법, 실행 결과, 오류와 해결 과정을 포함해야 합니다.
- 프로젝트 기록에는 역할, 사용 기술, 기능 기여도, 구조도, 결과 화면을 남겨야 합니다.
- 실패한 시도도 원인과 배운 점을 정리하면 문제 해결 역량을 보여주는 자료가 됩니다.

프로젝트를 시작할 때는 목표와 KPI, 기술 스택, 담당 역할을 문서화하는 것이 좋습니다. 진행 중에는 기능별 기여 내용과 의사결정 이유를 기록하고, 종료 후에는 문제 상황과 해결 과정을 기술 문서로 정리해야 합니다.

문제 해결 사례는 `문제 발생 → 원인 가설 → 해결 시도 → 결과 확인 → 개선점` 흐름으로 작성하면 논리성이 높아집니다. 해결에 실패한 사례도 시도한 접근과 한계를 명확히 설명하면 분석 역량을 보여줄 수 있습니다.

| 기록 대상 | 필수 기록 요소 | 취업 활용 방식 |
|---|---|---|
| 일일 학습 | 핵심 용어, 개념 요약, 질문과 답변 | 기술 이해도와 학습 지속성을 보여줍니다. |
| 실습 결과 | 구현 목표, 코드, 오류, 화면 캡처 | 포트폴리오의 기능 구현 근거가 됩니다. |
| 프로젝트 | 역할, 기술 스택, 기여, 구조, 성과 | 이력서와 면접의 핵심 경험이 됩니다. |
| 채용 공고 | 요구 기술, 우대 조건, 핵심 키워드 | 목표 직무에 맞는 역량 계획을 세웁니다. |

채용 공고를 지속적으로 분석하면 백엔드 개발 직무에서 반복적으로 요구하는 기술과 역량을 파악할 수 있습니다. 공고 속 핵심 키워드를 추출하고, 자신의 프로젝트 경험을 해당 요구사항과 연결하는 방식으로 이력서를 개선할 수 있습니다.

이력서는 프로젝트가 끝날 때마다 바로 업데이트하는 방식이 효과적입니다. 수료 이전부터 초안을 작성하고 경험을 누적하면, 수료 시점에는 지원 가능한 수준의 이력서와 포트폴리오를 갖출 수 있습니다.

### 핵심 키워드
`TIL` `포트폴리오` `이력서` `문제 해결` `채용 공고 분석`
