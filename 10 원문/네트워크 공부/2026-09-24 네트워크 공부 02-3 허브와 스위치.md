네트워크 공부 02

02-3 허브

1. 물리 계층 장비와 데이터 링크 계층 장비

네트워크 장비는 동작하는 계층에 따라 처리할 수 있는 정보가 다르다.

물리 계층의 대표 장비

- 허브
- 리피터
- 주소 개념이 없음
- 비트와 전기·광 신호를 처리
- 반이중 통신
- 충돌 가능
- CSMA/CD 사용

데이터 링크 계층의 대표 장비

- 스위치
- 브리지
- MAC 주소를 인식
- 이더넷 프레임을 처리
- 전이중 통신 지원
- 포트별로 콜리전 도메인 분리
- VLAN 구성 가능


2. 물리 계층과 데이터 링크 계층의 차이

물리 계층에는 주소 개념이 없다.

물리 계층은 호스트와 통신 매체를 연결하고, 통신 매체를 통해 비트 신호를 송수신하는 역할을 담당한다.

물리 계층 장비는 이더넷 프레임의 MAC 주소나 데이터 내용을 해석하지 않는다.

다만 리피터처럼 약해진 신호를 증폭하거나 재생하고, 허브처럼 수신한 신호를 다른 포트로 전달할 수는 있다.

따라서 “물리 계층 장비는 신호를 전혀 조작하지 않는다”보다는 “프레임의 주소와 내용을 해석하여 전달 여부를 판단하지 않는다”라고 이해하는 것이 정확하다.


데이터 링크 계층에는 MAC 주소 개념이 있다.

데이터 링크 계층 장비는 이더넷 프레임의 MAC 주소를 확인하여 송신지와 수신지를 구분할 수 있다.

따라서 다음과 같은 판단을 할 수 있다.

- 어느 포트로 프레임을 전달할지 결정
- 불필요한 포트로 프레임이 전달되지 않도록 차단
- 오류가 발생한 프레임 폐기
- VLAN을 이용하여 논리적으로 네트워크 분리


3. 허브

허브(hub)는 여러 호스트를 연결하는 물리 계층의 네트워크 장비이다.

오늘날에는 허브보다 스위치를 주로 사용하지만, 허브와 스위치의 차이를 이해하기 위해 허브의 동작 방식을 알아둘 필요가 있다.


4. 허브의 특징 1 모든 포트로 신호 전달

허브는 한 포트에서 신호를 받으면 신호를 받은 포트를 제외한 다른 모든 포트로 해당 신호를 전달한다.

허브는 물리 계층 장비이므로 이더넷 프레임의 수신지 MAC 주소를 확인하지 않는다.

예시

호스트 A가 호스트 C에게 데이터를 전송한다.

A ─┐
B ─┤
C ─┤ 허브
D ─┘

허브는 수신지가 C라는 사실을 판단하지 못한다.

따라서 A가 보낸 신호를 B, C, D가 연결된 모든 포트로 전달한다.

각 호스트의 NIC가 수신지 MAC 주소를 확인한다.

- 호스트 C: 자신의 MAC 주소이므로 프레임 수신
- 호스트 B: 자신과 관계없는 프레임이므로 폐기
- 호스트 D: 자신과 관계없는 프레임이므로 폐기

중요

허브가 MAC 주소를 확인하여 프레임을 폐기하는 것이 아니다.

허브는 모든 포트로 신호를 전달하고, 각 호스트의 NIC가 MAC 주소를 확인하여 자신과 관계없는 프레임을 폐기한다.


5. 허브의 특징 2 반이중 통신

허브는 일반적으로 반이중 통신을 사용한다.


반이중 통신 Half Duplex

양방향으로 통신할 수 있지만, 양쪽이 동시에 송신할 수는 없는 방식이다.

한쪽이 송신하는 동안 다른 쪽은 수신해야 한다.

1차선 도로에서 자동차가 번갈아 이동하는 것과 비슷하다.

예시

- 무전기
- 허브를 사용하는 이더넷


전이중 통신 Full Duplex

양쪽 장치가 동시에 데이터를 송수신할 수 있는 방식이다.

송신과 수신을 동시에 할 수 있다.

예시

- 전화 통화
- 스위치를 사용하는 현대적인 이더넷


6. 리피터

리피터(repeater)는 허브와 함께 물리 계층의 대표적인 장비이다.

전기 신호는 통신 매체를 따라 이동하면서 약해지거나 왜곡될 수 있다.

리피터는 약해지거나 왜곡된 신호를 재생하거나 증폭하여 더 먼 거리까지 전달한다.

리피터도 물리 계층 장비이므로 MAC 주소나 프레임의 내용을 해석하지 않는다.

허브는 여러 포트를 가진 리피터라고 볼 수 있으며, 리피터의 기능을 포함하는 경우가 많다.


7. 허브와 충돌

허브에 연결된 호스트들은 하나의 통신 매체를 공유하는 것처럼 동작한다.

여러 호스트가 동시에 데이터를 전송하면 신호가 서로 겹치면서 충돌이 발생한다.

허브에 연결된 호스트가 많을수록 동시에 데이터를 전송할 가능성이 커지므로 충돌 발생 가능성도 높아진다.


8. 콜리전 도메인

콜리전 도메인(collision domain)은 데이터 충돌이 발생할 수 있는 네트워크 영역이다.

허브에 연결된 모든 호스트는 하나의 콜리전 도메인에 속한다.


콜리전 도메인 구조

┌───────────────────────────────────────┐
│           하나의 콜리전 도메인        │
│                                       │
│   호스트 A  호스트 B  호스트 C  호스트 D │
│       │       │       │       │       │
│       └───────┴── 허브 ┴───────┘       │
└───────────────────────────────────────┘


허브에서는 모든 호스트가 같은 통신 영역을 공유한다.

따라서 A와 B가 동시에 데이터를 전송하면 충돌이 발생할 수 있다.

허브에 연결된 호스트가 많아질수록 콜리전 도메인이 넓어지고 충돌 가능성도 커진다.


9. 넓은 콜리전 도메인의 문제 해결

허브의 넓은 콜리전 도메인으로 발생하는 충돌 문제는 다음과 같은 방법으로 해결할 수 있다.

- CSMA/CD를 사용하여 충돌을 감지하고 재전송
- 허브 대신 스위치를 사용하여 콜리전 도메인 분리

CSMA/CD는 충돌 자체를 완전히 방지하는 기술이 아니다.

충돌 가능성을 줄이고, 충돌이 발생했을 때 이를 감지하여 처리하는 방식이다.


10. CSMA/CD

CSMA/CD는 Carrier Sense Multiple Access with Collision Detection의 약자이다.

반이중 이더넷에서 여러 호스트가 하나의 통신 매체를 공유할 때 충돌을 감지하고 처리하는 방식이다.


(1) Carrier Sense 캐리어 감지

데이터를 전송하기 전에 통신 매체가 사용 중인지 확인한다.

다른 호스트가 데이터를 전송하고 있다면 기다린다.


(2) Multiple Access 다중 접근

여러 호스트가 하나의 통신 매체를 함께 사용한다.

통신 매체가 비어 있다고 판단한 여러 호스트가 거의 동시에 데이터를 전송하면 충돌이 발생할 수 있다.


(3) Collision Detection 충돌 검출

데이터를 전송하면서 충돌이 발생했는지 확인한다.

충돌이 발생하면 다음 순서로 처리한다.

1. 데이터 전송을 중단한다.
2. 충돌이 발생했다는 것을 알리는 잼 신호를 보낸다.
3. 임의의 시간 동안 기다린다.
4. 통신 매체가 사용 중인지 다시 확인한다.
5. 통신 매체가 비어 있으면 데이터를 재전송한다.


CSMA/CD 동작 흐름

전송할 데이터 발생
        ↓
통신 매체가 사용 중인가?
    ┌───┴───┐
   예       아니요
   ↓          ↓
대기       데이터 전송
              ↓
        충돌이 발생했는가?
          ┌───┴───┐
         예       아니요
         ↓          ↓
     전송 중단    전송 완료
         ↓
      잼 신호 전송
         ↓
    임의의 시간 동안 대기
         ↓
         재전송


11. CSMA/CD와 현대 이더넷

CSMA/CD는 허브를 사용하는 반이중 이더넷에서 필요하다.

현대 이더넷에서는 대부분 스위치와 전이중 통신을 사용한다.

전이중 통신에서는 송신과 수신에 서로 다른 통신 경로를 사용하므로 충돌이 발생하지 않는다.

따라서 현대적인 스위치 기반 전이중 이더넷에서는 CSMA/CD가 필요하지 않다.



02-4 스위치

1. 스위치란?

스위치(switch)는 데이터 링크 계층의 대표적인 네트워크 장비이다.

허브가 수신한 신호를 모든 포트로 전달하는 것과 달리, 스위치는 이더넷 프레임의 MAC 주소를 확인하여 필요한 포트로만 프레임을 전달할 수 있다.

스위치는 일반적으로 전이중 통신을 지원하므로 CSMA/CD가 필요하지 않다.


2. 허브의 충돌 문제를 해결하는 방법

허브의 충돌 문제는 CSMA/CD로 어느 정도 처리할 수 있지만 근본적으로 충돌 가능성이 사라지는 것은 아니다.

더 근본적인 해결 방법은 다음과 같다.

- 프레임을 수신지 호스트가 연결된 포트로만 전달
- 포트별로 독립적인 통신 경로 사용
- 전이중 통신 사용

이러한 기능을 제공하는 장비가 스위치이다.


3. 허브와 스위치 비교

허브

- 물리 계층 장비
- 주소 개념이 없음
- MAC 주소를 확인하지 않음
- 수신한 신호를 다른 모든 포트로 전달
- 반이중 통신
- 연결된 모든 호스트가 하나의 콜리전 도메인
- 충돌 가능
- CSMA/CD 사용


스위치

- 데이터 링크 계층 장비
- MAC 주소를 확인
- 필요한 포트로만 프레임 전달 가능
- 전이중 통신 지원
- 포트별로 콜리전 도메인 분리
- 충돌 발생 가능성이 매우 낮음
- 전이중 통신에서는 CSMA/CD가 필요하지 않음
- VLAN 구성 가능


4. 스위치의 주요 기능

스위치의 대표적인 기능은 다음과 같다.

(1) MAC 주소 학습 기능

- 송신지 MAC 주소 학습
- MAC 주소 테이블 작성
- 필요한 포트로만 프레임 전달
- 포트별로 콜리전 도메인 분리


(2) VLAN 기능

- 하나의 물리적 스위치를 여러 개의 논리적인 LAN으로 분리
- 브로드캐스트 도메인 분리
- 불필요한 트래픽 감소
- 네트워크 성능과 보안 향상


5. 스위치와 콜리전 도메인

스위치는 각각의 포트를 별도의 콜리전 도메인으로 나눈다.

스위치 구조

┌──────────────┐  ┌──────────────┐
│ 콜리전 도메인 1 │  │ 콜리전 도메인 2 │
│    호스트 A     │  │    호스트 B     │
└───────┬──────┘  └───────┬──────┘
        │                 │
        └────── 스위치 ────┘
        │                 │
┌───────┴──────┐  ┌───────┴──────┐
│ 콜리전 도메인 3 │  │ 콜리전 도메인 4 │
│    호스트 C     │  │    호스트 D     │
└──────────────┘  └──────────────┘

스위치의 포트마다 독립된 콜리전 도메인이 형성된다.

따라서 한 포트에서 발생하는 통신이 다른 포트의 통신과 충돌하지 않는다.


6. MAC 주소 학습 기능

스위치의 MAC 주소 학습 기능을 MAC address learning이라고 한다.

스위치는 특정 포트와 해당 포트에 연결된 호스트의 MAC 주소 관계를 기억한다.

이 관계를 기록한 표를 MAC 주소 테이블이라고 한다.


MAC 주소 테이블 예시

포트        MAC 주소
1번 포트    AA:AA:AA:AA:AA:01
2번 포트    BB:BB:BB:BB:BB:02
3번 포트    CC:CC:CC:CC:CC:03
4번 포트    DD:DD:DD:DD:DD:04


스위치는 이 테이블을 이용하여 원하는 수신지가 연결된 포트로만 프레임을 전달한다.


7. 스위치는 어떤 주소를 학습하는가?

스위치는 프레임의 송신지 MAC 주소를 보고 MAC 주소를 학습한다.

중요

- 송신지 MAC 주소: 학습할 때 사용
- 수신지 MAC 주소: 전달할 포트를 결정할 때 사용


예시

호스트 A가 1번 포트를 통해 프레임을 전송했다.

프레임 정보

- 송신지 MAC 주소: A
- 수신지 MAC 주소: C
- 프레임이 들어온 포트: 1번 포트

스위치는 다음 관계를 학습한다.

1번 포트 ↔ 호스트 A의 MAC 주소


8. 스위치의 프레임 처리 순서

스위치가 프레임을 받으면 다음 순서로 처리한다.

1. 프레임이 들어온 포트를 확인한다.
2. 송신지 MAC 주소를 확인한다.
3. 송신지 MAC 주소와 들어온 포트의 관계를 MAC 주소 테이블에 저장한다.
4. 수신지 MAC 주소를 확인한다.
5. MAC 주소 테이블에서 수신지 MAC 주소를 검색한다.
6. 검색 결과에 따라 플러딩, 포워딩 또는 필터링한다.


9. 플러딩 Flooding

플러딩은 프레임이 들어온 포트를 제외한 다른 모든 포트로 프레임을 전달하는 동작이다.

스위치의 MAC 주소 테이블에 수신지 MAC 주소가 등록되어 있지 않을 때 플러딩이 발생한다.

이를 알 수 없는 유니캐스트 또는 Unknown Unicast라고 한다.


플러딩 예시

호스트 A가 호스트 C에게 프레임을 보낸다.

MAC 주소 테이블

포트        MAC 주소
1번 포트    호스트 A
2번 포트    등록되지 않음
3번 포트    등록되지 않음
4번 포트    등록되지 않음

스위치는 호스트 C가 어느 포트에 연결되어 있는지 모른다.

따라서 프레임이 들어온 1번 포트를 제외한 2번, 3번, 4번 포트로 프레임을 전달한다.

A ─ 1번 포트 → 스위치

스위치
├─ 2번 포트 → 호스트 B가 수신 후 폐기
├─ 3번 포트 → 호스트 C가 수신
└─ 4번 포트 → 호스트 D가 수신 후 폐기

플러딩은 허브와 비슷하게 여러 포트로 전송하지만 다음 차이가 있다.

- 허브: MAC 주소를 해석하지 못해 항상 모든 포트로 전달
- 스위치: 수신지 MAC 주소를 모르거나 브로드캐스트일 때만 플러딩


10. 포워딩 Forwarding

포워딩은 수신지 호스트가 연결된 포트로 프레임을 전달하는 동작이다.

MAC 주소 테이블에 수신지 MAC 주소가 등록되어 있으면 해당 포트로만 프레임을 전달한다.

예시

MAC 주소 테이블

포트        MAC 주소
1번 포트    호스트 A
2번 포트    호스트 B
3번 포트    호스트 C
4번 포트    호스트 D

호스트 A가 호스트 C에게 프레임을 보낸다.

스위치는 호스트 C가 3번 포트에 연결된 것을 알고 있으므로 3번 포트로만 프레임을 전달한다.


11. 필터링 Filtering

필터링은 프레임을 불필요한 포트로 전달하지 않는 동작이다.

호스트 A가 호스트 C에게 프레임을 보내면 스위치는 다음과 같이 처리한다.

- 호스트 C가 연결된 포트: 포워딩
- 호스트 B와 D가 연결된 포트: 필터링

프레임의 수신지가 프레임이 들어온 포트와 같은 포트에 존재한다면 다른 포트로 프레임을 내보내지 않는다.


12. 에이징 Aging

MAC 주소 테이블의 정보는 영구적으로 저장되지 않는다.

MAC 주소 테이블에 등록된 포트에서 일정 시간 동안 해당 MAC 주소의 프레임을 받지 못하면 스위치는 해당 항목을 삭제한다.

이러한 기능을 에이징이라고 한다.

에이징이 필요한 이유는 다음과 같다.

- 호스트가 다른 포트로 이동할 수 있음
- 케이블 연결이 변경될 수 있음
- 오래된 MAC 주소 정보가 남아 있으면 잘못된 포트로 프레임을 전달할 수 있음


13. MAC 주소 학습 과정 전체 정리

호스트 A가 호스트 C에게 처음 프레임 전송
        ↓
스위치는 송신지 MAC 주소 A를 학습
        ↓
MAC 주소 테이블에 수신지 C가 없음
        ↓
들어온 포트를 제외한 모든 포트로 플러딩
        ↓
호스트 C만 프레임 수신
        ↓
호스트 C가 응답 프레임 전송
        ↓
스위치는 송신지 MAC 주소 C를 학습
        ↓
이후 A와 C의 위치를 모두 알고 있음
        ↓
다음 프레임부터 필요한 포트로만 포워딩


14. 스위치의 전달 방식 정리

수신지 MAC 주소를 알고 있음

→ 해당 포트로만 포워딩
→ 나머지 포트는 필터링


수신지 MAC 주소를 모름

→ 들어온 포트를 제외한 모든 포트로 플러딩


수신지가 브로드캐스트 주소임

→ 들어온 포트를 제외한 모든 포트로 플러딩


수신지가 들어온 포트와 같은 포트에 존재함

→ 다른 포트로 전달하지 않고 필터링


일정 시간 동안 프레임을 받지 못함

→ MAC 주소 테이블의 해당 항목 삭제
→ 에이징


15. 브리지

브리지(bridge)는 데이터 링크 계층에서 동작하며 스위치와 유사한 장비이다.

브리지의 주요 기능은 다음과 같다.

- 네트워크 영역 구분
- 콜리전 도메인 분리
- 네트워크 확장
- MAC 주소 학습
- 프레임 포워딩
- 프레임 필터링

브리지와 스위치의 기본 원리는 비슷하다.

하지만 일반적으로 스위치가 브리지보다 포트 수가 많고 처리 속도가 빠르며 다양한 기능을 제공한다.

따라서 단일 장비로서의 브리지는 스위치에 비해 사용 빈도가 감소했다.

스위치를 멀티포트 브리지라고 설명하기도 한다.


16. VLAN

VLAN은 Virtual LAN의 약자이다.

VLAN은 한 대의 물리적인 스위치를 여러 개의 논리적인 LAN처럼 나누어 사용하는 방법이다.

하나의 스위치에 연결되어 있어도 서로 다른 VLAN에 속한 호스트들은 서로 다른 LAN에 존재하는 것으로 간주된다.


VLAN을 사용하지 않은 경우

한 대의 스위치
├─ 개발부 호스트
├─ 총무부 호스트
├─ 영업부 호스트
└─ 기타 호스트

모든 호스트가 하나의 LAN과 하나의 브로드캐스트 도메인에 속한다.


VLAN을 사용한 경우

한 대의 스위치
├─ VLAN 10 개발부
├─ VLAN 20 총무부
└─ VLAN 30 영업부

물리적으로는 하나의 스위치이지만 논리적으로 서로 다른 LAN으로 분리된다.


17. VLAN의 장점

(1) 브로드캐스트 도메인 분리

VLAN마다 서로 다른 브로드캐스트 도메인이 만들어진다.

한 VLAN에서 발생한 브로드캐스트는 일반적으로 다른 VLAN으로 전달되지 않는다.


(2) 불필요한 트래픽 감소

브로드캐스트가 필요한 VLAN 안에서만 전달되므로 불필요한 트래픽을 줄일 수 있다.


(3) 성능 향상

브로드캐스트 범위가 작아져 네트워크 장비와 호스트가 처리해야 하는 트래픽이 감소한다.


(4) 보안 향상

부서나 사용자 그룹을 VLAN으로 분리하여 서로의 네트워크 접근을 제한할 수 있다.


(5) 유연한 네트워크 구성

물리적인 위치가 아니라 부서와 역할에 따라 논리적으로 LAN을 구성할 수 있다.


18. VLAN과 브로드캐스트 도메인

VLAN은 사실상 서로 다른 LAN이다.

따라서 VLAN이 다르면 브로드캐스트 도메인도 달라진다.

예시

한 대의 스위치
├─ VLAN 2
│   ├─ 호스트 A
│   └─ 호스트 B
│
└─ VLAN 3
    └─ 호스트 C

호스트 A와 B는 VLAN 2에 속하므로 같은 LAN에 속한다.

호스트 C는 VLAN 3에 속하므로 A, B와 다른 LAN에 속한다.

VLAN 2에서 발생한 브로드캐스트는 VLAN 3으로 전달되지 않는다.


19. 서로 다른 VLAN 간 통신

서로 다른 VLAN은 서로 다른 네트워크로 간주한다.

따라서 일반적인 데이터 링크 계층 스위치만으로는 서로 다른 VLAN 사이에서 직접 통신할 수 없다.

서로 다른 VLAN끼리 통신하려면 다음과 같은 네트워크 계층 장비가 필요하다.

- 라우터
- 3계층 스위치 Layer 3 Switch

서로 다른 VLAN 사이의 통신을 Inter-VLAN Routing이라고 한다.


20. 포트 기반 VLAN

포트 기반 VLAN은 스위치의 포트에 VLAN을 할당하는 방식이다.

특정 포트에 VLAN 번호를 설정하고, 해당 포트에 연결된 호스트를 그 VLAN에 참여시킨다.


포트 기반 VLAN 구조

스위치 포트

1번 포트 → VLAN 1
2번 포트 → VLAN 1
3번 포트 → VLAN 2 → 호스트 A
4번 포트 → VLAN 2
5번 포트 → VLAN 2 → 호스트 B
6번 포트 → VLAN 3 → 호스트 C
7번 포트 → VLAN 3
8번 포트 → VLAN 1


정리

- 호스트 A와 B는 VLAN 2에 속한다.
- 호스트 A와 B는 같은 LAN에 속한 것으로 간주한다.
- 호스트 C는 VLAN 3에 속한다.
- 호스트 C는 A, B와 다른 LAN에 속한 것으로 간주한다.


포트 기반 VLAN의 특징

- 호스트가 연결된 포트에 따라 VLAN 결정
- 설정과 관리가 비교적 간단
- 호스트를 다른 포트로 옮기면 새로운 포트의 VLAN 설정을 적용받음


21. MAC 기반 VLAN

MAC 기반 VLAN은 호스트의 MAC 주소에 따라 VLAN을 결정하는 방식이다.

관리자는 MAC 주소와 VLAN의 관계를 미리 설정한다.

프레임의 MAC 주소를 확인하여 해당 호스트가 어느 VLAN에 속할지 결정한다.


MAC 기반 VLAN 예시

MAC 주소                  VLAN
AA:AA:AA:AA:AA:01        VLAN 10
BB:BB:BB:BB:BB:02        VLAN 10
CC:CC:CC:CC:CC:03        VLAN 20


MAC 기반 VLAN의 특징

- 연결된 포트가 아니라 MAC 주소를 기준으로 VLAN 결정
- 호스트가 다른 포트로 이동해도 같은 VLAN에 속할 수 있음
- MAC 주소와 VLAN의 대응 관계를 관리해야 함


22. 포트 기반 VLAN과 MAC 기반 VLAN 비교

포트 기반 VLAN

- 기준: 스위치 포트
- 설정이 비교적 간단
- 호스트가 포트를 이동하면 VLAN이 달라질 수 있음
- 일반적으로 많이 사용


MAC 기반 VLAN

- 기준: 호스트의 MAC 주소
- 호스트가 포트를 이동해도 같은 VLAN 유지 가능
- MAC 주소 등록과 관리 필요
- 포트 기반 방식보다 관리가 복잡할 수 있음


23. 액세스 포트와 트렁크 포트

액세스 포트 Access Port

일반적으로 하나의 VLAN에 속한 호스트를 연결하는 포트이다.

예시

- 사용자 컴퓨터
- 프린터
- 일반 서버


트렁크 포트 Trunk Port

여러 VLAN의 프레임을 하나의 연결을 통해 전달하는 포트이다.

주로 다음 장비 사이를 연결할 때 사용한다.

- 스위치와 스위치
- 스위치와 라우터
- 스위치와 3계층 스위치

트렁크 포트에서는 프레임이 어느 VLAN에 속하는지 구분하기 위해 VLAN 태그를 사용한다.

대표적인 VLAN 태깅 표준은 IEEE 802.1Q이다.



정보처리기사 핵심 정리

1. 계층별 대표 장비

물리 계층

- 리피터
- 허브

데이터 링크 계층

- 브리지
- 스위치


2. 허브

- 물리 계층 장비
- MAC 주소를 인식하지 못함
- 수신한 신호를 다른 모든 포트로 전달
- 반이중 통신
- 하나의 콜리전 도메인
- 충돌 가능
- CSMA/CD 사용


3. 리피터

- 물리 계층 장비
- 약해지거나 왜곡된 신호를 재생
- 신호 전송 거리 연장
- MAC 주소와 프레임 내용은 해석하지 않음


4. 콜리전 도메인

- 충돌이 발생할 수 있는 영역
- 허브에 연결된 모든 호스트는 하나의 콜리전 도메인
- 스위치는 포트별로 콜리전 도메인을 분리


5. CSMA/CD

- 반이중 이더넷에서 사용
- 매체 사용 여부 확인
- 충돌 발생 시 전송 중단
- 잼 신호 전송
- 임의의 시간 동안 대기
- 재전송
- 현대적인 스위치 기반 전이중 이더넷에서는 필요하지 않음


6. 스위치

- 데이터 링크 계층 장비
- MAC 주소를 인식
- MAC 주소 테이블 사용
- 송신지 MAC 주소를 학습
- 수신지 MAC 주소로 전달 포트 결정
- 전이중 통신 지원
- 포트별로 콜리전 도메인 분리
- VLAN 지원


7. 스위치의 주요 동작

학습 Learning

- 송신지 MAC 주소와 프레임이 들어온 포트의 관계 저장


플러딩 Flooding

- 수신지 MAC 주소를 모를 때 여러 포트로 전달
- 들어온 포트는 제외


포워딩 Forwarding

- 수신지가 연결된 포트로 프레임 전달


필터링 Filtering

- 불필요한 포트로 프레임을 전달하지 않음


에이징 Aging

- 일정 시간 사용되지 않은 MAC 주소 테이블 항목 삭제


8. VLAN

- Virtual LAN
- 한 대의 물리적 스위치를 여러 논리적 LAN으로 분리
- VLAN별로 브로드캐스트 도메인 분리
- 불필요한 트래픽 감소
- 성능과 보안 향상
- 서로 다른 VLAN 간 통신에는 라우터 또는 3계층 스위치 필요


9. VLAN 종류

포트 기반 VLAN

- 스위치 포트에 따라 VLAN 결정


MAC 기반 VLAN

- 호스트의 MAC 주소에 따라 VLAN 결정


10. VLAN 포트

액세스 포트

- 일반적으로 하나의 VLAN 전달
- 호스트 연결에 사용


트렁크 포트

- 여러 VLAN의 프레임 전달
- 스위치 간 연결 등에 사용
- IEEE 802.1Q 태그 사용


11. 허브와 스위치 최종 비교

허브

- 물리 계층
- 비트와 신호 처리
- MAC 주소 인식 불가능
- 모든 포트로 신호 전달
- 반이중 통신
- 하나의 콜리전 도메인
- CSMA/CD 필요


스위치

- 데이터 링크 계층
- 이더넷 프레임 처리
- MAC 주소 인식 가능
- 필요한 포트로 프레임 전달
- 전이중 통신
- 포트별로 콜리전 도메인 분리
- CSMA/CD 불필요
- VLAN 구성 가능


핵심 암기 문장

허브는 수신한 신호를 다른 모든 포트로 전달하는 물리 계층 장비이다.

허브에 연결된 모든 호스트는 하나의 콜리전 도메인에 속한다.

CSMA/CD는 충돌을 완전히 방지하는 방식이 아니라 충돌을 감지하고 처리하는 방식이다.

스위치는 프레임의 송신지 MAC 주소를 이용하여 MAC 주소를 학습한다.

스위치는 수신지 MAC 주소를 이용하여 프레임을 전달할 포트를 결정한다.

수신지 MAC 주소를 모르면 들어온 포트를 제외한 모든 포트로 플러딩한다.

VLAN은 하나의 물리적 스위치를 여러 개의 논리적인 LAN으로 분리하는 기술이다.

VLAN이 다르면 브로드캐스트 도메인도 달라진다.

서로 다른 VLAN끼리 통신하려면 라우터 또는 3계층 스위치가 필요하다.
